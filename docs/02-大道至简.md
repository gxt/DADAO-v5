# 大道至简

本体系架构借DADAO之名，寓意简单且实用。

- 简单的真实含义：每个系统都很复杂，其设计者都是盖世奇才；然后因为受限于各种接口与依赖，需要进行各种妥协，因此只能采用各种方式进行修修补补；
Dadao希望利用清晰简洁的内部设计和接口逻辑让多个系统尽量按照其本意顺畅运转起来。
就好像两个轮子要联动，可以把两个轮子做成相互咬合的齿轮，也可以用一根连动杆将速率一致的部位连接起来；
而不是在两个轮子旁边分别安放一个监控器，然后增加通知模块和同步模块，然后每个轮子有变化的时候相互通知，然后进行同步。
- 实用的真实含义：计算机系统处处都是权衡，很多权衡的真实原因是性能、成本和历史的包袱。
Dadao没有历史的包袱，也不刻意追求高性能，更不存在成本问题，所以一个底线就是可实用化；实用的评价指标就是模拟器和FPGA可实现且其性能可接受。

DADAO的版本号拟遵循语义化版本控制规范SemVer 2.0.0： <https://semver.org/lang/zh-CN/> 。
当前处于开发初始阶段，因此主版本号为零，即（0.y.z），一切都可能未事先声明而随时被改变。

## 设计之TAO概述

计算机系统处处是权衡。Dadao试图在理论和实践之间取得一种权衡，使得该架构既可以为一些理论想法提供探索的基础，又不能过于理想化而无法真正形成可用系统。

在设计顺序上，与传统的设计不同：

- 设计之初基于经验，设计过程中边迭代边改进，设计之末归于评测。
- 既非软件设计来指导硬件设计，也非硬件设计来指导软件设计；甚至于没有刻意遵循先定义ISA再开发软件和硬件，而是开发过程中逐步定义ISA
- 实现并非是设计的附庸，而是相互依存，相辅相成；因此，并非是先设计再实现，而是先做好整体的构思，然后开始实现，边实现边设计，边设计边实现
- 几个紧密相关的系统同时进行设计和实现，然后在此过程中进行设计改进

***DRY原则***

- Don't Repeat Yourself，避免重复造轮子
- 系统软件中，由于要支持多种体系架构，通常都会有generic的实现，Dadao的开发移植过程主要参考了generic的实现，避免重复造轮子

## 指令系统设计之TAO

所谓道生一、一生二、二生三、三生万物，在计算机系统中，三也是一个特殊的存在。
例如，在二进制中，二的三次方是8，故一个字节是8位，64位机器的字长是8个字节；一个cache line通常是64个字节，是8个8字节；一个page是64KiB。
Dadao的设计中，有意的以8为单位进行划分，例如指令位域的划分，寄存器的设计，再比如ABI中复合数据类型的对齐采用了8字节的对齐（对比AMD64，则采用了4字节对齐）

***32位固定长度，64位字长***

- 设计之初定下64位字长，没有32位的包袱，因此，并非在一个完备的32位指令系统上修修补补，为指令设计留下了足够的位域空间
- 设计的关键在于取舍，有舍才有得；不考虑16位长度的指令扩展，因此，不会对指令位域的使用做出过多限制
- 通常的RISC指令系统因为定长指令的位域固定，所以要物尽其用，而dadao在指令定义上更为自然，没有刻意追求所谓的精简，即reduced，同时，更好地利用了规整的位域，进行了一些具体功能上的可选择性，如逻辑指令的6位，多load多store
- 遵循`Simple is beautiful`的设计理念；但凡事总有例外，指令规整性的例外是rwii类型的立即数赋值操作，寄存器的例外是每个寄存器组的`0`号

***指令规整，采用了8/6/6/6/6的设计***

- 基本上所有指令都是规整的指令编码：256个opcodes，16个预留给hint指令，96个用户态指令，16个特权指令；
- 6位的操作数域符合了64位的设计理念，同时也限定了寄存器个数，6位的操作数域名称为ha/hb/hc/hd；
- opcode只区分了major-opcode和minor-opcode，即最高8位和ha位域，简化了opcode的判断；
- 通过规整的RISC指令，能够在体现软件本身的语义同时，避免复杂的软件实现和硬件实现；指令域的设计更为规整，宁可留白，也不刻意增加一些很少被用到的额外功能或者功能组合；
- 规整的编码可以促进编码的有效利用，dadao在进行编码设计时如果有额外的6位，会用作多个寄存器的选择，或者64位数据中的位数选择，从而扩展该条指令的应用范围；
- 精简的操作数；不在操作数上做文章，对比：arm的操作数可以是左移、右移后的结果，这种在一个指令中合并多个功能，增加了编译优化的难度，CPU设计也更复杂
- 部分指令可以采用四个操作数，优点是语义更为丰富，缺点是增加了寄存器堆的设计难度；例如乘除指令、条件赋值指令等

***取消CZSO标志位***

- 不提供专门的标识位寄存器，硬件设计上去除了CZSO的限制；既防止了为了标志位定义额外的指令，又解决了很多语义上的隐藏联系；重点是简化了程序员可见的ISA抽象层；
- 虽然编译器作为转换层对这类差异进行了屏蔽，但是软硬件之间的这种理解上的差异，即硬件采用标识符的各种组合来实现软件思维中不同数据类型的大小判断，对理解和实现的影响都不容忽视；
- Dadao通过寄存器中的数值为正、负、零等来判断是否满足条件，更符合软件设计开发人员的逻辑思维判断方式
- 事实上，程序通常不判断标志位，这类指令可以舍弃标志位，而需要判断的时候，则通过部分指令生成完整结果来实现
- 取消CZSO之后，加减指令无需区分有符号数还是无符号数；以add指令为例，在不同的操作数类型情况下分开不同的溢出处理方案

***立即数赋值指令的设计***

- SimRISC设计了专门的立即数赋值指令，在规整的同时，保持了灵活性；这一类指令可以直接对各种需要很多位数的立即数的情况进行赋值，从而避免采用ld指令从函数结尾取立即数，也就避免了dcache的污染
- 在定长指令系统中实现全字长的立即数赋值，既没有临时寄存器的参与，也不使用额外的存储空间
- 具体操作可以先用setzw/setow设置16位，然后orw/andnw进行部分位的改动。因此，对于16位的short类型，可以一条指令设置完成；对于32位的int类型，也只需要两条指令。
- 所增加的指令还可以支持其他功能：setow和setzw可以直接生成部分立即数，orw和andnw可以直接对相应位置1或置0，在逻辑操作、驱动程序里也都非常有用
- 对比：对于全字长的数据，arm中采用的是ldr rx, [pc, imm]指令，通过相对寻址从代码节中读取数据，既造成dcache的污染，也增加了一次访存

***多个连续数据的处理***

- 寄存器赋值扩展为多个连续的寄存器赋值，与multiload/multistore对应，在寄存器个数扩展为64个的情况下，这一扩展很有必要
- 扩展multiload/multistore功能，可以一条指令处理多个寄存器的读写操作

***条件赋值指令***

- 条件赋值指令是增加IPC的一类重要指令，Dadao也对此进行了支持；
- 一种极端情况：部分RISC架构支持带条件码的指令，通过conditional code的设置，只有当该条件码对应的条件为真时，才执行该指令；Dadao则只支持条件赋值指令，既避免了位域的滥用，也有效减少了分支跳转的出现
- Dadao的cscc指令与cmovcc的区别在于：cmovcc在条件满足时赋值，不满足时不赋值；而cscc在条件满足时赋值，不满足时也赋值
- 四个操作数的条件赋值指令，为编译提供了更好的灵活性

## 寄存器设计之TAO

***寄存器设计***

- 寄存器分组；对比x86和arm都是通用加浮点；Dadao把基址寄存器和返回地址寄存器单独分组
- 基址寄存器的设计：参见下面的RB的设计
- 返回地址寄存器的设计：参见下面的RAS的设计
- 每组寄存器的0号寄存器是特殊寄存器，rd0在很多ISA中都有类似设计，rb0则解决了绝对寻址和相对寻址的指令设计问题，rf0则复用为fcsr寄存器
- 0号寄存器只是辅助性功能，而不能将简单的事情搞复杂，例如rb0只读，不能在add-rb或ldrb指令中被赋值，再比如rd0在四操作数的时候做为写入寄存器，可以表示舍弃操作结果

***基址寄存器的设计***

- 将基址寄存器从数据寄存器中剥离出来，可以让数据寄存器更多的参与到运算中，而将地址的处理独立出来
- 无论绝对寻址还是相对寻址都需要基址寄存器，事实上，在指令设计上，基址寄存器的位域是明确且固定的
- 思考一下代码空间和数据空间的区别：1、代码空间只读，是以相对地址为主，跳转位置通常集中在一个区域中；2、数据空间可读可写，是以绝对地址为主，位置不集中；3、所以，数据空间的LD/ST指令主要用绝对地址，代码空间的JUMP/BR/CALL指令主要用相对地址；
- 在工具链中可以更好的提供基址寄存器的支持：在gcc编译器中，是明确区分代码和数据的，symbol_ref是data，label_ref是code；
- 链接之后的空间划分，也是明确区分代码和数据，但是，编译器经常会在代码中混入只读数据，这部分支持需要考量
- 将当前指令地址编码为0号，可以将绝对地址和相对地址进行统一处理；ld/st指令可以直接用rb0组成symbol的地址；否则，需要采用额外的多条指令进行拼接，并且还需要额外的一个寄存器
- 为基址寄存器专门增加了addrb/subrb/cmprb指令

***返回地址栈的设计***

- 显式的RAS可以把ra寄存器的保存恢复操作从函数的homekeeping中释放出来，从而减少其对cache的污染；同时，对microarchitecture的优化有明显好处
- Dadao采用了RegRAS + MemRAS的设计方案，从而在调用深度不超过63个时，完全可以用RegRAS负责解决；而在递归调用等情况下，则有MemRAS协助解决
- 对于递归程序，还是会有性能上的影响；可针对递归的情况进行专门的优化：
  - 方案如下：返回地址的可用位数为程序的可见空间，缺省为48位，可以利用高16位或高8位作为递归计数，将相同的返回地址存放在同一个RA寄存器中，从而更为有效的利用RegRAS
- 把RAS和传统的栈分离为两个栈的好处还在于：只有一个栈时，返回地址需要存放在栈上，当程序出错时，可能导致取回错误的返回地址，从而跑飞的错误现象；而分离为两个栈，则维护了正确的函数调用和返回关系，代码执行逻辑不易出错，程序错误表现为数据错误。

***浮点rf0寄存器的设计***

- 浮点rf0寄存器复用为fcsr寄存器（浮点配置状态寄存器），延续了所有寄存器组的0号寄存器为特殊寄存器的惯例
- 简化了浮点指令的设计，无需为读取浮点状态或设置舍入模式等操作提供额外的指令
- rf0既是单精的qNaN，也是双精的qNaN，可以在浮点程序中作为qNaN使用，如果程序中误用，计算结果也可追溯

## ABI设计之TAO

**寄存器使用**
* 7号寄存器作为intra-procedure-call scratch reg，这是arm的一种用法，简单易用，“一足矣”
* rd/rb/rf中各有16个参数寄存器，且返回值寄存器与参数寄存器反向；除非一些极端情况，参数都是可以用寄存器来传递
* rd1专门用作errno，为系统软件和应用软件之间，以及用户态和特权态之间搭建更简易的桥梁；解决了多线程中的errno共享问题，并且对性能有微小的提升
* 系统调用号存放在rd15寄存器中

## 系统软件设计理念

* 系统软件的原则之一：Warning is error（FOR ALL）
** 目标：消除所有的warning
* 系统软件的原则之一：注意区分arch-dep和arch-undep，尽量不修改或者少修改arch-undep代码

**decodetree**
* 参考qemu的解码树的方案，对汇编器、反汇编器、模拟器中的不同解码的处理提供自动化的代码转换
* 在指令位域产生变化时，可以同步而快速的完成系统软件的修改

**汇编预处理**
* 汇编指令，两套助记符，一套是开发人员看的，称之为MNEMONIC，一套是按位域顺序的，称之为RAWFIELD
* 在RAWFIELD助记符下，操作数的顺序在汇编语言和指令编码上是保持一致的。优点是简化汇编语言的实现，减少不必要的复杂性；汇编语言本身，直接使用的人很少，没有必要增加过多的符号或打乱顺序来增强所谓的可阅读性。
* 在助记符的处理上：更直观的助记符：有符号数的指令助记符增加了s后缀，以区分无符号数的u后缀：优点是将数据类型明确添加到助记符中，避免歧义；例如：cmp改为cmps，div改为divs
* 助记符的长度：统一为3字符至6字符
