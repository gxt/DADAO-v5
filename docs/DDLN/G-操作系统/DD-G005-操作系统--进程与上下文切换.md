# 操作系统 -- 进程与上下文切换

**本册要点**

- 上下文 = **通用寄存器 + 返回地址栈（深度与内容）+ 栈指针 + 地址空间**。
- 返回地址栈是硬件结构：切换时必须保存**深度**，否则返回跳到别人的地址。
- 内核栈与用户栈分离；进内核时换栈，出内核时恢复。
- 首次进入用户态靠**构造一个陷阱返回帧**，不是"跳过去"。
- 地址空间切换顺序固定：换基址/ASID → 显式失效 → 恢复寄存器。

## 1. 上下文切换要保存什么？

**答：** 四类：被调用者保存的通用寄存器、返回地址栈、栈指针、地址空间标识。

- **寄存器**：按 ABI 约定，被调用者保存集必须由切换代码处理。
- **返回地址栈**：稀疏的硬件结构，必须连同深度一起保存。
- **栈指针**：内核栈指针（用户栈指针在陷阱帧里）。
- **地址空间**：页表基址或 ASID。
- **判据**：切过去再切回来，所有状态与切之前一致。

## 2. 为什么返回地址栈是难点？

**答：** 因为它不是普通寄存器：深度可变、内容在硬件栈里；只保存"当前栈顶"会丢掉多层返回地址。

- **结构**：一个深度计数 + 若干条目（可能还有内存后备）。
- **保存**：深度 + 有效条目；恢复时按深度重建。
- **症状**：返回跳到别的进程地址、或返回地址错位一级。
- **代价**：每次切换多读写若干条。
- **判据**：多层调用后切换，返回路径仍正确。

## 3. 内核栈与用户栈怎么分？

**答：** 每个进程一个内核栈；陷入时从用户栈切到内核栈，退出时切回。

- **进入**：硬件或入口代码把栈指针换成内核栈。
- **保存**：用户栈指针存在陷阱帧里。
- **退出**：从陷阱帧恢复用户栈指针。
- **好处**：内核不被用户栈溢出破坏。
- **判据**：嵌套异常时内核栈不越界。

## 4. 首次进入用户态怎么构造？

**答：** 伪造一个"从异常返回"的帧：设好用户栈指针、返回地址、模式与掩码，然后走异常返回路径。

- **做法**：填陷阱帧 → 执行返回 → 落在用户入口。
- **不要**：直接跳转到用户地址（会跳过模式与掩码切换）。
- **必备字段**：返回地址、栈指针、前一模式、前一掩码。
- **判据**：第一次进入用户态后，能正常陷入回内核。

## 5. 地址空间切换的顺序是什么？

**答：** 先换基址或 ASID，再显式失效 TLB，最后恢复寄存器并返回。

- **顺序**：配置 → 失效 → 恢复 → 返回。
- **为什么**：配置不隐含失效；失效后才能保证新地址空间生效。
- **批量**：多个进程切换可以先累积配置，再统一失效。
- **代价**：全量失效很贵，尽量用 ASID 或区间失效。
- **判据**：切换后能正确访问新进程的页。

## 6. 切换的正确性怎么验证？

**答：** 两个进程来回切，检查寄存器、返回路径、地址空间三者都不串。

- **用例一**：两个进程交替打印，输出不交错。
- **用例二**：多层调用后切换，返回地址正确。
- **用例三**：一个进程写自己的页，另一个进程看不到。
- **用例四**：频繁切换不泄漏栈或返回地址栈条目。
- **判据**：长时间压力测试后状态仍一致。

## 7. 各家内核怎么做（对照）

**答：** 都用"进程/线程两层结构 + 一段汇编切换"，差别在有没有硬件返回地址栈、以及浮点状态是否惰性保存。

- **Linux**：任务结构 + 切换汇编，浮点状态惰性保存。
- **FreeBSD**：进程与线程两层 + 陷阱帧。
- **Windows**：进程对象 + 线程对象，内核栈与线程绑定。
- **macOS**：任务与线程两层，异常经 Mach 层。
- **Minix**：固定进程表 + 消息队列，切换简单。
- **Unix（历史）**：进程表 + 保存/恢复寄存器例程。

**是统一标准吗**：不是；共同点是"切换代码必须知道自己保存了哪些状态"。

## 背景知识

### 术语与概念

- **上下文**：寄存器、返回地址栈、栈指针、地址空间。
- **返回地址栈**：硬件维护的返回地址结构。
- **陷阱帧**：异常进入时保存的现场。
- **内核栈**：每进程一份的内核态栈。
- **ASID**：地址空间标识。

### 对照

**切换实现**

- **保存深度 + 条目**：本设计。
- **只保存栈顶**：会丢多层返回。
- **判据**：多层调用后能否正确返回。
