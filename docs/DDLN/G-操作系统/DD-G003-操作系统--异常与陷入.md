# 操作系统 -- 异常与陷入

**本册要点**

- 移植早期第一件事是**装向量**：没有向量，任何异常都变成静默停机。
- 向量按 cfx 分配：四种模式的监视器 + hart、串口、物理内存、页表各自的入口。
- 进入的十步里，**大半由硬件完成**；软件只需保证掩码、切换目标、向量地址事先配好。
- `escape` 只能返回"原指令"或"下一条指令"（偏移 0/4），异常返回必须落在这两种语义上。
- 定时中断属于 hart，**不进模式监视器**——这是移植最常见的错配。
- 嵌套由软件保存现场；硬件不阻止，但会覆盖。

## 1. 为什么第一件事是装向量？

**答：** 因为内核一旦开始配置硬件就可能触发异常（对齐、权限、非法指令）；没有向量，异常进入空地址，表现为"卡死且无日志"。

- **先装后配**：先设向量与切换目标，再动其它寄存器。
- **四个模式**：每个模式的监视器各有一个向量。
- **设备与 hart**：串口、定时器、物理内存、页表也各有入口。
- **判据**：故意触发一次异常，能看到处理程序输出。
- **代价**：向量页要常驻、不能被换出。

## 2. 要装哪些向量？

**答：** 至少六类：四模式监视器、页表、hart（定时与核间）、串口、物理内存（DMA）；按需再补电源。

- **监视器**：用户、监狱、主管、超管各一个入口。
- **页表**：所有缺页与权限失败统一进它。
- **hart**：本地定时器与核间中断。
- **串口**：每个实例一位，进串口入口。
- **物理内存**：DMA 完成或出错。
- **电源**：关机/复位类，属系统控制，不按一般路径处理。

## 3. 十步进入流程里软件要做什么？

**答：** 软件只要保证"掩码、切换模式、切换掩码、向量地址"这四项事先配好；其余由硬件完成。

- **掩码**：按最小授权配置四类同步掩码与两类中断掩码。
- **切换**：设定陷入后切到哪个模式、用哪套掩码。
- **向量**：每个 cfx 每种模式一个入口地址。
- **现场**：硬件保存前一模式、前一掩码、原因、返回地址。
- **软件侧**：处理程序自己保存"可能被嵌套覆盖"的部分。

## 4. `escape` 的两种返回语义怎么用？

**答：** 偏移 0 表示重试触发指令；偏移 4 表示跳过它。异常返回必须明确选哪一种，否则会死循环或跳过必要工作。

- **偏移 0**：缺页处理完、权限修好后重试。
- **偏移 4**：不可恢复但可忽略的指令（如探测性访问）。
- **陷阱帧**：目标必须是当前 cfx，且当前 cfx 有有效帧。
- **非法偏移**：手工编码非零低位会被判非法指令。
- **判据**：每条异常路径都能说出"返回哪"。

## 5. 嵌套与屏蔽怎么配合？

**答：** 用切换掩码屏蔽同类异常，减少无谓嵌套；处理程序自己保存现场，防止被覆盖。

- **屏蔽**：进入后切换到更严格的掩码，挡住同类。
- **保存**：把现场存到栈或暂存寄存器。
- **恢复**：退出前恢复掩码与现场。
- **风险**：屏蔽过宽会丢中断；过窄会递归。
- **判据**：嵌套两层后仍能正确返回。

## 6. 定时中断为什么必须进 hart？

**答：** 因为定时器属于 hart（每核一个比较器），中断源是 hart，路由就进 hart 的入口；进监视器等于找错了处理者。

- **归属**：谁产生中断，谁处理。
- **后果**：装到监视器上会表现为"tick 不动"。
- **全局时间**：只读、不产生中断，不能替代定时器。
- **核间中断**：同样进 hart。
- **判据**：定时中断处理程序里能看到"确实被调用"。

## 7. 调试异常问题用什么手段？

**答：** 三类：原因表（每 cfx 独立）、待处理位、计数寄存器；再配合最小输出。

- **原因码**：one-hot 且每 cfx 独立，先读目标 cfx 再查它的表。
- **待处理位**：被屏蔽的中断挂在这里，读它可判断"是不是被挡了"。
- **计数**：trap / 同步 / 异步次数能证明"进没进过"。
- **最小输出**：处理程序第一行打印 cfx 与原因。
- **判据**：能否区分"没触发"与"触发但被屏蔽"。

## 8. 各家内核怎么做（对照）

**答：** 都用"陷阱帧 + 分派"，差别在异常与中断是否同一条路径、以及有没有第二层（信号）语义。

- **Linux**：陷阱表 + 中断描述符，异常与中断共用入口后分派。
- **FreeBSD**：trapframe 保存现场，异常与中断统一分派。
- **Windows**：陷阱帧 + 中断优先级（IRQL），异常与中断是两套语义。
- **macOS**：Mach 异常一层、BSD 信号一层，两层各管一段。
- **Minix**：内核调用与异常进内核，服务出错由重启服务接管。
- **Unix（历史）**：trap 表直接对应信号编号。

**是统一标准吗**：不是；共同点是"进入内核的第一段代码只做保存与分派"。

## 背景知识

### 术语与概念

- **向量**：每个 cfx 每种模式的异常入口。
- **切换掩码**：陷入后生效的掩码。
- **陷阱帧**：`escape` 依赖的现场。
- **原因表**：每 cfx 独立的 one-hot 编码。
- **待处理位**：被屏蔽中断的挂起记录。

### 对照

**异常安装**

- **先装向量再配硬件**：本设计。
- **先配硬件后装向量**：常见失败路径。
- **判据**：能否故意触发一次并看到输出。
