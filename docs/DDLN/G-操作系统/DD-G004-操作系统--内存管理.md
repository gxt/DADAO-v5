# 操作系统 -- 内存管理

**本册要点**

- 虚拟地址 **42 位**、物理地址 **56 位**；内存窗口必须开页表，不走直通。
- 只有**一份页表基址**：切换地址空间靠"换基址或换 ASID + 显式失效"。
- 页大小 64 KiB，另有 512 MiB 超页；每页再分 8 个小页，按需加载粒度是 8 KiB / 64 MiB。
- 权限两套：页表的模式许可（HSJU）+ 读写执行（R/W/X）；与 cfx 两轴权限互不替代。
- TLB 并入页表 cfx：没有独立开关，**写基址/ASID 都不隐含失效**。
- 缺页处理要按固定优先级判断：缺失 → 小页 → 模式许可 → 读写执行。

## 1. 地址口径是什么？

**答：** CPU 地址 48 位，高 6 位选分区：`0` 是内存窗口（虚拟地址 42 位），`1–63` 是 cfx 内部空间。

- **内存窗口**：必须经页表转成 56 位物理地址。
- **关掉转换**：窗口访存直接报核内地址错误，不直通。
- **cfx 内部空间**：不经过页表。
- **物理地址**：56 位，比虚拟地址宽——映射可以"低位到高位"。
- **判据**：任一地址先判断它属于哪个分区。

## 2. 只有一份页表基址怎么支撑多进程？

**答：** 靠 ASID：切换进程时写新 ASID（或新基址），再失效 TLB；进程多时靠换出页表页。

- **基址**：64 KiB 对齐，无有效位；是否启用由开关决定。
- **ASID**：16 位，用于区分地址空间。
- **切换步骤**：写 ASID/基址 → 显式失效 → 保证失效完成。
- **早期映射**：启动时先建一个最小映射（内核 + 串口），再逐步扩展。
- **判据**：切换后旧进程的页不再命中。

## 3. 两级页表与超页怎么选？

**答：** 小对象用 64 KiB 普通页，大块连续区域用 512 MiB 超页；超页减少页表层级与 TLB 压力。

- **普通页**：两级索引 + 16 位页内偏移。
- **超页**：一级索引 + 29 位页内偏移，512 MiB 对齐。
- **用法**：内核直接映射、大块 DMA 缓冲适合超页；用户小对象用普通页。
- **代价**：超页内部碎片大，按需加载粒度也粗（64 MiB）。
- **判据**：这段内存是否"大且连续"。

## 4. 小页（fragment）怎么用于按需加载？

**答：** 每页分 8 份，页表里用位图标记哪份已在内存；缺页时只搬需要的那份。

- **粒度**：普通页每份 8 KiB；超页每份 64 MiB。
- **位图**：普通页用 8 位小页位；超页同理。
- **全置 1**：等价于整页加载，不需要按需加载时用。
- **收益**：省外存 I/O，不省物理内存（物理页要预留）。
- **判据**：缺页处理能否定位到"哪一份"。

## 5. 权限怎么配？

**答：** 页表里有模式许可位与读写执行位；内核按"最小权限"配：用户页允许用户态访问，内核页只允许特权态。

- **模式许可**：H/S/J/U 各一位，当前模式对应位为 1 才允许。
- **读写执行**：取指要执行位、读要读位、写要写位。
- **不做隐含放宽**：硬件不会"特权态自动覆盖用户页"，策略由内核定。
- **与 cfx 权限的关系**：cfx 权限管资源访问，页表权限管内存访问，两者独立。
- **判据**：越权访问能被预期的异常捕获。

## 6. ASID 与失效怎么配合？

**答：** 切换地址空间后必须显式失效；失效有全部/单地址/区间，可带"忽略 ASID"标志。

- **不隐含**：写基址、写 ASID、开转换都不失效 TLB。
- **批量优化**：先改多个配置，最后做一次大范围失效。
- **全局页**：跨 ASID 复用，切换时不必失效（前提是映射一致）。
- **代价**：漏失效会出现"偶发读到上一个进程的页"。
- **判据**：每次切换都能指出失效点在哪。

## 7. 缺页处理路径怎么走？

**答：** 读原因码定位到具体缺失类型，再决定"分配/调入/复制/杀进程"；处理后按语义选择重试或跳过。

- **缺失类型**：一级缺失、超页缺失、超页小页缺失、二级缺失、普通页小页缺失。
- **权限类型**：模式许可不符、读/写/执行不符。
- **优先级**：缺失先于小页，小页先于模式许可，模式许可先于读写执行。
- **处理**：分配物理页 → 填页表 → 失效相关 TLB → 重试。
- **判据**：每种原因都有对应处理分支，且有测试覆盖。

## 8. 各家内核怎么做（对照）

**答：** 页表层级与分配器各家不同，但都把"缺页原因"当成第一分类依据。

- **Linux**：多级页表 + 伙伴分配器 + 页缓存，缺页按虚拟内存区域判断。
- **FreeBSD**：页结构 + 对象/影子链管理，缺页按对象回溯。
- **Windows**：页框数据库 + 工作集，页表由内存管理器统一维护。
- **macOS**：物理映射层 + 虚拟内存对象，缺页由对象提供后备。
- **Minix**：结构简单，区域管理与页表较直接。
- **Unix（历史）**：早期用段式或简单分页，功能有限。

**是统一标准吗**：不是；共同点是"先判断缺页类型，再决定补什么"。

## 背景知识

### 术语与概念

- **内存窗口**：需要页表转换的分区。
- **页表基址**：唯一一份，64 KiB 对齐。
- **超页**：512 MiB 大页。
- **小页（fragment）**：页内 8 分之一。
- **HSJU**：四种模式的访问许可位。
- **ASID**：地址空间标识。
- **缺页优先级**：缺失 → 小页 → 模式许可 → 读写执行。

### 对照

**页表设计**

- **两级 64 KiB + 超页 + 小页**：本设计。
- **多级 4 KiB 页**：通用设计。
- **判据**：页表大小、TLB 覆盖、按需加载粒度。
