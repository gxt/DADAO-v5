# 操作系统 -- 用户态与移植工程

**本册要点**

- 用户态的第一道门是**挂载 initramfs 并执行 init**；跑通它才算"进用户态"。
- 系统调用表**每架构一份**，调用号以最新规范为准；参数与返回值沿用函数调用约定。
- 错误码用**最小约定**：返回值负值表示错误，绝对值为错误号。
- 线程指针由内核在进程建立时设置好，用户库从固定寄存器读取。
- 首版**静态链接优先**：少一层加载器，问题面小一半。
- 工具链缺口按"生成 / 编译 / 运行"三阶段归类，不要笼统说"工具链有问题"。

## 1. initramfs 怎么挂？

**答：** 内核启动时把内存镜像当根文件系统挂载，然后执行其中的 init；镜像格式要简单、可校验。

- **格式**：打包的归档（可压缩），内核早期就能解析。
- **挂载**：作为根文件系统，或先挂到临时目录再切换。
- **init 路径**：由启动参数指定，缺省固定。
- **校验**：魔数与校验和，防止半截镜像。
- **判据**：能看到 init 的第一行输出。

## 2. 系统调用表怎么定？

**答：** 每架构一份表：调用号进固定寄存器、参数进约定寄存器、返回值进固定寄存器；调用号以最新规范为准，讲义不写死编号。

- **调用号**：只增不改；表由架构维护。
- **参数**：沿用函数调用约定，内核入口再存成统一现场。
- **返回值**：整数放通用返回寄存器，指针放地址返回寄存器。
- **有内核之后**：半主机不再是唯一通道，退为**引导与调试**用途；两者不要混在一条路径上。
- **指针校验**：用户地址先验范围再访问。
- **判据**：一条最简单的系统调用能往返。

## 3. 最小错误码约定是什么？

**答：** 返回值负值表示错误、绝对值为错误号；合法负值（如指针差）不与系统调用返回值混用。

- **约定**：`< 0` 即错误；`-1` 到 `-N` 为错误号。
- **不做的**：完整错误号表、线程局部错误变量（首版可后置）。
- **风险**：与"合法的负返回值"冲突——所以只对返回"长度/指针"的调用适用。
- **文档**：在系统调用表里逐条标明返回类型。
- **判据**：错误路径能被用户程序区分。

## 4. 线程指针怎么给？

**答：** 内核在建立进程时把线程指针寄存器设好，用户库从固定寄存器读出；不需要动态链接器参与。

- **寄存器**：架构约定一个基址寄存器作为线程指针。
- **设置时机**：进程创建、exec、线程创建时。
- **用户库**：从该寄存器算自己的线程控制块。
- **判据**：线程局部存储能读写。
- **注意**：切换进程时要恢复该寄存器。

## 5. 为什么首版静态链接优先？

**答：** 因为动态链接要加载器、搜索路径、重定位三件套；任何一件没通，用户态都起不来。

- **静态**：单文件、无解释器依赖。
- **动态**：需要解释器路径、库搜索、符号解析；**能不能动态取决于加载器**（属资源管理层），不取决于库本身。
- **顺序**：先静态跑通 init 与基本工具，再加动态。
- **代价**：镜像大、升级麻烦。
- **判据**：init 能在无加载器的情况下启动。

## 6. 工具链缺口怎么归类？

**答：** 三阶段：生成阶段（编译/汇编/链接报错）、运行阶段（能生成但跑错）、环境阶段（模拟器或计时配置）。

- **生成阶段**：编译错误、链接重定位、汇编语法。
- **运行阶段**：代码生成错误、ABI 不符、未定义行为暴露。
- **环境阶段**：模拟器参数、计时精度、设备缺失。
- **用途**：不同阶段找不同人；混在一起只会互相推诿。
- **判据**：每个失败都能落到一个阶段。

## 7. 里程碑判据与回归怎么定？

**答：** 按三层判据设里程碑：日志、用户态、系统调用往返；每层都有可重跑的回归脚本。

- **里程碑一**：内核日志连续输出。
- **里程碑二**：initramfs 挂载并执行 init。
- **里程碑三**：系统调用往返与错误路径。
- **回归**：每次改动重跑三层；失败定位到层。
- **判据**：换机器、换日期，结果一致。

## 8. 各家内核怎么做（对照）

**答：** 用户态起步都是"挂根文件系统 → 启动第一个进程"，差别在有没有动态链接器、以及系统调用的入口形式。

- **Linux**：内存盘 + 每架构系统调用表，init 由内核直接执行。
- **FreeBSD**：内存盘根 + 系统调用表（编号与名称对应）。
- **Windows**：会话管理器拉起首个用户进程，系统调用经 ntdll 桩。
- **macOS**：启动服务管理器拉起用户态，动态链接器在内核外。
- **Minix**：服务进程体系，驱动与文件系统都在用户态，靠消息通信。
- **Unix（历史）**：init 进程 + 静态链接为主。

**是统一标准吗**：不是；共同点是"第一个用户进程必须能起来，否则后面无从谈起"。

## 背景知识

### 术语与概念

- **initramfs**：内存中的根文件系统镜像。
- **系统调用表**：每架构一份的调用号映射。
- **最小错误码**：负值返回、绝对值为错误号。
- **线程指针**：线程局部存储的基址寄存器。
- **静态链接**：库打进可执行文件。
- **三阶段缺口**：生成 / 运行 / 环境。

### 对照

**用户态起步**

- **先静态 + 内存盘**：本设计。
- **先动态 + 块设备**：问题面大，首版不建议。
- **判据**：能否在最短路径上看到 init 输出。
