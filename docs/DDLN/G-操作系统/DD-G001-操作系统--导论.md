# 操作系统 -- 导论

**本册要点**

- 目标：**单核 Linux 移植**，先把"能引导到用户态"做通，再谈多核与性能。
- 三层判据：**有内核日志 → 能进用户态 → 能完成一次系统调用并返回**。
- 首版取舍：块设备用内存盘、静态链接优先、错误码用最小约定。
- 两道已知硬墙：**时钟与异常投递**、**上下文切换**。
- 边界：机制在资源管理册，装配在系统集成册，判据在测试体系册。

## 1. 移植目标怎么定？

**答：** 目标不是"跑起一个发行版"，而是"一条可复现的启动链走到用户态，并能完成一次系统调用往返"。

- **可复现**：同输入、同配置、同结果。
- **最小闭环**：引导 → 控制台 → 时钟与中断 → 内存 → 进程 → 用户态。
- **不做的事**：多核、动态链接、复杂块设备、性能优化（首版）。
- **判据可执行**：每层都有可观察的输出或退出码。
- **反例**："内核没崩"不等于"起来了"。

## 2. 三层判据分别看什么？

**答：** 看输出、看进程、看往返——三者任何一层不过，就说明候选墙还在。

- **第一层**：早期控制台有内核日志（引导、内存、串口都通）。
- **第二层**：initramfs 挂载，第一个用户程序能跑。
- **第三层**：系统调用往返正确（参数、返回值、错误路径）。
- **用途**：定位"卡在哪一层"，而不是笼统说"起不来"。
- **代价**：每层都要先有观测手段。

## 3. 单核 MVP 的边界在哪？

**答：** 只做单核：核间中断、共享资源仲裁、缓存一致性都只留接口，不实现、不测试。

- **保留**：数据结构留出核编号与每核状态字段。
- **不实现**：核间中断投递、跨核失效广播、多核启动。
- **理由**：多核会把"每核私有 / 全系统共享"的边界问题放大，首版先把单核跑通。
- **代价**：将来加多核要改启动流程与锁设计。
- **判据**：代码里能否指出"这个决策是多核才需要的"。

## 4. 与相邻系列怎么分工？

**答：** 资源管理给机制，系统集成给装配，测试体系给判据，运行平台给环境；本系列只讲内核怎么用。

- **资源管理**：地址空间、页表、TLB、异常、设备寄存器。
- **系统集成**：工具链、C 库、工具集、根文件系统、镜像。
- **测试体系**：启动判定、系统接口测试、权限场景。
- **运行平台**：模拟器配置、计时精度、观测手段。
- **判据**：这段话是在说"机制是什么"还是"内核怎么用"。

## 5. 两道已知硬墙是什么？

**答：** 一是时钟与异常投递（没有可用时钟事件与向量，忙等永不退出），二是上下文切换（寄存器集与返回地址栈的保存恢复）。

- **墙一的表现**：卡在"等 tick 变化"的忙等循环。
- **墙一的解法**：装真实向量 + 用 hart 定时器做单次触发时钟事件 + 用本地周期计数做时钟源。
- **墙二的表现**：能进内核线程，但切不到用户进程。
- **墙二的难点**：返回地址栈必须按深度保存恢复，否则返回跳到别人的地址。
- **顺序**：先墙一，再墙二——没有时钟就没有调度。

## 6. 首版取舍是什么？

**答：** 内存盘、静态链接、最小错误码约定；先把"能跑通"与"能判定"做实。

- **块设备**：内存盘（initramfs），DMA 只做存在性验证。
- **链接**：静态优先，动态链接留到用户态稳定之后。
- **错误码**：返回值负值表示错误，绝对值为错误号；不做完整取值表。
- **多核**：不做。
- **代价**：后期要补动态链接、块设备、多核。

## 7. 已定与遗留

**已定（本期口径）**

- **单核 MVP**：多核与核间中断只在接口层预留，不实现、不测试。
- **块设备先用内存盘**：DMA 只做"存在性验证"，不作为首版依赖。
- **最小错误码约定**：系统调用返回负值表示错误，绝对值为错误号；错误号取值由用户态库与内核对齐，架构不规定；合法负值不得与错误返回值混用。
- **静态链接优先**：动态链接留到用户态稳定之后。

**仍待定**

- 上游基线的具体版本与"只写架构目录"的界线。
- 错误号的完整取值表（谁定义、谁维护）。
- 何时引入动态链接与多核。
- 性能相关配置（计时精度）是否纳入里程碑判据。

## 8. 各家内核怎么做（对照）

**答：** 同一件事在不同内核里的分工差别很大：有的把移植面收在一个架构目录里，有的靠硬件抽象层，有的干脆把服务搬到用户态。

- **Linux**：架构目录集中放启动、异常、页表、时钟；系统调用表每架构一份。
- **FreeBSD**：同样有架构目录，但总线与 DMA 抽象更早分层（总线空间、DMA 标签）。
- **Windows NT**：硬件抽象层 + 内核两层，中断按优先级（IRQL）管理，驱动模型独立。
- **macOS（XNU）**：Mach 微内核 + BSD 层混合，驱动走内核扩展框架。
- **Minix 3**：微内核，驱动与文件系统作为用户态服务进程，靠消息传递。
- **Unix（历史）**：以可移植性为目标，早期靠汇编层移植，后逐步抽象。

**是统一标准吗**：不是。共同点只有"把与硬件相关的部分隔离出来"这一原则。

## 背景知识

### 术语与概念

- **最小闭环**：能引导、能打印、能计时、能中断、能建进程、能进用户态。
- **三层判据**：日志 / 用户态 / 系统调用往返。
- **内存盘**：把根文件系统放进内存的镜像。
- **最小错误码**：负值返回、绝对值为错误号。
- **硬墙**：必须先解决才能继续的阻塞点。

### 对照

**移植策略**

- **先跑通再优化**：本设计。
- **先完备再启动**：常见失败路径，永远起不来。
- **判据**：能否在每一步给出可观察输出。
