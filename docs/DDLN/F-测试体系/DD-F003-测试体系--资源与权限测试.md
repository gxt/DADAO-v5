# 测试体系 -- 资源与权限测试

**本册要点**

- arch 测的是**资源访问与权限**，不是单条指令的算术语义。
- 用**状态矩阵**覆盖：模式 × 资源 × 操作。
- 判据是**现场**（原因码 + 上下文），不是"程序非零退出"。
- 负例可以机械枚举：保留编号、不存在的寄存器、非法窗口、越权访问。
- per-hart / per-system 与中断类资源（定时器、IPI、串口、电源）单独成组。

## 1. arch 到底测什么？

**答：** 测"谁能访问什么、越权时发生什么"：陷入与退出、cfx 寄存器读写、各类掩码、异常原因、跨 hart 与系统级资源。

- **访问路径**：寄存器读写、窗口访存、取指。
- **权限层次**：运行模式、资源掩码、地址转换权限。
- **异常形态**：原因码、现场保存、嵌套与重入。
- **资源类别**：monitor、地址转换、存储层次、执行资源、时间与设备。

## 2. 状态矩阵怎么建？

**答：** 三个维度：模式（user/jail/supv/hypv）× 资源（各 cfx 段）× 操作（读/写/陷入/退出/访存），每格给"期望成功或期望原因码"。

- **模式**：四种模式各有独立入口与能力集。
- **资源**：按 cfx 编号分段，不同段归不同模式所有。
- **操作**：寄存器访问、窗口访存、陷入/退出。
- **组合爆炸的控制**：先用"等价类"合并（同权限同行为的格合并），再对边界单独测。
- **缺口显式**：未覆盖的格登记理由，不静默跳过。

## 3. 为什么断言现场而不是退出码？

**答：** 因为退出码只能说明"程序结束了"，说明不了"该报的异常报了、报的原因对不对、现场保没保存"。

- **现场内容**：原因码、返回地址、前一模式与掩码、待处理位。
- **典型缺陷**：异常报了但原因码错；现场没保存导致返回错位；嵌套时覆盖了外层现场。
- **断言方式**：读现场并与期望逐字段比对。
- **代价**：需要能读现场的手段（模拟器接口或专用指令）。

## 4. 负例怎么枚举？

**答：** 四类可机械生成：保留的资源编号、不存在的寄存器编号、非法窗口地址、越权访问；每类都应有明确的期望原因码。

- **保留编号**：访问未实现的 cfx ⇒ 期望"非法指令"类原因。
- **不存在寄存器**：越界编号 ⇒ 期望"寄存器不存在"类原因。
- **非法窗口**：访问不在窗口内的地址 ⇒ 期望"窗口非法"。
- **越权**：低权限访问高权限资源 ⇒ 期望"权限不足"。
- **价值**：负例比正例更便宜，也更容易发现"静默通过"的实现缺陷。

## 5. per-hart / per-system 与中断怎么测？

**答：** 分开测：per-hart 资源看隔离性，per-system 资源看共享与仲裁；中断类（定时器、IPI、串口、电源）要测"置位—分发—处理—清除"全链。

- **隔离性**：一个 hart 的操作不应影响另一个 hart 的本地状态。
- **共享资源**：访问顺序与仲裁由软件约定，测试要能构造竞争场景。
- **中断链**：触发源 → 待处理位 → 分发 → 处理 → 清除。
- **电源**：关机/复位类操作的收尾顺序（停调度、刷缓存、关中断）。
- **未判定**：单 hart 环境无法测多 hart 行为 ⇒ 记未判定，不算通过。

## 背景知识

### 术语与概念

- **cfx**：按功能划分的核内资源单元。
- **原因码**：异常的分类标识。
- **现场**：异常发生时保存的架构状态。
- **等价类**：权限与行为相同、可合并测试的格。
- **per-hart / per-system**：每核私有 / 全系统共享。
- **待处理位**：中断或异常请求的挂起标记。

### 对照

**系统态测试形态**

- **内核自测**：在 guest 内核态断言异常与权限。
- **架构合规测试**：跨异常级别，需参考模型。
- **本设计**：状态矩阵 + 现场断言 + 负例枚举。
