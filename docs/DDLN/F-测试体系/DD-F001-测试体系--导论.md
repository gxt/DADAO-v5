# 测试体系 -- 导论

**本册要点**

- 测试按**被测边界**分四个范围：指令语义（inst）、资源与权限（arch）、模块自测（unit）、外部套件（tset）；启动（boot）预留。
- 平台是独立维度：`system`（整机模拟）用于 inst/arch，`user`（成品系统）用于 tset，`hw` 预留。
- 门控四档：完整性（L1）、四范围 smoke（L2）、四范围全量（L3）、夜跑（只读报告）。
- 测试源在 `tests/`，驱动与生成器在工具区，运行产物独立存放。
- 范围划分的判据是"**被测边界**"，不是语言、不是工具。

## 1. 为什么按"被测边界"分范围？

**答：** 因为不同边界的判据、平台与失败形态都不同：单条指令看状态转移，资源与权限看现场与原因码，模块自测看接口，外部套件看整机行为。按边界切，出错时才知道该查哪一层。

- **反例**：按语言分（C 程序 / 汇编程序）——同一个 C 探针可能测的是单指令语义，也可能是系统调用。
- **反例**：按工具分（lit / pytest）——工具会换，边界不会。
- **判据**：问"这条用例的判据依赖什么"：只依赖指令状态 ⇒ inst；依赖权限与现场 ⇒ arch；依赖模块接口 ⇒ unit；依赖成品系统 ⇒ tset。

## 2. 四个范围各管什么？

**答：** inst 管单指令与短序列；arch 管资源与权限；unit 管模块自身；tset 管外部套件。

- **inst**：执行语义、边界值、异常（对齐/越界/非法编码）；首期只跑整机模拟平台。
- **arch**：陷入与退出、cfx 寄存器访问、各类掩码、异常原因、per-hart/per-system、定时器/中断/串口/电源。
- **unit**：编译器（编码与代码生成）、链接器、模拟器、C 库、仓库工具；跑在宿主。
- **tset**：第三方套件（C 库测试、编译器测试套件、基准）在成品系统上运行；跑在 `user` 平台。
- **boot**：整系统启动到用户态，预留。

## 3. 平台维度怎么放？

**答：** 平台是用例属性，不是目录属性：用例声明能在哪些平台跑，runner 只在"声明 ∩ 可用"上执行；没有对应平台就记未判定，不算通过。

- **`system`**：整机模拟，能测权限、异常与设备。
- **`user`**：成品系统上的用户态，能测库与系统调用接口，测不到特权态。
- **`hw`**：硬件在环，预留。
- **兼容性**：同一向量在不同平台期望可能不同 ⇒ 拆成两条用例，不写环境分叉。
- **记录**：结果必须写明平台，否则趋势不可比。

## 4. 门控四档与触发点

**答：** L1 只看完整性与可用性；L2 跑四范围 smoke；L3 跑四范围全量；夜跑跑长套件并只产只读报告。

- **L1**：清单、编码、合法性、引用、残留 + 组件可用性冒烟；不跑被测语义。
- **L2**：四范围 smoke，任务收尾必跑。
- **L3**：四范围全量 + 语义探针，里程碑必跑。
- **夜跑**：外部套件全量 + 长资源测试；队列空档启动，报告供里程碑消费。
- **互斥**：写共享状态的目标与门控串行化（锁排队），避免读到半成品。

## 5. 目录与索引地图

**答：** 测试源按范围分目录，每个范围一份根级清单；驱动与生成器集中在工具区；运行产物独立存放。

- **源**：`inst/<扩展>/`、`arch/<资源>/`、`unit/<模块>/`、`tset/<套件>/`、`shared/`（启动、链接、运行时、宏）。
- **索引**：每范围一份清单（稳定 ID、文件、平台、级别、依赖），门控检查其自洽。
- **工具**：共享 harness、各范围驱动、生成器、清管与夜跑脚本。
- **产物**：每次运行独立目录 + 三件套；权威跑单独保留。
- **禁止**：范围下再套同类子层；索引另建目录；工具散落在测试源里。

## 背景知识

### 术语与概念

- **scope**：被测边界划分。
- **平台**：用例可运行的环境（system/user/hw）。
- **根级清单**：范围级用例索引。
- **smoke / full**：门控级别。
- **未判定**：无可用平台或工具，结果既非通过也非失败。

### 对照

**边界划分**

- **QEMU**：单测 / 设备协议 / guest / 整机。
- **LLVM**：结构断言 / 执行与性能。
- **本设计**：inst / arch / unit / tset（+boot）。

**平台组织**

- **用例属性**（本设计）：平台写在用例里，runner 选交集。
- **目录属性**：按平台分目录，迁移成本高。
