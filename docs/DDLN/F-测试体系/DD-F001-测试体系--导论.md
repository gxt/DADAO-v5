# 测试体系 -- 导论

**本册要点**

- 测试按**被测边界**分四个范围：指令语义（inst）、资源与权限（arch）、模块自测（unit）、外部套件（tset）；启动（boot）预留。
- 门控分**六个层次**：任务级 → 静态（L1）→ 四范围 smoke（L2）→ 全量（L3）→ 里程碑 → 夜跑。
- **一层一列**：同一个检查只在**一个**层直接列出，上层可以把它当前置依赖，但不重复计层。
- 重活不进日常门控：外部套件的全量放夜跑，里程碑只**消费报告**，不内联跑长套件。
- 平台是独立维度：整机模拟用于 inst/arch，成品系统用于 tset，硬件在环预留。
- 报告必须有：全量跑落结构化报告，缺报告即失败（不是跳过）。

## 1. 为什么按"被测边界"分范围？

**答：** 因为不同边界的判据、平台与失败形态都不同：单条指令看状态转移，资源与权限看现场与原因码，模块自测看接口，外部套件看整机行为。

- **inst**：单指令与短序列的执行语义；整机模拟平台。
- **arch**：资源访问与权限；只有整机模拟能看到特权态。
- **unit**：模块自身功能；跑在宿主。
- **tset**：第三方套件在成品系统上的行为；用户态平台。
- **反例**：按语言或工具分（C 程序 / 测试框架），边界会随工具变化。

## 2. 六个门控层次各管什么？

**答：** 任务级管"这次改动的最小验证"，静态层管"仓库是否完整"，smoke 层管"四范围是否没坏"，全量层管"语义是否全过"，里程碑管"该归档的东西齐不齐"，夜跑管"长套件与长场景"。

- **任务级**：任务书固定写 `scope` / `level`（targeted 或 smoke）/ `cmd`，限时两分钟内；审查者重跑**同一条命令**。
- **L1 静态**：索引与 ID、身份清单、生成器重派生比对、引用与残留、跨模块静态一致性、组件可用性冒烟；**不跑被测语义**。
- **L2 四范围 smoke**：inst / arch / unit / tset 各自的代表集；任务收尾必跑。
- **L3 全量**：inst 全量 + arch 全量 + unit 全量 + 浮点探针 + 集成链；逐成员执行并写报告。
- **里程碑**：归档结构/内容、知识目录白名单、里程碑册与任务号、**夜跑报告**与 **L3 报告**的存在性/结构/覆盖/结果。
- **夜跑**：外部套件全量（静态与动态各一遍）+ 长资源测试；报告只读，次日由里程碑消费。

## 3. "一层一列"怎么理解？

**答：** 同一个检查目标只能在一个层直接列出；上层若需要它，只能作为**前置依赖**间接跑到，不算重复列层。

- **示例**：模块自测的 smoke 只在 L2 列；L3 用的是"全量版"目标，它内部会带上 smoke 那一步。
- **为什么严格**：同一目标出现在两层，耗时统计、失败归因、层边界都会失真。
- **判据**：问"这个目标直接写在哪一层"，只能有一个答案。
- **代价**：需要"全量版"目标来承载前置依赖。

## 4. 重活为什么不进日常门控？

**答：** 因为慢检查一旦进入高频路径就会被绕过；正确做法是把它们放到低频层，并用**报告**把结果传回里程碑。

- **夜跑**：外部套件全量、长资源场景；小时级。
- **里程碑**：只读报告，验证"存在、结构正确、结果无失败"。
- **缺报告 = 失败**：没跑不等于通过，这条必须写死。
- **代价**：问题发现得晚；可接受，因为这些检查本就不是每日动作。

## 5. 平台维度怎么放？

**答：** 平台是用例属性：用例声明能在哪些平台跑，runner 只在"声明 ∩ 可用"上执行；缺平台记未判定，不算通过。

- **整机模拟**：能测特权态、异常与设备。
- **成品系统（用户态）**：能测库与系统调用接口，测不到特权态。
- **硬件在环**：预留，用例 ID 不变。
- **拆例原则**：同一用例在不同平台期望不同时，拆成两条，不写环境分叉。

## 6. 目录与索引怎么组织？

**答：** 源按范围分目录，每范围一份根级清单，驱动与生成器集中在工具区，运行产物独立存放。

- **源**：`inst/<扩展>/`、`arch/<资源>/`、`unit/<模块>/`、`tset/<套件>/`、`shared/`。
- **清单**：每范围一份（稳定 ID、文件、平台、级别、依赖）。
- **工具**：共享 harness、各范围驱动、生成器、清管与夜跑脚本。
- **产物**：每次运行独立目录 + 三件套；权威与全量报告各自保留。
- **禁止**：范围下再套同类子层；索引另建目录；工具散落在测试源里。

## 背景知识

### 术语与概念

- **scope**：被测边界划分。
- **任务级验证**：任务书里写死的最小验证命令。
- **smoke / full**：代表集 / 全量。
- **一层一列**：同一目标只在一个层直接列出。
- **报告消费**：里程碑读报告而非重跑。
- **未判定**：无可用平台或工具，非通过非失败。

### 对照

**分层方式**

- **任务级 + 快速 + 全量 + 低频**：本设计。
- **仅快慢两层**：常见，但低频检查容易被遗忘。
- **只有全量**：一定被绕过。

**报告形态**

- **结构化报告 + 消费门控**：可追溯。
- **只看退出码**：无法证明"跑过什么"。
