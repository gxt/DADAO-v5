# 测试体系 -- 结果与产物

**本册要点**

- 每次运行一个独立目录，内含**三件套**：结构化结果、原始日志、元数据。
- **权威跑**单独保留；子集跑不得写权威区。
- 驱动不得有固定默认输出目录；输出路径必须显式传参。
- 结果分**通过 / 失败 / 未判定**三列，并带版本与平台。
- 夜跑只产只读报告，由里程碑消费；清理与复现都要有目标。

## 1. 为什么运行产物要单独成目录？

**答：** 因为"跑过一次"必须可追溯：谁跑的、跑的是什么、结果是什么、用了哪版工具链。散落在仓库里的输出既不可追溯，也会污染工作树。

- **目录名**：时间戳 + 套件 + 模式，保证可排序、可去重。
- **三件套**：结构化结果（机器读）、日志（人读）、元数据（命令与版本）。
- **隔离**：与源码树分离，避免"产物留在仓库"。
- **保留策略**：按批次保留，权威跑长期保留。

## 2. 权威跑与子集跑为什么要分开？

**答：** 因为"结论"只能来自完整、可复现的运行；子集跑用于快速反馈，若也能写入权威区，就会把"没跑全"伪装成"已验证"。

- **权威跑**：全量或约定范围，产物保留、可引用。
- **子集跑**：smoke/调试用，产物可清理。
- **写入规则**：子集跑禁止写权威区。
- **引用规则**：结论引用必须指向权威跑。

## 3. 驱动为什么要禁止默认输出目录？

**答：** 因为默认目录会让"忘了传参"变成"覆盖上一次结果"：两次运行写同一处，历史消失、比对失效。

- **要求**：输出路径必填，由调用方指定。
- **好处**：结果可并存、可比对。
- **检查**：静态检查驱动是否含固定默认目录。
- **配套**：运行目录命名规则统一。

## 4. 统计口径怎么定？

**答：** 三列状态 + 四类归因 + 三个维度（范围、平台、版本）；单列"未判定"，禁止并入通过。

- **状态**：通过 / 失败 / 未判定（含跳过、环境不支持）。
- **归因**：编码 / 语义 / 工具链 / 环境或套件自身。
- **维度**：按范围（inst/arch/unit/tset）、按平台、按版本。
- **趋势**：只有版本可比的两次运行才能比趋势。
- **反模式**：只报通过率；把未判定算通过；跨版本直接比数量。

## 5. 夜跑报告怎么用？

**答：** 夜跑产出汇总报告（范围/套件/返回码/日志路径），只读、不参与日常门控；里程碑检查它是否存在且无失败项。

- **内容**：每个套件一行，返回码 + 日志指针。
- **检查**：里程碑层验证报告存在、结构正确、无失败项；未跑即失败（不是跳过）。
- **价值**：把"长套件"从提交门控里挪走，同时保证它真的在跑。
- **触发**：队列空档启动，一次只跑一个。

## 背景知识

### 术语与概念

- **三件套**：结果、日志、元数据。
- **权威跑**：被保留、可引用的正式运行。
- **未判定**：非通过非失败的状态。
- **夜跑**：低频长跑，报告只读。
- **复现**：从干净状态重建产物并比对。

### 对照

**产物组织**

- **强**：独立目录 + 三件套 + 权威区。
- **弱**：输出散落仓库或临时目录。
- **判据**：换个人能否复现同一结论。

**统计口径**

- **强**：三列 + 归因 + 版本。
- **弱**：单列通过率。
