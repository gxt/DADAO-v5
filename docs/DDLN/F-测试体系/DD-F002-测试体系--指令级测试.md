# 测试体系 -- 指令级测试

**本册要点**

- inst 只测**单条指令与短序列**的执行语义，不测系统接口。
- 首期只跑整机模拟平台（能看特权态与异常），用户态平台后置。
- 期望值必须**独立派生**：来自编码表与规范，不从模拟器输出反推。
- smoke 与 full 按**机械规则**分，不手挑。
- 失败按"身份/格式类"聚合，便于一次修一类。

## 1. 为什么 inst 首期只跑整机模拟？

**答：** 因为指令语义的一大半在异常与特权行为上：非法编码、对齐错误、保留位、陷入原因，只有在能观察特权态的整机模拟里才看得见。

- **整机模拟能提供**：异常原因、特权级别、内存映射、设备。
- **用户态平台的局限**：异常被宿主转换，看不到原始原因码。
- **后置理由**：用户态平台的价值在"库与系统调用"，属另一范围。
- **代价**：整机启动比用户态慢；用 smoke 子集控制时长。

## 2. 用例粒度怎么定？

**答：** 一条用例只验证一个语义点：一条指令的一种操作数形态，或一组最小前导序列（如"先装载再比较"）。多条语义混在一条用例里，失败后无法归因。

- **单点原则**：一条用例一个期望状态，避免"多处断言一锅端"。
- **短序列**：需要前置状态时（如标志位、内存内容），用最少的指令搭建。
- **边界优先**：端点值、对齐边界、寄存器号端点、零寄存器用法。
- **命名**：ID 体现"扩展 + 序号"，语义写在用例说明里。

## 3. 期望值怎么来，为什么必须独立？

**答：** 期望值来自编码表与规范的手工派生或生成器；若从模拟器输出反推，测出来的只是"模拟器与自己一致"，测不出它错。

- **来源**：手算（边界）、生成器（批量）、签名（跨实现比对）。
- **独立性检查**：生成脚本不得读模拟器产物；期望值带来源标记。
- **非法编码**：期望是"必须拒绝"，而不是"随便返回什么"。
- **重派生**：生成器支持重新生成并逐字节比对，防漂移。

## 4. smoke 与 full 怎么分？

**答：** smoke 是"每个扩展/格式类各取代表 + 全部边界用例"，full 是全量。代表集由机械规则生成（如每个身份取第一条），不手挑。

- **机械派生**：按身份取代表，避免"只挑容易过的"。
- **边界必进 smoke**：端点与非法编码最能暴露问题。
- **full**：全量向量，含组合与长序列。
- **数量核对**：计数现场统计，不写死期望值。

## 5. 失败怎么定位？

**答：** 先按身份聚合，再看是否集中在同一格式类或同一操作数形态；同类集中通常是一个根因。

- **聚合维度**：身份、格式类、操作数形态、端序/对齐。
- **典型模式**：某格式类全错 ⇒ 编码或解码问题；某身份全错 ⇒ 语义实现问题。
- **定位产物**：保留失败用例的输入、期望状态、实际状态。
- **回归**：修好后把该身份加入 smoke，防止复发。

## 背景知识

### 术语与概念

- **身份**：编码表中的唯一操作，不等于助记符。
- **格式类**：编码模板（操作数个数与字段位置）。
- **短序列**：为搭前置状态而写的最小指令集合。
- **独立派生**：期望值不经过被测实现。
- **签名**：把最终状态压缩成可比较字符串。

### 对照

**指令测试形态**

- **合规套件**：用例内自检 + 签名比对。
- **模拟器测试**：向量驱动，逐指令比对状态。
- **硬件验证**：随机指令序列 + 参考模型逐拍比对。
- **本设计**：向量 + 独立期望 + 整机模拟执行。
