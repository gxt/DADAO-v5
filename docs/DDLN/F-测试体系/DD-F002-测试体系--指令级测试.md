# 测试体系 -- 指令级测试

**本册要点**

- inst 只测单条指令与短序列的执行语义，不测系统接口。
- 首期只跑整机模拟平台；用户态与硬件在环只预留字段。
- 期望值必须独立派生：来自编码表与规范，不从模拟器输出反推。
- 任务级验证按 `CASE=` 选单例，smoke 是代表集，全量进全量层。
- 失败按"身份/格式类"聚合，便于一次修一类。

## 1. 为什么 inst 只跑整机模拟？

**答：** 因为指令语义的一大半在异常与特权行为上：非法编码、对齐错误、保留位、陷入原因，只有在能观察特权态的整机模拟里才看得见。

- **能提供**：异常原因、特权级别、内存映射、设备。
- **用户态平台的局限**：异常被宿主转换，看不到原始原因码。
- **后置理由**：用户态平台的价值在库与系统调用，属另一范围。
- **代价**：整机启动慢；用 smoke 与单例子集控制时长。

## 2. 用例粒度怎么定？

**答：** 一条用例只验证一个语义点：一条指令的一种操作数形态，或一组最小前导序列；多语义混在一起，失败后无法归因。

- **单点原则**：一条用例一个期望状态。
- **短序列**：用最少指令搭建前置状态。
- **边界优先**：端点值、对齐边界、寄存器号端点、零寄存器用法。
- **命名**：ID 体现"扩展 + 序号"，语义写在用例说明里。

## 3. 期望值怎么来？

**答：** 手算（边界）、生成器（批量）、签名（跨实现）；生成脚本不得读模拟器产物，期望值要带来源标记。

- **手算**：少量边角，可审计。
- **生成器**：批量派生，支持重派生比对。
- **非法编码**：期望"必须拒绝"，不是"随便返回"。
- **独立性检查**：脚本依赖与来源标记可机械核对。

## 4. 任务级、smoke、全量怎么分？

**答：** 任务级跑单例（按用例或扩展选），smoke 跑机械派生的代表集，全量跑全部载体；三级都不重复列出同一目标。

- **任务级**：`check-inst-smoke CASE=<用例>`，两分钟内完成，审查者重跑同一条命令。
- **smoke**：按身份机械取代表，边界必进。
- **全量**：包含所有扩展与组合；较长，进全量层。
- **计数**：现场统计，不写死期望数量。
- **缺口**：未纳入全量的扩展要显式登记（如个别扩展暂未接线）。

## 5. 失败怎么定位？

**答：** 先按身份聚合，再看是否集中在同一格式类或同一操作数形态；同类集中通常是一个根因。

- **聚合维度**：身份、格式类、操作数形态、端序与对齐。
- **典型模式**：某格式类全错 ⇒ 编码或解码问题；某身份全错 ⇒ 语义实现问题。
- **保留现场**：输入、期望状态、实际状态。
- **回归**：修好后把该身份加入 smoke，防止复发。

## 背景知识

### 术语与概念

- **身份**：编码表中的唯一操作，不等于助记符。
- **格式类**：编码模板（操作数个数与字段位置）。
- **targeted**：按单例或单扩展选跑。
- **代表集**：机械规则抽出的子集。
- **独立派生**：期望值不经过被测实现。

### 对照

**指令测试形态**

- **合规套件**：用例内自检 + 签名比对。
- **模拟器测试**：向量驱动，逐指令比对状态。
- **硬件验证**：随机指令序列 + 参考模型。
- **本设计**：向量 + 独立期望 + 整机模拟执行。
