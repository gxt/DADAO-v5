# 测试体系 -- 判据与覆盖

**本册要点**

- 判据只能**独立派生**（规范/编码表/参考模型），不能从被测实现反推。
- 覆盖按"**身份 × 检查项 × 边界**"统计，缺口显式登记。
- 生成器必须能**重派生并逐字节比对**，否则会悄悄漂移。
- **覆盖率回答"跑到没跑到"**，注入/变异回答"发现不发现得到"。
- 断言必须能失败；弃权要单列。

## 1. 判据有哪几种来源？

**答：** 四种：手算（边界）、生成器（批量）、签名（跨实现）、程序输出（端到端）。粒度不同，用途不同。

- **手算**：少量边角，可审计，不可扩展。
- **生成器**：批量派生，必须可重派生比对。
- **签名**：压缩状态，便于跨实现比较，定位信息少。
- **程序输出**：最接近用户视角，粒度最粗。
- **独立性**：派生路径不得经过被测实现；期望值带来源标记。

## 2. 覆盖矩阵怎么建？

**答：** 以编码表的每个**身份**为行，以"检查项 × 边界"为列：编码、合法性、语义、异常各一列；边界取端点值。

- **身份**：唯一操作编码，不是助记符。
- **检查项**：字节编码、该拒绝的拒绝、语义结果、异常路径。
- **边界**：立即数端点与越界前一位、对齐边界、寄存器号端点、条件组合、双目的写回、零寄存器用法。
- **合并**：等价类可合并（同权限同行为），但端点单独保留。
- **缺口**：允许未覆盖，必须登记理由，不允许静默缺席。

## 3. 生成器为什么要能重派生？

**答：** 因为产物会漂移：输入改了没重跑、生成器改了没发现、产物被手改。只有"重新生成 + 逐字节比对"才能把漂移变成失败。

- **确定性要求**：顺序固定、无时间戳、无绝对路径、随机固定种子。
- **比对方式**：逐字节，不做语义等价判断。
- **差异报告**：指出第一处不同的位置。
- **进门控**：自动跑，不靠人工。

## 4. 未覆盖怎么处理？

**答：** 显式登记：哪些身份没有用例、原因是什么（功能暂缓、无消费方、实现不支持），并定期复核。

- **登记内容**：身份、原因、计划（补齐/不补）、复核时点。
- **禁止**：用"总覆盖率"掩盖缺口；用"跳过"冒充通过。
- **复核**：里程碑或版本发布时检查一次。
- **优先级**：影响语义正确性的缺口优先补。

## 5. 覆盖与有效性有什么区别？

**答：** 覆盖只说明"跑到了"，有效性说明"改动会被发现"。一条恒真断言可以覆盖 100% 却什么也发现不了。

- **有效性验证**：注入一处改动，看检查是否变红（注入/变异）。
- **指标**：注入发现比例，比行覆盖率更接近"有效"。
- **成本**：注入要重跑，适合关键模块与夜间。
- **报告**：覆盖与有效性并列展示，禁止只报覆盖率。

## 背景知识

### 术语与概念

- **独立判据**：不从被测实现反推的期望值。
- **身份**：编码表的唯一操作。
- **重派生**：由输入与生成器重新产出并比对。
- **变异得分**：注入改动中被发现的比例。
- **未判定**：环境或工具不支持，结果非通过非失败。
- **等价类**：行为相同、可合并的测试格。

### 对照

**覆盖度量**

- **弱**：行覆盖率、用例条数。
- **中**：身份 × 检查项 × 边界。
- **强**：注入/变异得分 + 功能覆盖。

**期望值来源**

- **强**：规范派生 + 手算复核。
- **弱**：被测实现输出反推。
