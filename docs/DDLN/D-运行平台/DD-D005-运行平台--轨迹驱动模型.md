# 运行平台 -- 轨迹驱动模型

**本册要点**

- 轨迹驱动只吃**访存/指令轨迹**，不执行程序；换来的是快几个数量级。
- 它擅长评**存储子系统算法**：替换、预取、写回、访存调度。
- 它评不了**控制流相关**的东西：分支预测、取指、乱序发射。
- 轨迹的代表性决定结论的有效性；样本不对，跑得再快也没意义。
- 它适合**快速迭代与参数扫描**，最终结论要与执行驱动交叉验证。

## 1. 轨迹驱动是怎么工作的？

**答：** 先把程序的一次执行录成轨迹（地址、读写、大小、可选的时间戳），再让模型"重放"轨迹，统计命中、缺失、延迟与带宽。

- **输入**：访存序列（必需）、指令类型（可选）、时间戳（可选）。
- **模型**：缓存层次、替换策略、预取器、写缓冲、内存调度器。
- **输出**：命中率、缺失数、平均访存延迟、带宽占用。
- **优点**：不执行指令，跑得极快；同一轨迹可反复用于多组配置。
- **缺点**：轨迹一旦录好，程序行为就冻结了——预取改变了访存顺序，轨迹却不会变。

## 2. 它能评什么、不能评什么？

**答：** 能评"给定访存流下的存储子系统行为"；不能评任何依赖控制流或执行反馈的东西。

- **能评**：替换策略、预取器、写回策略、行缓冲、访存调度、缓存容量/关联度敏感性。
- **不能评**：分支预测、取指、乱序发射、寄存器重命名、依赖链。
- **半能评**：预取对整体性能的影响——轨迹驱动看不到"预取减少了停顿"的反馈，只能看命中率变化。
- **判据**：结论里出现"IPC""分支惩罚"⇒ 轨迹驱动不适用。

## 3. 轨迹从哪来，代表性怎么保证？

**答：** 轨迹来自功能级模拟或插桩；代表性靠"程序、输入、区间、长度"四项说明，缺一项结论就不可复用。

- **来源**：功能级模拟器的跟踪、编译器插桩、硬件跟踪。
- **代表性**：程序集、输入规模、采样区间（是否跳过启动）、轨迹长度。
- **工作集**：轨迹要覆盖目标工作集，否则缓存结论失真。
- **多轨迹**：单一轨迹的结论不能当普遍规律。
- **记录**：轨迹来源与哈希必须随结果保存。

## 4. 为什么它适合快速迭代？

**答：** 因为"录一次、跑很多次"：同一轨迹换十组缓存配置，只需重放十次；执行驱动要重跑十次程序。

- **参数扫描**：容量、关联度、替换策略、预取阈值。
- **消融实验**：关掉预取看基线，开一半看中间态。
- **上界分析**：用最优替换策略算命中率上限，衡量现有策略差距。
- **代价**：结论只对这条轨迹成立。

## 5. 怎么与执行驱动交叉验证？

**答：** 同一组配置、同一程序，两边各跑一次，比较"命中率/缺失数"这类同口径指标；差异来自模型粒度与反馈缺失。

- **可比指标**：命中率、缺失数、带宽；不要比 IPC（轨迹驱动给不出）。
- **差异来源**：轨迹驱动无执行反馈、预取不改变后续访存、时序简化。
- **校准**：用执行驱动校准轨迹驱动的偏差，之后才可大批量扫描。
- **纪律**：交叉验证不通过时，不以轨迹驱动结论为准。

## 背景知识

### 术语与概念

- **轨迹（trace）**：程序执行产生的访存/指令序列。
- **重放**：把轨迹输入模型并统计。
- **工作集**：程序在时间窗口内访问的地址集合。
- **上界分析**：用理想策略（如最优替换）给出性能上限。
- **校准**：用更精确的模型修正快速模型的系统偏差。

### 对照

**轨迹驱动 vs 执行驱动**

- **速度**：轨迹驱动快几个数量级。
- **范围**：轨迹驱动只覆盖存储子系统。
- **反馈**：轨迹驱动没有执行反馈。
- **用途**：快速迭代用轨迹，最终结论用执行驱动。
