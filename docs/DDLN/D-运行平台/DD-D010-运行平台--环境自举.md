# 运行平台 -- 环境自举

**本册要点**

- "换台机器就跑不起来"的根因几乎都不是代码，而是**环境三件套**：工具链、模拟器、依赖脚本。
- 自举要解决两件事：**能自检**（缺什么一眼看出）、**能一键起**（不靠记忆）。
- 产物包只装"换机器也必须有"的东西，不装运行产物与临时文件。
- 容器解决"环境一致"，不解决"怎么跑"；判据是"多人多机"与"长期归档"。
- 容器必须能**从零重建**，否则只是把漂移封进了镜像。

## 1. 为什么需要"环境自举"？

**答：** 因为开发环境的正确性靠的是一组隐式前提（版本、路径、权限、可用设备），没有自检就只能靠"我这儿能跑"。

- **隐式前提**：编译器/链接器/模拟器版本、Python 依赖、系统库、路径优先级。
- **症状**：编译过但运行报错；换机器链接失败；门控在本机绿、在 CI 红。
- **代价**：每次换环境都要重新踩一遍。
- **自举的目标**：把隐式前提变成显式检查。

## 2. 环境自检要检什么？

**答：** 四类：**存在性**（工具在不在）、**版本**（对不对）、**可用性**（能不能跑通最小例子）、**权限与路径**（能不能写、会不会串版本）。

- **存在性**：编译器、汇编器、链接器、模拟器、脚本解释器。
- **版本**：精确版本或提交，不看"最新"。
- **可用性**：跑一条最小命令（如打印目标列表、加载一个空镜像）。
- **权限**：安装根可写、临时目录可用、锁目录可建。
- **路径**：确保没有宿主同名工具抢先（这是最常见的隐性错配）。

## 3. 一键脚本怎么组织？

**答：** 一个入口、幂等、失败可诊断：同一条命令跑两次结果一致；失败时打印"缺什么、怎么补"，而不是只报非零。

- **入口**：一条命令覆盖"自检 → 构建 → 冒烟"。
- **幂等**：重复执行不产生副作用，不重复下载/覆盖。
- **可诊断**：每一步打印期望与实际，失败给出修复建议。
- **可跳过**：允许只跑自检（快速）或只跑冒烟。
- **记录**：把检查结果落文件，便于附在问题报告里。

## 4. 只读产物包里装什么？

**答：** 装"换机器也必须有"的：工具链安装根、模拟器、版本与哈希清单、自检脚本、最小示例；不装运行产物、临时文件、与源码重复的东西。

- **装**：可执行工具、库、头文件、脚本、清单（版本 + 哈希）。
- **不装**：测试运行产物、构建中间物、日志、编辑器配置。
- **哈希**：每个文件或整包一个哈希，便于核对。
- **体积**：工具链包通常以 GB 计，分发前先量。
- **可审计**：包内清单能对应到版本锁。

## 5. 容器什么时候才需要？

**答：** 当"多人多机 + 长期归档 + 环境隔离"同时成立时。只有一个人一台机器时，容器是纯负担。

- **判据**：出现"我这里能跑"、需要半年后复现、要交给外部、CI 与开发环境不一致——命中两条以上再上。
- **镜像只装**：工具链、模拟器、入口脚本；源码用挂载。
- **构建可复现**：固定基础镜像摘要、离线构建、依赖清单入库。
- **坑一**：镜像能跑但宿主构建流程是错的（镜像掩盖问题）。
- **坑二**：把运行产物打进镜像，体积失控且不可审计。

## 6. 怎么控体积与可复现？

**答：** 三条：分层（基础镜像 / 工具链 / 脚本）、只装必需、从零重建验证。

- **分层**：基础系统与工具链分开，改脚本不用重建工具链层。
- **最小化**：不装编译器不需要的包；调试符号按需。
- **从零验证**：定期删掉本地镜像与缓存，做一次完整重建。
- **版本记录**：镜像标签 + 包哈希 + 构建脚本版本。
- **判据**：别人拿到标签能否重建出同一镜像。

## 背景知识

### 术语与概念

- **环境自举**：把开发环境从零准备好并可验证。
- **幂等**：重复执行结果一致。
- **产物包**：只读的分发包，含工具与清单。
- **镜像分层**：容器镜像按层缓存与复用。
- **离线构建**：不依赖网络的可复现构建。
- **宿主泄漏**：宿主工具或头文件意外参与构建。

### 对照

**分发形态**

- **一键脚本**：轻、可审、依赖宿主。
- **产物包**：中、可归档、需匹配宿主架构。
- **容器**：重、隔离好、需运行时支持。
- **虚拟机/ISO**：最重，仅在需要整机时用。

**适用判据**

- **单人单机**：脚本足够。
- **多人多机**：容器或产物包。
- **长期归档**：产物包 + 哈希。
- **整机交付**：镜像（属系统集成）。
