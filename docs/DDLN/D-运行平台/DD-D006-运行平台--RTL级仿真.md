# 运行平台 -- RTL 级仿真

**本册要点**

- RTL 级建模到寄存器传输：周期精确、可看总线与外设协议。
- 它能给出仿真周期，但**不等于综合后时序，更不等于硅**。
- 面积、功耗要在综合后才有意义；仿真本身给不出。
- SoC 生成器（如 Chisel 类工具）让"改配置重建 SoC"成为常规操作。
- 代价高：一次仿真可能几十分钟到几小时，必须学会裁剪与并行。

## 1. RTL 级仿真能回答什么？

**答：** 周期级的硬件行为：每条指令用几拍、总线事务顺序、外设协议、复位与中断时序；以及"这个设计在结构上对不对"。

- **周期**：指令级周期数、流水线停顿、总线等待。
- **协议**：总线读写顺序、握手、突发长度。
- **外设**：中断触发与响应、DMA 行为。
- **结构**：复位、时钟域、边界条件。
- **不能**：综合后时序（要跑综合与静态时序分析）、真实功耗（要功耗分析）。

## 2. SoC 生成器在其中扮演什么角色？

**答：** 它把"配置 → RTL"变成常规操作：改缓存大小、加外设、换总线，重新生成即可；代价是引入了"生成器本身的正确性"这一层风险。

- **配置化**：核心数、缓存、外设、地址映射。
- **生成物**：RTL + 仿真环境 + 约束文件。
- **风险**：生成器 bug 会被当成"设计 bug"；生成配置要版本化。
- **好处**：同一套软件可在不同配置上跑，做敏感性分析。

## 3. 怎么跑一次仿真？

**答：** 三件事：生成/编译 RTL、准备软件镜像与激励、选择仿真器（开源快、商用全）。

- **仿真器**：开源仿真器快但覆盖有限；商用仿真器支持完整时序与断言。
- **激励**：复位序列、引导镜像、测试程序。
- **时间尺度**：跑操作系统启动要很久，必须裁剪（只跑到关注点）。
- **并行**：多配置并行跑，注意机器资源与随机种子。
- **记录**：配置、生成器版本、仿真器版本一并落盘。

## 4. 怎么观测？

**答：** 波形（信号级）、断言（协议/时序检查）、以及软件侧的打印与计数器。

- **波形**：看信号跳变，定位时序问题；代价是文件巨大。
- **断言**：把"协议必须满足"写成检查，失败即停。
- **计数器**：在 RTL 里加性能计数器，导出周期与事件。
- **软件侧**：串口输出、半主机、退出码。
- **成本控制**：只对关注模块开波形，避免全芯片记录。

## 5. 为什么它的结论不能直接当"芯片性能"？

**答：** 因为仿真是理想化的：没有工艺、没有布线延迟、没有供电噪声；这些要到综合、布局布线、流片后才成立。

- **周期精确 ≠ 频率**：仿真给周期数，频率取决于综合与工艺。
- **面积/功耗**：要综合与功耗分析，不是仿真输出。
- **时序违例**：仿真不检查建立/保持时间。
- **正确用法**：结构验证、周期级相对比较、协议检查。

## 6. 成本怎么控制？

**答：** 分层：先用功能级筛掉大部分用例，再用 RTL 跑少量关键场景；仿真只跑到关注点，波形只开关键模块。

- **筛选用例**：功能级跑全量，RTL 只跑代表集。
- **裁剪**：缩短引导、跳过无关外设初始化。
- **并行**：多配置/多用例并行。
- **缓存结果**：同一场景不重复跑。
- **判据**：一次 RTL 回归的时长应可接受，否则会被跳过。

## 背景知识

### 术语与概念

- **RTL**：寄存器传输级描述。
- **周期精确**：每个周期行为与设计一致。
- **综合**：RTL → 门级网表，之后才有面积/时序。
- **断言**：对协议或时序的形式化检查。
- **波形**：信号随时间变化的记录。
- **SoC 生成器**：用配置生成 RTL 与仿真环境的工具。

### 对照

**仿真器类型**

- **开源**：快、易集成，覆盖有限。
- **商用**：完整时序、断言、调试，慢且贵。
- **选择**：先开源跑通，再用商用查细节。

**结论可信度**

- **周期**：可信（对应该 RTL）。
- **频率**：不可信（要综合后）。
- **面积/功耗**：不可信（要综合/功耗分析）。
