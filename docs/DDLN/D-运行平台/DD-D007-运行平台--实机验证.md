# 运行平台 -- 实机验证

**本册要点**

- 实机（FPGA）给的是**真实频率、板级行为、长时间稳定性**，这是仿真给不了的。
- 它不是 ASIC：布线、时钟约束、供电、封装都不同，频率与功耗不能直接换算。
- 板级问题（复位、上电时序、引脚约束、跨时钟域）只有实机能暴露。
- 观测手段有限：逻辑分析仪、片上计数器、串口——比仿真难得多。
- 实机测试的价值在"最后一公里"，不是替代仿真。

## 1. 实机能回答什么仿真答不了的问题？

**答：** 真实运行下的频率、板级时序、长时间稳定性、外设电气行为、以及"设计在真实约束下还能不能跑"。

- **频率**：综合布线后的实际可达频率。
- **板级**：上电时序、复位行为、时钟抖动、电源噪声。
- **长跑**：几小时到几天的稳定性（仿真跑不了这么久）。
- **外设**：真实器件的时序与电气特性。
- **不能**：硅的功耗与面积、最终流片频率。

## 2. 为什么 FPGA 不等于 ASIC？

**答：** 因为实现介质不同：FPGA 用可编程逻辑与固定布线资源，ASIC 用标准单元与定制布线；频率、功耗、面积、时序余量全都不同。

- **频率**：FPGA 通常显著低于同设计 ASIC。
- **功耗**：FPGA 静态功耗与 IO 功耗占比高。
- **面积**：不可直接比较。
- **结论**：FPGA 上"能跑多快"只能说明"这个设计在 FPGA 上能跑多快"。

## 3. 板级问题有哪些？

**答：** 复位与上电顺序、时钟与跨时钟域、引脚约束、存储器初始化、外设电平——这些问题在仿真里通常被简化掉。

- **复位**：上电复位是否覆盖所有寄存器；软复位是否彻底。
- **时钟**：多时钟域、时钟使能、抖动。
- **引脚**：约束错误导致功能正常但时序不满足。
- **未初始化存储**：仿真常默认为 0，实机不是。
- **调试**：需要在线逻辑分析仪与串口。

## 4. 怎么观测？

**答：** 三条路：片上逻辑分析仪（抓信号）、性能计数器（周期/事件）、软件侧输出（串口/半主机）。

- **逻辑分析仪**：抓内部信号，容量有限，需要触发条件设计。
- **计数器**：在 RTL 里埋点，导出周期与事件统计。
- **软件输出**：串口打印、退出码。
- **限制**：观测会影响时序（插入探针），要评估影响。
- **记录**：比特流版本、板卡型号、时钟配置必须落盘。

## 5. 实机测试怎么组织？

**答：** 少量关键场景 + 长时间跑；用例要能在无人值守下自恢复（失败重试、日志留存），并区分"功能性失败"与"环境性失败"。

- **场景选择**：启动、外设、长跑稳定性、边界条件。
- **自恢复**：看门狗、自动重载、日志落盘。
- **失败分类**：功能错 / 时序违例 / 板级环境 / 比特流问题。
- **重复性**：同一比特流多次上电结果应一致。
- **成本**：板卡数量有限，需要排队与预约。

## 6. 什么时候必须上实机？

**答：** 当问题只与真实时序、真实外设或长时间运行有关时；能用仿真回答的，不要占用实机。

- **必须上**：频率可达性、板级时序、长跑稳定性、真实外设。
- **不必上**：语义正确性、协议检查、大部分功能回归。
- **判据**：仿真里"无法建模或被简化"的因素是否影响结论。
- **成本**：实机吞吐低，适合做"最后一公里"验证。

## 背景知识

### 术语与概念

- **比特流**：FPGA 的配置数据。
- **在线逻辑分析仪**：片内信号抓取工具。
- **跨时钟域**：信号在两个时钟域之间传递。
- **看门狗**：超时自动复位机制。
- **约束文件**：引脚、时钟、时序约束。
- **长时间稳定性**：数小时以上无故障运行。

### 对照

**仿真 vs 实机**

- **仿真**：可控、可观测、慢但不真实。
- **实机**：真实、快、但难观测、受板级限制。
- **共同点**：都只是"某个实现"的行为，不是规范。

**FPGA vs ASIC**

- **频率**：FPGA 低。
- **功耗**：构成不同。
- **成本**：FPGA 可重配置，ASIC 不可。
- **结论**：不可直接换算。
