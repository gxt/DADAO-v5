# 运行平台 -- 执行驱动模型

**本册要点**

- 执行驱动 = 真的执行指令，边执行边建模微架构；因此能评分支预测、乱序与缓存。
- 两种模式：用户态（只跑程序）与系统级（含 OS 与设备）。
- CPU 模型决定精度：原子、顺序、乱序，代价依次上升。
- 同配置下的**相对比较**可信；绝对值依赖模型精度。
- 预热、重复、配置一致性是数字可信的三个前提。

## 1. 执行驱动与轨迹驱动差在哪？

**答：** 执行驱动"边跑边算"：指令逐条执行，微架构模型根据真实控制流与依赖更新状态；轨迹驱动只吃访存流，不知道分支与数据依赖。

- **执行驱动能评**：分支预测、取指、乱序发射、寄存器重命名、缓存层次。
- **轨迹驱动能评**：替换策略、预取、访存调度（在给定轨迹上）。
- **代价**：执行驱动慢几个数量级。
- **结论**：问题里有"控制流"或"依赖"，就必须执行驱动。

## 2. 两种模式怎么选？

**答：** 用户态模式只跑程序，快、不用起 OS；系统级模式含内核与设备，能测系统行为但慢。

- **用户态模式**：适合程序级性能、库与编译器对比；系统调用被模拟或转发。
- **系统级模式**：适合启动、驱动、页表、异常与多核交互。
- **代价**：系统级要起 OS 镜像，配置复杂。
- **一致性**：两种模式的结果不可直接比较，必须分别标注。

## 3. CPU 模型怎么影响精度与代价？

**答：** 原子模型只保证功能与时序无关；顺序模型按时序推进；乱序模型建模发射、重命名与执行端口。精度越高，越接近真实，也越慢。

- **原子模型**：最快，接近功能级；不能评流水线相关结论。
- **顺序模型**：有周期概念，能看缓存与部分时序；不建模乱序。
- **乱序模型**：能评 IPC、分支惩罚、窗口大小；最慢。
- **选择判据**：结论涉及"发射/乱序/分支惩罚" ⇒ 乱序模型；只关心缓存 ⇒ 顺序模型可能够。

## 4. 它能评什么？

**答：** 微架构与性能：IPC、缓存命中率、分支预测准确率与惩罚、乱序窗口敏感性、总线与内存延迟影响。

- **性能指标**：IPC、每千指令缺失数、平均访存延迟。
- **结构敏感性**：窗口大小、缓存容量、关联度、预取开关。
- **算法对比**：替换策略、预取器、分支预测器——在真实控制流下比较。
- **系统交互**：页表、异常、系统调用对性能的影响。

## 5. 怎么让数字可信？

**答：** 三个前提：配置一致（同缓存/同模型）、充分预热（跳过冷启动）、多次重复（报告方差）。

- **配置一致**：比较两个方案时只改一个变量。
- **预热**：跳过冷缓存阶段，或明确报告是否含冷启动。
- **重复与方差**：多次运行，报告中位数与波动。
- **工作负载**：说明程序、输入、编译选项；单程序结论不能外推。
- **记录**：配置、版本、命令一并落盘。

## 6. 不能外推什么？

**答：** 绝对值、硅频率、功耗、面积；这些要么依赖模型精度，要么根本不在模型范围内。

- **绝对值**：模型精度决定误差，不能当真实芯片的周期数。
- **频率**：模型不建模工艺与物理约束。
- **功耗/面积**：需要 RTL 与综合。
- **外推前提**：相对比较可跨配置复用，绝对数字不行。

## 背景知识

### 术语与概念

- **执行驱动**：真实执行指令并建模微架构。
- **轨迹驱动**：只吃访存/指令轨迹。
- **原子/顺序/乱序模型**：精度与代价依次上升的 CPU 模型。
- **IPC**：每周期完成的指令数。
- **预热**：跳过冷启动阶段，进入稳态后再统计。
- **敏感性分析**：改变一个参数看结论如何变化。

### 对照

**模型精度**

- **原子**：最快，接近功能级。
- **顺序**：有周期，无乱序。
- **乱序**：最真，最慢。

**评测用途**

- **选型对比**：同配置相对比较。
- **敏感性研究**：参数扫描。
- **系统行为**：系统级模式。
- **不适用**：语义判据、硅级频率/功耗。
