# 运行平台 -- 功能级模拟

**本册要点**

- 功能级只保证**架构可见结果**：寄存器、内存、异常；不建模时序。
- 它能回答"对不对"，不能回答"快不快"。
- 半主机与设备是**平台**的一部分，不是指令语义。
- 观测手段是它的强项：跟踪、日志、调试接口。
- 它是其他载体的**参照**，但不是判据来源。

## 1. 功能级模拟保证什么、不保证什么？

**答：** 保证"同样的输入得到同样的架构状态"；不保证"用多少拍、走哪条流水线"。因此它适合语义验收，不适合性能结论。

- **保证**：指令语义、异常与陷入、系统调用与半主机、启动流程。
- **不保证**：周期数、缓存行为、分支预测、乱序执行。
- **副作用**：功能级跑得极快，能在分钟级覆盖大量用例。
- **风险**：跑得快容易被误当成"性能参考"——指令计数不是周期数。

## 2. 它能测什么？

**答：** 语义正确性、异常路径、启动与引导、系统调用与库交互、以及"程序能不能跑通"。

- **指令与序列**：单指令语义、短序列、边界值。
- **异常**：非法编码、对齐错误、权限拒绝、陷入与返回。
- **系统**：启动流程、半主机 I/O、系统调用、库初始化。
- **覆盖**：能配合覆盖统计看"哪些指令/路径被走到"。

## 3. 它不能测什么？

**答：** 一切与时序相关的东西：性能、缓存、分支预测、总线争用、功耗。

- **性能**：没有周期模型，无法给出可信的耗时。
- **缓存/预取**：多数功能级模拟不建模缓存层次。
- **并发时序**：多核交错是"实现选择"，不是架构语义（内存模型除外）。
- **替代方案**：需要时序时换周期级模型或 RTL。

## 4. 怎么把它跑起来？

**答：** 三件事：机器模型（内存布局、复位向量、设备）、加载方式（镜像或 ELF）、以及平台服务（半主机/系统调用）。

- **机器模型**：地址空间、RAM 段、复位入口、异常向量。
- **加载**：直接加载二进制，或加载 ELF 由模拟器解析。
- **平台服务**：半主机（文件/控制台/退出）、或完整系统调用链。
- **参数化**：位宽、扩展、端序、内存大小——配置不同，语义边界不同。
- **记录**：跑之前把配置写进结果，否则结论不可复现。

## 5. 怎么观测？

**答：** 三条路：执行跟踪（指令流/访存流）、结构化日志（异常与系统调用）、调试接口（断点/单步/寄存器读写）。

- **跟踪**：看执行了哪些指令、访存到哪里；也可作为轨迹驱动模型的输入。
- **日志**：异常原因、系统调用参数与返回值。
- **调试接口**：远端调试协议，设断点、读寄存器、看内存。
- **开销**：跟踪会显著变慢，但不改变语义。

## 6. 为什么它是参照而不是判据？

**答：** 因为模拟器自己也会错：它的输出是"一个实现的行为"，不是"规范的要求"。判据必须来自规范与独立派生。

- **用法一**：作为差分的一路（与其他实现交叉）。
- **用法二**：作为快速冒烟，先排除"跑不通"。
- **用法三**：作为轨迹来源（供轨迹驱动模型）。
- **禁止**：用它的输出生成期望值；把它的一致当成正确。
- **纪律**：发现分歧时先判"哪边错"，不默认被测错。

## 背景知识

### 术语与概念

- **功能级模拟**：只保证架构可见结果的模拟器。
- **机器模型**：地址空间、内存、复位与设备的定义。
- **半主机**：guest 通过特殊陷入请求宿主 I/O。
- **跟踪**：记录执行过的指令与访存。
- **调试接口**：断点、单步、寄存器/内存访问。

### 对照

**功能级模拟的定位**

- **语义验收**：首选，快且可自动化。
- **轨迹来源**：为轨迹驱动模型提供访存流。
- **差分一路**：与其他实现交叉验证。
- **不适用**：性能、时序、缓存结论。

**各家实现**

- **多架构模拟器**：覆盖面广，设备模型多。
- **专用模拟器**：针对本架构，启动快、可控。
- **共同点**：都只保证架构可见结果。
