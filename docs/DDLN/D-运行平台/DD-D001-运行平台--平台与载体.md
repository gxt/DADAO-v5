# 运行平台 -- 平台与载体

## 为什么要把“运行环境”和“载体/粒度”分开看？

**答：** 同一个 ISA 的验证有两个正交维度：**运行环境**（裸机 / 用户态 / 完整系统）决定“软件跑到哪一层”，**载体与粒度**（模拟器 / RTL / FPGA；功能 / 周期 / 性能）决定“硬件模型有多真”。两者混在一起，容易把“用户态”和“周期级”当成同一类选项。

- **运行环境**：裸机、用户态模拟、完整系统模拟。
- **载体**：功能模拟器、RTL 仿真、FPGA/ASIC。
- **粒度**：功能级、周期级、性能级。
- **选择原则**：先定验收目标（语义 / ABI / 系统 / 时序），再选环境与载体。

## 1. 运行环境

### 1.1 裸机（bare metal）

- **形态**：bootrom + 应用镜像直接加载到机器模型（`-bios` 或 ELF 单镜像），没有操作系统。
- **用途**：指令向量（L1 编码 / L2 结构 / L3 执行）、ISA 语义、standalone 测试程序（newlib + `crt0` + semihosting）。
- **特点**：可控、可观测；没有进程、页表、驱动，适合“一条指令/一个语义”的精确验证。

### 1.2 用户态模拟（qemu-linux-user 类）

- **形态**：guest ELF 直接跑在宿主内核上，guest 的 syscall 转发为宿主 syscall（qemu-user）。
- **用途**：libc/测试套件（musl、libc-test）、应用级行为。
- **特点**：启动快、不需要内核镜像；但只覆盖用户态，不覆盖内核、驱动、启动流程。

### 1.3 完整系统模拟（qemu-system 类）

- **形态**：完整机器——CPU + RAM + 外设 + bootrom + SEE + OS。
- **用途**：启动流程、驱动、系统调用、OS 级 E2E。
- **特点**：最接近真实机器；但慢、依赖镜像与配置。

## 2. 载体（跑在哪）

- **功能级模拟器（QEMU / ISS）**：在宿主上解释/翻译 guest 指令，只保证架构可见结果；启动快、易自动化。
- **RTL 仿真（Verilator 等）**：用硬件描述语言仿真 CPU/SoC，可观测内部信号与周期级时序。
- **FPGA / ASIC 实机**：真实芯片或 FPGA 上的 SoC，能测频率、功耗、外设与真实时序。

## 3. 粒度（仿真到多细）

- **功能级**：只保证寄存器、内存、异常等架构可见结果，不建模时序；QEMU、ISS。
- **周期级**：建模每级流水线、总线、cache 的周期行为；RTL 仿真。
- **性能/时序模型**：建模吞吐、延迟、微架构参数；gem5 等，用于性能研究。

## 4. 载体 × 粒度

- **功能模拟器**：功能级。
- **RTL 仿真**：周期级（也可只跑功能级）。
- **FPGA / ASIC**：真实时序（可测频率、功耗、外设）。
- **性能模型**：性能级（不用于语义验收）。

## 5. 选择原则

- **语义验收**：功能级（最快、最易自动化）。
- **时序 / 异常 / 总线**：周期级（RTL）。
- **频率 / 功耗 / 外设**：FPGA / ASIC。
- **性能研究**：性能模型。

## 6. 每个环境的库、链接与宿主接口

- **裸机**：`newlib` / `picolibc`；静态链接；semihosting（`SYS_EXIT`、文件 I/O）。
- **用户态模拟**：`musl` / `glibc`；动态/静态；guest syscall 转发到宿主。
- **完整系统**：`musl` / `glibc`；静态/动态/PIE；guest 内核 syscall，经 SEE/驱动。

## 小结

- **语义验收**：裸机 + 功能级模拟器。
- **ABI/应用验收**：用户态模拟 + 功能级。
- **系统验收**：完整系统模拟（可上 RTL/FPGA）。
- **时序/性能**：周期级 RTL、FPGA/ASIC、性能模型。
