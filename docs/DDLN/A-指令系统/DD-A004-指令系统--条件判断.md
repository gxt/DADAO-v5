# 指令系统 -- 条件判断

**本册要点**

- 主流 CZSO 的动机：几乎免费、编码省位、一次比较多个谓词、多精度。
- CZSO 的代价：隐式状态、假依赖、重命名/异常恢复复杂、比较结果不可复用。
- SimRISC 取消 CZSO：条件直接来自寄存器值。
- 六种条件：N/NN/Z/NZ/P/NP；两寄存器另有 EQ/NE。
- `cmp` 产生 -1/0/1；`.s`/`.u` 区分符号性。
- `br.eq`/`br.ne` 把两寄存器比较融进分支。
- 条件赋值 `cs.*` 以寄存器为条件源。
- `cs.*` 是"二选一"（两条路径都写），区别于 `cmovcc` 的条件写。

## 1. 主流 ISA 为什么都是 CZSO？

**答：** 准确地说，是 **x86 / ARM 这类商业主流 ISA 用 CZSO（Carry/Zero/Sign/Overflow）**；RISC-V 就明确不用标志位。它们采用 CZSO 的主要原因：

- **几乎免费**：ALU 本来就要算出进位、零、符号、溢出，把这 4 位暴露出来成本很低。
- **编码省位**：条件隐含在标志位里，条件分支**不需要携带"条件源寄存器"**，指令更短、代码密度更高（x86 的 `jcc` 只有 2 字节）。
- **一次比较、多个谓词**：4 个标志位通过组合可以表达 EQ/NE/LT/LE/GT/GE 的有符号与无符号版本；`cmp` 本质上就是一次"丢弃结果的减法"，标志位留下。
- **多精度算术**：C 位天然支持带进位加 / 带借位减链。
- **历史与兼容**：早期机器从"累加器 + 标志位"演化而来；x86/ARM 的二进制兼容与生态又把这个模式固化下来。
- **各家做法**：x86（EFLAGS）、ARM64（NZCV）、SPARC（icc）、PowerPC（CR）用标志位/条件码；RISC-V、MIPS 明确不设标志位，用比较指令产生 0/1。
- **为什么 x86/ARM 保留**：二进制兼容与生态；RISC-V/MIPS 从零设计，选择更简单的显式比较。

## 2. CZSO 与实际使用（六种条件）之间的差距在哪里？如何弥补？

**答：** 先对齐口径：SimRISC 实际使用的是**六种单操作数条件**——负数 N、非负数 NN、零 Z、非零 NZ、正数 P、非正数 NP；两寄存器比较另有 EQ/NE。

**差距：**

- **标志位是 ALU 的中间产物，不是软件的条件**。软件想的是"这个值是不是负数/零/正数"，硬件给的是 C/Z/S/O 四个位；要从标志位得到六种条件，必须做**组合译码**（例如有符号 `<` 看 `S≠O`，无符号 `<` 看 `¬C`，`≤` 还要并上 `Z`）。
- **同一组标志位对应两套语义**：有符号与无符号的比较要用不同的标志位组合，所以 ISA 得提供两套分支助记符（`jl` vs `jb`），编译器按类型选择。
- **标志位是隐式状态**：分支依赖"最近一次写标志位的指令"，而不是某个具名值；这带来隐藏依赖、部分写标志位（有的指令只更新部分位）、难以重命名等问题。
- **比较结果不可直接复用**：标志位不能当普通值保存/传递，要额外 `setcc` 才能物化，而且会被后续指令覆盖。
- 一句话：**4 个标志位要覆盖"6 种条件 × 2 种符号性"（再加 EQ/NE），是一层组合编码，而不是条件的直接表示。**

**如何弥补（主流做法）：** 提供有符号/无符号两套分支；用 `setcc`/`cmovcc` 把条件物化成值；`cmp`+分支做宏融合；编译器做标志位活跃性分析与条件码选择。也就是说，**差距主要靠编译器和指令变体来填**。

- **各家做法**：x86 用 `setcc`/`cmovcc` + `jcc`；ARM64 用 `CSEL`/`CSET`/`B.cond`；RISC-V 用 `slt`/`sltu` + 分支（`Zicond` 提供 `czero.*`）；MIPS 用 `slt`/`sltu` + `beq`/`bne`；SPARC 用 `icc` + `b<cond>`/`tcc`；PowerPC 用 `CR` + `bc`/`crand`。

## 3. CZSO 对硬件设计与实现的影响有多大？

**答：** 分实现档次看——**面积不大，但依赖与推测的复杂度高**。

- **简单顺序流水线**：影响小。4 位标志位寄存器 + ALU 的标志位输出 + 分支读标志位，面积和延迟都可忽略。
- **乱序/超标量**：
  - 标志位要像寄存器一样**重命名**；部分写标志位还需要合并（x86 的标志位合并是典型复杂点）。
  - **假依赖**：每条写标志位的指令都会和前一条形成 WAW/WAR；分支依赖最近的标志位写者，限制乱序窗口。
  - **精确异常与推测**：标志位是架构状态，要保存检查点/恢复；分支误预测要恢复标志位。
  - 需要额外的前递/旁路通路。
- **编译器**：要做标志位活跃性分析，且不能随意重排"写标志位"的指令。
- **结论**：标志位本身只值几个触发器，真正的代价在**依赖跟踪、重命名、异常恢复**——这正是 RISC-V 选择"不要标志位"的原因之一。
- **各家选择**：x86/ARM 保留 CZSO/NZCV（兼容/生态）；RISC-V/MIPS 不设标志位（简化乱序/重命名）；SPARC/PowerPC 保留条件码（历史/兼容）。

## 4. SimRISC 是如何解决这一问题的？

**答：** 直接**取消 CZSO，不设标志位寄存器**，把条件判断建立在**寄存器中的值**上。

- **六种条件直接看值**：`br.n`/`br.nn`/`br.z`/`br.nz`/`br.p`/`br.np` 都带一个 `rd` 寄存器，按它的值判断（`br.z`/`br.nz` 另有 `rb` 变体）。
- **两寄存器比较**：`br.eq`/`br.ne` 直接比较两个 `rd`。
- **关系比较靠 `cmp` 组合**：`cmp.s*`/`cmp.u*` 产出 **-1/0/1**，后续用六种条件就能组合出 `<`、`≤`、`>`、`≥` 等关系。
- **条件赋值同理**：`cs.*`（条件赋值）也以寄存器为条件源。
- **好处**：没有隐藏状态、没有标志位假依赖，条件的来源是显式的寄存器操作数；加减指令的 `.s`/`.u` 只决定高位扩展（进位/高半部分），不再为标志位服务。
- **代价**：条件指令要多带一个寄存器操作数。
- **与 RISC-V 的对比**：两者都不设标志位；RISC-V 用 `slt`/`sltu` 产生 0/1，SimRISC 用 `cmp` 产生 -1/0/1；关系比较都是"比较 + 条件分支"两步。

## 5. 为什么要引入 br.eq/br.ne 指令？

**答：** 因为"两个寄存器是否相等"是最高频的条件分支，而它值得一条指令完成。

- **没有标志位时，等价写法是两条指令**：先 `cmp` 产生 -1/0/1，再用 `br.z`/`br.nz` 判断——多一条指令，还多占一个结果寄存器。
- **`br.eq`/`br.ne` 把比较融进分支**：直接比较两个 `rd`，不写结果寄存器、不产生中间值。
- **高频依据**：`br.ne` 与 `br.eq` 的占比约 **7.4%**，优化这个高频模式收益明显。
- **编码形态**：`rrii`（两个寄存器 + 相对偏移），只读不写；`br.nz rd0` 恒假、`br.z rd0` 恒真，也是有用的编码特例。
- **各家做法**：x86 `cmp` + `je`/`jne`（两条）；ARM64 `CBZ`/`CBNZ`（一条，比较一个寄存器与 0）；RISC-V `beq`/`bne`（一条，两寄存器）；MIPS `beq`/`bne`（一条）。
- **为什么 SimRISC 单独设**：没有标志位，`cmp`+`br.z` 要两条；`br.eq/ne` 把两寄存器比较融进分支，省一条。

## 6. cmp 指令为何要区分有符号数和无符号数？

**答：** 因为**同一串位模式，按有符号和无符号解释，大小关系可能相反**（例如全 1 既可能是 -1，也可能是 2^64−1）。

- 比较结果只能是 **-1/0/1** 中的一种，它必须对应某一种解释；硬件无法从位模式知道程序员想要哪种类型。
- 所以由指令编码来区分：`cmp.s*`（有符号）与 `cmp.u*`（无符号）；位宽后缀（`.b/.w/.t/.o`）决定比较宽度，符号性决定比较时按有符号/无符号解释；结果统一按 64 位写满（-1 为全 1）。
- 具体形态：`cmp.si`/`cmp.ui`（12 位立即数），`cmp.so`/`cmp.uo`（寄存器）；源按位宽截断后比较，结果写目的寄存器全 64 位；`cmp.uo-rb` 则对两个基址寄存器做整 64 位无符号比较。
- 这与带标志位的 ISA 用不同分支助记符表达有符号/无符号是同一问题的两种解法：**SimRISC 把类型信息放在 `cmp` 指令里**，后续六种条件只负责"看结果的正、负、零"。
- **各家做法**：x86 `jl`/`jb`（有符号/无符号分支）；ARM64 `B.LT`/`B.LO`；RISC-V `slt`/`sltu`；MIPS `slt`/`sltu`；SPARC `bl`/`blu`；PowerPC 用 `cmpw`/`cmplw` 写 CR，再用 `blt` 测字段。
- **为什么 SimRISC 放在 `cmp` 里**：后续六种条件只读 -1/0/1，不需要两套分支助记符。

## 7. 使用条件码的指令，如跳转或条件赋值，为何都需要额外的 RD 寄存器来作为条件判断的源头？

**答：** 因为没有了标志位，条件必须来自某个**具体的值**，指令就必须指明"判断哪个寄存器"。

- **带标志位的 ISA 的对比**：条件隐含在标志位中，分支指令不带条件源操作数——编码省位，但依赖是隐藏的（分支依赖最近一次标志位写入）。
- **SimRISC 的必然选择**：`br.n_riii_rd` 带一个 `rdHA`，`br.eq`/`br.ne` 带两个 `rd`，`cs.*` 也带条件源寄存器。条件源是**显式操作数**。
- **代价**：多一个寄存器操作数、多一个读端口，编码里要多花 6 位。
- **收益**：依赖显式可见，没有隐藏状态；寄存器本来就要重命名，不需要再为标志位单独做重命名/合并；编译器也不必做标志位活跃性分析。
- 一言以蔽之：**这是"去掉 CZSO"的必然代价，也是它简单的地方——没有额外的状态要维护。**
- **各家做法**：x86/ARM/SPARC/PowerPC 的条件隐含在标志位/条件码里；RISC-V/MIPS 的比较/分支显式带寄存器；SimRISC 与 RISC-V/MIPS 同属"显式条件源"，但用 -1/0/1 + 六种条件。

## 8. 为什么条件赋值用 cscc（两条路径都赋值），而不是 cmovcc（条件不满足就不赋值）？

**答：** 因为 `cs.*` 在条件成立和不成立时都写目的寄存器，语义是"二选一"，不需要保留旧值；这让它少一个隐式输入，也让编译器更容易把它排进依赖链。

- **cmovcc 的语义**：条件成立时写目的，不成立时目的保持原值——目的寄存器既是输出又是输入，形成读-写依赖。
- **cs.* 的语义**：`if (cond) rdHB = rdHC; else rdHB = rdHD`——两个源都显式给出，目的只写不读。
- **四操作数**：`cs.n`/`cs.z`/`cs.p` 用 `rdHA` 作条件源、`rdHB` 作目的、`rdHC`/`rdHD` 作两个候选值；`cs.eq`/`cs.ne` 用两个寄存器做条件。
- **好处**：没有"旧值"这个隐藏输入，寄存器重命名/乱序更简单；编译器可以把两个候选值都算好，再用一条 `cs.*` 选。
- **代价**：多一个源寄存器操作数（4 操作数），编码和寄存器堆端口压力更大。
- **对比**：x86 的 `cmovcc` 是条件写（不成立保持旧值）；ARM 的 `CSEL` 是二选一（与 `cs.*` 同型）。
- **各家做法**：x86 `cmovcc`（条件写）；ARM64 `CSEL`（二选一）；RISC-V `Zicond` 的 `czero.eqz`/`czero.nez`（条件清零，不是通用二选一）；MIPS `movz`/`movn`（条件搬移，读-改-写）；SPARC/PowerPC 的条件搬移。
- **为什么 SimRISC 选二选一**：避免目的寄存器的读-改-写依赖；四操作数让两个候选值都显式。

## 背景知识

### 术语与概念

- **条件码（condition codes）**：由 ALU 顺带产生的标志位（C/Z/S/O），供后续分支/条件指令读取。
- **谓词（predicate）**：由条件决定是否执行/赋值，而不是跳转。
- **分支预测**：硬件猜测分支方向，猜错要恢复；条件码是隐式状态，猜错恢复更复杂。
- **乱序执行与重命名**：标志位若作为架构状态，也要像寄存器一样重命名；部分写标志位需要合并。
- **指令融合（macro-fusion）**：把 `cmp` + 条件分支合并成一个内部操作，减少指令数。
- **有符号/无符号比较**：同一组位模式，两种解释的大小关系可能相反；ISA 要么给两套分支，要么在比较指令里区分。

### 对照

- **x86**：**单独寄存器** `RFLAGS`（64 位；32 位时代为 `EFLAGS`）。条件位：`CF`(0)、`PF`(2)、`AF`(4)、`ZF`(6)、`SF`(7)、`OF`(11)；另有 `DF`/`IF`/`TF` 等控制位。`cmp`/`test`/算术指令置位；`jcc` 读条件位分支，`setcc` 物化 0/1，`cmovcc` 条件搬移；`lahf`/`sahf`、`pushf`/`popf` 可整体读写。
- **ARM**：**不是通用寄存器**，条件位在 `PSTATE`（A64）/ `CPSR`（A32）里：`N`(31)、`Z`(30)、`C`(29)、`V`(28)。`cmp`/`cmn`/`tst`/`teq` 置位；`b.cond` 读位分支，A32 还支持条件执行，A64 用 `csel`/`cset`；`MRS`/`MSR` 读写 `PSTATE.NZCV`。
- **RISC-V**：**没有标志位寄存器**。`beq`/`bne`/`blt`/`bge`/`bltu`/`bgeu` 直接比较两个寄存器；需要物化时用 `slt`/`sltu` 产生 0/1，再用普通分支。
- **MIPS**：**没有标志位寄存器**。`beq`/`bne` 直接比较寄存器；`slt`/`sltu` 物化 0/1；分支有延迟槽。
- **SPARC**：条件码在 `PSR` 里，不是通用寄存器：`icc`（32 位）含 `N`/`Z`/`V`/`C`；V9 另有 `xcc`（64 位）。`cmp`/`subcc`/`addcc` 置位；`b<cond>` 读位分支，`tcc` 条件陷入。
- **PowerPC**：**单独寄存器** `CR`（32 位，8 个 4 位字段 `CR0`–`CR7`）；每个字段含 `LT`/`GT`/`EQ`/`SO`。`cmp`/`cmpi`/`cmpl`/`cmpli` 写指定字段；`add.`/`and.` 等 `record` 形式写 `CR0`；`bc` 测试 CR 位/字段；`crand`/`cror` 等组合 CR 位；`mfcr`/`mtcrf` 整体读写。
- **SimRISC**：**没有标志位寄存器**。六种条件（N/NN/Z/NZ/P/NP）直接看寄存器值；`br.eq`/`br.ne` 比较两个寄存器；`cmp` 产生 -1/0/1，后续用六种条件组合。
