# 大道至简——寄存器

## 1. 为什么要把通用寄存器分解为 RD 和 RB？

**答：** 核心是**把"算数据"和"算地址"分开**：基址使用量很大，且基址总是明确的（显式指定，或相对寻址隐含 IP），所以单独设一组不会带来歧义。

- **职责分离**：`rd` 专注数据运算，`rb` 专注基址/地址运算；数据寄存器不再被地址计算占用，寄存器压力下降。地址运算也有专用指令（`add.si-rb`/`add.so-rb`/`sub.so-rb`/`cmp.uo-rb`），不必挤进数据指令。
- **等效翻番**：`rd` 与 `rb` 各 64 个，合计相当于 **128 个通用寄存器**——在 64 个数据寄存器之外多出一倍的可用寄存器，显著降低寄存器压力与寄存器溢出。
- **基址使用量很大**：几乎每次访存和相对跳转都要用一个基址；若与数据共用一组寄存器，地址会长期占用数据寄存器。单独设一组 `rb`，解决的是"地址常驻占用"的问题，而不是"地址运算很多"。
- **基址总是明确的**：`ld`/`st`/`br`/`jump`/`call` 显式写出基址；相对寻址虽然隐含基址，但也明确就是 IP（`rb0`）。不会把"数据"误当"地址"；再加上位域固定，译码器也不必猜。
- **代价**：`rb` 不能当通用数据寄存器用，灵活性略降；换来的是规整、专用化和更少的寄存器压力。

## 2. 为什么每个寄存器组都是 64 个寄存器？

**答：** 6 位字段是**组内编号**；它属于哪一组，由指令的 `opc`/`opx` 和操作数格式决定——同一条指令的多个字段可以分属不同组，所以每组都是 64 个。

- **字段属于哪一组，由指令决定**：`opc`/`opx` 和操作数格式规定了每个 6 位字段对应 `rd`/`rb`/`rf`/`ra` 中的哪一组；同一条指令的多个字段可以分属不同组（如 `rb2rd` 的源是 rb、目的是 rd；`ra2rd` 的源是 ra、目的是 rd）。
- **6 位 = 组内编号**：每个字段都是它所在组内的编号，固定 6 位，`2^6 = 64`，所以每组 64 个寄存器。
- **与"以 8 为单位"自洽**：64 = 8 × 8，和 64 位字长、64 字节高速缓存行、64 KiB 页是同一套节奏。

## 3. 为什么每个组的 0 号用来做特殊寄存器？

**答：** 0 号槽本来就在编码里，用它承载特殊状态，可以省掉专门的 flags/CSR/FCSR 寄存器。

- **省掉专用寄存器**：`rd0` = 常数 0、`rb0` = IP、`rf0` = 浮点状态（FCSR）、`ra0` = RAS 控制/状态——特殊状态都放在各组的 0 号槽里，不需要再设 flags/CSR/FCSR 等独立寄存器。
- **减少特殊指令**：`rf0` 让设置舍入模式/读异常状态不必另设 FCSR 指令（用普通 `set.w`/浮点操作即可）；`rb0` 让相对/绝对寻址只靠"选哪个基址寄存器"来切换，不需要专门的寻址模式指令；`rd0` 提供现成的全 0 操作数，不需要额外的清零/取零指令。
- **0 号仍属于本组的范畴**：`rd0` 是数据（常数 0）、`rb0` 是地址（IP）、`ra0` 是地址相关的栈元数据（`MRPTR`）、`rf0` 是浮点值/状态；`rf0` 既是 FCSR，又是单精/双精 qNaN，也就是**合法的浮点格式**，可以作浮点源操作数，不是"保留编码"。
- **各取所需、只做辅助**：`rd0` 提供常数 0 与"丢弃结果"的目的槽；`rb0` 解决绝对/相对寻址的基址问题；`rf0` 复用为浮点状态；`ra0` 存放栈的有效条目数与内存栈指针。同时 `rb0` 只读、不能作目的；`rd0` 只在特定格式下作为"丢弃结果"的目的；`ra0` 不存普通返回地址。

## 4. 为什么 RD0 要固定只读为 0，写无效或非法？

**答：** 因为"常数 0"是最有用的常数；rd0 只读，写它没有实际用途，只会引入特例。

- **用途广**：清零、比较、寄存器搬移（`or rd, rs, rd0`）、取反（`xnor.o rd, rs, rd0`）、取负（`sub rd, rd0, rs`）等，都直接受益于"读出一个确定的 0"。
- **读为 0 是确定值**：作源操作数时读出 0，不触发 ILLI；"存 0 到内存"这类用法也合法。
- **作目的有明确规则**：`rrrr` 双目的格式允许其中一个目的为 `rd0`（丢弃对应半结果），但不能两个同时为 `rd0`、也不能为同一个非 `rd0` 寄存器；`ret rd0, 0` 允许（表示不需要返回值）；除这几类特殊情况外，目的为 `rd0` 一律触发 ILLI。
- **只读的硬件好处**：不需要真实的寄存器存储和写端口，没有写后读冒险；译码时直接给出常数 0。

## 5. 为什么 rb0 是 rbip，指向的是当前指令的地址，而非主流 ISA 的下一条指令？这样做对硬件实现有什么影响？

**答：** `rb0` 就是 IP，指向当前指令的地址；把它作为显式基址，相对寻址和绝对寻址就可以共用同一套指令。

- **相对/绝对寻址统一（最关键）**：三种基本形态——`[rbx, imm]` 基址+偏移、`[rbx, rdy]` 基址+变址、`rrii` 的 `[rbHA, rdHB, imm]` 基址+变址+偏移；基址既可以是 `rb0`（相对寻址），也可以是其它 `rb`（绝对寻址）。它们共用同一套指令。
- **主流 ISA 的对比**：主流 ISA 基本不把 PC 作为**显式寄存器**使用（不能写进指令的寄存器操作数）；而且它们大多不是固定长度——要么变长（x86），要么有 16 位压缩/扩展长度（ARM Thumb、RISC-V C）。SimRISC 是定长 32 位，又允许 `rb0` 作为显式操作数，所以可以直接用它做基址。
- **消除差一错误**：主流 ISA 的 PC 通常已是"下一条指令地址"（取指后自增），用它做基址要减 4 或用 `PC+4` 口径；DADAO 明确取"当前指令地址"，从定义上消除偏移错误。
- **对 `call` 的影响**：主流 ISA 的 PC 已指向下一条指令，可直接把它作为返回地址；SimRISC 的 IP 是当前指令地址，`call` 需要 `IP + 4` 才是返回地址。因为指令固定 4 字节，这个 `+4` 是确定的，不会出现变长指令下按"下一条指令实际长度"计算的歧义。
- **硬件实现**：当前指令的地址在**取指时就已经固定**，执行期间不再变化；它不能放在寄存器堆里——寄存器堆只有一个"当前值"，而流水线里同时有多条指令，各有各的地址。做法是**在取指时把该指令的地址保存下来**（随指令一起送入后续流水级/指令标记），执行时直接使用。
- **例外/中断**：IP 指向出错指令本身，天然支持精确异常与"处理后重新执行"。

## 6. 为什么 rf0 作为 FCSR？

**答：** `rf0` 既是浮点格式（qNaN），又是 FCSR；非 FCSR 部分按设计忽略写入，所以它能像普通 `rf` 一样作源/目的，现场保存恢复也更简洁。

- **一条寄存器读写状态**：`rf0[33:32]` 是舍入模式（RNE/RTZ/RDN/RUP），`rf0[4:0]` 是异常状态（NV/DZ/OF/UF/NX）；读写用普通浮点寄存器操作即可，不必新增 CSR 或专用指令。
- **`rf0` 是合法浮点格式**：它既是单精 qNaN 又是双精 qNaN，可作浮点源操作数。
- **可作源/目的**：`set.w`（立即数赋值）、`rd2rf`/`rf2rd`（寄存器复制）、`ld`/`st`（取数存数）都允许 `rf0` 作源或目的；写入只更新 FCSR 相关位，其余位按设计忽略。
- **现场保存/恢复简洁**：保存 `rf0`–`rf63` 就把 FCSR 一起保存了，恢复同理，不需要单独保存/恢复 FCSR。
- **不能作浮点运算目的**：浮点运算会更新状态位，所以 `rf0` 不可作浮点运算的目的；这也能防止手写汇编时把 `rf0` 误当普通目的寄存器。

## 7. 为什么 ra 是个栈？

**答：** 把返回地址从"软件保存/恢复"变成"硬件 call/ret 自动维护"，省访存、省高速缓存污染，也更不容易跑飞。

- **调用/返回自动压弹**：`call` 压入返回地址，`ret` 弹出；函数序言/尾声不再需要保存恢复返回地址，减少函数序言/尾声的整理工作和访存。
- **寄存器栈 + 内存栈**：`ra1`–`ra63` 是 63 槽的 RegRAS；`ra0` 的 `MRPTR` 指向 MemRAS（内存栈）。调用深度不超过 63 层时只用 RegRAS；超过时把最旧的条目溢出到 MemRAS。递归（尤其是 P 调 Q、Q 又调 P 的互递归）返回地址交替变化，递归折叠不生效，RegRAS 消耗更快，更容易用到 MemRAS。
- **大部分应用用 RegRAS 就够**：63 个槽位足以覆盖绝大多数程序的调用深度，MemRAS 只是深调用/互递归时的兜底。
- **递归折叠**：返回地址相同且递归计数未满时，只增加高 16 位的递归计数，不重复压栈，节省槽位。
- **与数据栈分离**：返回地址不会被数据溢出或错误写坏；出错时表现为数据错误，而不是取回错误返回地址导致控制流"跑飞"。
- **硬件实现**：架构上是 `ra1`–`ra63` 的软件可见视图，但实现不必逐条搬移——可用环形缓冲 + 隐藏的基准索引完成压栈/弹栈；软件访问 `ra_i` 时按基准索引换算，保持架构视图一致。
- **对微架构友好**：返回地址栈天然适合返回地址预测等优化。

## 8. 为什么需要 ra0 作为特殊寄存器？

**答：** `ra0` 是为了解决"返回地址统一管理"引出的问题：其它 ISA 的 `call`/`ret` 只管单个返回地址，多层保存交给编译器（函数序言/尾声）；SimRISC 把返回地址统一交给 RAS 管理，就必须有 `ra0` 记录栈的状态。

- **对比其它 ISA**：其它 ISA 的 `call`/`ret` 只处理单个返回地址，嵌套调用由编译器在函数序言/尾声保存/恢复；SimRISC 用 RAS 统一管理多层返回地址，`ra0` 是这个管理的状态字。
- **`ra0[53:48]` = `RACNT`**：RegRAS 有效条目数（0–63）。有效性判据是 `RACNT`，不是看条目自身的值。
- **`ra0[47:0]` = `MRPTR`**：MemRAS 栈顶地址（8 字节对齐）。`MRPTR == 0` 表示不启用 MemRAS，只有 RegRAS，超过 63 层触发 RASOF，由程序自己处理；`MRPTR != 0` 表示 MemRAS 已事先分配，硬件自动压栈/弹栈维护。
- **`ra0[63:54]` = SBZ**（写无效）。
- **没有它就无法管理栈**：硬件要知道"有几个有效条目""内存栈顶在哪"；放在 `ra0` 里，进程切换时保存/恢复 `ra0`–`ra63` 即可。

## 9. RAS 为什么会溢出？

**答：** 因为 RAS 是有限的硬件栈——调用深度超过容量会上溢，返回地址不够弹时会下溢；两者同样重要。

- **上溢（RASOF）**：`call` 要压栈但没有地方放。RegRAS 只有 63 个槽；`RACNT == 63` 且 `MRPTR == 0` 时触发 RASOF。
- **下溢（RASUF）**：`ret` 要弹栈但没有有效条目。`RACNT == 0` 且 `MRPTR == 0` 时触发；或启用了 MemRAS、但 MemRAS 条目的递归计数为 0 时触发。
- **即使启用了 MemRAS，上溢/下溢仍会发生**：MemRAS 是事先分配的内存区，容量有限，耗尽后仍会上溢（硬件不检测，交给 OS 处理）；下溢则按 MemRAS 条目的判定照常触发。
- **软件介入分两种情况**：没有 MemRAS（`MRPTR == 0`）时，程序要自己维护返回地址——上溢时把返回地址存到其它的数据区，下溢时从其它的数据区恢复或报错；有 MemRAS（`MRPTR != 0`）时，常规压弹由硬件完成，软件只在 MemRAS 容量耗尽（硬件不检测，交 OS）或 MemRAS 条目判定为下溢时介入。

## 背景知识

### 术语与概念

- **寄存器（register）**：CPU 内部的小块高速存储，用来存放操作数、地址、状态等；访问速度远高于内存，数量受编码位宽限制。
- **寄存器堆（register file）**：CPU 内存放寄存器的一组存储单元，带若干读/写端口；分组（bank）会增加端口与面积。
- **寄存器堆的读写端口**：一条指令可能要读多个源、写一个目的；端口越多越贵，所以寄存器数量与分组要权衡。
- **寄存器分组（bank）**：把寄存器堆按用途拆成几组，每组有自己的编号空间和读写端口；指令按操作数位置决定用哪一组。好处是各组按用途优化（数据/地址/浮点/返回地址）、减少端口冲突；代价是分组越多硬件越复杂，跨组搬运要专门指令。对比：x86/ARM/RISC-V 一般是"通用 + 浮点"两组；SimRISC 分成 `rd`/`rb`/`rf`/`ra` 四组。
- **ABI（应用二进制接口）**：寄存器用途、参数传递、谁保存/恢复哪些寄存器等约定。
- **调用约定**：返回地址、参数、局部变量放在哪里；返回地址由硬件保存还是软件保存，是 ISA 设计的一个分界。
- **调用栈**：后进先出（LIFO）的数据结构，通常放在内存，由栈指针维护。
- **IEEE 754**：浮点格式、舍入、异常与 NaN 的标准。
- **NaN 的两种形态**：IEEE 754-1985 把 NaN 分为 qNaN（安静）与 sNaN（signaling），用尾数最高位区分（1 = qNaN，0 = sNaN）；qNaN 用于传播，sNaN 用于触发无效运算（NV）。
- **精确异常**：异常发生时，处理器能精确指出出错的那条指令，并保证它之前的指令已完成、之后的指令没有产生可见效果；处理后可以从该指令重新执行。

### 对照

**1. 寄存器分组与宽度**

- **x86-64**：通用寄存器 16×64 位；SIMD 16×128 位（AVX-512 可到 32×512 位）；x87 8×80 位；另有段寄存器（6×16 位，遗留）、RIP、RFLAGS。
- **ARM64**：通用 31×64 位（X0–X30，另有 SP/ZR）；SIMD/浮点 32×128 位（V0–V31）；系统寄存器单独。
- **ARM32（AArch32）**：通用 16×32 位（R0–R15，R15=PC）；NEON 16×128 位；VFP 寄存器单独。
- **RISC-V（RV64）**：整数 32×64 位（x0–x31）；浮点 32×64 位（f0–f31）；CSR 单独。
- **SimRISC**：4 组 × 64 个 × 64 位——`rd`（数据）、`rb`（基址/地址）、`rf`（浮点）、`ra`（返回地址）。

**2. 数据/基址分组的 ISA：Motorola 68000**

- **分组**：8 个数据寄存器 D0–D7（32 位）+ 8 个地址寄存器 A0–A7（32 位）；A7 兼作栈指针（实际有 USP/SSP 两个）。
- **与 SimRISC 的相同点**：都把"数据"和"地址"分成两组；地址寄存器可以参与地址运算（68000 有 ADDA/SUBA/LEA）。
- **不同点**：68000 只有 8+8 = 16 个寄存器（SimRISC 是 64+64 = 128）；68000 是 32 位（SimRISC 是 64 位、48 位有效地址）；68000 没有独立的浮点组（浮点靠 68881 协处理器），SimRISC 有 `rf` 组；68000 的地址寄存器还能当数据源/目的做部分搬移，SimRISC 的 `rb` 只做地址运算与搬移。

**3. 浮点状态寄存器**

- **x86-64**：**独立**——SSE 用 MXCSR、x87 用状态/控制字；指令 `stmxcsr`/`ldmxcsr`、`fnstsw`/`fldcw`。
- **ARM64**：**独立**——FPCR（控制）/FPSR（状态）两个系统寄存器；指令 `MRS`/`MSR`。
- **RISC-V**：**独立**——`fcsr` 是一个 CSR（含舍入模式 `frm` 与异常标志 `fflags`）；指令 `csrrw`/`csrrs`/`csrrc`（伪指令 `frcsr`/`fscsr`/`fsrm`/`fsflags`）。
- **SimRISC**：**不独立**——就是 `rf0`（浮点寄存器组的 0 号），同时是 qNaN；写用 `set.w rf0, wp2/wp0`，读用 `rf2rd`，运算时可直接作源。

**4. 0 号寄存器的特殊之处**

- **`rd0`（常数 0）**：x86 没有硬连线的 0 号寄存器；ARM64 有 XZR（读 0、写丢弃）；RISC-V 有 x0（读 0、写忽略）；SimRISC 的 `rd0` 读 0、只读，作目的按规则丢弃或 ILLI。
- **`rb0`（IP）**：x86 的 RIP 不是通用寄存器；ARM（AArch32）的 PC 可读但带流水线偏移，AArch64 没有 PC 通用寄存器；RISC-V 的 pc 不是通用寄存器；SimRISC 的 `rb0` 是显式可用的基址寄存器，值 = 当前指令地址。
- **`rf0`（FCSR + qNaN）**：x86 MXCSR/x87 状态、ARM FPCR/FPSR、RISC-V fcsr 都是独立状态寄存器；SimRISC 的 `rf0` 同时是浮点数据寄存器（qNaN），可作源、不可作浮点运算目的。
- **`ra0`（RAS 控制）**：x86 用内存栈、ARM 用 LR（x30）、RISC-V 用 `ra`（x1），都没有软件可见的 RAS；SimRISC 的 `ra0` 存 `RACNT` 与 `MRPTR`，是 RAS 的状态字。
