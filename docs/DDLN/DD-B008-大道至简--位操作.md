# 大道至简——位操作

**本册要点**

- 逻辑：`and.o`/`or.o`/`xor.o`/`xnor.o`；无 `not`，用 `xnor` + `rd0`。
- 移位：`shl`/`shr.u`/`shr.s`/`rol`；`shl`/`rol` 不分符号。
- 移位量：寄存器取低位，立即数越界 ILLI。
- `rev`：逐块反转，`k` 为 one-hot，覆盖 bswap/bitreverse。
- `ctlz`/`cttz`/`ctpop`：`hd` 指定有效位上界，全 0 返回 `hd+1`。
- `clmul.o`：GF(2) 无进位乘，128 位结果。
- `ext.uo`/`ext.so`：64 位位段符号/零扩展。

## 1. 为什么逻辑指令只有 and/or/xor/xnor，没有 not？

**答：** 因为 `xnor(x, rd0)` 就是按位取反——`rd0` 读出全 0，同或的结果就是逐位取反；省掉一条 `not`，也省掉一个编码。

- **四种基本逻辑**：`and.o`（全 1 为 1）、`or.o`（有 1 为 1）、`xor.o`（相异为 1）、`xnor.o`（相同为 1），都是 64 位、`orrr` 格式。
- **取反**：`xnor.o rd, rs, rd0` 得到 `~rs`；反过来 `xnor.o rd, rd0, rs` 也一样。
- **清零**：`and.o rd, rs, rd0`、`xor.o rd, rs, rs` 都能清零；`or.o rd, rs, rd0` 是寄存器搬移。
- **取负**：`sub.uo {rd0, rd}, rd0, rs` 用减法实现，不需要逻辑指令。
- **对比**：x86 有 `not`、ARM 有 `MVN`、RISC-V 有 `xori rd, rs, -1`；SimRISC 用同或 + `rd0` 统一表达。
- **各家做法**：x86 `not`/`andn`；ARM64 `MVN`/`BIC`；RISC-V `xori rd, rs, -1`；MIPS `nor rd, rs, $zero`；SPARC/PowerPC 的 `orn`/`nor`。
- **为什么 SimRISC 不设 not**：`xnor` + `rd0` 已覆盖取反；少一条指令、少一个编码。

## 2. 为什么移位分成 shl/shr/rol，而且 shl/rol 不分有符号和无符号？

**答：** 因为左移和循环左移对"符号"不敏感——低位补 0、位串旋转，结果位型与符号解释无关；只有右移需要区分"高位补 0"还是"高位补符号位"。

- **左移 `shl`**：低位补 0，符号位自然被移出；有符号/无符号的结果位型相同。
- **逻辑右移 `shr.u`**：高位补 0；**算术右移 `shr.s`**：高位补符号位——这两者必须分开。
- **循环左移 `rol`**：把寄存器当位串旋转，不存在"符号位"的特殊处理；反向旋转用 `rol(x, 64−n)` 表达，不需要单独的 `ror`。
- **移位量**：寄存器形式取 `rdHD` 的低位（天然对宽度取模），立即数形式取 `immu6`。
- **值语义**：结果写满 64 位（窄宽度按零/符号扩展），不再"高位保留"。
- **各家做法**：x86 `shl`/`shr`/`sar`/`rol`/`ror`；ARM64 `LSL`/`LSR`/`ASR`/`ROR`；RISC-V `sll`/`srl`/`sra`（`Zbb` 才补 `rol`/`ror`）；MIPS `sll`/`srl`/`sra`；SPARC/PowerPC 的移位。
- **为什么 shl/rol 不分符号**：左移与循环移位的位型与符号无关；只有右移要区分补 0/补符号。

## 3. 为什么移位量越界要触发 ILLI？

**答：** 因为立即数形式的移位量是编码的一部分，越界说明指令本身写错了；让它在译码/执行时明确报错，比"静默取模"更容易发现汇编器或编译器的错误。

- **立即数形式**：64 位 `shl.o`/`rol.o`/`shr.*` 的 `immu6` 必须 ≤ 63；32 位必须 ≤ 31；16 位必须 ≤ 15；8 位必须 ≤ 7。越界触发 ILLI。
- **SBZ 位**：32/16/8 位的立即数形式还有高位应为 0 的约束，非零同样触发 ILLI。
- **寄存器形式**：只取 `rdHD` 的低若干位（64 位取 6 位、32 位取 5 位、16 位取 4 位、8 位取 3 位），天然对宽度取模，不会越界。
- **对比**：x86 的移位量对 32/64 位取模（`shl r64, cl` 只用 cl 的低 6 位）；ARM 的立即数移位量在编码里范围有限；RISC-V 规定 `shamt ≥ XLEN` 为非法。SimRISC 选择"立即数越界即非法"。
- **各家做法**：x86 寄存器移位取模、立即数越界不报错；ARM64 立即数移位量编码有限；RISC-V `shamt ≥ XLEN` 非法；MIPS 取模；SimRISC 立即数越界 ILLI。
- **为什么 ILLI**：立即数是编码的一部分，越界说明汇编器/编译器写错；静默取模会掩盖错误。

## 4. 为什么需要 rev（逐块反转）？

**答：** 因为字节序转换、位反序、CRC/加解密都要"按块翻转"，而普通的移位/逻辑指令拼一个 `bswap` 要十几条；`rev` 一条完成。

- **逐块反转**：把 64 位源切成 `64/S` 个块，每块再按 `k` 位切成单元，反转单元顺序（单元内部位序不变）。
- **四种块大小**：`rev.o`（S=64）、`rev.t`（S=32）、`rev.w`（S=16）、`rev.b`（S=8）。
- **典型映射**：`rev.o` + `k=8` = `bswap64`；`rev.t` + `k=8` = `bswap32`（要求源高 32 位为 0）；`rev.w` + `k=8` = `bswap16`；`rev.o` + `k=1` = 64 位整体位反序。
- **注意**：`rev.t`/`rev.w` + `k=1` 只反转各块内部的位序，不是 64 位整体位反序，不能误用。
- **对比**：x86 有 `bswap`（但没有任意块大小的通用反转）；ARM 有 `RBIT`/`REV` 系列；RISC-V 的 `Zbb` 有 `rev8`，位反序要软件合成。SimRISC 用一条参数化的 `rev` 覆盖多种组合。

## 5. 为什么 rev 的 k 必须是 one-hot？

**答：** 因为 `k` 是"单元宽度"，必须是 2 的幂才能把块整除成整数个单元；one-hot 编码还让硬件译码简单、非法值容易检测。

- **约束**：`k` 必须是 2 的幂，且 `k < S`；非 one-hot（0、3、5、6…）或 `k ≥ S` 触发 ILLI。
- **整除**：`S/k` 必须是整数，否则"切成单元"没有定义。
- **排除恒等档**：`k = S` 时每个块只有一个单元，反转后不变，没有意义，所以排除。
- **硬件**：one-hot 的 `k` 直接对应一组多路选择，译码不需要除法器；非法值在编码阶段就能查出来。
- **对比**：ARM 的 `REV`/`RBIT` 是固定几种块大小；SimRISC 用参数化 `k` 换取灵活性，代价是增加合法性检查。
- **各家做法**：x86 `bswap` 固定 16/32/64 位；ARM64 `REV`/`REV16`/`REV32`/`RBIT` 固定几种；RISC-V `Zbb` 的 `rev8` 固定按字节；SimRISC 用 `k` 参数化。
- **为什么 one-hot**：`k` 必须是 2 的幂才能整除块；one-hot 译码简单，非法值易查。

## 6. 为什么 ctlz/cttz/ctpop 没有位宽后缀？

**答：** 因为有效位宽由立即数 `hd` 在运行时给出——`hd` 是"有效位上界"，参与运算的只是源的 `rdHC[hd:0]`，一条指令覆盖 8/16/32/64 位。

- **`hd` 的含义**：6 位无符号立即数（0..63），有效位是 `rdHC[hd:0]`，共 `hd+1` 位；`hd` 以上的位不参与。
- **覆盖四种宽度**：`hd = 7/15/31/63` 分别对应 8/16/32/64 位；不需要 `clz8`/`clz16`/`clz32`/`clz64` 四条指令。
- **结果写满 64 位**：结果范围 0..64，高位清零（值语义）。
- **全 0 的定值**：`ctlz`/`cttz` 在全 0 时返回 `hd+1`（有效位宽），`ctpop` 返回 0。
- **对比**：RISC-V 需要 `clz`/`clzw` 两条才覆盖到 32 位；x86 的 `lzcnt`/`tzcnt` 按操作数宽度返回；ARM 的 `CLZ` 固定按 32/64 位。
- **各家做法**：x86 `lzcnt`/`tzcnt`/`popcnt`；ARM64 `CLZ`（popcount 在较新扩展）；RISC-V `Zbb` 的 `clz`/`ctz`/`cpop`；MIPS/SPARC/PowerPC 的位扫描/计数。
- **为什么用 `hd`**：一条指令覆盖 8/16/32/64 位；不需要为每个宽度设一条。

## 7. 为什么 ctlz(0) 返回 hd+1，而不是未定义？

**答：** 因为"全 0 有多少个前导零"在数学上就是有效位宽；给出定值可以消除 C 的 `__builtin_clz(0)` 那种未定义行为，让软硬件结果一致。

- **定值**：`ctlz`/`cttz` 在 `rdHC[hd:0]` 全 0 时返回 `hd+1`；`ctpop(0)` 返回 0。
- **与主流一致**：RISC-V 的 `clz`/`ctz` 对 0 返回 XLEN；x86 的 `lzcnt`/`tzcnt` 返回操作数宽度；ARM 的 `CLZ(0)` 返回 32/64。
- **对比 C**：C 的 `__builtin_clz(0)` 是未定义行为，编译器可以假设输入非 0；ISA 给出定值后，编译器不必为 0 单独分支。
- **实现**：全 0 检测就是"没有 1"，返回有效位宽即可，不需要额外电路。

## 8. 为什么需要 clmul（无进位乘）？

**答：** 因为 GF(2) 上的多项式乘法（CRC、纠错码、密码学）与整数乘法不同——它每位只做"与"、结果之间做"异或"，不能有进位；用普通 `mul` 算不出这个结果。

- **语义**：把两个 64 位数各视为 GF(2) 上的多项式，系数相乘是"与"、相加是"异或"，位间无进位。
- **例子**：`0b11 × 0b11` 在 GF(2) 上是 `(x+1)² = x²+1 = 0b101`（5），而整数乘法得 9。
- **结果宽度**：128 位，写 `{rdHA, rdHB}`，布局与 `mul.uo` 相同。
- **只有 `.o`**：无进位 ⇒ 窄宽度的结果只是 64 位结果的低位子集，用结果掩码即可，不需要 `.t`/`.w`/`.b`。
- **反向版本**：`clmulr(a,b) = rev(clmul(rev(a), rev(b)))`，用 `rev.o` 组合，不单设指令。
- **对比**：x86 的 `PCLMULQDQ` 是 128 位 SIMD 指令；ARM 有 `PMULL`；RISC-V 的 `Zbc` 扩展有 `clmul`/`clmulh`/`clmulr`。SimRISC 用一条标量 `clmul.o` 覆盖。

## 9. 为什么需要 ext（位段扩展）？为什么只保留 64 位？

**答：** 因为从任意 bit `hd` 开始把低位段符号/零扩展成 64 位，是位段提取和窄值提升的通用操作；窄宽度算术已经自带扩展语义，所以只保留 64 位的 `ext.uo`/`ext.so`。

- **语义**：`ext.uo rdHB, rdHC, hd` 复制 `rdHC[hd:0]`，把 `rdHB[63:hd+1]` 清零；`ext.so` 把高位填 `rdHC[hd]`（符号扩展）。
- **两种格式**：`orrr`（`rdHD` 给 `hd`）和 `orri`（`immu6` 给 `hd`）；`hd ≤ 63`，否则 ILLI。
- **用途**：位段提取、把窄值提升到 64 位、从打包字段中取一段。
- **为什么只有 64 位**：8/16/32 位的算术/比较/移位已经是值语义（结果自动按 `.s`/`.u` 扩展），不需要再单独 `ext`；64 位是唯一需要"从任意 bit 起扩展"的宽度。
- **对比**：x86 用 `movsx`/`movzx` + 移位/掩码；ARM 有 `SBFX`/`UBFX`（位段提取）；RISC-V 用 `slli`+`srai` 或 `zext` 组合。SimRISC 用一条参数化的 `ext` 覆盖。

## 背景知识

### 术语与概念

- **位编号（bit numbering）**：本文按 bit0 为最低位、bit63 为最高位书写；`rdHC[hd:0]` 表示低 `hd+1` 位。
- **前导零 / 末尾零（leading/trailing zeros）**：从最高有效位/最低有效位开始连续 0 的个数。
- **popcount**：二进制表示中 1 的个数。
- **one-hot**：只有一个位为 1 的编码；这里要求 `k` 是 2 的幂，正好对应 one-hot。
- **bswap**：按字节反转（`bswap64`/`bswap32`/`bswap16`），用于大小端转换。
- **bitreverse**：整个字的位序反转（bit0 与 bit63 互换，依此类推）。
- **GF(2) 多项式乘法**：系数在 {0,1} 上、加法为异或、乘法为与的乘法；无进位乘就是它的实现。
- **值语义**：结果写满 64 位，高位按零/符号扩展，不是"只写低位"。

### 对照

**逻辑与移位**

- **x86-64**：`and`/`or`/`xor`/`not`；`shl`/`shr`/`sar`/`rol`/`ror`；移位量用 `cl` 或立即数。
- **ARM64**：`AND`/`ORR`/`EOR`/`BIC`/`MVN`；`LSL`/`LSR`/`ASR`/`ROR`；移位可作为许多指令的操作数修饰。
- **RISC-V**：`and`/`or`/`xor`/`andi`/`ori`/`xori`；`sll`/`srl`/`sra`；没有 `not`/`rol`（`Zbb` 有 `rol`/`ror`）。
- **SimRISC**：`and.o`/`or.o`/`xor.o`/`xnor.o`；`shl.o`/`shr.uo`/`shr.so`/`rol.o`；窄宽度各一套。

**位扫描与位计数**

- **x86-64**：`bsf`/`bsr`（位扫描）、`lzcnt`/`tzcnt`（前导/末尾零）、`popcnt`。
- **ARM64**：`CLZ`、`RBIT`、`CNT`（向量）；标量 popcount 在较新扩展中。
- **RISC-V**：`Zbb` 提供 `clz`/`ctz`/`cpop`；基础 ISA 没有。
- **SimRISC**：`ctlz`/`cttz`/`ctpop`，用 `hd` 指定有效位上界，一条覆盖 8/16/32/64 位。

**字节反转 / 位反序**

- **x86-64**：`bswap`（16/32/64 位）。
- **ARM64**：`REV`/`REV16`/`REV32`/`RBIT`。
- **RISC-V**：`Zbb` 的 `rev8`；位反序要软件合成。
- **SimRISC**：`rev.o`/`rev.t`/`rev.w`/`rev.b` + `k`，覆盖 bswap 与 bitreverse。

**无进位乘**

- **x86-64**：`PCLMULQDQ`（SIMD）。
- **ARM64**：`PMULL`/`PMULL2`（部分实现）。
- **RISC-V**：`Zbc` 的 `clmul`/`clmulh`/`clmulr`。
- **SimRISC**：`clmul.o`，128 位结果，反向用 `rev.o` 组合。
