# 大道至简——访存与地址运算

**本册要点**

- 48 位虚拟地址（256 TiB），物理地址 64 位。
- `rb` 64 位；访存取低 48 位，高 16 位作地址溢出标记。
- 地址运算专用指令：`add.o`/`sub.o`/`cmp.uo-rb`/`add.si`/`aip.si`。
- `aip`：IP 相对，±512 MiB，4 KiB 粒度。
- load 的符号/零扩展：`ld.sb/ub`、`ld.sw/uw`、`ld.st/ut`、`ld.o`。
- `ldm`/`stm`：1–63 个连续寄存器。
- RB/RA 只有 `.o`，RF 有 `.t`/`.o`；多寄存器检查 0 号/重叠/原始地址。
- 对齐按宽度；未对齐 MALIGN。
- `ld` 目的不能是 `rd0`；`st` 源可以是 `rd0`。
- 大端序。

## 1. 为什么只有 48 位地址空间？

**答：** 48 位 = 256 TiB，足够用；而且 48 位正好对应"64 个 PTBR + 两级 64 KiB 页表 + 64 KiB 页"的划分。

- **容量**：2⁴⁸ = 256 TiB，远超当前需要。
- **与页表结构对齐**：`VA[47:42]` = 6 位 PTBR 索引（64 个地址空间）、`VA[41:29]` = 13 位 L1 索引、`VA[28:16]` = 13 位 L2 索引、`VA[15:0]` = 16 位页内偏移；6+13+13+16 = 48。每个页表 2¹³ × 8 B = 64 KiB，页 64 KiB，正好自洽。
- **物理地址仍是 64 位**：48 位是虚拟/核内地址；地址转换后可以生成 64 位物理地址，所以不会限制物理内存。
- **高位保留**：64 位寄存器的 bits[63:48] 在地址转换时被忽略、在寄存器中保持原值。
- **各家做法**：x86-64 48 位 VA（4 级页表，可扩展 57 位）；ARM64 48/52 位；RISC-V Sv39/Sv48/Sv57；MIPS64 64 位；SPARC V9 64 位；PowerPC 64 位。
- **为什么是 48**：与 64 个 PTBR + 两级 64 KiB 页表 + 64 KiB 页对齐；物理地址仍 64 位，容量不是瓶颈。

## 2. 为什么 rb 寄存器仍然是 64 位，即高 16 位可用？

**答：** 因为机器字长和寄存器统一是 64 位，地址运算也按 64 位做；高 16 位不是浪费，而是地址溢出的"标记位"。

- **统一 64 位**：所有寄存器都是 64 位，不需要为地址单独做 48 位寄存器。
- **可作 RD 的备份**：`rb` 与 `rd` 一样是 64 位，`rd2rb`/`rb2rd` 可以在两者之间搬运；特殊情况下（如 RD 压力大）可以用 `rb` 临时保存数据，只是它不参与数据运算。
- **全 64 位运算**：`add.o`/`sub.o`/`add.si`/`aip.si` 都按 64 位算，结果完整保留 64 位。
- **高 16 位 = 溢出检测**：地址只有 48 位有效；运算结果超过 2⁴⁸ 时，高 16 位非零，软件可据此判断地址计算溢出，避免静默回绕。
- **访存取低 48 位**：只有真正访存时，硬件才取 `rb[47:0]` 作为有效地址；高 16 位保留在寄存器里，继续参与后续运算。
- **控制流同理**：跳转/调用结果写回 `rb0`，取低 48 位作为下一条地址，高 16 位保留并参与后续运算。
- **各家做法**：x86 的 RIP 不是通用寄存器；ARM A32 的 PC 可读但带流水线偏移，AArch64 无 PC 通用寄存器；RISC-V 的 pc 不是 GPR；SimRISC 把 `rb0` 做成显式基址（读当前 IP）。
- **为什么保留 64 位**：统一寄存器宽度；高 16 位当地址溢出标记；访存只取低 48 位。

## 3. 为什么要设置那几条专门的地址加减指令，分别对应哪种具体操作？

**答：** 因为地址运算的结果要落在 `rb` 组、源又要混合 `rb`/`rd`，普通的数据运算表达不了；这几条分别覆盖地址运算的几种基本形态。

- `add.o rbHB, rbHC, rdHD`：**基址 + 变址**（RB + RD，结果写 RB）——基址加一个计算出来的偏移。
- `sub.o rbHB, rbHC, rdHD`：**基址 − 变址**（RB − RD，结果写 RB）。
- `sub.o rdHB, rbHC, rbHD`：**地址差**（RB − RB，结果写 RD）——两个指针相减，得到距离（数据值）。
- `add.si rbHA, imms18`：**自增/自减**（RB += 18 位有符号立即数）——移动栈指针等；没有 push/pop，栈指针就靠它显式加减。
- `aip.si rbHA, imms30`：**IP 相对**（RB = IP + 字节偏移）——把 IP 相对地址物化到 RB。
- `cmp.uo rdHB, rbHC, rbHD`：**地址比较**（两个 RB 做无符号比较，结果 -1/0/1 写 RD）。
- **各家做法**：x86 用 `lea` 做地址加减；ARM64 `ADD`/`SUB`；RISC-V `add`/`sub`；MIPS `addu`/`addiu`；SPARC/PowerPC 的地址运算。
- **为什么 SimRISC 单独设 RB 形式**：地址结果要落 `rb`、源混合 `rb`/`rd`；普通数据指令写 `rd`，表达不了。

## 4. 为什么需要 aip 指令？

**答：** 为了一条指令就把"相对当前指令的地址"算进 RB，供后续访存直接当基址。

- **IP 相对寻址**：`aip.si rbHA, imms30` 计算 `IP + imms30`（汇编层按字节写，必须是 4 KiB 的整数倍；编码层是 4 KiB 块偏移），可覆盖 ±512 MiB。
- **位置无关代码**：全局变量/symbol 用"相对当前指令"的偏移表示，不需要绝对地址重定位。
- **与后续访存配合**：`aip` 给出一个与 IP 同低 12 位的基址（块与块间隔 4 KiB，IP 低位不清零），剩余偏移由后面 `ld`/`st` 的 12 位立即数补齐。
- **边界无空余**：`aip` 的 `imms30` 是 4 KiB 的整数倍，`ld`/`st` 的 `imms12` 是 12 位有符号（−2048..+2047）；任意字节偏移 `d` 都能写成 `4096k + r`（`r ∈ [−2048, +2047]`），相邻 4 KiB 块在边界处相接，没有空档。例（IP = `0x1000_0000`）：
  - 目标 `0x1000_07FF`：`aip 0` + `ld 2047`；
  - 目标 `0x1000_0800`：`aip 4096` + `ld -2048`；
  - 目标 `0x0FFF_F7FF`：`aip -4096` + `ld 2047`。
- **对比**：没有 `aip`，要么用多条指令拼 48 位绝对地址，要么走常量池；`aip` 一条就够，而且写进 RB 组，直接当基址用。
- **各家做法**：ARM64 `ADR`/`ADRP`（PC 相对，ADRP 4 KiB 页）；RISC-V `auipc`（PC 相对，4 KiB 块）+ `addi`；x86 `lea reg, [rip+disp]`；MIPS 用 `lui`/`addiu` 或 `$gp`。
- **为什么 SimRISC 用 `aip` + 12 位偏移**：`aip` 给 4 KiB 块基址，`ld/st` 的 12 位偏移补足块内；两部分首尾相接，见上面的边界例。

## 5. 为什么 cmp.uo-rb 是无符号数的比较？

**答：** 因为地址是 0..2⁴⁸−1 的无符号值；按有符号比较会把高地址当成负数。

- **地址语义**：地址没有负数，比较"谁在前/谁在后"必须按无符号数。
- **高 16 位参与**：`cmp.uo` 比较整 64 位（bits[63:48] 参与），所以地址溢出的高位也会影响结果。
- **结果 -1/0/1**：小于/等于/大于，后续用 N/NN/Z/NZ/P/NP 六种条件组合判断。
- **有符号比较会错**：48 位地址的 bit47 为 1 时，按有符号解释就是负数，排序和区间判断都会反。
- **各家做法**：x86 用 `setb`/`jb`（无符号）；ARM64 `B.LO`；RISC-V `sltu`；MIPS `sltu`；SPARC `blu`；PowerPC `cmplw` + `blt`。
- **为什么 SimRISC 用 `cmp.uo`**：地址是 0..2⁴⁸−1 的无符号值；有符号比较会把高地址当负数。

## 6. 为什么 load 要区分符号扩展和零扩展？

**答：** 因为窄数据装进 64 位寄存器时必须确定高位的填充方式，而 C 的 `char`/`short`/`int` 同时需要"有符号"和"无符号"两种解释。

- **一条指令两种语义**：`ld.sb`/`ld.sw`/`ld.st` 按符号扩展填满 64 位，`ld.ub`/`ld.uw`/`ld.ut` 按零扩展填满 64 位；`ld.o` 取满 64 位，不需要区分。
- **对应 C 的类型**：`signed char`/`short`/`int` 用 `.s` 变体，`unsigned char`/`short`/`int` 用 `.u` 变体；编译器按类型选指令，不需要额外的符号扩展指令。
- **与存储对称**：`st.b`/`st.w`/`st.t` 只写低 8/16/32 位，高位的处理由 load 侧决定，所以 store 不需要 `.s`/`.u` 变体。
- **对比**：MIPS64/RISC-V 用 `lb`/`lbu`、`lh`/`lhu`、`lw`/`lwu`；x86 用 `movsx`/`movzx` 两条独立指令——SimRISC 把扩展方式编码进 load 的后缀，指令更整齐。

## 7. 为什么提供多寄存器 ldm/stm？

**答：** 因为 64 个寄存器 + 6 位计数字段，让"一条指令搬一串寄存器"很自然；它主要服务函数序言/尾声的寄存器保存恢复。

- **一条顶多条**：`ldm`/`stm` 用 `immu6` 指定寄存器个数（1–63），一条指令完成连续多个寄存器的读写，减少指令数与取指带宽。
- **地址只算一次**：`[rbHB, rdHC]` 的基址+变址只计算一次，后续寄存器按宽度递增地址，省掉重复的地址计算。
- **与 64 个寄存器匹配**：寄存器多，函数序言/尾声要保存的寄存器也多；多寄存器指令把这段开销压下来。
- **限制明确**：计数为 0、起始+计数超过 64 都触发 ILLI，不环绕、不截断；范围包含变址寄存器 `rdHC`（RB 形式为基址 `rbHB`）时，地址仍按原始值计算。
- **代价**：指令语义变复杂（对齐、重叠、异常中间状态），但换来的是代码密度和可预测的保存恢复序列。
- **各家做法**：ARM `LDM`/`STM`（可带写回）；x86 用 `push`/`pop` 或逐条 `mov`；RISC-V 基础 ISA 无多寄存器 load/store（`Zcmp` 提供 push/pop 对）；MIPS/SPARC/PowerPC 无。
- **为什么 SimRISC 提供**：64 个寄存器 + 6 位计数字段；序言/尾声的保存恢复收益最大。

## 8. 为什么对齐要求按访问宽度区分？

**答：** 因为对齐是硬件访存通路的前提；按宽度要求对齐，可以用最简单的地址译码和数据选择，而不必处理跨行/跨字的拆分。

- **对齐规则**：`.o` 需 8 字节、`.t` 需 4 字节、`.w` 需 2 字节、`.b` 无要求；未对齐触发 MALIGN。
- **硬件简单**：对齐后，一个数据不会跨两个 cache line/存储字，访存通路不需要拆分与重组，时序和异常都简单。
- **多寄存器同样适用**：`ldm`/`stm` 按单个元素的宽度要求对齐；起始地址对齐后，后续元素自然对齐。
- **代价**：非对齐访问要由软件拆成多次字节访问，或由 OS 模拟；换来的是硬件通路的规整。
- **对比**：x86 硬件支持非对齐访问（代价是跨行时性能下降）；ARM 早期要求对齐，后面可配置；RISC-V 允许平台选择是否支持非对齐。
- **各家做法**：x86 硬件支持非对齐（跨 cache line 时性能下降）；ARMv7+ 普通内存可配置非对齐（`SCTLR.A`）；RISC-V 允许平台选择；MIPS/SPARC 传统上要求对齐并陷入。
- **为什么 SimRISC 要求对齐**：访存通路简单、异常确定；非对齐由软件拆分或 OS 模拟。

## 9. 为什么 ld 的目的不能是 rd0，而 st 的源可以是 rd0？

**答：** 因为 `rd0` 是只读常数 0：load 必须写一个真实目的寄存器，而 store 只是"读"源，读 `rd0` 正好得到 0。

- **load 的目的**：`ld` 要把内存内容写进寄存器；`rd0` 只读、写无效，若允许就变成"丢弃 load 结果"的隐式语义，容易掩盖错误，所以触发 ILLI。
- **store 的源**：`st rd0, [rb, imm]` 读出 0 并写入内存，是合法的"存 0"用法，不需要额外指令。
- **rb0 同理**：`ld` 的目的为 `rb0` 触发 ILLI（IP 只读）；`st` 的源为 `rb0` 合法（读出当前指令地址）。
- **规则一致**：目的寄存器必须可写，源寄存器只要可读即可——这条规则贯穿 `rd0`/`rb0`。
- **各家做法**：x86 没有硬连线 0 号寄存器；ARM64 `XZR`（读 0、写丢弃）；RISC-V `x0`（读 0、写忽略）；MIPS `$zero`；SimRISC `rd0` 只读、作目的按规则丢弃或 ILLI。
- **为什么 load 禁止 rd0**：load 必须写真实目的；允许 `rd0` 会变成隐式"丢弃 load 结果"，掩盖错误。

## 10. 为什么选择大端序？

**答：** 大端序让"内存里的字节顺序"和"位域/数值的书写顺序"一致，取指、调试、数据交换都更直观；指令和数据统一用大端，也省掉了端序转换。

- **和位域图/数值书写一致**：文档按 bit31→bit0 写，内存按低地址→高地址排；多字节数的高位字节也在低地址（`0x12345678` 在内存里就是 `12 34 56 78`），读 hex dump 和调试都直观。
- **和网络序一致、指令与数据统一**：大端就是网络字节序，和外部设备/协议交换数据时不用转换；指令和数据都用大端，也不需要像小端机器那样做 `bswap` 或端序切换。
- **代价**：与 x86（小端）/ARM（通常小端、可配置）不同，跨平台交换数据时需要转换。
- **标准/各家**：网络序（RFC 1700）是大端；x86 小端；ARM 可配置（实际多用小端）；RISC-V 小端；MIPS 可配置；SPARC 大端；PowerPC 可配置（传统大端，ppc64le 小端）。
- **为什么 SimRISC 选大端**：指令与数据统一、hex dump 可读、与网络序一致；代价是与 x86/ARM 交换数据要转换。

## 11. RB/RA/RF 怎么存取？ldm/stm 还有哪些限制？

**答：** RB/RA 是 64 位，只有 `.o` 形式；RF 分单精/双精，有 `.t`/`.o`；多寄存器还要检查 0 号寄存器、范围和重叠。

- **RB/RA**：只有 `ld.o`/`st.o`、`ldm.o`/`stm.o`；8 字节对齐。
- **RF**：`ld.t`/`st.t`（32 位单精）、`ld.o`/`st.o`（64 位双精）、`ldm.t`/`stm.t`、`ldm.o`/`stm.o`；`.t` 4 字节对齐、`.o` 8 字节对齐。
- **0 号寄存器**：`ld.o rb0`/`ldm.o rb0` → ILLI；`st.o rb0`/`stm.o rb0` 合法（读出 IP）。`ra0` 可读写；`rf0` 可作目的，写入按 FCSR 写语义（只更新 `[33:32]` 与 `[4:0]`，其余位写无效；`ld.t`/`ldm.t` 的 `[63:32]` 不变），作源读出完整 64 位。
- **rd 形式**：`ld`/`ldm` 的目的为 `rd0` → ILLI；`st`/`stm` 的源为 `rd0` 合法（读出 0）。
- **计数与范围**：`immu6 = 0`、起始+计数 > 64 → ILLI；不环绕、不截断。
- **重叠**：`ldm`/`stm` 的源/目的范围可以重叠（按序号递增逐对处理，先读后写）；块复制 `rd2rd` 等则不允许重叠。
- **地址基准**：范围包含 `rdHC`（RB 形式为 `rbHB`）时，地址仍按原始值计算；每个元素的地址按宽度递增。
- **窄宽度**：8/16/32 位的 `ldm`/`stm` 每个寄存器只放一个数据，多个数据用多个连续寄存器（不是打包）。
- **各家做法**：x86 `mov` 的宽度由寄存器名决定（`mov al`/`mov ax`/`mov eax`/`mov rax`）；ARM64 `LDRB`/`LDRH`/`LDR`/`LDRSW`；RISC-V `lb`/`lh`/`lw`/`ld`；MIPS/SPARC/PowerPC 的 load/store 宽度。
- **为什么 SimRISC 分 RB/RA/RF**：RB/RA 都是 64 位（只有 `.o`）；RF 分单精/双精（`.t`/`.o`）；组不同，宽度后缀不同。

## 背景知识

### 术语与概念

- **load/store 架构**：运算只对寄存器，访存只由 load/store 完成；访存指令不参与算术。
- **寻址方式（addressing mode）**：指令如何给出有效地址。SimRISC 的基本形态是"基址 + 偏移"（`[rb, imm]`）和"基址 + 变址"（`[rb, rd]`），多寄存器再加一个计数。
- **有效地址（effective address）**：基址与偏移相加得到的地址；SimRISC 只取结果的低 48 位访存。
- **对齐（alignment）**：数据地址是其宽度的整数倍；未对齐访问可能触发异常或由硬件拆分。
- **大端序 / 小端序**：大端序把高字节放在低地址，小端序把低字节放在低地址；本 ISA 的指令字与数据都按大端存放。
- **MMU / 页表**：把虚拟地址翻译成物理地址；SimRISC 用 64 个 PTBR、两级 64 KiB 页表、64 KiB 页。
- **常量池（literal pool）**：集中存放常量的数据区，用 PC 相对 load 取；省的指令换一次访存。

### 对照

**端序（大端/小端）**：

- x86：小端。
- ARM：可配置（bi-endian），实际系统多用小端。
- RISC-V：小端。
- MIPS：可配置（bi-endian）。
- SPARC：大端（V8/V9 传统）。
- PowerPC：可配置（传统大端；ppc64le 是小端变体）。
- SimRISC：大端（指令与数据一致）。

**load 的扩展方式**：

- **x86-64**：`movsx`/`movzx` 是独立的扩展指令；`mov` 从内存读窄数据时按操作数大小决定。
- **ARM64**：`LDRSB`/`LDRSH`/`LDRSW`（符号）与 `LDRB`/`LDRH`/`LDR`（零扩展）成对。
- **RISC-V**：`lb`/`lbu`、`lh`/`lhu`、`lw`/`lwu` 成对。
- **MIPS**：`lb`/`lbu`、`lh`/`lhu`、`lw`/`lwu` 成对。
- **SimRISC**：`ld.sb`/`ld.ub`、`ld.sw`/`ld.uw`、`ld.st`/`ld.ut` 成对，`ld.o` 全宽。

**多寄存器访存**：

- **ARM**：`LDM`/`STM`（可带写回），一条指令搬一组寄存器。
- **x86**：没有多寄存器 load/store；靠 `push`/`pop` 或逐条 `mov`。
- **RISC-V / MIPS / SPARC / PowerPC**：没有多寄存器 load/store（RISC-V 的 `Zcmp` 扩展提供 push/pop 对）。
- **SimRISC**：`ldm`/`stm`，计数 1–63，按宽度递增地址。
