# 资源管理 -- 异常进入与退出

**本册要点**

- 所有同步异常与异步中断都是**精确异常**：同步异常触发指令未完成、无副作用；异步中断在指令边界识别，被中断指令已提交。
- 异常原因编码是 **one-hot**，且**每个 cfx 独立编址**：同一个位在不同 cfx 含义不同。
- 进入分十步：定 cfx → 查不可屏蔽 → 查掩码 → 过滤中断来源 → 查原因掩码 → 计数 → 保存现场 → 切换 → 保存原因 → 跳向量。
- 中断是**电平触发**，在指令边界检查；同一界多源**一次性**进入同一次捕获（位图并集），不按编号串行。
- `escape` 只用于同步帧：目标必须是当前 cfx，`cg5` 偏移只允许 0 或 4；`imms18[1]` 的 `cg9` 编码仍合法但不用于异步返回（`cg9` 是捕获缓冲，执行 ⇒ `CFXESC`），`imms18 = 3` ⇒ `ILLI`。
- 异步每次进入都覆盖 `cfx_hart cg9` 捕获缓冲，嵌套由软件负责（`cfx_smon` 是普通系统态）。

## 1. 为什么强调"精确异常"？

**答：** 因为处理程序要能确定"哪条指令出错、错在哪"，并在修复后重试；如果指令已部分执行，重试就会重复副作用。

- **同步异常**：IP 指向触发指令，指令未完成。
- **异步中断**：在指令边界识别，被中断指令**已提交**，`async_cause_ip` = 提交后的 `rb0`（跳转即目标）。
- **同步无副作用**：目标寄存器、内存、返回地址栈都未更新；异步不重放已提交指令。
- **例外**：电源类系统控制动作不适用一般保存语义。
- **价值**：可重试、可恢复、可审计。

## 2. 进入流程的十步各做什么？

**答：** 先确定"进哪个 cfx"，再判断"能不能进"，最后保存现场并跳转。

- **① 定 cfx**：特权指令按目标编号；其它同步异常按当前模式进监视器；页表异常进当前模式监视器；核内地址异常按地址高位或当前模式；异步中断统一进 `cfx_hart`（`cfxha` 15）。
- **② 不可屏蔽**：查该 cfx 的不可屏蔽位图，命中则跳过后续掩码检查。
- **③ 每核掩码**：目标 cfx 非自身时查当前掩码；被屏蔽的同步异常转 `ILLI`，异步源被屏蔽则置 `cfx_hart cg9` 的 pending。
- **④ 异步来源过滤**：按当前运行模式取该 monitor 的 `cg8 rc1`；允许即投递 `cfx_hart` 并覆盖捕获缓冲，屏蔽则挂起。
- **⑤ 原因掩码**：查该 cfx 对应模式的原因掩码。
- **⑥ 计数**：按类型递增 trap / 同步 / 异步计数。
- **⑦ 保存现场**：前一模式、前一 cfx（`cg5`）；**不保存任何来源掩码**。
- **⑧ 切换**：模式与当前 cfx 换成切换寄存器的值；不动来源掩码。
- **⑨ 保存原因**：原因编号、指令指针、辅助信息。
- **⑩ 跳向量**：跳到该 cfx 对应模式的异常向量。

## 3. 为什么原因编码 per-cfx 独立？

**答：** 因为每个 cfx 处理的事情不同：同一位在监视器里可能是非法指令，在页表 cfx 里可能是权限错误，在 hart 里可能是核间中断。

- **one-hot**：一个原因一位，便于位图判断。
- **独立编址**：不跨 cfx 冲突，硬件靠编号区分。
- **公共低位**：功能调用、核内访存、寄存器访问、退出帧错误这四类在所有 cfx 中含义一致。
- **专有高位**：设备中断、DMA、定时器等由各 cfx 自己分配。
- **软件视角**：先读目标 cfx，再按它的表解释原因。

## 4. 待处理位与不可屏蔽位怎么用？

**答：** 待处理位记录"被屏蔽但已发生"的异步源，按位由硬件置位、投递或源 ack 后由硬件落位；软件只读，不写。

- **置位**：源事件被掩码屏蔽时置 `cfx_hart cg9 rc4`（`async_src_pending`）对应位，不影响其他位。
- **清除**：投递时硬件清位；源在源 cfx 被 ack（`timer_cmp` 重装 / `dma_status` W1C）后自动落位——**软件不写**。
- **触发**：掩码解除后，若待处理位仍为 1，在下一指令边界投递 `cfx_hart`。
- **不可屏蔽**：不受掩码控制，直接进入；用于必须处理的故障。
- **注意**：同步异常本身就是不可屏蔽的，只有异步源会被挂起。

## 5. 多个中断同时来怎么办？

**答：** 电平触发、指令边界检查；同一指令边界上所有 pending 且放行的源**一次性**进入同一次捕获（`async_src_frame` 位图并集），不按 cfx 编号串行投递。

- **电平**：源持续有效且掩码开启，就在边界触发。
- **同界多源**：位图并集，一次进入；`excp_async_num` 每次进入 +1（与源个数无关）。
- **不串行**：不把同一界面的多个源拆成多次进入，也不需要软件定义优先级。
- **记录**：处理程序读 `cfx_hart cg9 rc3`（`async_src_frame`）确认本次捕获了哪些源。
- **公平性**：不按编号排序，软件按帧内位逐源处理。

## 6. `escape` 的语义与限制是什么？

**答：** 退出当前 cfx 的 **`cg5` 同步帧**：目标必须是当前 cfx，`imms18[17:2]` 为 SBZ，合法 `imms18 ∈ {0, 1, 2}`（`3` ⇒ `ILLI`）；`cg5` 帧返回地址 = `excp_cause_ip` + 偏移（只允许 0 或 4）。`cg9` 是异步进入的捕获缓冲，**不承担返回**。

- **目标**：非当前 cfx ⇒ `CFXESC`；`cg5` 帧无效（`excp_cause_id = 0`）⇒ `CFXESC`。
- **偏移**：编码层为 18 位字偏移；汇编层 `imms20` 合法值 `{0, 4, 8}`（`8` 只是 `cg9` 帧选择的合法编码，不提供异步返回）。
- **非法偏移**：手工编码非零的低位 ⇒ `ILLI`。
- **`imms18[1] = 1`**：编码仍合法，但 `cg9` 不是返回帧 ⇒ 执行时 `CFXESC`，不改变 cfx/运行模式/`cg9`；异步返回走 smon/umon 正常路径。
- **恢复**：前一模式、前一 cfx（同步帧）；**不恢复任何来源掩码**。
- **为什么限制偏移**：异常返回不是任意跳转，允许任意偏移等于给出一条隐藏的跳转指令。

## 7. 嵌套怎么处理？

**答：** 由软件负责：进入处理程序前保存现场，退出时恢复；同步异常硬件不阻止同 cfx 嵌套（会覆盖上一次现场）；异步每次进入都覆盖 `cfx_hart cg9` 捕获缓冲，软件把它当新的捕获处理。

- **风险**：同一 cfx 再次进入会覆盖 `excp_prev_*` 与 `excp_cause_*`；异步再次进入覆盖 `cg9`。
- **做法**：处理程序开头把现场存到自己的栈/暂存区；异步在关中断窗口把 `cg9` + GPR 搬到 `task_pt_regs` 后进 `cfx_smon`。
- **开关**：需要减少嵌套时，用当前运行模式 monitor 的 `cg8 rc1` 屏蔽源（策略），不靠 `cg9` 的"帧状态"。
- **代价**：保存/恢复要多几条指令。
- **判据**：能否在嵌套后正确返回到最外层。

## 背景知识

### 术语与概念

- **精确异常**：触发指令未完成，可重试。
- **one-hot 原因**：每个原因一位。
- **待处理位**：被屏蔽异步源的挂起记录（`cfx_hart cg9 rc4`，硬件写、软件只读）。
- **异步来源掩码**：monitor 的 `cg8 rc1`，位 = 源 cfxha；是策略，不随帧保存/恢复。
- **异常帧**：现场寄存器集合。

### 对照

**异常模型**

- **统一入口 + 原因码**：本项目。
- **多向量入口**：按原因直接跳不同向量。
- **判据**：软件分派成本 vs 硬件复杂度。
