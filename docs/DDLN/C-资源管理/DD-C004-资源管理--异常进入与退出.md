# 资源管理 -- 异常进入与退出

**本册要点**

- 所有同步异常与异步中断都是**精确异常**：触发指令未完成，无副作用。
- 异常原因编码是 **one-hot**，且**每个 cfx 独立编址**：同一个位在不同 cfx 含义不同。
- 进入分十步：定 cfx → 查不可屏蔽 → 查掩码 → 过滤中断来源 → 查原因掩码 → 计数 → 保存现场 → 切换 → 保存原因 → 跳向量。
- 中断是**电平触发**，在指令边界检查；多个同时挂起时**低编号 cfx 优先**。
- `escape` 的目标必须是当前 cfx，偏移只允许 0 或 4。
- 嵌套由软件负责：硬件不阻止，也不保存多级现场。

## 1. 为什么强调"精确异常"？

**答：** 因为处理程序要能确定"哪条指令出错、错在哪"，并在修复后重试；如果指令已部分执行，重试就会重复副作用。

- **同步异常**：IP 指向触发指令，指令未完成。
- **异步中断**：IP 指向下一条指令边界。
- **无副作用**：目标寄存器、内存、返回地址栈都未更新。
- **例外**：电源类系统控制动作不适用一般保存语义。
- **价值**：可重试、可恢复、可审计。

## 2. 进入流程的十步各做什么？

**答：** 先确定"进哪个 cfx"，再判断"能不能进"，最后保存现场并跳转。

- **① 定 cfx**：特权指令按目标编号；其它同步异常按当前模式进监视器；页表异常进页表 cfx；核内地址异常按地址高位或当前模式；异步中断按中断源。
- **② 不可屏蔽**：查该 cfx 的不可屏蔽位图，命中则跳过后续掩码检查。
- **③ 每核掩码**：目标 cfx 非自身时查当前掩码；被屏蔽的同步异常转 `ILLI`，异步中断置待处理位。
- **④ 中断来源过滤**：查模式行掩码与监视器全局掩码，任一屏蔽则挂起。
- **⑤ 原因掩码**：查该 cfx 对应模式的原因掩码。
- **⑥ 计数**：按类型递增 trap / 同步 / 异步计数。
- **⑦ 保存现场**：前一模式、前一掩码；`trap` 另存全局中断掩码并置全 1。
- **⑧ 切换**：模式与掩码换成切换寄存器的值。
- **⑨ 保存原因**：原因编号、指令指针、辅助信息。
- **⑩ 跳向量**：跳到该 cfx 对应模式的异常向量。

## 3. 为什么原因编码 per-cfx 独立？

**答：** 因为每个 cfx 处理的事情不同：同一位在监视器里可能是非法指令，在页表 cfx 里可能是权限错误，在 hart 里可能是核间中断。

- **one-hot**：一个原因一位，便于位图判断。
- **独立编址**：不跨 cfx 冲突，硬件靠编号区分。
- **公共低位**：功能调用、核内访存、寄存器访问、退出帧错误这四类在所有 cfx 中含义一致。
- **专有高位**：设备中断、DMA、定时器等由各 cfx 自己分配。
- **软件视角**：先读目标 cfx，再按它的表解释原因。

## 4. 待处理位与不可屏蔽位怎么用？

**答：** 待处理位记录"被屏蔽但已发生"的中断，按位或置位、写 0 清除；不可屏蔽位由硬件静态设置，软件只读。

- **置位**：被掩码屏蔽时置位，不影响其他位。
- **清除**：软件写 0 清对应位。
- **触发**：掩码解除后，若待处理位仍为 1，在下一指令边界进入。
- **不可屏蔽**：不受掩码控制，直接进入；用于必须处理的故障。
- **注意**：同步异常本身就是不可屏蔽的，只有异步中断会被挂起。

## 5. 多个中断同时来怎么办？

**答：** 电平触发、指令边界检查；多个待处理位同时置位或不同 cfx 同时中断时，**编号小的 cfx 优先**。

- **电平**：源持续有效且掩码开启，就在边界触发。
- **优先级**：按 cfx 编号，不按到达时间。
- **同 cfx 多个原因**：按该 cfx 的优先级表（如缺页先于权限）。
- **公平性**：低编号优先意味着高编号可能饿死，软件需自行轮转。
- **记录**：处理程序应读待处理位，确认处理了哪一个。

## 6. `escape` 的语义与限制是什么？

**答：** 退出当前 cfx 的异常帧：目标必须是当前 cfx，返回地址 = 原因地址 + 偏移，偏移只允许 0 或 4。

- **目标**：非当前 cfx ⇒ `CFXESC`；当前 cfx 没有有效帧 ⇒ `CFXESC`。
- **偏移**：编码层 18 位字偏移；汇编层只允许 0（重试）或 4（跳过）。
- **非法偏移**：手工编码非零的低位 ⇒ `ILLI`。
- **恢复**：前一模式、前一掩码、`trap` 时保存的全局中断掩码。
- **为什么限制偏移**：异常返回不是任意跳转，允许任意偏移等于给出一条隐藏的跳转指令。

## 7. 嵌套怎么处理？

**答：** 由软件负责：进入处理程序前保存现场，退出时恢复；硬件不阻止同 cfx 嵌套，但会覆盖上一次现场。

- **风险**：同一 cfx 再次进入会覆盖 `excp_prev_*` 与 `excp_cause_*`。
- **做法**：处理程序开头把现场存到自己的栈/暂存区。
- **开关**：用切换掩码屏蔽同类异常，减少无谓嵌套。
- **代价**：保存/恢复要多几条指令。
- **判据**：能否在嵌套后正确返回到最外层。

## 背景知识

### 术语与概念

- **精确异常**：触发指令未完成，可重试。
- **one-hot 原因**：每个原因一位。
- **待处理位**：被屏蔽中断的挂起记录。
- **切换掩码**：陷入后生效的掩码。
- **异常帧**：现场寄存器集合。

### 对照

**异常模型**

- **统一入口 + 原因码**：本项目。
- **多向量入口**：按原因直接跳不同向量。
- **判据**：软件分派成本 vs 硬件复杂度。
