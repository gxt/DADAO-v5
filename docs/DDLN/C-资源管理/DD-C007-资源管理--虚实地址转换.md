# 资源管理 -- 虚实地址转换

**本册要点**

- 48 位 VA = 6 位 PTBR + 13 位 L1 + 13 位 L2 + 16 位页内偏移。
- 64 个 PTBR；两级 64 KiB 页表；64 KiB 页。
- `ptw` 管页表/权限；`tlb` 管翻译缓存/维护。
- 权限：模式权限 + R/W/X；TLB 异常是 `ptw` 子集。
- 超页：L1 SP=1；512 MiB 对齐。

## 1. 为什么是 48 位 VA、64 个 PTBR、两级 64 KiB 页表？

**答：** 因为 48 位正好切成“6 位 PTBR + 13 位 L1 + 13 位 L2 + 16 位页内偏移”，每个页表 2¹³ × 8 B = 64 KiB，页也是 64 KiB，和整体的 8/64 节奏自洽。

- **划分**：`VA[47:42]` 选 PTBR（64 个）；`VA[41:29]` 是 L1 索引；`VA[28:16]` 是 L2 索引；`VA[15:0]` 是页内偏移。
- **页表大小**：2¹³ × 8 B = 64 KiB；页 64 KiB。
- **物理地址**：转换后生成 64 位 PA；48 位只是 VA/核内地址。
- **对比**：x86 4/5 级分页；ARM VMSA；RISC-V Sv39/Sv48；MIPS TLB；SPARC MMU；PowerPC 哈希/radix——级数和页大小各不相同。

## 2. 为什么 `ptw` 和 `tlb` 是两个 cfx，而不是一个？

**答：** 因为 `ptw` 管“页表怎么走/PTBR 怎么配/权限位图”，`tlb` 管“翻译缓存怎么维护”；两者的寄存器、异常和维护操作都不同。

- **`ptw`**：`ptbr_enable`、`ptbr[0..63]`、`pthi`、`pahi`、`user/jail/supv/hypv_perm`。
- **`tlb`**：`tlb_exist`、`tlb_enable`、`tlb_control`（invalid all / by range）、`tlb_addr_start`、`tlb_addr_size`。
- **为什么分开**：页表步进是“慢路径”，TLB 是“快路径”；维护粒度/频率不同。
- **对比**：x86 的页表配置（CR3）与 `INVLPG` 是分开的；ARM 的 TTBR 与 `TLBI` 分开；RISC-V 的 `satp` 与 `sfence.vma` 分开。

## 3. TLB 命中/缺失时，权限检查在哪一步？

**答：** 命中时检查 TLB 表项里的 SPF/GPF 与 R/W/X；缺失时走页表步进，在 L1/L2 表项里检查 Present、Superpage、SPF/GPF 与 R/W/X。

- **命中**：TLB 表项带 SPF/GPF 和权限；不符 → `PFTRAP`/`NRPERM`/`NWPERM`/`NXPERM`。
- **缺失**：先查 PTBR 权限（`NUPERM` 等），再走 L1/L2；权限检查可在地址计算后做。
- **模式权限**：`cfx_ptw_user/jail/supv/hypv_perm` 决定“当前模式能不能用这个 PTBR”。
- **对比**：x86 的 U/S + R/W + NX；ARM 的 AP + XN；RISC-V 的 U + R/W/X；MIPS 的 TLB 权限位；SPARC/ PowerPC 的页表权限。

## 4. 为什么 TLB 异常是 `ptw` 异常原因的子集？

**答：** 因为 TLB 只是页表的缓存；TLB 命中时发现的缺页/权限问题，和页表步进时是同一类问题，最终都要由 `ptw` 的 handler 处理。

- **子集**：TLB 的 `PFTRAP`/`NRPERM`/`NWPERM`/`NXPERM` 属于 `ptw` 的异常原因。
- **处理**：TLB handler 调用 `ptw` 的功能；`ptw` 处理完后，TLB 再 invalid/fill。
- **为什么**：避免两套页表语义；页表是唯一真源，TLB 只是缓存。
- **对比**：x86 的 page fault 统一由页表 handler 处理；ARM 的 abort 也统一；RISC-V 的 page fault 统一。

## 5. 超页（superpage）怎么表示？为什么要有超页？

**答：** 超页是 L1 表项直接映射大页（SP=1），省掉一次 L2 步进；用来减少大块内存的页表开销和 TLB 压力。

- **表示**：L1 表项的 Superpage 位；SPF 字段标记各小页；PPN 高位给 `PA[47:29]`，低 13 位强制 0。
- **对齐**：超页按 512 MiB 对齐（PPN[28:16] 为零）。
- **好处**：大块连续内存只占一个 L1 表项；TLB 覆盖范围更大。
- **代价**：权限/映射粒度变粗；部分小页可以不映射（SPF=0）。
- **对比**：x86 的 2 MiB/1 GiB 大页；ARM 的 block mapping；RISC-V 的 megapage/gigapage；MIPS 的 TLB 大页。

## 背景知识

### 术语与概念

- **VA/PA**：虚拟地址/物理地址；VA 48 位，PA 64 位。
- **PTBR**：页表基址寄存器，共 64 个，由 `VA[47:42]` 选择。
- **页表**：两级，每级 2¹³ 个 8 字节表项，共 64 KiB。
- **TLB**：地址转换缓存；`tlb_control` 支持全部/按范围 invalid。
- **超页**：一级页表直接映射大页，省一次页表步进。
- **权限位**：R/W/X 与模式权限位图。

### 对照

**x86-64**：4 级/5 级分页；CR3 指向页表；`INVLPG` 失效。

**ARM64**：VMSA；TTBR0/TTBR1；`TLBI` 失效。

**RISC-V**：Sv39/Sv48；`satp`；`sfence.vma` 失效。

**MIPS**：TLB + 软件页表；`TLBP`/`TLBR`/`TLBWI`。

**SPARC**：MMU + TLB；`flush` 指令。

**PowerPC**：哈希页表或 radix 页表；`tlbie` 失效。
