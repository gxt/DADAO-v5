# 资源管理 -- 存储层次

**本册要点**

- `cache` cfx：`exist`/`enable`/`ctrl`（invalid I/D、flush D）。
- `llc` cfx：`exist`/`ctrl`（invalid all）；跨 hart 共享。
- `pmem` cfx：最多 64 个不连续 DRAM 区域；`start`/`size`/`attr`。
- device 不算 `pmem`。
- `prefetchable`/`coherent` 属性。
- cache/TLB/页表协作：先改页表 → 清 TLB → 清 cache。

## 1. 为什么 cache 也是 cfx，而不是一条 `cache` 指令？

**答：** 因为 cache 是“有实例、有存在性、有使能、有维护操作”的资源；做成 cfx 后，软件用统一的 cfx 寄存器模型管理它，不必为每种 cache 发明新指令。

- **`cache_exist`**：该 VA 空间是否有 cache。
- **`cache_enable`**：按位开关 I/D-cache。
- **`cache_ctrl`**：bit0 invalid I-cache、bit1 invalid D-cache、bit2 flush D-cache。
- **为什么**：不同实现有不同 cache 数量/集合；cfx 让“存在性 + 控制 + 维护”统一。
- **对比**：x86 用 `CLFLUSH`/`WBINVD`；ARM 用 `DC`/`IC`；RISC-V 用 CBO；MIPS 用 `cache` 指令——都是“指令 + 控制寄存器”混合，cfx 统一成资源。

## 2. 为什么 `llc` 要跨 hart 共享？

**答：** 因为最后一级缓存通常在多个 hart 之间共享；把它做成共享 cfx，才能统一做 invalid/维护，不必每个 hart 各管一份。

- **`llc_exist`**：是否有 LLC。
- **`llc_ctrl`**：bit0 invalid all。
- **为什么共享**：LLC 的物理结构就是跨 hart 的；共享 cfx 让维护操作只有一个入口。
- **代价**：多 hart 同时访问要仲裁；维护时可能影响所有 hart。
- **对比**：x86 的 LLC 由 MESIF/MESI 维护，`WBINVD` 作用于所有 cache；ARM 的 `TLBI`/`DC` 按共享域广播。

## 3. 为什么 `pmem` 最多 64 个不连续区域？为什么 device 不算 `pmem`？

**答：** 因为物理内存可能不连续，6 位索引正好支持 64 个区域；`pmem` 只描述普通 DRAM，device 存储由各设备 cfx 自己管理。

- **区域**：`pmem_start[0..63]`、`pmem_size[0..63]`、`pmem_attr[0..63]`。
- **为什么 64**：6 位索引；够描述常见的不连续 DRAM 布局。
- **device 不算**：device 存储不是 DRAM；它的寄存器/缓冲由设备 cfx 管，混进 `pmem` 会让“内存”和“设备”边界不清。
- **对比**：x86 用 e820/UEFI memory map；ARM 用 device tree memory node；RISC-V 用 DT/ACPI；它们也区分 DRAM 与 device。

## 4. `prefetchable`/`coherent` 属性怎么用？

**答：** 它们描述该物理内存区域是否允许预取、是否参与缓存一致性；软件/硬件据此决定访问策略。

- **`prefetchable`**：允许预取；对 MMIO 类区域通常要关掉。
- **`coherent`**：参与缓存一致性；非 coherent 区域要软件维护。
- **用途**：区分普通 DRAM、非 coherent 内存、设备内存。
- **对比**：x86 的 MTRR/PAT；ARM 的 MAIR；RISC-V 的 PMA；都是“内存属性”机制。

## 5. cache/TLB/页表三者怎么协作？

**答：** 页表在内存里，cache 可能缓存页表项；TLB 缓存“VA→PA”的翻译；三者的一致性要靠维护操作和顺序保证。

- **页表步进**：读页表项，可能命中 cache。
- **TLB**：缓存翻译；页表修改后要 invalid TLB。
- **cache**：缓存数据/页表；DMA 或页表修改后要 flush/invalid。
- **顺序**：先改页表 → 清 TLB → 必要时清 cache；顺序错了会读到旧翻译/旧数据。
- **对比**：x86 `INVLPG` + `CLFLUSH`；ARM `TLBI` + `DC`；RISC-V `sfence.vma` + CBO。

## 背景知识

### 术语与概念

- **I-cache / D-cache**：指令/数据高速缓存。
- **LLC**：最后一级缓存，跨 hart 共享。
- **物理内存区域**：`pmem` 描述的 DRAM 区间；最多 64 个，可不连续。
- **coherent**：该区域是否参与缓存一致性。
- **prefetchable**：该区域是否允许预取。

### 对照

**x86-64**：`CLFLUSH`/`CLFLUSHOPT`/`WBINVD` 做 cache 维护；MTRR/PAT 描述内存属性。

**ARM64**：`DC`/`IC` 维护指令；MAIR 描述内存属性。

**RISC-V**：CBO 扩展（`cbo.clean`/`cbo.flush`/`cbo.inval`）；PMA/PMP 描述属性。

**MIPS**：`cache` 指令做维护。

**SPARC**：cache 维护指令 + MMU 属性。

**PowerPC**：`dcbf`/`dcbi`/`icbi` 等维护指令。
