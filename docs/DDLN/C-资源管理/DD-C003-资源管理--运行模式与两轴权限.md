# 资源管理 -- 运行模式与两轴权限

**本册要点**

- 四种模式：user（00）、jail（01）、supv（10）、hypv（11）；jail 是受限用户态，当前阶段行为与 user 一致。
- 权限是**两轴**：模式轴（用哪一行 `cg0`–`cg3`）× 资源轴（位掩码里对应源 cfx 的位）。
- 四类同步入口各有独立掩码；异步来源掩码只有一个层次（monitor 的 `cg8 rc1`）——**不能合成一个开关**。
- 陷入时用 `switch_run_mode` 切换模式；不改动任何来源掩码。
- 缺省只允许 hypv 监视器，其它模式必须由初始化代码显式放开。
- 页表权限（HSJU/R/W/X）是第三层，与 cfx 权限互不替代。

## 1. 四种模式怎么分工？

**答：** user 跑普通应用，jail 跑受限应用（当前阶段与 user 同行为），supv 跑主管系统，hypv 跑超管系统；模式决定"用哪一行权限寄存器"。

- **编码**：两比特，正好对应模式号。
- **权限**：user/jail 是用户态，supv/hypv 是特权态。
- **当前阶段**：jail 的受限规则（禁指令、二阶段翻译）留待后续定义。
- **模式与 cfx 独立**：模式决定权限行，cfx 决定资源。

## 2. 两轴权限怎么判？

**答：** 先看模式轴选中哪一行，再看资源轴里源 cfx 对应的位：两位都允许才通过；访问自己时只绕资源轴。

- **模式轴**：当前模式决定用 `cg0`/`cg1`/`cg2`/`cg3` 中哪一行。
- **资源轴**：目标 cfx 的那一行里，位索引是**源 cfx**；`0=允许`、`1=屏蔽`。
- **自身例外**：访问自己 cfx 时该位被硬件忽略，只按模式轴判。
- **拒绝后果**：`CFXPERM`，进入**当前模式的监视器**。
- **为什么两轴**：模式决定"谁能做什么"，资源决定"这条路径通不通"。

## 3. 四类同步掩码为什么要分开？

**答：** 因为四类入口的风险不同：能陷入不等于能访存，能读寄存器不等于能取指；合成一个开关就无法做最小授权。

- **控制转移**：`trap`/`escape` 的目标。
- **核内访存**：普通 `ld/st` 访问该 cfx 的 SRAM/MMIO。
- **寄存器访问**：`cfx2rd`/`cfx2rc`。
- **取指进入**：直接跳转/取指进入该 cfx。
- **最小授权**：按用途逐类放开，而不是"一开全开"。

## 4. 异步来源掩码怎么配合？

**答：** 只有一层：按**当前运行模式**选该模式 monitor 的 `cg8 rc1`（`cfx_<monitor>_async_intr_mask`），位 = 源 cfxha，`0=允许`、`1=屏蔽`；允许即投递 `cfx_hart`，屏蔽则挂起到 `cfx_hart cg9` 的待处理位图。

- **载体**：`cfx0`–`cfx3` 的 `cg8 rc1`，每个 monitor 一个。
- **求值**：U→umon、J→jmon、S→smon、H→hmon；与当前 cfx 无关。
- **允许**：源事件进入 `cfx_hart`，捕获缓冲 `async_src_frame` 每次进入覆盖。
- **被屏蔽**：置 `cfx_hart cg9 rc4`（`async_src_pending`），mask 解除后由硬件补投。
- **为什么只有一层**：策略只按运行模式选；pending 是投递状态，不是第二层掩码。

## 5. 陷入时怎么切换？

**答：** 进入异常时，硬件把运行模式换成 `switch_run_mode` 的值；没有独立的 cfx 屏蔽层，异步来源掩码在 monitor 的 `cg8 rc1`。退出时只恢复运行模式（同步帧另恢复前一 cfx），不改动掩码。

- **`switch_run_mode`**：从该模式陷入后切到哪个模式。
- **不切换屏蔽层**：异常进入不改任何来源掩码；异步来源过滤按当前运行模式取 monitor 的 `cg8 rc1`，pending 记在 `cfx_hart cg9`。
- **为什么要切换**：处理程序需要更高权限；异步每次进入覆盖 `cg9` 捕获缓冲，嵌套由软件处理。
- **恢复**：`escape` 从 `excp_prev_run_mode` 恢复（同步帧另恢复 `excp_prev_cfx_code`）；**不保存、不恢复任何来源掩码**。
- **代价**：软件必须为每种模式配好切换目标，否则一陷入就落在错误模式。

## 6. 初始化时为什么要收紧默认值？

**答：** 因为默认只允许 hypv 监视器：其它模式若要访问资源，必须显式放开；反过来，如果默认全开，就等于把所有资源暴露给用户态。

- **默认同步来源**：只有第 3 位（hypv 监视器）为 0，其余为 1。
- **默认中断来源**：monitor 的 `cg8 rc1` 复位全 1（全屏蔽）。
- **初始化职责**：按最小授权原则，逐个放开 user/jail/supv 需要的入口。
- **常见错误**：直接写全 0，等于把所有 cfx 对所有模式开放。
- **判据**：列出"这个模式需要访问哪些 cfx、哪类入口"。

## 背景知识

### 术语与概念

- **两轴权限**：模式轴 × 资源轴。
- **源 cfx**：发起访问的一方，位索引用它。
- **异步来源掩码**：monitor 的 `cg8 rc1`，位 = 源 cfxha；按当前运行模式求值，`trap`/`escape` 不保存/不恢复。
- **待处理位**：被屏蔽的异步源挂起处（`cfx_hart cg9 rc4`，硬件写、软件只读）。
- **最小授权**：只放开需要的入口。

### 对照

**权限模型**

- **两轴位掩码**：细粒度、可组合（本设计）。
- **单一权限级**：简单但无法表达"能读不能写"。
- **判据**：能否只放开一类入口而不放开其他。
