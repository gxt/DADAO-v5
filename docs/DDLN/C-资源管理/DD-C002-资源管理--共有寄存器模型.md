# 资源管理 -- 共有寄存器模型

**本册要点**

- 每个 cfx 都有一段**共有寄存器**（`cg0`–`cg7`），语义全系统一致；`cg8` 以上才是专有寄存器。
- `cg0`–`cg3` 是**按模式分行**的权限与切换寄存器：每种运行模式一套。
- `cg4` 是身份与计数，`cg5` 是异常现场，`cg6` 是暂存，`cg7` 描述自己的内部空间。
- `cg7` **只描述、不传输**：空间块存在性、起点、大小、属性，全部只读。
- 访问不存在的 `cg`/`rc` 触发 `CFXREG`；保留位写 0 被忽略。

## 1. 为什么先把 `cg0`–`cg7` 定为共有？

**答：** 因为权限、切换、现场、暂存这几件事对每个 cfx 都一样；定成共有后，软件可以用同一套代码遍历所有 cfx，不必为每个资源写一套初始化。

- **共有部分**：四种模式的权限行、配置与计数、异常现场、暂存、空间描述。
- **专有部分**：`cg8` 以上，各 cfx 自己定义。
- **好处**：通用例程只写一遍；新增 cfx 只补专有部分。
- **代价**：共有部分要预留足够寄存器，且不能随意改语义。

## 2. `cg0`–`cg3` 为什么按模式分行？

**答：** 因为"从哪个模式陷入时用什么权限、切到哪个模式、跳到哪个向量"是逐模式不同的策略；分行后，同一 cfx 可以为四种模式配四套策略。

- **每行内容**：四类同步来源掩码（控制转移、核内访存、寄存器访问、取指进入）+ 异步中断来源掩码 + 切换模式 + 异常向量。
- **位索引是源 cfx**：`0 = 允许`、`1 = 屏蔽`；访问自己时该位被硬件忽略。
- **默认值**：同步来源掩码缺省只允许 hypv 监视器（第 3 位为 0，其余为 1），异步中断来源掩码缺省全屏蔽。
- **`rc5`–`rc7` 保留**：访问触发 `CFXREG`。

## 3. 四类同步掩码与两类中断掩码各管什么？

**答：** 四类同步掩码管"这类访问能不能进这个 cfx"，两类中断掩码管"这个 cfx 的中断能不能投递"。

- **控制转移掩码**：`trap`/`escape` 的目标是否允许。
- **核内访存掩码**：普通 `ld/st` 访问该 cfx 的 SRAM/设备是否允许。
- **寄存器访问掩码**：`cfx2rd`/`cfx2rc` 是否允许。
- **取指掩码**：直接跳转/取指进入该 cfx 是否允许。
- **中断来源掩码**（每模式一套）：按当前 cfx 过滤异步中断来源。
- **全局中断掩码**（每个监视器一个）：监视器级别的总过滤。
- **两层同时允许才投递**：任一屏蔽即挂起到待处理位。

## 4. `cg4` 放什么？

**答：** 身份与计数：标识、版本、陷入次数（trap / 同步 / 异步 / 退出）、暂存寄存器数量。

- **只读项**：标识、版本、暂存数量。
- **计数项**：trap 次数、同步异常次数、异步中断次数、exit 次数；硬件自增，软件只读。
- **用途**：性能与调试统计；也是"这个 cfx 到底有没有被用到"的证据。
- **注意**：计数是每 cfx 的，不是每模式的。

## 5. `cg5` 与 `cg6` 各放什么？

**答：** `cg5` 保存异常现场（前一模式、原因、返回地址、辅助信息、待处理位）；`cg6` 是软件暂存。

- **现场寄存器**：`excp_prev_run_mode`、`excp_cause_id`、`excp_cause_ip`、`excp_cause_info`、`excp_pending`。
- **待处理位**：按位或语义，写 0 清位。
- **不保存独立屏蔽状态**：异常现场没有前一 cfx 掩码；异步中断屏蔽与 pending 由 monitor 的 `cfx_intr_mask`、`global_cfx_intr_mask` 与 `excp_pending` 承担。
- **暂存数量**：由 `cg4` 的数量寄存器给出，至少 2、最多 64；越界访问触发 `CFXREG`。
- **用途**：中断处理程序保存自己的上下文；不要与异常现场混用。

## 6. `cg7` 为什么只描述不传输？

**答：** 因为空间描述是"这个 cfx 内部有什么"的静态事实；批量传输指令已经删除，需要搬运时由各 cfx 自己的机制（如物理内存的 DMA）负责。

- **结构**：16 个空间块，每块 4 个 `rc`（描述字、起点、大小、属性）。
- **描述字**：存在位 + 类型（SRAM/ROM/MMIO/DRAM/其它，存在时恰一位）。
- **起点与大小**：42 位内部偏移；`start + size ≤ 2^42`。
- **属性**：读/写/执行、可缓存、可共享、设备/易失。
- **只读**：任何写都触发 `CFXREG`。
- **判据**：想"改布局"只能换实现，不能在运行时改。

## 背景知识

### 术语与概念

- **共有寄存器**：`cg0`–`cg7`，语义全系统一致。
- **专有寄存器**：`cg8` 以上，各 cfx 自定义。
- **两轴权限**：模式轴（`cg0`–`cg3`）× 资源轴（位掩码）。
- **异常现场**：`cg5` 保存的架构状态。
- **空间块**：`cg7` 描述的一段内部地址范围。

### 对照

**寄存器组织**

- **按功能分层**：共有 + 专有（本设计）。
- **平铺编号**：简单但难以保证一致性。
- **判据**：新增资源要不要重写通用代码。
