# 资源管理 -- 时间与中断

**本册要点**

- 中断要分四层看：**源、策略、捕获、处理**；四层各自拥有不同状态，不能合并。
- 同步异常有“原因编号”，异步中断的身份是**源**，不占同步原因编号。
- 放行掩码是**策略**，不是异常现场；进入/退出不保存、不恢复来源掩码。
- 异步捕获是“这一界看到了哪些源”的快照，不是队列，也不是可返回的帧。
- 同一指令边界上的多个放行源合并为一次进入；硬件不替软件排优先级。
- 全局时间只读、不产生中断；定时事件由本地比较器产生，属于异步源。

## 1. 为什么中断要分层？

**答：** 因为“谁产生事件”“现在允不允许”“这次看到哪些源”“软件怎么处理”是四个不同的问题，合并会让状态互相污染。

- **源**：产生事件，维护自身事件状态和子事件。
- **策略**：当前运行模式决定是否放行某个源。
- **捕获**：在指令边界把本界放行的源合并成一次进入。
- **处理**：软件保存快照、回源确认、再交给调度/设备处理。
- **原则**：产生、放行、捕获、处理各自独立；任何一层都不替另一层做决定。

## 2. 源层拥有什么？

**答：** 源拥有“事件是否发生、有什么子事件、何时被确认”；它不拥有全局原因编号，也不决定自己被投递到哪。

- **事件**：定时器到期、设备收发、内存传输完成等，由源产生。
- **子事件**：同一源可以有多个子事件；细节回源读，不扩成全局原因位。
- **挂起与确认**：事件可以被记录为待处理；确认只由源完成。
- **身份**：异步源的身份是“源”，不是同步异常原因。
- **原则**：源是事件的主人，细节留在源内。

## 3. 策略层拥有什么？

**答：** 策略层回答“当前运行模式允不允许这个源”，它是可变的策略，不是异常现场。

- **按运行模式**：不同模式的放行策略可以不同。
- **不随现场保存**：异常进入/退出不改写策略，也不把它当成现场字段。
- **与源内掩码分开**：源可以有子事件掩码；它和运行模式放行是两层判断，不能合并。
- **原则**：策略决定“现在能不能进”，现场决定“刚刚发生了什么”。

## 4. 捕获层拥有什么？

**答：** 捕获层只负责“这一界有哪些源进来了”，并记录被中断的上下文；它不解释具体设备，也不替软件排序。

- **统一入口**：所有异步源走同一个捕获入口，避免每个源一套返回路径。
- **多源合并**：同一指令边界上所有放行源合并为一帧，源集合用位图表示。
- **无队列**：不把同一界的多个源拆成多次进入，也不按源编号串行。
- **覆盖**：每次进入整体覆盖上一份捕获；没有“活动帧/帧有效”的硬件状态。
- **原则**：捕获是快照，不是队列，也不是返回帧。

## 5. 处理层拥有什么？

**答：** 处理层负责保存快照、回源确认、恢复调度；它决定“怎么处理”，不改变硬件已经记录的源集合。

- **保存**：在关中断窗口把捕获与必要的寄存器上下文搬到任务现场。
- **回源**：按捕获的源集合回源读事件状态/子事件。
- **确认**：完成处理后回源确认，清对应的待处理位。
- **返回**：走正常调度/交接路径，不把异步捕获当作异常返回帧。
- **原则**：硬件只保证“这一界有哪些源”，软件负责“怎么处理”。

## 6. 为什么源身份和原因编号要分开？

**答：** 因为同步异常需要“分类”，异步中断需要“识别来源”；两者混在一起会让原因空间被设备数量撑爆。

- **同步原因**：用于异常分类，属于当前异常处理路径。
- **异步源**：用于识别谁产生事件；一个源内部可以有多个子事件。
- **不占原因编号**：异步源不把每个设备/子事件扩成全局原因位。
- **细节回源**：同一源的差异回源读，不在捕获层解释。
- **原则**：原因回答“为什么异常”，源回答“谁打断了我”。

## 7. 为什么掩码不是现场？

**答：** 因为掩码是“现在的策略”，现场是“刚发生的事实”；把策略存进现场会让恢复和策略变更互相干扰。

- **现场只记录**：异常前模式/cfx/IP、原因等是事实。
- **策略只判断**：当前模式是否放行某个源，是运行时策略。
- **进入不保存**：异常进入不改写策略。
- **退出不恢复**：异常退出不恢复来源掩码；策略由软件在合适层次维护。
- **原则**：现场是证据，策略是判断。

## 8. 多个源同时到来怎么处理？

**答：** 同一指令边界上的所有放行源合并为一次进入；不按源编号串行，也不做“低编号优先”。

- **位图并集**：本次捕获的源集合是各源位的并集。
- **一次进入**：进入计数只加一，和源个数无关。
- **软件排序**：处理顺序由软件按帧内位决定，硬件不替软件仲裁。
- **无饥饿问题**：不按编号排队，不存在“高编号被低编号饿死”的固定顺序。
- **原则**：硬件只回答“这一界有哪些源”，不回答“先处理谁”。

## 9. 同步与异步如何分流？

**答：** 同步异常走当前模式监视器，异步中断走统一捕获入口；两者共享“精确”原则，但返回路径不同。

- **同步**：触发指令未完成；处理程序可以重试/跳过；返回走同步退出意图。
- **异步**：被中断指令已提交；不重放；返回走正常调度/交接。
- **原因**：同步有原因分类；异步有源身份和源内细节。
- **不混用**：不要把异步源塞进同步原因表，也不要把同步退出帧用于异步返回。
- **原则**：同步是“故障恢复”，异步是“抢占交接”。

## 10. 时间与设备为什么也按这个模型？

**答：** 因为定时器、设备、内存传输都只是“源”；它们共享同一套策略、捕获、确认模型，只是细节回各自的源。

- **定时器**：事件到期置位；放行后进统一捕获；处理完回源确认。
- **设备**：收发事件置位；细节在设备源；处理程序回源读状态并确认。
- **内存传输**：完成/出错置位；细节在内存源；确认只清事件，不清传输状态。
- **全局时间**：只读、不产生中断；它是时间基准，不是中断源。
- **原则**：源可以不同，分层模型相同。

## 11. 常见错误

- 把异步捕获当成异常帧，继续用同步返回路径。
- 让源自己决定投递，绕过策略层。
- 把运行模式策略和源内子事件掩码合成一层。
- 按源编号给异步中断排优先级，制造固定顺序和饥饿。
- 把设备/子事件扩成全局同步原因，导致原因空间膨胀。
- 在捕获层解释具体设备；捕获只应回答“有哪些源”。

## 背景知识

### 术语与概念

- **源**：产生异步事件的部件，拥有事件、子事件、待处理与确认。
- **策略**：当前运行模式对源的放行/屏蔽判断，不是现场。
- **捕获**：异步进入瞬间的源集合与上下文快照，每次覆盖。
- **处理**：软件保存快照、回源确认、恢复调度。
- **源身份**：异步中断的来源标识，不等同于同步异常原因。
- **待处理**：源事件被记录但尚未处理的状态，确认由源完成。

### 对照

**中断分层模型**

- **源 / 策略 / 捕获 / 处理四层**：本项目；状态职责清晰。
- **源直接投递到固定向量**：简单，但设备差异进入全局原因空间。
- **捕获即返回帧**：把抢占交接伪装成故障恢复，容易重放。
- **低编号固定优先**：实现简单，但会制造饥饿和顺序耦合。
- **判据**：新增一个源时，是否需要修改全局原因表或仲裁顺序。
