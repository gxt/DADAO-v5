# 资源管理 -- 外部设备

**本册要点**

- 设备也走 cfx：串口与电源各占一个编号，寄存器用 `cfx2rd`/`cfx2rc` 访问。
- 串口有存在性位与 **32 组 × 64 个**寄存器；窄寄存器单独占一个编号。
- 电源提供三个动作：关机、硬复位、软复位；它们属**系统控制**，不走一般异常语义。
- 启动 ROM 挂在电源 cfx 下，复位向量在 ROM 内固定偏移；该空间必须可执行。
- 设备存储不归物理内存管理；设备中断按来源 cfx 路由。

## 1. 串口怎么建模？

**答：** 一个存在性位 + 32 组寄存器组，每组 64 个；寄存器含义由具体硬件协议定义，窄宽度操作单独占一个 64 位编号。

- **存在性**：该串口实例是否有效。
- **组数**：32 组，覆盖多实例场景。
- **寄存器**：每组 64 个；8 位或 16 位宽的寄存器也各占一个编号。
- **访问**：`cfx2rd`/`cfx2rc`。
- **判据**：实例是否存在、哪一组、哪个寄存器。

## 2. 串口中断怎么表示？

**答：** 每个实例一位，从固定高位开始编号；可屏蔽，触发时进入串口 cfx 的异常入口。

- **位编号**：从 32 开始，对应 0–31 号实例。
- **可屏蔽**：受两层中断掩码控制。
- **信息**：辅助信息全零，软件靠位编号判断是哪个实例。
- **路由**：进串口 cfx，不进监视器。
- **判据**：处理程序能否区分实例。

## 3. 电源管理做什么？

**答：** 一个控制寄存器，三个动作：关机、硬复位、软复位；写即触发，没有完成状态。

- **关机**：停止系统。
- **硬复位**：整机复位。
- **软复位**：不切电的复位。
- **系统控制例外**：不适用一般异常的返回地址/现场保存语义。
- **收尾**：由发起方负责（停调度、回写缓存、关中断）。
- **判据**：复位后能否回到确定状态。

## 4. 启动 ROM 为什么挂在电源 cfx？

**答：** 因为复位向量必须在一个"上电就可读可执行"的空间里；把它放在电源 cfx 下，复位后无需任何配置就能取指。

- **大小**：256 KiB。
- **复位向量**：ROM 内固定偏移。
- **属性**：必须可执行（否则复位取指失败）。
- **只读**：运行期不可改写。
- **判据**：复位后第一条指令能否取到。

## 5. 为什么设备存储不归物理内存管理？

**答：** 因为物理内存管理只描述普通内存区域的属性；设备寄存器有自己的访问语义（宽度、副作用、顺序要求），混在一起会破坏这些语义。

- **物理内存**：只描述普通内存。
- **设备**：由各自 cfx 管理，经核内地址空间访问。
- **属性差异**：设备通常不可缓存、有副作用。
- **判据**：这个地址是否允许预取、是否允许合并访问。

## 6. 设备中断怎么路由？

**答：** 按中断来源 cfx 路由：串口中断进串口 cfx，定时器中断进 hart cfx，物理内存 DMA 中断进物理内存 cfx。

- **归属**：谁管理设备，谁处理它的中断。
- **两层掩码**：模式行掩码 + 监视器全局掩码。
- **被屏蔽**：置该 cfx 的待处理位。
- **优先级**：多 cfx 同时中断时编号小的先处理。
- **判据**：能否从原因编号直接定位到设备。

## 背景知识

### 术语与概念

- **存在性位**：设备实例是否有效。
- **寄存器组**：一组设备寄存器，按组号索引。
- **系统控制动作**：关机/复位，不走一般异常语义。
- **启动 ROM**：复位后可取指只读空间。
- **设备路由**：中断按来源 cfx 分发。

### 对照

**设备访问**

- **cfx 寄存器访问**：统一编号、统一权限（本设计）。
- **MMIO 窗口**：传统做法，需要地址分配与映射。
- **判据**：设备能否纳入统一的权限与异常模型。
