# 资源管理 -- 外部设备

**本册要点**

- `uart` cfx：`uart_exist`、32 组 × 64 个寄存器。
- `power` cfx：关机/硬复位/软复位。
- 设备存储不归 `pmem`；由设备 cfx 管理。
- 设备中断置 pending，按 cfx 路由。
- 设备 cfx 与 `pmem`/`cache`/`tlb` 的边界。

## 1. 为什么 UART 是 cfx，而不是一段 MMIO 寄存器？

**答：** 因为 UART 是“有实例、有存在性、有权限”的资源；做成 cfx 后，软件用统一的 `cfx2rd`/`cfx2rc` 访问，不需要为每个 UART 保留一段 MMIO 地址。

- **`uart_exist`**：该 UART 是否存在。
- **寄存器组**：32 组 UART，每组 64 个寄存器。
- **为什么不是 MMIO**：cfx 提供统一的资源号、权限、异常路由；MMIO 要为每个设备分配地址窗口。
- **对比**：x86/ARM/RISC-V 的设备多用 MMIO；cfx 把设备寄存器收进资源命名空间。

## 2. 为什么支持 32 个 UART？每个 64 个寄存器怎么用？

**答：** 32 个 UART 覆盖多串口场景；每组 64 个寄存器按硬件协议定义控制/状态/数据/FIFO 等。

- **数量**：32 组（0–31）。
- **每组**：64 个寄存器；具体含义“参照硬件协议”。
- **为什么 32**：多串口/多实例；`cfxha` 只有一个 uart cfx，用组号区分实例。
- **对比**：x86 用 PCI/MMIO 枚举多个 UART；ARM 用 device tree；RISC-V 用 DT/ACPI。

## 3. `power` 的关机/硬复位/软复位分别做什么？谁来收尾？

**答：** `power_ctrl` 的 bit0 关机、bit1 硬复位、bit2 软复位；收尾由发起方（通常是 OS/最后退出的 hart）负责，硬件执行最终动作。

- **bit0**：关机；停止系统。
- **bit1**：硬复位；整机复位。
- **bit2**：软复位；不切断电源的复位。
- **谁收尾**：OS 停止调度、刷 cache、关中断；最后由 power cfx 执行。
- **对比**：x86 的 ACPI 电源管理；ARM 的 PSCI；RISC-V 的 SBI shutdown/reset。

## 4. 设备中断怎么进入 cfx 的异常向量？

**答：** 设备置 pending 位，按 cfx 的 mask/向量进入对应 handler；具体是进设备 cfx 还是 monitor，按实现/测试机约定。

- **pending**：设备中断先置位；handler 读 pending 分派。
- **mask**：cfx mask/switch mask 决定是否屏蔽。
- **向量**：每个 cfx 有自己的 `*_excp_vector`。
- **待核**：UART 中断具体进 uart cfx 还是 umon/smon，需按实现/测试机核对。
- **对比**：x86 APIC/IDT；ARM GIC；RISC-V PLIC；MIPS/SPARC/PowerPC 的中断控制器。

## 5. 设备 cfx 与 `pmem`、`cache`、`tlb` 的边界怎么划？

**答：** 设备寄存器/内部 SRAM 归设备 cfx；`pmem` 只描述 DRAM；`cache`/`tlb` 管存储层次，不直接管设备寄存器。

- **`pmem`**：只描述普通 DRAM，不含 device。
- **设备 cfx**：UART/power 等寄存器与内部 SRAM。
- **`cache`**：缓存内存数据/页表；设备寄存器一般不走 cache。
- **`tlb`**：只翻译 VA→PA；设备 cfx 寄存器不是 VA。
- **对比**：x86 用 MMIO + UC 属性；ARM 用 Device memory 属性；RISC-V 用 I/O 属性；cfx 把设备从地址空间里拿出来。

## 背景知识

### 术语与概念

- **UART**：串口控制器；cfx 提供 32 组、每组 64 个寄存器。
- **MMIO**：把设备寄存器映射到内存地址；cfx 设备走 cfx 寄存器窗口。
- **设备寄存器**：设备自己的控制/状态/数据寄存器。
- **中断**：设备通过 pending 位请求处理。
- **电源管理**：关机/硬复位/软复位。

### 对照

**x86-64**：MMIO + PCI 配置空间；中断经 APIC。

**ARM64**：MMIO + GIC；设备树描述。

**RISC-V**：MMIO + PLIC；设备树描述。

**MIPS**：MMIO + 中断控制器。

**SPARC**：MMIO + 中断向量。

**PowerPC**：MMIO + MPIC/OpenPIC。
