# 资源管理 -- 核芯功能扩展

**本册要点**

- 所有资源都是 cfx：统一编号、寄存器、权限、异常与地址窗口。
- `cfxha` 6 位、64 个槽；0–3 monitor、4–6 ptw/tlb/cache、15–18 hart/llc/pmem/timer、62–63 uart/power。
- 四条 cfx 指令：`trap`/`escape`/`cfx2rd`/`cfx2rc`；`cfxld`/`cfxst` 归 C004。
- `CFXMEM`（地址窗口）/`CFXREG`（寄存器）/`ILLI`（reserved）三种错误。
- 测试机只实现 `cfx0/1/2/3/63`，是实现范围。
- 新资源 = 新 cfx；reserved 是扩展位。

## 1. 为什么用 cfx 统一管理所有资源，而不是按资源类型分设 CSR/MSR/MMIO？

**答：** 因为 cfx 把“资源”变成统一的编号对象：一个 6 位 `cfxha` + 一组 `cg`/`rc` 寄存器 + 一个异常向量 + 一个 64 KiB 窗口 + 一套 mask；不需要为每种资源发明新的 CSR/MSR/MMIO 约定。

- **统一译码**：`cfxha` 就在 `ha` 字段；`crrr`/`crii`/`ciii` 一套格式覆盖寄存器传输、陷入/退出、块传输。
- **统一权限**：cfx mask + switch mask + PTBR 权限；资源不再各自一套权限规则。
- **统一异常**：每个 cfx 有自己的向量和 cause 码；异常按 cfx 路由，不靠全局向量表。
- **统一窗口**：48 位核内地址高 6 位选 cfx；每个 cfx 64 KiB。
- **扩展**：新资源 = 新 cfx；reserved 编号就是扩展位，不需要新 opcode。
- **代价**：cfx 寄存器要 `cfx2rd`/`cfx2rc` 间接访问，比直接 CSR 多一条指令；换来统一与可扩展。

**各家做法**：

- **x86-64**：MSR + 4 个 ring + VMX/SVM；资源靠 MSR/MMIO，没有统一的 6 位资源号。
- **ARM64**：system registers（MRS/MSR）+ EL0–EL3；资源靠系统寄存器/MMIO。
- **RISC-V**：CSR（12 位）+ M/S/U；资源靠 CSR/MMIO。
- **MIPS**：CP0（5 位）+ kernel/user；资源靠 CP0/MMIO。
- **SPARC**：ASR + trap level；资源靠 ASR/MMIO。
- **PowerPC**：MSR + SPR（10 位）+ hypervisor；资源靠 SPR/MMIO。

## 2. `cfxha` 为什么是 6 位？64 个编号怎么分？为什么 monitor 按模式分？

**答：** 6 位是因为 `ha` 就是 6 位，正好 64 个槽；编号按“模式 monitor → 地址/存储 → 执行/内存/时间 → 设备”分区；monitor 按模式分，是为了让每个模式有独立的同步异常入口。

- **编号**：0–3 `umon`/`jmon`/`smon`/`hmon`；4–6 `ptw`/`tlb`/`cache`；15–18 `hart`/`llc`/`pmem`/`timer`；62–63 `uart`/`power`；7–14、19–61 reserved。
- **为什么 6 位**：`ha` 是 6 位，不额外占位；64 个槽够当前资源 + 预留。
- **为什么 monitor 分四个**：每个模式都有自己的异常向量、mask、prev 状态；`umon` 处理 user、`jmon` 处理 jail、`smon` 处理 supv、`hmon` 处理 hypv。
- **为什么 reserved**：扩展空间；reserved `cfxha` 上的 cfx 指令 → `ILLI`。
- **对比**：x86 的 MSR 地址分散、没有窗口/向量语义；ARM system register 16 位编码；RISC-V CSR 12 位；MIPS CP0 5 位；SPARC ASR；PowerPC SPR 10 位。

## 3. 为什么 cfx 指令只有 trap/escape/cfx2rd/cfx2rc？为什么只连 rd？

**答：** 因为这四类指令覆盖“控制转移 + 寄存器访问”；`cfxld`/`cfxst` 是块传输（deferred）；`cfx2rd`/`cfx2rc` 只连 `rd` 是为了数据通路简单，`rb`/`rf` 走 `set.rd` 中转。

- **`trap`/`escape`**：进入/退出 cfx 的异常向量；`ciii` 格式。
- **`cfx2rd`/`cfx2rc`**：cfx 寄存器与 `rd` 互传；`crrr` 格式，`cfxha` + `cg` + `rc` + `rd`。
- **`cfxld`/`cfxst`**：cfx 内部 SRAM 与内存的块传输；`crii` 格式，当前 deferred。
- **为什么只连 `rd`**：cfx2rd/cfx2rc 的数据通路只到 `rd`；`rb`/`rf` 先用 `rb2rd`/`rf2rd` 转到 `rd`，汇编器用 `set.rd` 简化。
- **对比**：x86 `RDMSR`/`WRMSR`（ECX 选 MSR）；ARM `MRS`/`MSR`；RISC-V `csrrw` 等；MIPS `mfc0`/`mtc0`；SPARC `RDASR`/`WRASR`；PowerPC `MFSPR`/`MTSPR`——都是“寄存器 ↔ GPR”的直接通路，cfx 多了一层 `cg`/`rc` 间接。

## 4. 为什么地址窗口非法是 CFXMEM，寄存器不存在是 CFXREG？

**答：** 因为地址窗口和寄存器是两条不同的访问路径：`ld`/`st`/取指打的是 cfx 的 64 KiB 窗口，越界/非法 → `CFXMEM`；`cfx2rd`/`cfx2rc` 打的是 cfx 的 `cg`/`rc`，寄存器不存在/权限不符 → `CFXREG`。

- **`CFXMEM`**：核内地址空间访问非法；目标 cfx 由 `addr[47:42]` 决定。
- **`CFXREG`**：cfx 寄存器访问非法（不存在的 `cg`/`rc`、权限不符）。
- **为什么分开**：两种访问的对象、检查点、恢复方式都不同；异常原因码也独立。
- **对比**：x86 的缺页 vs `#GP`/`#UD`；ARM 的 data abort vs undefined；RISC-V 的 page fault vs illegal instruction；MIPS 的 TLB 异常 vs reserved instruction；SPARC 的 data access exception vs illegal instruction；PowerPC 的 data storage vs program exception。

## 5. 为什么 reserved `cfxha` 是 ILLI，而不是“读回 0”？

**答：** 因为 reserved `cfxha` 表示“这个资源根本不存在”，执行 cfx 指令就是非法指令；读回 0 会掩盖错误，还会逼硬件为不存在的资源造一个默认寄存器组。

- **reserved 编号**：7–14、19–61。
- **ILLI 的触发**：reserved `cfxha`；cfx mask 禁止；已定义编码的非法操作数。
- **与 `CFXREG` 的区别**：`CFXREG` 是“cfx 存在，但寄存器不存在/无权限”；`ILLI` 是“cfx 本身不存在/指令非法”。
- **对比**：x86 保留 opcode → `#UD`；ARM → `UNDEFINED`；RISC-V → illegal instruction；MIPS → reserved instruction；SPARC/PowerPC → illegal instruction。

## 6. 测试机只实现 `cfx0/1/2/3/63`，是架构限制还是实现范围？

**答：** 实现范围，不是架构限制；测试机只需要 monitor + power，其他 cfx 可以不存在。

- **测试机实现**：`cfx0`/`cfx1`/`cfx2`/`cfx3`/`cfx63`（`umon`/`jmon`/`smon`/`hmon`/`power`）。
- **RAM 与复位向量**：测试机把 RAM 放在 `cfx63`（power）段；复位向量是 `cfx_power_hypv_excp_vector`。
- **缺席的 cfx**：访问不存在的 cfx 寄存器 → `CFXREG`；reserved `cfxha` → `ILLI`。
- **对比**：x86/ARM/RISC-V 的实现也只实现可选扩展的子集；CSR/MSR 的存在性是实现定义的。

## 7. cfx 扩展策略：reserved 编号怎么分配？新资源一定要新 cfx 吗？

**答：** reserved 编号是扩展位；新资源原则上 = 新 cfx（新寄存器组 + 向量 + 窗口），但不要求所有实现都实现它；扩展时要同时定义编号、`cg`/`rc`、权限、异常原因码。

- **扩展位**：7–14、19–61 reserved；新增 cfx 时按资源类别分配。
- **新资源 = 新 cfx**：不需要新 opcode；但需要规范/软件约定一起定义。
- **不要求全实现**：缺席的 cfx 访问 → `CFXREG`；reserved 编号 → `ILLI`。
- **对比**：x86 MSR/ARM system register/RISC-V CSR 的扩展也是“加编号寄存器”；cfx 额外要求资源级的窗口/向量/权限语义。

## 背景知识

### 术语与概念

- **cfx（核芯功能扩展）**：一个可独立寻址的资源对象，带自己的寄存器组、异常向量、权限位与 64 KiB 地址窗口。
- **`cfxha`**：6 位 cfx 编号，位于核内地址 `[47:42]`，也位于 cfx 指令的 `ha` 字段。
- **`cg`/`rc`**：cfx 寄存器的组号与组内编号；`cg0`–`cg7` 通用，`cg8`+ 专有。
- **monitor**：处理某一运行模式同步异常的 cfx（`umon`/`jmon`/`smon`/`hmon`）。
- **`trap`/`escape`**：进入 cfx 异常向量 / 从 cfx 异常退出。
- **核内地址空间**：48 位地址空间，高 6 位选 cfx，每个 cfx 64 KiB。

### 对照

**x86-64**：MSR 是 32 位编号的模型专用寄存器，`RDMSR`/`WRMSR` 用 ECX 选号；异常走 IDT；特权用 4 个 ring。资源没有统一的“编号 + 窗口 + 向量”语义。

**ARM64**：system register 用 `MRS`/`MSR` 访问；异常按 EL0–EL3 路由；设备多用 MMIO。EL 是权限层次，不是资源编号。

**RISC-V**：CSR 是 12 位编号；M/S/U 三种模式；设备多用 MMIO/PLIC。CSR 是“控制状态寄存器”，不是资源对象。

**MIPS**：CP0 是 5 位编号的协处理器寄存器；kernel/user 两种模式；异常走统一入口。CP0 偏“处理器控制”，不覆盖外设。

**SPARC**：ASR 是辅助状态寄存器；trap level 表示中断屏蔽层级；MMU 独立。资源分散在 ASR/MMIO。

**PowerPC**：SPR 是 10 位编号；MSR 管模式与中断；hypervisor 有独立位。资源分散在 SPR/MMIO。
