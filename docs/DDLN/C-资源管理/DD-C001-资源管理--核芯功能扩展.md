# 资源管理 -- 核芯功能扩展

**本册要点**

- 所有资源都是核芯功能扩展（cfx）：异常、地址转换、缓存、hart、物理内存、时间、设备、电源。
- 最多 **64 个**，编号就是地址高 6 位 `addr[47:42]`。
- 作用域分两段：**0–15 每核私有，16–63 全系统共享**。
- CPU 地址固定 **48 位**：`0` 是内存窗口（42 位虚拟地址），`1–63` 是各 cfx 的内部空间（各 42 位）；**`cfx0` 没有内部空间**。
- 五类错误分工明确：窗口/核内地址（`CFXMEM`）、寄存器（`CFXREG`）、保留编号（`ILLI`）、退出帧（`CFXESC`）、两轴权限（`CFXPERM`）。

## 1. 为什么资源都建模成 cfx？

**答：** 因为这样只需要一套编号、一套寄存器访问、一套异常路由、一套地址窗口，新增资源不必新增指令编码。

- **一个命名空间**：6 位编号，64 个槽。
- **一套访问方式**：`trap` / `escape` / `cfx2rd` / `cfx2rc`；普通 `ld/st` 走地址窗口。
- **一套异常路由**：每个 cfx 有自己的向量与原因表。
- **一套权限**：模式轴 × 资源轴（两轴模型）。
- **代价**：寄存器要间接访问，比直接编号多一层。

## 2. 64 个编号怎么分？

**答：** 前 16 个给每核私有的监视器与核心资源，16 之后给全系统共享的存储、时间与设备。

- **0–3**：四个模式的监视器（user / jail / supv / hypv）。
- **4**：页表步进（**TLB 也在这里**，没有独立的 TLB 编号）。
- **5**：每核缓存管理。
- **6–14**：保留。
- **15**：hart 管理（编号、周期、退休指令、本地定时器）。
- **16**：最后一级缓存（跨核共享）。
- **17**：物理存储器管理（区域 + 内部 SRAM + DMA）。
- **18**：全局时间计数器。
- **19–61**：保留。
- **62 / 63**：串口 / 电源（含启动 ROM）。

## 3. 作用域为什么要分两段？

**答：** 因为本地资源必须每核独立（否则多核互相踩），共享资源必须单份（否则一致性无从谈起）。

- **每核私有（0–15）**：监视器现场、页表开关、缓存控制、hart 计数——同一份代码在不同核上是不同实例。
- **全系统共享（16–63）**：最后一级缓存、物理内存描述、全局时间、设备——所有核看到同一份。
- **判据**：问"这个资源被两个核同时改会怎样"。
- **地址空间**：私有 cfx 的内部空间也按核区分，核内地址不跨核。

## 4. 五类错误怎么分工？

**答：** 按"访问路径"分：地址窗口错报 `CFXMEM`，寄存器访问错报 `CFXREG`，保留编号报 `ILLI`，退出帧错报 `CFXESC`，权限拒绝报 `CFXPERM`。

- **`CFXMEM`**：核内地址空间非法（窗口外、保留 cfx 的普通访存、SRAM 越界）。
- **`CFXREG`**：访问不存在或越界的 cfx 寄存器（含保留的 `cg`/`rc`、超数量的 scratch）。
- **`ILLI`**：指令本身或目标 cfx 非法（保留编号上的 `trap`/`escape`/`cfx2rd`/`cfx2rc`）。
- **`CFXESC`**：`escape` 的目标不是当前 cfx，或当前 cfx 没有有效异常帧。
- **`CFXPERM`**：两轴权限拒绝（资源掩码不允许源 cfx）。
- **为什么分开**：恢复方式不同——地址错要改映射，寄存器错要改代码，权限错要改配置。

## 5. 地址窗口怎么工作？

**答：** CPU 地址高 6 位选 cfx，低 42 位是该 cfx 内部偏移；`0` 不是 cfx，而是内存窗口，要经页表转换。

- **`addr[47:42] = 0`**：内存窗口；虚拟地址 42 位，物理地址 56 位。
- **`addr[47:42] = 1–63`**：对应 cfx 的内部空间，各 42 位，直接 `ld/st`。
- **`cfx0` 没有内部空间**：它的编号只用于陷入路由。
- **页表开关**：内存窗口是否转换由 `ptw_enable` 决定；关闭时窗口访存直接报 `CFXMEM`，**不直通物理内存**。
- **转换开关不影响 cfx 内部空间**：核内地址永远直接访问。

## 6. 扩展策略是什么？

**答：** 新资源 = 新 cfx；保留编号就是扩展位，不需要新指令编码；未实现的编号要给出确定行为。

- **保留编号**：普通 `ld/st` 报 `CFXMEM`；`trap`/`escape`/寄存器访问报 `ILLI`。
- **已分配未实现**：由实现约定行为（测试机按未实现处理）。
- **新增资源**：分配编号 + 定义 `cg8+` 专有寄存器 + 定义原因表。
- **不要复用**：编号一旦分配不复用，否则旧代码会打到新资源上。

## 背景知识

### 术语与概念

- **cfx**：核芯功能扩展，资源的最小管理单元。
- **作用域**：每核私有 / 全系统共享。
- **内存窗口**：`addr[47:42]=0` 的分区，经页表转换。
- **核内地址**：`addr[47:42]=1–63` 的分区，直接访问。
- **原因表**：每个 cfx 可处理的异常位集合。

### 对照

**资源建模**

- **cfx 模型**：统一编号 + 统一访问 + 统一异常。
- **传统模型**：CSR/MSR 分散编号 + MMIO 窗口。
- **判据**：新增资源是否需要新指令/新地址约定。
