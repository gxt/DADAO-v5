# 风险管控 -- 元风险

**本册要点**

- 保证体系最大的敌人不是"没规矩"，而是**规矩退化**：评审变签字、门控变仪式。
- **抽审**是唯一能发现退化的手段：抽样、只看证据、匿名汇总。
- **复盘**必须产出两样东西：一条判据 + 一条机械检查，否则等于没复盘。
- **度量会被博弈**：指标一旦成为目标，就会失真；所以要配对、要看趋势、不挂个人。
- **回滚与复现**属于保证的一部分：退不回去、重建不了，等于没有保证。
- 体系的演进规则要写死：加规矩要说明压什么风险，删规矩要说明为什么不再需要。

## 1. 保证体系为什么会退化成仪式？

**答：** 因为每个动作都在"时间压力"与"动作成本"之间被权衡：一旦某个动作的成本高于它压住的风险的可见代价，人就会绕过它，而绕过的第一步通常只是"这次先跳过"。

- **四种典型退化**：评审只签字、门控只跑不判、复盘只写总结、指标只求达标。
- **为什么难以察觉**：所有"形式"都还在——记录有、结论有、绿灯有。
- **加速因素**：动作太慢（被跳过）、责任不清（没人真正判）、指标绑定考核（被优化）。
- **判据**：随机抽一条规矩，问"最近它拦住过什么问题"，答不出即为退化。
- **代价**：抽审要人力；换来的是体系不会悄悄失效。

**各家做法**：

- **运维**：定期复盘真实故障，检查响应流程是否还灵。
- **航空**：独立审计，检查流程执行而非仅检查结果。
- **制造**：过程审核（工序是否按标准执行）。
- **企业**：内审 + 外审。
- **一般项目**：无抽审，退化不可见。

**是统一标准吗**：不是。

## 2. 抽审怎么做才不是抓人？

**答：** 三条原则：抽样（不针对个人）、只看证据（不评价态度）、匿名汇总（结论对体系不对人）。抽审的目的是验证"流程是否还在起作用"，不是追责。

- **抽什么**：已完成任务中的随机样本；高风险任务额外抽样。
- **看什么**：预检是否真做了、门控输出是否真跑过、证据是否真实存在、评审意见是否具体。
- **怎么判**：以"证据能否支撑结论"为标准，不看"谁做的"。
- **产出**：体系级改进项（哪一类动作系统性失效），不是个人考核。
- **频率**：里程碑级；太频繁会变成负担，太稀疏发现不了退化。

**各家做法**：

- **航空**：独立审计团队，按标准条款抽样。
- **金融**：合规抽检，结果用于流程修订。
- **制造业**：工序审核 + 纠正措施。
- **开源**：社区信任为主，少抽审。
- **一般项目**：出事后才回看。

**是统一标准吗**：不是。

## 3. 复盘怎么产出可执行改动？

**答：** 三问定因，两物落地：判断错在哪一步、当时的信号是什么、下次怎么提前发现；产出一条判据与一条机械检查，缺一不算闭环。

- **判断错在哪**：信息不足、还是信息足够但被忽略。
- **当时的信号**：哪一个可观测现象已经提示了问题。
- **下次的检查**：新增或修改哪条门控/流程。
- **落地两物**：判据（进教训台账）+ 检查（进对应层）。
- **不写什么**："大家要更仔细""加强沟通"——无法执行的话。
- **代价**：每次复盘多写两行；换来的是同类问题不再重复。

**各家做法**：

- **运维**：无指责复盘，聚焦机制改进。
- **航空/医疗**：事件报告 + 流程修订 + 跟踪验证。
- **制造**：根因分析 + 作业标准更新。
- **企业**：复盘会开完即结束，无落地。
- **一般项目**：出事后口头总结。

**是统一标准吗**：不是；但"复盘必须产出可执行改动"是共同要求。

## 4. 度量被博弈怎么办？

**答：** 三条防线：配对使用（任何单一指标都会被优化）、看趋势不看单点、指标不挂个人。再配以抽审验证数据真实性。

- **为什么会博弈**：指标一旦成为目标，行为就朝指标而非目标优化（古德哈特定律）。
- **配对示例**：通过率配逃逸缺陷；评审速度配缺陷发现率；覆盖率配变异得分。
- **不挂个人**：挂个人就必然出现"数字好看、问题照旧"。
- **抽审验证**：随机回看数据来源，防止"只记录想记录的"。
- **代价**：多维护几项指标；换来的是指标还可信。

**各家做法**：

- **运维**：错误预算用于决策，不用于个人考核。
- **制造**：质量指标与生产指标成对考核。
- **软件**：缺陷密度配逃逸率。
- **企业**：单指标考核是常见失败源。
- **一般项目**：无指标，或只有"完成率"。

**是统一标准吗**：不是。

## 5. 回滚与复现为什么算保证的一部分？

**答：** 因为"能退回去"与"能重建"是保证的最后一道：无法回滚意味着每次改动都是单向赌注；无法复现意味着结论不可复核。

- **回滚**：改动能否被安全撤销（提交粒度、特性开关、数据迁移可逆）。
- **复现**：产物能否从零重建（依赖是否锁定、构建是否确定、文档是否足够）。
- **演练**：定期做一次"回到上一版本"与"从零构建"，比写文档有效。
- **代价**：演练要时间；换来的是出事时不用即兴发挥。
- **常见缺失**：只保证"往前"，从不验证"往后"。

**各家做法**：

- **互联网**：灰度与快速回滚是发布流程的标配。
- **硬件**：不可回滚，所以前端评审最重。
- **发行版**：包可回退到旧版本，需保证依赖仍可用。
- **企业**：灾备演练定期进行。
- **一般项目**：从不演练，出事才发现退不回去。

**是统一标准吗**：不是。

## 6. 体系本身怎么演进？

**答：** 加规矩要说明"压什么风险、压不住什么"；删规矩要说明"为什么不再需要"；每条规矩都要有归属与复核时点。否则体系只会膨胀，最后被整体绕过。

- **加**：新规矩必须绑定风险类别与证据形式。
- **删**：长期零命中（且抽审确认）的规矩可以删，避免告警疲劳。
- **改**：调整阈值要记录依据（例如门控耗时趋势）。
- **归属**：每条规矩有负责人与复核周期。
- **判据**：规矩总量与人力是否匹配；不匹配就说明该合并或自动化。

**各家做法**：

- **标准组织**：规范修订有流程与版本。
- **运维**：SLO 与告警定期评审。
- **制造**：作业标准随工艺演进修订。
- **企业**：制度只增不减，最终无人遵守。
- **一般项目**：规矩随人走，人走规矩消失。

**是统一标准吗**：不是。

## 7. 实例：评审变成签字

**现象**：所有改动都有"已评审"记录，但最近半年没有任何一条评审意见导致改动；出问题回看，评审记录里只有"LGTM"。

**根因**：评审没有具体判据（看什么、判什么），也没有抽审验证它是否还在起作用。

- **规矩**：评审必须留下"查了什么、结论依据是什么"，不接受无内容通过。
- **机械防**：抽审随机回看评审记录，统计"有实质意见的比例"；过低即触发流程修订。

## 8. 实例：指标达标但问题仍在

**现象**：评审通过率、门控通过率、覆盖率全部达标，但逃逸缺陷没有下降。

**根因**：指标被单独优化（快速通过、只跑容易过的用例），没有配对指标与抽审。

- **规矩**：指标必须配对使用，且以"逃逸缺陷"作为最终判据。
- **机械防**：报告固定展示配对指标（通过率 + 逃逸率、覆盖率 + 变异得分）；抽审验证数据来源。

## 背景知识

### 术语与概念

- **元风险**：保证体系自身失效带来的风险。
- **抽审**：随机回看已完成任务，验证流程是否仍在起作用。
- **无指责复盘**：聚焦机制而非个人的事后分析。
- **古德哈特定律**：指标成为目标后即失真。
- **配对指标**：互相制约、需同时看的两个指标。
- **回滚**：把系统退回到上一个可用状态。
- **复现**：从零重建产物与结论。
- **残余风险**：采取对策后仍存在的风险。

### 对照

**抽审形态**

- **强**：随机抽样 + 只看证据 + 匿名汇总。
- **弱**：针对个人检查，导致掩盖。
- **频率**：里程碑级为宜。

**复盘落地**

- **闭环**：判据 + 机械检查。
- **半闭环**：只有判据，没有检查。
- **不闭环**：只有会议纪要。

**度量防博弈**

- **强**：配对 + 趋势 + 不挂个人 + 抽审。
- **弱**：单指标 + 个人考核。
