# 指令系统 -- 控制流

**本册要点**

- 分支用相对地址；偏移左移 2 位。
- `br.eq`/`br.ne`：两寄存器比较，±8 KiB。
- `br.n/nn/z/nz/p/np`：六种条件，±512 KiB；`br.z/nz` 有 `rb` 变体。
- `jump`/`call`：相对（±32 MiB）与绝对（基址+变址+偏移）。
- `call` 压入 RAS，`ret` 弹出；RegRAS 63 槽 + MemRAS。
- `call` 返回地址 = `IP + 4`；`ret` 可能从 MemRAS 取；`rb` 变体按整 64 位判零。
- `ra0`：`RACNT` + `MRPTR`。
- RASOF/RASUF；递归折叠。
- `ret rd, imm` 带返回值；RAS 与数据栈分离。

## 1. 为什么分支指令都用相对地址？

**答：** 因为相对地址让代码位置无关、不需要重定位，而且 4 字节对齐让偏移的低 2 位可以省掉，用同样的位宽换更大的跳转范围。

- **位置无关**：分支目标写成"相对当前 IP 的偏移"，代码段整体搬到哪里都能用，链接器不需要为每条分支做重定位。
- **省 2 位**：指令 4 字节对齐，偏移低 2 位恒为 0；编码里不存，执行时左移 2 位（`imms12/18/24 << 2`），范围扩大 4 倍。
- **范围分级**：`br.eq`/`br.ne` 用 12 位偏移（±8 KiB）；`br.n`/`br.nn`/`br.z`/`br.nz`/`br.p`/`br.np` 用 18 位偏移（±512 KiB）；`jump`/`call` 用 24 位偏移（±32 MiB）。
- **地址计算**：`Addr = rb0 + (imms << 2)`，64 位计算后写回 `rb0`，取低 48 位作为下一条地址。
- **对比**：x86 的分支也是相对偏移（变长编码）；ARM 的 `B` 是 26 位相对偏移；RISC-V 的 `jal` 是 20 位相对偏移。相对分支是 RISC 的通用做法。
- **各家做法**：x86 `jmp rel8/rel32`；ARM64 `B`/`BL` 26 位（±128 MiB）、`B.cond` 19 位（±1 MiB）；RISC-V `jal` 20 位（±1 MiB）、`beq` 12 位（±4 KiB）；MIPS `beq` 16 位（±128 KiB）；SPARC/PowerPC 的 22/24 位偏移。
- **为什么用相对**：位置无关、无需重定位；4 字节对齐省 2 位；代价是范围有限。

## 2. 为什么单独设 br.eq/br.ne？

**答：** 因为"两个寄存器相等/不等"是最常见的分支形态，单独设两条指令可以用更短的编码、也更贴近编译器的输出。

- **占比高**：COD（Computer Organization and Design）P226 指出，`br.eq` 和 `br.ne` 这两条指令的占比约 **7.4%**。
- **两寄存器比较**：`br.eq {rdHA, rdHB}?, [rb0, imms14]` 直接比较两个 `rd`，不需要先 `cmp` 再 `br.z`，省一条指令。
- **编码更短**：12 位偏移（±8 KiB）对条件分支通常够用；比 18 位偏移少占 6 位，可以多放一个寄存器字段。
- **与 `cmp` + `br.z` 并存**：三路比较（小于/等于/大于）仍用 `cmp` + `br.n`/`br.z`/`br.p`；`br.eq`/`br.ne` 只覆盖"相等/不等"这一高频特例。
- **各家做法**：x86 `cmp` + `je`/`jne`（两条）；ARM64 `CBZ`/`CBNZ`（一条，寄存器与 0）；RISC-V `beq`/`bne`（一条，两寄存器）；MIPS `beq`/`bne`（一条）。
- **为什么 SimRISC 单独设**：没有标志位，`cmp`+`br.z` 要两条；`br.eq/ne` 把比较融进分支。

## 3. 为什么条件只有 N/NN/Z/NZ/P/NP 六种？

**答：** 因为比较结果被编码成 -1/0/1，六种条件正好覆盖"负/非负/零/非零/正/非正"，不需要 CZSO 的进位/溢出组合。

- **六种条件**：`br.n`（负）、`br.nn`（非负）、`br.z`（零）、`br.nz`（非零）、`br.p`（正）、`br.np`（非正）。
- **对 -1/0/1 的完备划分**：-1 是负、0 是零、+1 是正；非负 = 0 或 +1，非正 = -1 或 0，非零 = -1 或 +1。
- **没有进位/溢出条件**：地址/整数溢出由软件用高 16 位或双目的高半判断，不需要 `jc`/`jo` 这类条件。
- **`rb` 变体**：`br.z`/`br.nz` 另有 `rb` 形式，按整 64 位判零；其余四种条件只有 `rd` 形式。
- **`rd0` 特例**：`br.z rd0` 条件恒真、`br.nz rd0` 条件恒假——`rd0` 读出 0，正好是"无条件跳转/永不跳转"的简写。
- **对比**：x86/ARM 的条件码有十几到二十种组合（等于、不等、大于、小于、进位、溢出……）；SimRISC 只有六种，靠"比较结果就是值"来覆盖。
- **各家做法**：x86 `jcc` 用 EFLAGS 组合；ARM64 `B.cond` 用 NZCV；RISC-V 用 `beq`/`bne`/`blt`/`bge` 比较两寄存器；MIPS 用 `beq`/`bne` + `slt`；SPARC `b<cond>` 用 icc；PowerPC `bc` 用 CR。
- **为什么只有六种**：比较结果是 -1/0/1，六种条件完备；没有进位/溢出条件。

## 4. 为什么 jump/call 同时支持相对和绝对两种形式？

**答：** 因为函数内跳转用相对地址（位置无关、范围大），跨模块/间接跳转用绝对地址（基址 + 变址 + 偏移），两种场景都需要。

- **相对形式**：`jump [rb0, imms26]`、`call [rb0, imms26]`，编码 24 位偏移左移 2 位，范围 ±32 MiB；适合函数内和模块内跳转。
- **绝对形式**：`jump [rbHA, rdHB, imms14]`、`call [rbHA, rdHB, imms14]`，地址 = `rbHA + rdHB + (imms12 << 2)`；`rbHA` 只读，不修改。
- **`rb0` 特例**：当 `rbHA` 是 `rb0` 时，绝对形式退化成"IP + 变址 + 偏移"，仍是相对跳转——两种形式共用同一套编码。
- **间接跳转**：把目标地址算进 `rdHB`（如跳转表、函数指针），用绝对形式一条完成。
- **对比**：x86 的 `jmp rel`/`jmp r/m`、ARM 的 `B`/`BR`、RISC-V 的 `jal`/`jalr` 都是"相对 + 间接"两类；SimRISC 把间接形式做成"基址 + 变址 + 偏移"。
- **各家做法**：x86 `jmp rel8/rel32` + `jmp r/m`；ARM64 `B`/`BR`/`BL`/`BLR`；RISC-V `jal`/`jalr`；MIPS `j`/`jal`/`jr`；SPARC `ba`/`jmpl`；PowerPC `b`/`bcctr`/`bclr`。
- **为什么两种都保留**：模块内用相对（位置无关、范围大）；间接/跨模块用绝对（基址+变址+偏移）。

## 5. 为什么 call/ret 用返回地址栈（RAS），而不是让软件保存返回地址？

**答：** 因为把返回地址从"软件保存/恢复"变成"硬件 call/ret 自动维护"，省访存、省高速缓存污染，也更不容易跑飞。

- **调用/返回自动压弹**：`call` 压入返回地址，`ret` 弹出；函数序言/尾声不再需要保存恢复返回地址，减少函数序言/尾声的整理工作和访存。
- **寄存器栈 + 内存栈**：`ra1`–`ra63` 是 63 槽的 RegRAS；`ra0` 的 `MRPTR` 指向 MemRAS（内存栈）。调用深度不超过 63 层时只用 RegRAS；超过时把最旧的条目溢出到 MemRAS。
- **大部分应用用 RegRAS 就够**：63 个槽位足以覆盖绝大多数程序的调用深度，MemRAS 只是深调用/互递归时的兜底。
- **与数据栈分离**：返回地址不会被数据溢出或错误写坏；出错时表现为数据错误，而不是取回错误返回地址导致控制流"跑飞"。
- **硬件实现**：架构上是 `ra1`–`ra63` 的软件可见视图，但实现不必逐条搬移——可用环形缓冲 + 隐藏的基准索引完成压栈/弹栈；软件访问 `ra_i` 时按基准索引换算，保持架构视图一致。
- **对微架构友好**：返回地址栈天然适合返回地址预测等优化。
- **各家做法**：x86 `call` 把返回地址压数据栈（微架构有 RSB）；ARM64 `BL` 写 `LR`（x30）；RISC-V `jal`/`jalr` 写 `ra`（x1）；MIPS `jal` 写 `ra`（r31）；SPARC `call` 写 `o7`；PowerPC `bl` 写 `LR`。
- **为什么 SimRISC 用硬件 RAS**：省掉序言/尾声的保存恢复与访存；代价是 RAS 状态与溢出处理。

## 6. ra0 里存了什么？为什么需要它？

**答：** `ra0` 是 RAS 的状态字：`RACNT` 记录 RegRAS 的有效条目数，`MRPTR` 记录 MemRAS 的栈顶地址；没有它，硬件就不知道"栈里有多少条、内存栈在哪"。

- **`ra0[53:48]` = `RACNT`**：RegRAS 有效条目数（0–63）。有效性判据是 `RACNT`，不是看条目自身的值。
- **`ra0[47:0]` = `MRPTR`**：MemRAS 栈顶地址（8 字节对齐）。`MRPTR == 0` 表示不启用 MemRAS，只有 RegRAS，超过 63 层触发 RASOF，由程序自己处理；`MRPTR != 0` 表示 MemRAS 已事先分配，硬件自动压栈/弹栈维护。
- **`ra0[63:54]` = SBZ**（写无效）。
- **对比其它 ISA**：其它 ISA 的 `call`/`ret` 只处理单个返回地址，嵌套调用由编译器在函数序言/尾声保存/恢复；SimRISC 用 RAS 统一管理多层返回地址，`ra0` 是这个管理的状态字。
- **进程切换**：保存/恢复 `ra0`–`ra63` 就保存/恢复了整个 RAS 状态。
- **各家做法**：x86 用数据栈 + RSP；ARM64 用 `LR`（x30）；RISC-V 用 `ra`（x1）；MIPS 用 `ra`（r31）；SPARC 用 `o7`；PowerPC 用 `LR`；都没有软件可见的 `ra0` 状态字。
- **为什么需要 ra0**：硬件要知道有效条目数与 MemRAS 栈顶；放在 0 号槽，进程切换一次保存/恢复。

## 7. RAS 为什么会溢出？

**答：** 因为 RAS 是有限的硬件栈——调用深度超过容量会上溢，返回地址不够弹时会下溢；两者同样重要。

- **上溢（RASOF）**：`call` 要压栈但没有地方放。RegRAS 只有 63 个槽；`RACNT == 63` 且 `MRPTR == 0` 时触发 RASOF。
- **下溢（RASUF）**：`ret` 要弹栈但没有有效条目。`RACNT == 0` 且 `MRPTR == 0` 时触发；或启用了 MemRAS、但 MemRAS 条目的递归计数为 0 时触发。
- **即使启用了 MemRAS，上溢/下溢仍会发生**：MemRAS 是事先分配的内存区，容量有限，耗尽后仍会上溢（硬件不检测，交给 OS 处理）；下溢则按 MemRAS 条目的判定照常触发。
- **软件介入分两种情况**：没有 MemRAS（`MRPTR == 0`）时，程序要自己维护返回地址——上溢时把返回地址存到其它的数据区，下溢时从其它的数据区恢复或报错；有 MemRAS（`MRPTR != 0`）时，常规压弹由硬件完成，软件只在 MemRAS 容量耗尽（硬件不检测，交 OS）或 MemRAS 条目判定为下溢时介入。
- **各家做法**：x86 的返回地址在数据栈上，溢出由栈保护/OS 处理；ARM64/RISC-V/MIPS 的 `LR`/`ra` 由软件在序言/尾声保存，深调用由数据栈承载；SimRISC 的 RASOF/RASUF 是架构异常。
- **为什么 SimRISC 用异常**：RAS 是硬件栈，溢出/下溢必须让软件知道；否则会静默取错返回地址。

## 8. 为什么 ret 要带返回值赋值？

**答：** 因为函数返回时经常要"设置返回值 + 返回"，把两件事合成一条指令，省一条指令、也省一个返回路径上的寄存器写。

- **形式**：`ret rdHA, imms18`——弹出返回地址并跳转，同时把 18 位有符号立即数符号扩展后写进 `rdHA`。
- **典型用法**：返回值寄存器放 0 或 -1，`ret rd1, 0` / `ret rd1, -1` 一条完成 `return 0` / `return -1`。
- **不需要返回值**：`ret rd0, 0` 表示普通返回；`rd0` 是只读的，所以立即数必须为 0，否则非法（汇编期报错，运行期 ILLI）。
- **对比**：x86/ARM/RISC-V 的返回指令只负责跳转，返回值要单独 `mov`；SimRISC 把返回值写和返回合并，减少返回路径上的指令。
- **各家做法**：x86 `ret`（可带 `pop` 返回值）；ARM64 `RET`；RISC-V `jalr x0, ra, 0`；MIPS `jr ra`；SPARC `retl`/`jmpl`；PowerPC `blr`；返回值都要单独的 `mov`。
- **为什么 SimRISC 合并**：返回路径上少一条指令；`ret rd0, 0` 保留普通返回。

## 9. 为什么需要递归折叠？

**答：** 因为递归调用（尤其是 P 调 Q、Q 又调 P 的互递归）会反复压入相同的返回地址，快速耗尽 63 个槽；折叠让相同地址只占一个槽、用高 16 位计数。

- **递归计数**：`ra` 条目的 `[63:48]` 是递归计数，`[47:0]` 是返回地址；首次压栈计数为 1，递归调用递增。
- **折叠条件**：返回地址相同且递归计数未满时，只增加高 16 位的计数，不重复压栈，节省槽位。
- **互递归的限制**：P 调 Q、Q 又调 P 时，返回地址在两个值之间交替变化，折叠不生效，RegRAS 消耗更快，更容易用到 MemRAS。
- **代价**：计数只有 16 位，超过 65535 层仍要另想办法；但绝大多数递归深度远小于此。
- **对比**：x86/ARM/RISC-V 的返回地址由软件保存，没有架构可见的递归计数；SimRISC 把它做成 `ra` 条目的高 16 位，硬件可以直接利用。
- **各家做法**：x86 的 RSB 只做预测，不压缩重复地址；ARM64/RISC-V/MIPS 的 `LR`/`ra` 由软件保存，深递归落数据栈；SimRISC 用硬件递归计数折叠。
- **为什么 SimRISC 做折叠**：RegRAS 只有 63 槽；递归/互递归会快速耗尽，折叠能显著延长 RegRAS 的覆盖深度。

## 10. 为什么把 RAS 和数据栈分成两个栈？

**答：** 因为返回地址和数据混在一个栈里时，数据溢出或错误写会破坏返回地址，导致控制流"跑飞"；分成两个栈，错误表现为数据错误，而不是跳到未知地址。

- **数据栈**：局部变量、参数、保存的寄存器；由软件用 `add.si` 移动栈指针维护。
- **返回地址栈**：`ra` 组 + MemRAS；由硬件 `call`/`ret` 自动维护。
- **错误隔离**：数据写坏只影响数据；返回地址链仍然正确，程序不会因为一个缓冲区溢出就跳到任意地址。
- **调试友好**：返回地址栈可以独立观察调用链，便于回溯。
- **代价**：多一个栈的存储与状态（`ra0`），上下文切换要保存/恢复 `ra` 组。
- **各家做法**：x86 返回地址与数据同栈；ARM64 `LR`/RISC-V `ra`/MIPS `ra` 由软件保存到数据栈；SPARC 用寄存器窗口 + 数据栈；PowerPC `LR` 由软件保存。
- **为什么 SimRISC 分离**：返回地址链不被数据溢出破坏；错误表现为数据错误，不会跑飞。

## 11. call 的返回地址是什么？ret 一定从 ra63 取吗？

**答：** `call` 的返回地址是 `IP + 4`（下一条指令）；`ret` 的来源不一定是最顶层的 `ra63`，取决于 `RACNT`/`MRPTR` 的状态。

- **call 的返回地址**：指令固定 4 字节，`call` 把 `IP + 4` 作为返回地址；压栈时写成 `{递归计数, 返回地址}`，返回地址在 `[47:0]`、计数在 `[63:48]`。
- **ret 的来源**：`RACNT > 0` 时从 RegRAS 栈顶（`ra63`）弹出；`RACNT == 0` 且 `MRPTR != 0` 时从 MemRAS 栈顶读条目（D4b）；两者都没有则 RASUF。
- **精确异常**：压/弹栈先完成 `RASOF`/`RASUF` 判定，再修改 RA 寄存器或 MemRAS；异常时状态保持原状。
- **返回值**：`ret rdHA, imms18` 同时把符号扩展的 18 位立即数写进 `rdHA`；`rdHA = rd0` 时立即数必须为 0。
- **各家做法**：x86 `call` 把下一条 IP 压数据栈；ARM64 `BL` 写 `LR`（下一条指令地址）；RISC-V `jal`/`jalr` 写 `ra`；MIPS `jal` 写 `ra`；SPARC `call` 写 `o7`；PowerPC `bl` 写 `LR`。
- **为什么 SimRISC 用 IP+4**：指令固定 4 字节；IP 指当前指令，返回地址自然是下一条。

## 背景知识

### 术语与概念

- **相对寻址 / 绝对寻址**：目标地址由"当前 IP + 偏移"给出，或由"基址 + 变址 + 偏移"给出。
- **位置无关代码（PIC）**：不依赖绝对地址的代码，整体搬家后仍可运行。
- **返回地址栈（RAS）**：硬件维护的后进先出栈，`call` 压入、`ret` 弹出。
- **RegRAS / MemRAS**：寄存器实现的返回地址栈（`ra1`–`ra63`）/ 内存中的溢出栈（由 `MRPTR` 指向）。
- **RASOF / RASUF**：RAS 上溢（压栈时没有空槽）/ 下溢（弹栈时没有有效条目）。
- **递归折叠**：相同返回地址只占一个槽，用高 16 位计数表示重复次数。
- **函数序言/尾声（prologue/epilogue）**：函数入口/出口保存恢复寄存器、调整栈指针的代码。
- **延迟槽（delay slot）**：分支/跳转后的一条指令槽；SimRISC 不设延迟槽。

### 对照

**返回地址的保存方式**

- **x86-64**：`call` 把返回地址压入**数据栈**，`ret` 从数据栈弹出；没有独立 RAS（微架构有 RSB 预测）。
- **ARM64**：`BL` 把返回地址写入 `LR`（x30）；嵌套调用由序言/尾声保存 `LR` 到数据栈。
- **RISC-V**：`jal`/`jalr` 把返回地址写入 `ra`（x1）；嵌套调用由软件保存。
- **MIPS**：`jal` 写 `ra`（r31），有分支延迟槽。
- **SPARC**：`call` 写 `o7`，配合寄存器窗口。
- **PowerPC**：`bl` 写 `LR`。
- **SimRISC**：`call` 压入 RAS（`ra63`），`ret` 弹出；63 槽 RegRAS + MemRAS 溢出。

**分支偏移范围**

- **x86-64**：`jmp rel8/rel32`、`jcc rel8/rel32`；范围随编码变化。
- **ARM64**：`B`/`BL` 26 位偏移（±128 MiB）；`CBZ`/`CBNZ` 19 位（±1 MiB）；`B.cond` 19 位。
- **RISC-V**：`jal` 20 位偏移（±1 MiB）；`beq` 等 12 位（±4 KiB）。
- **MIPS**：`beq` 16 位偏移（±128 KiB）；`j` 26 位目标。
- **SimRISC**：`br.eq`/`br.ne` 12 位（±8 KiB）；`br.*` 18 位（±512 KiB）；`jump`/`call` 24 位（±32 MiB）。

**条件分支的条件来源**

- **x86 / ARM**：条件码/标志位（ZF/SF/CF/OF 或 NZCV）。
- **RISC-V**：`beq`/`bne`/`blt`/`bge` 等直接比较两个寄存器。
- **MIPS**：`beq`/`bne` 比较两个寄存器；`slt` + `bne` 做大小比较。
- **SimRISC**：`cmp` 产生 -1/0/1，`br.n/nn/z/nz/p/np` 读这个值；`br.eq`/`br.ne` 直接比较两个寄存器。
