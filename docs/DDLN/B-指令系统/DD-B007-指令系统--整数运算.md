# 指令系统 -- 整数运算

**本册要点**

- `.s`/`.u` 决定高位扩展，不是标志位。
- 64 位加减/乘法用双目的 `{rdHA, rdHB}` 给 128 位结果。
- 窄宽度（8/16/32）运算：只算低位，结果扩展到 64 位。
- `cmp` 结果 -1/0/1；-1 统一为 64 位全 1（不按 `.u` 零扩展），供六种条件使用。
- 乘法：64 位给 128 位；窄宽度给 64 位单目的。
- 除零/溢出返回定值；有符号除法向零截断。
- `add.si`：18 位立即数自增/自减，全 64 位。

## 1. 取消 CZSO 之后，为什么加减还要分有符号和无符号？

**答：** 因为 `.s`/`.u` 不再是为了产生标志位，而是为了决定**结果的高位怎么填**：64 位加减用两个目的寄存器给出 128 位结果，窄宽度加减要把结果扩展到 64 位。

- **64 位加减**：`add.so`/`sub.so` 把源按符号扩展（SX）到 128 位，`rdHA` 是高 64 位；`add.uo`/`sub.uo` 把源按零扩展（ZX）到 128 位，`rdHA` 是进位/借位（0 或 1）。同一组操作数，选哪个变体取决于"高半部分要当什么用"。
- **窄宽度加减**：`add.st`/`add.ut`、`add.sw`/`add.uw`、`add.sb`/`add.ub` 只算低 32/16/8 位，结果分别按符号/零扩展写满 64 位——这就是 C 的 `int`/`unsigned` 语义。
- **没有标志位可依赖**：没有 CZSO，溢出不能从"标志寄存器"读，只能由 `.s`/`.u` 变体直接给出正确的高半部分或扩展结果。
- **对比**：x86 的 `add` 同时产生结果和 EFLAGS，符号性由后续 `jo`/`jc` 解释；SimRISC 把符号性放进指令后缀，结果本身就是完整的值。
- **各家做法**：x86 用 EFLAGS 的 CF/OF；ARM64 用 NZCV；RISC-V 没有标志位（进位用 `sltu` 比较结果与操作数）；MIPS 的 `add` 溢出陷入、`addu` 不陷入；SPARC 用 `icc`、PowerPC 用 `CR` 条件码。
- **为什么 SimRISC 用 `.s`/`.u` 变体**：没有标志位，进位/高半必须由结果直接给出；`.s`/`.u` 决定源的扩展方式，而不是为条件码服务。

## 2. 为什么加减的目的要写成两个寄存器（{rdHA, rdHB}）？

**答：** 因为 64 位加减的完整结果有 65 位（进位/借位）或 128 位（符号扩展的高半），一个 64 位目的装不下；两个目的寄存器让"要不要高半"由寄存器选择决定。

- **布局**：`add.so {rdHA, rdHB}, rdHC, rdHD`——`rdHA` 存高 64 位，`rdHB` 存低 64 位。
- **丢弃高半**：`{rd0, rdHB}` 只要低 64 位，等价于普通 64 位加法；`{rdHA, rd0}` 只要高半（进位/高 64 位）。
- **合法性**：两个目的可以有一个是 `rd0`，但不能同时为 `rd0`，也不能是同一个非 `rd0` 寄存器；否则触发 ILLI。
- **读后写**：硬件先读全部源操作数再写结果，源被覆盖前其值已捕获，行为确定。
- **对比**：x86 用 EFLAGS 的 CF/OF 保存进位/溢出，MIPS 用 HI/LO 保存乘除结果；SimRISC 用"第二个目的寄存器"统一表达，不引入隐藏状态。
- **各家做法**：x86 `mul` 给 RDX:RAX；ARM64 `MUL` 低 64 + `UMULH`/`SMULH` 高 64；RISC-V `mul`/`mulh`/`mulhu`/`mulhsu` 分四条；MIPS `mult`/`multu` 写 HI:LO；SPARC/PowerPC 用 HI/LO 或专用高位指令。
- **为什么 SimRISC 用双目的**：不引入 HI/LO 隐藏状态；两个目的可任选丢弃一半；代价是 `rrrr` 编码和寄存器堆端口。

## 3. 为什么 64 位之外还要 8/16/32 位运算？

**答：** 因为 C 的整数类型有宽度，窄宽度运算要按类型语义截断并扩展；如果只有 64 位运算，编译器就得在每次运算后补一条扩展/截断指令。

- **值语义**：`add.st`/`add.ut` 只算低 32 位，结果按符号/零扩展写满 64 位；16/8 位同理。高位不是"保留"，而是明确按后缀扩展。
- **对应 C 类型**：`char`/`short`/`int` 的加减乘除、比较都能一条指令完成，不需要额外的 `ext` 指令。
- **溢出静默丢弃**：窄宽度运算溢出部分直接丢弃，符合 C 的无符号回绕/有符号实现定义行为（本 ISA 给出确定的位模式）。
- **`ext` 仍然保留**：64 位的 `ext.uo`/`ext.so` 用于把任意起始位扩展；32/16/8 位的 `ext.ut`/`ext.st` 已删除，因为窄宽度运算本身已经带扩展语义。
- **代价**：指令数量随宽度翻倍（每个宽度一套 add/sub/mul/div/rem/cmp/shift），但换来"一条指令对应一个 C 运算"。
- **各家做法**：x86 用 `movsx`/`movzx`；ARM64 用 `SXTB`/`UXTB` 等；RISC-V 用 `sext.b`/`zext.b`（Zbb）或移位对；MIPS 用 `seb`/`seh`。
- **为什么 SimRISC 把宽度放进指令**：每条窄宽度运算自带截断/扩展，省掉单独的扩展指令；代价是指令数随宽度翻倍。

## 4. 为什么比较指令的结果是 -1/0/1，而不是条件码？

**答：** 因为 -1/0/1 把"小于/等于/大于"三种关系编码成一个普通数值，后续用 N/NN/Z/NZ/P/NP 六种条件直接判断，不需要标志寄存器。

- **三路结果**：`cmp.si`/`cmp.ui`（12 位立即数）、`cmp.so`/`cmp.uo`（寄存器）以及 `.st`/`.ut`、`.sw`/`.uw`、`.sb`/`.ub` 都把结果 -1/0/1 写满目的寄存器。
- **六种条件**：负数（N）、非负（NN）、零（Z）、非零（NZ）、正数（P）、非正（NP）；`br.n`/`br.nn`/`br.z`/`br.nz`/`br.p`/`br.np` 直接读这个结果。
- **比较就是一次减法**：`cmp` 不产生副作用，结果可以保存、复用、参与运算；没有"标志位被后续指令覆盖"的问题。
- **对比**：x86/ARM 的比较只设置标志位，结果本身不保留；RISC-V 用 `slt`/`sltu` 产生 0/1，SimRISC 用 -1/0/1 直接区分三路。
- **各家做法**：x86/ARM 用标志位；RISC-V 用 `slt`/`sltu` 产生 0/1；MIPS 用 `slt`/`sltu` + 分支；SPARC 用 `icc`、PowerPC 用 `CR`。
- **为什么 SimRISC 用 -1/0/1**：三值直接对应 `<`/`=`/`>`，六种条件只看符号/零；代价是比较结果占一个完整寄存器。

## 5. 为什么 cmp.ut/cmp.uw/cmp.ub 的 -1 是 64 位全 1，而不是按 .u 零扩展？

**答：** 因为比较结果是三值编码（-1/0/1），不是"该宽度的整数值"；`-1` 必须保持 64 位负数形态，后续 `br.n` 才能判出"小于"。

- **三值编码**：比较只回答"小于/等于/大于"，结果固定为 -1/0/1；与操作数是 8/16/32/64 位无关。
- **零扩展的后果**：若 `cmp.ut` 的 -1 按 32 位零扩展，得到 `0x0000_0000_FFFF_FFFF`，bit63=0；`br.n` 会判"非负"、`br.p` 会判"正"，条件分支全错。
- **统一写满 64 位**：所有 `cmp.*` 的 -1 都写 `0xFFFF_FFFF_FFFF_FFFF`，0 写 0，+1 写 1；这样六种条件（N/NN/Z/NZ/P/NP）对任何宽度都成立。
- **与算术的区别**：`add.st`/`add.ut` 等算术结果要保留"该宽度的值"，所以按 `.s`/`.u` 符号/零扩展；比较结果是"关系标记"，不按宽度扩展。
- **`.u` 只影响比较**：`.u` 决定两个源按无符号解释（例如 32 位下 `0xFFFF_FFFF > 0`），不影响结果 -1 的编码。
- **代价**：比较结果不能直接当"该宽度的 -1"用；需要宽度语义时，软件自行截断/掩码。
- **各家做法**：x86/ARM 比较只置标志位，不产生 -1；RISC-V `slt`/`sltu` 产生 0/1；MIPS `slt` 产生 0/1；SPARC/PowerPC 用条件码。
- **为什么 SimRISC 选 -1/0/1**：三值编码让 `br.n`/`br.z`/`br.p` 直接可用，不需要额外的 `slt` + 分支。

## 6. 为什么乘法的结果要 128 位？

**答：** 因为两个 64 位数相乘的精确积是 128 位；给出完整积，多精度乘法、除法和高精度库才能一条指令拿到全部位。

- **布局**：`mul.so`/`mul.uo` 用 `{rdHA, rdHB}` 存 128 位结果，`rdHA` 高 64 位、`rdHB` 低 64 位。
- **只要低半**：`{rd0, rdHB}` 等价于普通 64 位乘法；`{rdHA, rd0}` 取高半（相当于 `mulhu`/`mulhs`）。
- **窄宽度乘法**：`mul.st`/`mul.ut`、`mul.sw`/`mul.uw`、`mul.sb`/`mul.ub` 只有一个 64 位目的——两个 32 位数之积不超过 64 位，不需要第二个目的。
- **合法性**：双目的规则与加减相同（可有一个 `rd0`，不能同时 `rd0`、不能同寄存器）。
- **对比**：MIPS 用 HI/LO 两个隐藏寄存器存积；RISC-V 用 `mul`/`mulh`/`mulhu`/`mulhsu` 多条指令；SimRISC 用双目的一条指令覆盖低半和高半。

## 7. 为什么除零和除法溢出返回定值，而不是触发异常？

**答：** 因为整数没有 Inf/NaN，除零必须由 ISA 约定一个结果；SimRISC 选"定值 + 不陷入"，与 x86 的陷阱、ARM 的 0、RISC-V 的全 1 都不同，取舍在"确定性/简单"与"可诊断/可恢复"之间。

- **SimRISC**：有符号 `div` 除零 → 全 1（-1）；无符号 → 全 1（该宽度最大值）；`rem` → 被除数；`INT_MIN ÷ −1` → `INT_MIN`，`rem` → 0；不陷入、无状态位。
- **x86-64**：`div`/`idiv` 除零 → `#DE`（divide error）异常，由 OS/语言运行时处理；错误不会被静默，但精确异常路径与恢复复杂。
- **ARM64**：`SDIV`/`UDIV` 除零 → 0，不陷入；实现简单，但 0 与真实商 0 无法区分，软件要先检查除数。
- **RISC-V**：`div`/`divu` 除零 → 全 1（最大值），`rem`/`remu` → 被除数；不陷入；全 1 是可识别的哨兵值。
- **MIPS**：`DIV`/`DIVU` 除零结果未定义，软件需先检查；不提供统一定值。
- **SPARC / PowerPC**：SPARC V8 的整数除零触发 `division_by_zero` 陷阱；PowerPC 的 `divw`/`divwu` 除零结果未定义，`OE=1` 时置 `XER[OV]`/`SO`、不陷入。
- **为什么 SimRISC 选定值**：没有精确异常路径，模拟器/FPGA 简单；结果确定，软硬件容易对齐；C 的整数除零是未定义行为，ISA 层"定值化"不违背语言语义。
- **代价**：软件要自己检查除零/溢出；不同语言运行时要把定值映射回自己的语义。

## 8. 为什么需要 add.si 这种"寄存器 + 18 位立即数"的自增指令？

**答：** 因为栈指针、循环计数、结构体指针的调整都是"加一个小常数"，一条 18 位立即数指令比"先装立即数再相加"省一条指令、也省一个临时寄存器。

- **全 64 位运算**：`add.si rdHA, imms18` 把 18 位有符号立即数符号扩展后与寄存器相加，结果写回同一寄存器；立即数是补码，所以加减共用一条。
- **没有 push/pop**：栈指针就靠 `add.si` 显式加减；`add.si rbHA, imms18` 对应 RB 组。
- **不能单独判溢出**：`add.si` 只给结果；需要进位/溢出时用 `add.uo`/`add.so` 的 rrrr 形式。
- **范围**：18 位有符号立即数覆盖 −131072..131071，足够大多数局部调整；更大的偏移用多条或先算到寄存器。
- **对比**：x86 的 `add r, imm32`、ARM 的 `ADD Rd, Rn, #imm12` 都是同类思路；SimRISC 把它做成独立格式 `riii`。
- **各家做法**：x86 `add r, imm32`；ARM64 `ADD Rd, Rn, #imm12`（可带移位）；RISC-V `addi rd, rs, imm12`；MIPS `addiu rt, rs, imm16`；SPARC/PowerPC 的立即数加法。
- **为什么 SimRISC 用 18 位**：6 位字段 + 12 位扩展，覆盖 ±128 KiB，足够栈指针/结构体偏移；更大的偏移用多条或先算到寄存器。

## 9. 为什么窄宽度乘法不需要 128 位结果？

**答：** 因为两个 32/16/8 位数之积最多 64/32/16 位，一个 64 位目的寄存器就装得下，扩展规则由 `.s`/`.u` 后缀决定。

- **32 位**：两个 32 位数之积 ≤ 64 位，`mul.st`/`mul.ut` 写一个 64 位目的。
- **16/8 位**：积分别 ≤ 32/16 位，仍写 64 位目的，高位按符号/零扩展。
- **与 64 位乘法的区别**：只有 `mul.so`/`mul.uo` 需要 `{rdHA, rdHB}` 双目的；窄宽度不需要。
- **一致性**：加减、乘除在窄宽度上遵循"只算低位、结果扩展到 64 位"；比较结果则统一按 64 位三值编码（-1 为全 1）。
- **各家做法**：x86 `mul` 按操作数宽度给 RDX:RAX 或 DX:AX；ARM64 `MUL` 低 64（窄宽度用 W 寄存器）；RISC-V `mul`/`mulw`；MIPS `mult`/`multu` 写 HI:LO；窄宽度都不需要 128 位目的。
- **为什么 SimRISC 单目的**：窄宽度积 ≤ 64 位；只有 64×64 才需要双目的。

## 背景知识

### 术语与概念

- **补码（two's complement）**：用"取反加一"表示负数；同一套加法硬件对有符号/无符号的低位结果相同，差别在高位的解释。
- **进位/借位（carry/borrow）**：无符号加减超出 64 位时产生的第 65 位；SimRISC 把它放在 `rdHA`。
- **符号扩展 / 零扩展**：把窄值扩展到 64 位时，高位填符号位或填 0。
- **值语义**：指令结果写满整个目的寄存器（按后缀扩展），而不是"只写低位、高位保留"；比较结果是例外——统一写 -1/0/1 的 64 位编码。
- **截断（truncation）**：窄宽度运算丢弃超出该宽度的位。
- **truncate-toward-zero**：有符号除法向零截断，余数符号与被除数一致（C99 规定）。
- **多精度运算**：用多条"带进位/借位"的加减拼出大于 64 位的运算；`add.uo`/`sub.uo` 的 `rdHA` 就是为此准备。

### 对照

**加减的进位/溢出表达**

- **x86-64**：结果 + EFLAGS（CF 进位、OF 溢出、SF/ZF 等）。
- **ARM64**：结果 + NZCV 标志；`ADDS`/`SUBS` 才更新标志。
- **RISC-V**：没有标志位；需要进位用 `sltu` 比较结果与操作数。
- **MIPS**：普通 `addu` 不陷入，`add` 溢出陷入；没有标志寄存器。
- **SimRISC**：双目的 `{rdHA, rdHB}`——`rdHA` 直接给进位/借位或高 64 位。

**乘法的结果宽度**

- **x86-64**：`mul` 给 RDX:RAX（128 位），`imul` 有单目/双目形式。
- **ARM64**：`MUL` 给低 64 位，`UMULH`/`SMULH` 给高 64 位。
- **RISC-V**：`mul`/`mulh`/`mulhu`/`mulhsu` 分四条。
- **MIPS**：`mult`/`multu` 写 HI:LO。
- **SimRISC**：`mul.so`/`mul.uo` 一条给 `{高, 低}`；窄宽度 `mul.st`/`mul.ut` 等单目的。

**除零的处理**

- **x86**：`div`/`idiv` 除零触发 #DE 异常。
- **ARM64**：整数除零默认返回 0（`SDIV`/`UDIV`），不陷入。
- **RISC-V**：除零返回全 1（`div`/`divu`），不陷入；溢出返回 `INT_MIN`。
- **MIPS**：除零结果未定义，可用 trap 指令检查。
- **SimRISC**：除零/溢出都返回定值，不陷入；规则与 RISC-V 的"不陷入"一致，定值按宽度给出。

**比较结果**

- **x86 / ARM**：比较只设置标志位，结果不落地。
- **RISC-V**：`slt`/`sltu` 产生 0/1。
- **SimRISC**：产生 -1/0/1，直接区分三路。
