# 指令系统 -- 原子操作

**本册要点**

- LR/SC 合成任意 RMW，不需要 AMO。
- `lr` 设置保留标记，`sc` 条件写并返回 0/1。
- `lr` 的 `hb` 固定为 `rd0`，`hb ≠ 0` → ILLI。
- acquire/release 后缀：`lr.*.an/.ar`、`sc.*.nr/.ar`。
- `fence`：`fm`/`pred`/`succ` 位掩码。
- 保留粒度由平台定义；LR/SC 按宽度对齐。
- 异常/中断/另一条 `lr` 会清除保留；SC 可能偶发失败。

## 1. 为什么用 LR/SC，而不是原子 RMW（AMO）指令？

**答：** 因为 LR/SC 用一对 load/store 形态的指令就能合成任意"读-改-写"，不需要在存储侧放 ALU；代价是可能失败、要在循环里重试。

- **LR（Load Reserved）**：从 `[rbHD]` 读数据到 `rdHC`，并在该地址上设置保留标记。
- **SC（Store Conditional）**：检查保留标记；仍在则把 `rdHC` 写入 `[rbHD]`、`rdHB = 0`（成功）；不在则不写、`rdHB = 1`（失败）；无论成败都清除本 hart 的所有保留标记。
- **一条机制覆盖所有 RMW**：`lr` + 计算 + `sc` 可以合成 `fetch-add`、`compare-and-swap`、`swap` 等任意操作，不需要为每种运算设一条 AMO。
- **硬件简单**：不需要在内存/缓存侧做"读+运算+写"的原子通路，只需要一个保留标记和一次条件写。
- **代价**：SC 可能偶发失败（spurious failure），软件必须写成重试循环；高竞争下重试成本高。
- **对比**：RISC-V 的 A 扩展同时有 LR/SC 和 AMO；x86 用 `lock` 前缀 + `cmpxchg`/`xadd`；ARM 有 LDXR/STXR 和 LSE 的原子指令。SimRISC 只保留 LR/SC 一套，减少指令与硬件通路。
- **各家做法**：x86 `lock cmpxchg`/`xadd`；ARM64 `LDXR`/`STXR` + LSE 的 `CAS`/`LDADD`；RISC-V `lr`/`sc` + `amo*`；MIPS `ll`/`sc`；SPARC `cas`/`swap`；PowerPC `lwarx`/`stwcx.`。
- **为什么 SimRISC 只留 LR/SC**：一套机制覆盖所有 RMW，不需要存储侧 ALU；代价是可能失败、要重试。

## 2. 为什么 LR/SC 要带 acquire/release 语义？

**答：** 因为弱内存模型下，"读-改-写"前后还需要限制其它访存的重排；把 `a`（acquire）/`r`（release）直接编码进指令，比额外插 `fence` 更省指令、也更精确。

- **acquire（a）**：该指令之后的所有访存不得被重排到它之前；适合"拿锁之后读临界区"。
- **release（r）**：该指令之前的所有访存不得被重排到它之后；适合"写完临界区再放锁"。
- **`n`（none）**：没有额外的顺序限制。
- **典型配对**：拿锁用 `lr.an`（acquire），放锁用 `sc.nr`（release）；需要更强顺序时用 `.ar`（acquire + release）。
- **与 `fence` 的分工**：`fence` 是独立的屏障指令，适合批量/复杂场景；LR/SC 的后缀把最常见的 acquire/release 直接带在原子操作上。
- **对比**：RISC-V 的 `lr.w.aq`/`sc.w.rl` 是同一套思路；ARM 的 `LDAR`/`STLR` 把 acquire/release 做成独立指令。
- **各家做法**：x86 `lock` 前缀隐含全屏障；ARM64 `LDAR`/`STLR`；RISC-V `lr.w.aq`/`sc.w.rl`；PowerPC `lwsync`/`sync`；MIPS `sync`。
- **为什么把 a/r 编进指令**：省掉单独的 fence，常见的锁/引用计数一对就够；更强顺序用 `.ar` 或 fence 补。

## 3. 为什么 lr 只有 nn/an/ar，sc 只有 nn/nr/ar？

**答：** 因为规范只定义这三种组合，缺的组合编码为 reserved、汇编器拒绝；常用的配对是"load 带 acquire、store 带 release"。

- **lr 的组合**：`nn`（无顺序）、`an`（acquire）、`ar`（acquire + release）；**没有 `nr`**。
- **sc 的组合**：`nn`（无顺序）、`nr`（release）、`ar`（acquire + release）；**没有 `an`**。
- **命名规则**：`<lr|sc>.<b|w|t|o>.<nn|an|nr|ar>`——数据宽度在前、存储序在后，以 `.` 分隔。
- **典型用法**：`lr.an` + `sc.nr` 覆盖绝大多数锁/引用计数场景；`.ar` 用于需要双向屏障的场合。
- **其余组合**：助记符不存在，对应编码为 reserved——这样既减少编码空间，也避免语义不清的组合。
- **各家做法**：RISC-V 的 `lr`/`sc` 有 `.aq`/`.rl` 两位，组合是 4 种（含 `aq+rl`）；ARM64 的 `LDAR`/`STLR` 把 acquire/release 做成独立指令；x86 的 `lock` 是隐含全屏障。
- **为什么 SimRISC 只留三种**：常用的配对是 load-acquire / store-release；`lr.nr` 和 `sc.an` 语义不清、使用少，省掉编码。

## 4. 为什么 sc 成功返回 0、失败返回 1？

**答：** 因为 0/非 0 正好对应 C 的"成功/失败"布尔判断，软件可以直接 `br.nz` 重试，不需要再比较。

- **返回值**：`sc rdHB, rdHC, [rbHD]`——成功写 `rdHB = 0`，失败写 `rdHB = 1`。
- **重试循环**：`lr` → 计算 → `sc` → `br.nz` 回到 `lr`；失败时 `rdHB` 非 0，直接触发重试。
- **清除保留**：无论成功还是失败，SC 都清除当前 hart 上的所有保留标记，避免"失败后旧标记还在"的歧义。
- **与 RISC-V 一致**：RISC-V 的 `sc.w` 也是成功返回 0、失败返回非 0。
- **对比**：x86 的 `cmpxchg` 用 ZF 表示成功/失败；ARM 的 `STXR` 返回 0/1 状态。
- **各家做法**：RISC-V `sc.w` 成功 0、失败非 0；ARM64 `STXR` 成功 0、失败 1；x86 `cmpxchg` 用 ZF（1 成功/0 失败）；PowerPC `stwcx.` 用 CR0.EQ；MIPS `sc` 成功 1、失败 0。
- **为什么选 0/1**：与 C 的布尔/`br.nz` 直接对应；失败非 0，重试循环简单。

## 5. 为什么 fence 用 pred/succ 位掩码，而不是一条"全屏障"？

**答：** 因为不同场景只需要部分顺序（读-读、读-写、写-读、写-写，以及设备 I/O），位掩码让一条指令表达任意组合，避免"全屏障"带来的过度串行化。

- **位域**：`fence immu18` 的 `fm[17:12]` 是屏障模式，`pred[11:6]` 是前序访问类型集合，`succ[5:0]` 是后序访问类型集合。
- **四类访问**：R（读）、W（写）、I（设备输入）、O（设备输出）；汇编层用 `PRED_R`/`PRED_W`/`PRED_I`/`PRED_O` 与 `SUCC_*` 常量按位或组合。
- **例子**：`fence PRED_R|PRED_W|SUCC_R|SUCC_W`（`immu18 = 0x00C3`）是最常见的读写屏障。
- **`fm`**：`0` 是已定义的常规屏障；`8` 是 TSO 预留（当前未定义）；其余保留，保留编码触发 ILLI。
- **SBZ**：`pred[11:10]` 与 `succ[5:4]` 是 SBZ，非零即非法。
- **对比**：RISC-V 的 `fence` 也是 pred/succ 位掩码；x86 的 `mfence`/`lfence`/`sfence` 是固定的几种全屏障。
- **各家做法**：RISC-V `fence pred, succ`；x86 `mfence`/`lfence`/`sfence`；ARM64 `DMB`/`DSB`/`ISB`；PowerPC `sync`/`lwsync`/`isync`；MIPS `sync`。
- **为什么用位掩码**：不同场景只需部分顺序；一条指令表达任意组合，避免全屏障的过度串行化。

## 6. 为什么保留标记的粒度由平台定义？

**答：** 因为"精确到地址"和"精确到 cache line"都能实现正确的 LR/SC，前者简单、后者更容易在多核/缓存一致性下实现；平台按成本选择，软件不能假设粒度。

- **两种实现**：保留标记可以跟踪精确地址，也可以跟踪该地址所在的 cache line。
- **对软件的影响**：粒度越粗，越容易因为"同一条 cache line 上的其它写"而让 SC 失败；软件必须按"可能偶发失败"来写重试循环。
- **规范口径**：保留标记的粒度由平台定义；LR/SC 只保证"标记还在则写成功、否则失败"，不保证"只有同地址写才失败"。
- **对比**：RISC-V 的 LR/SC 也允许平台选择保留粒度；ARM 的 exclusive monitor 同样有地址/ cache line 两种粒度。
- **各家做法**：x86 `lock` 锁 cache line/总线；ARM exclusive monitor 可跟踪地址或 cache line；RISC-V 保留集合粒度由平台定义；SimRISC 同。
- **为什么平台定义**：精确地址简单、cache line 易做一致性；软件必须按"可能偶发失败"重试。

## 7. 为什么 LR/SC 要按数据宽度对齐？

**答：** 因为原子性要求"一次访存"不可分割；未对齐的访问会跨 cache line/存储字，硬件无法用一次操作完成，只能报 MALIGN。

- **对齐规则**：`.b` 需 1 字节、`.w` 需 2 字节、`.t` 需 4 字节、`.o` 需 8 字节对齐；否则触发 MALIGN。
- **与普通 load/store 一致**：普通 `ld`/`st` 也按宽度要求对齐；LR/SC 沿用同一套规则，不引入新的对齐语义。
- **原子性**：对齐后，一次 LR/SC 只涉及一个存储单元，保留标记和条件写才有明确的对象。
- **对比**：x86 的 `lock` 前缀要求访问对齐（跨 cache line 时性能大幅下降，某些情况还会触发总线锁）；ARM/RISC-V 的 exclusive 访问也要求自然对齐。
- **各家做法**：x86 `lock` 对齐（跨行性能差/可能总线锁）；ARM64 `LDXR`/`STXR` 自然对齐；RISC-V `lr`/`sc` 自然对齐；MIPS `ll`/`sc` 对齐；PowerPC `lwarx`/`stwcx.` 对齐。
- **为什么对齐**：原子性要求一次访存不可分割；未对齐会跨 cache line/存储字。

## 8. 为什么异常/中断/另一条 lr 会清除保留标记？

**答：** 因为保留标记只保证"从 LR 到 SC 之间没有别的写"，一旦控制流离开这段区间，旧标记就不再可信；清掉它可以让 SC 明确失败，而不是误写。

- **清除事件**：另一 hart 对保留地址（或其 cache line）的写、当前 hart 执行另一条 `lr`、异常或中断进入。
- **异常处理的影响**：如果 hart 在 LR 和 SC 之间进入异常处理程序，SC 必定失败——这是规范明确的行为。
- **SC 自身**：无论成功失败，SC 都清除当前 hart 的所有保留标记。
- **软件含义**：重试循环必须把"LR 到 SC"之间的代码写成可重入的（不调用可能陷入的函数、不执行可能被中断打断的长序列）。
- **对比**：RISC-V 的保留集合同样会被这些事件清除；ARM 的 exclusive monitor 在异常/上下文切换时也会失效。
- **各家做法**：RISC-V 保留集合被另一 hart 的写、另一条 `lr`、异常/中断清除；ARM exclusive monitor 在异常/上下文切换失效；x86 `lock` 不需要保留标记。
- **为什么清除**：保留标记只保证"LR 到 SC 之间没有别的写"；控制流离开这段区间后旧标记不可信。

## 9. lr 的 hb 为什么固定为 rd0？

**答：** 因为 `lr` 的目的只有一个数据寄存器（`rdHC`），没有第二个目的；`rdHB` 槽位空着，就固定写 0，手工编码 `hb ≠ 0` 视为非法。

- **汇编形式**：`lr.<宽度>.<序> rdHC, [rbHD]`，只写两个操作数；`rdHB` 不出现。
- **编码**：`lr` 仍是 `orrr`；`hb` 固定为 0，若手工编码 `hb ≠ 0` → ILLI。
- **对比**：`sc` 的 `rdHB` 是成功/失败目的（0/1），所以 `sc` 写三个操作数；`lr` 没有这个返回值。
- **为什么**：固定字段让编码器/译码器不必为 `lr` 单独设计格式，也让非法编码容易检测。
- **各家做法**：RISC-V `lr.w rd, (rs1)` 只有两个操作数（rd + 地址），没有 hb 槽；ARM64 `LDXR Wt, [Xn]` 同样两个；x86 没有 LR。
- **为什么固定 hb=0**：`lr` 没有第二个目的；固定字段让 `orrr` 格式复用，非法编码易查。

## 背景知识

### 术语与概念

- **原子操作（atomic operation）**：对外表现为不可分割的一次操作；其它 hart 看不到中间状态。
- **RMW（read-modify-write）**：读、改、写三步的原子组合，如 `fetch-add`、`swap`、`compare-and-swap`。
- **LR/SC**：Load Reserved / Store Conditional，用一对指令实现 RMW。
- **保留标记（reservation）**：LR 在 hart 上设置的标记；SC 检查它是否还在。
- **spurious failure**：没有真正冲突也失败；软件必须重试。
- **acquire / release**：acquire 阻止后续访存上移，release 阻止前序访存下移。
- **弱内存模型（weak memory model）**：允许访存重排，需要显式屏障/acquire/release 来约束。
- **fence**：内存屏障指令，按前序/后序访问类型集合串行化。
- **TSO（Total Store Order）**：一种较强的内存模型；`fm = 8` 为其预留（当前未定义）。

### 对照

**原子指令的形态**

- **x86-64**：`lock` 前缀 + `cmpxchg`/`xadd`/`xchg` 等；也有 `mfence`/`lfence`/`sfence`。
- **ARM64**：`LDXR`/`STXR`（exclusive）、`LDAR`/`STLR`（acquire/release）；LSE 扩展提供 `LDADD`/`CAS`/`SWP` 等。
- **RISC-V**：A 扩展的 `lr`/`sc` + `amoswap`/`amoadd`/`amoor`/`amoand`/`amoxor`/`amomax`/`amomin` 等。
- **MIPS**：`ll`/`sc`。
- **SPARC**：`ldstub`、`cas`、`swap`。
- **PowerPC**：`lwarx`/`stwcx.`、`lbarx`/`stbcx.` 等。
- **SimRISC**：`lr.*`/`sc.*`（无 AMO）+ `fence`。

**acquire/release 的编码**

- **x86**：`lock` 前缀隐含全屏障；`mfence`/`lfence`/`sfence` 显式。
- **ARM64**：`LDAR`/`STLR` 把 acquire/release 做成指令；也可用 `DMB`/`DSB`。
- **RISC-V**：`lr.w.aq`/`sc.w.rl` 用后缀；`fence rw,rw` 显式。
- **SimRISC**：`lr.*.an`/`lr.*.ar`、`sc.*.nr`/`sc.*.ar` 用后缀；`fence` 显式。

**保留粒度**

- **x86**：`lock` 锁定 cache line（或总线）。
- **ARM**：exclusive monitor 可跟踪地址或 cache line。
- **RISC-V**：保留集合的粒度由平台定义。
- **SimRISC**：保留标记的粒度由平台定义（精确地址或 cache line）。
