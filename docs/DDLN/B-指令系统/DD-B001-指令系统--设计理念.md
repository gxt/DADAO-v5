# 指令系统 -- 设计理念

**本册要点**

- **简单** = 清晰简洁的内部设计与接口逻辑；**实用** = 模拟器 / FPGA 可实现，性能可接受。
- 设计顺序：边实现边定义，不先写死 ISA；软硬件相互依存。
- DRY：复用 generic 实现，避免重复造轮子。
- 为什么要新 ISA：教学载体、没有历史包袱、在 RISC 上做探索、软硬件协同。
- 为什么 64 位：字长/寄存器/地址一起定，位域够用，没有 32 位包袱。
- 为什么 RISC：规整、load/store、可实现可验证；但不教条。
- 数据宽度命名：byte/wyde/tetra/octa（Knuth/MMIX）。
- 产业界 ISA（12 个）与其他开放/教学 ISA（7 个）的对照。
- **设计目标与非目标**：可实现、可验证、可教学；不追求商用性能、不背兼容、不追求指令数最少。
- **主要取舍**：定长/变长、值条件/标志位、分组/统一、RAS/软件栈、拼接/常量池、大端/小端、LR-SC/AMO。

本体系架构借DADAO之名，寓意简单且实用。

> **明道若昧，进道若退，夷道若纇。**——《道德经》第四十一章
>
> - **明道若昧**：光明的道看似暗昧；真正明白“道”的人，外表反而显得愚昧。
> - **进道若退**：前进的道看似后退；真正在“道”上前进的人，反而像在退步。
> - **夷道若纇**：平坦的道看似崎岖；**平坦的道路在实践中却显得崎岖不平**。
>
> 所以“大道至简”不是“一路平坦”：真正的简单，往往要在实践中穿过崎岖。

- 简单的真实含义：每个系统都很复杂，其设计者都是盖世奇才；然后因为受限于各种接口与依赖，需要进行各种妥协，因此只能采用各种方式进行修修补补；
Dadao希望利用清晰简洁的内部设计和接口逻辑让多个系统尽量按照其本意顺畅运转起来。
就好像两个轮子要联动，可以把两个轮子做成相互咬合的齿轮，也可以用一根连动杆将速率一致的部位连接起来；
而不是在两个轮子旁边分别安放一个监控器，然后增加通知模块和同步模块，然后每个轮子有变化的时候相互通知，然后进行同步。
- 实用的真实含义：计算机系统处处都是权衡，很多权衡的真实原因是性能、成本和历史的包袱。
Dadao没有历史的包袱，也不刻意追求高性能，更不存在成本问题，所以一个底线就是可实用化；实用的评价指标就是模拟器和FPGA可实现且其性能可接受。

DADAO的版本号拟遵循语义化版本控制规范SemVer 2.0.0： <https://semver.org/lang/zh-CN/> 。
当前处于开发初始阶段，因此主版本号为零，即（0.y.z），一切都可能未事先声明而随时被改变。

## 设计之TAO概述

计算机系统处处是权衡。Dadao试图在理论和实践之间取得一种权衡，使得该架构既可以为一些理论想法提供探索的基础，又不能过于理想化而无法真正形成可用系统。

在设计顺序上，与传统的设计不同：

- 设计之初基于经验，设计过程中边迭代边改进，设计之末归于评测。
- 既非软件设计来指导硬件设计，也非硬件设计来指导软件设计；甚至于没有刻意遵循先定义ISA再开发软件和硬件，而是开发过程中逐步定义ISA
- 实现并非是设计的附庸，而是相互依存，相辅相成；因此，并非是先设计再实现，而是先做好整体的构思，然后开始实现，边实现边设计，边设计边实现
- 几个紧密相关的系统同时进行设计和实现，然后在此过程中进行设计改进

***DRY原则***

- Don't Repeat Yourself，避免重复造轮子
- 系统软件中，由于要支持多种体系架构，通常都会有generic的实现，Dadao的开发移植过程主要参考了generic的实现，避免重复造轮子

## 1. 为什么要设计一个新的指令系统？

**答：** 动机可以分四层，正好对应 SimRISC 名字的三重含义（Simple RISC / Simulated RISC / Similar RISC）。

- **教学与实验的载体（Simulated RISC）**：需要一个能**完整跑起来、能观察、能改**的 ISA。商用 ISA 文档再全，学生也很难在一个课程周期内从指令编码一路做到汇编器、模拟器和 FPGA；SimRISC 的设计初衷就是完全基于模拟环境开发，让每一层都可验证、可动手。
- **没有历史包袱的重新取舍**：x86/ARM 都背着兼容性、性能、成本与生态的包袱，很多设计是"在既有接口上修补"。DADAO 没有这些包袱，可以按"简单且实用"重新决定：指令多长、几位给操作数、要不要标志位、寄存器怎么分组。
- **在 RISC 基础上做探索（Similar RISC）**：不是再造一个"标准 RISC"，而是把 RISC 当起点，试验一些在商用 ISA 里不容易落地的想法——寄存器分组（`rd`/`rb`/`rf`/`ra`）、取消 CZSO、条件赋值、多寄存器 load/store、独立返回地址栈、立即数赋值指令等。
- **软硬件协同的方法论**：ISA 不是先写完再实现，而是"边实现边定义"；规范、LLVM、QEMU、Chipyard 同步演进。最终评价标准很务实：**模拟器和 FPGA 可实现，且性能可接受**。

## 2. 为什么需要 64 位？

**答：** 这里的"64 位"同时指**机器字长 64 位**和**寄存器 64 位**，两者是一起定的。

- **地址空间**：现代程序需要远大于 32 位的地址空间。SimRISC 用 64 位寄存器承载地址，有效虚拟地址为 48 位——既够用，又把高 16 位留出来做溢出检测等用途（访存时取低 48 位）。
- **没有 32 位的包袱**：如果先做一个完备的 32 位 ISA、再补 64 位，往往要加前缀或模式切换（如 x86 的 REX、ARM 的 ARM/Thumb 状态），编码和译码都变复杂。DADAO 从一开始就定 64 位，不必"打补丁"。
- **位域空间**：32 位定长指令划分为 `8/6/6/6/6`，正好 8+6+6+6+6 = 32；6 位操作数域恰好编码 64 个寄存器。64 位字长 + 64 个寄存器让"规整编码"成立，不必为了塞进 32 位而压缩字段。
- **以 8 为单位的工程自洽**：2³ = 8，1 字节 8 位，64 位 = 8 字节；高速缓存行通常 64 字节（8×8），页通常 64 KiB；ABI 的复合类型也按 8 字节对齐。寄存器、位域、对齐都按 8 的节奏划分。
- **数据宽度**：64 位整数与双精浮点（IEEE 754）都是一次处理 64 位；四种定长类型 `byte/wyde/tetra/octa` 统一在 64 位字长之下。
- **32→64 的历史包袱**：x86 用 REX 前缀和长模式扩展，留下变长编码、模式切换、段式遗留；ARM 另起 AArch64，但要维护 AArch32/AArch64 双状态；MIPS64 保留分支延迟槽与 32 位兼容模式。这些都是"在 32 位 ISA 上打补丁"的代价，包袱很重；RISC-V 从开始就同时定义 RV32/RV64、SimRISC 一开始就是 64 位，没有这段包袱。

## 3. 为什么是 RISC 设计理念？

**答：** 因为 RISC 的"规整"最直接地换来**可实现、可验证、可解释**，但 DADAO 并不教条。

- **规整 → 译码简单**：32 位定长、4 字节对齐、统一的 `8/6/6/6/6` 位域，`opc`（8 位主编码）/`opx`（6 位副编码）两级；译码器简单，模拟器和 FPGA 都容易实现，课堂上也能逐位讲清楚。
- **load/store 架构 + 简单指令**：运算只对寄存器，访存只有 load/store；不在一条指令里塞多个功能（对比 ARM 把移位合并进操作数），编译优化和处理器设计都更简单。
- **"Simple is beautiful"，但不是"越少越好"**：DADAO 不刻意追求 RISC 意义上"精简"的极小指令数，而是利用规整位域做功能可选性（如逻辑指令的 6 位、多寄存器 load/store）；宁可留白，也不堆很少用到的功能组合。
- **Similar RISC：保留骨架，放开探索**：保留 RISC 的定长与规整，同时做 RISC 之外的尝试——寄存器分组（`rb` 专管地址、`ra` 独立成栈、`rf0` 复用为 FCSR）、取消 CZSO（用数值的正/负/零判断）、条件赋值、四操作数指令、立即数赋值等。
- **教学价值**：规则少而一致，才能在一个学期里把"编码 → 汇编 → 模拟器 → 流水线/FPGA"串起来——这正是"大道至简"在指令系统上的体现。

## 4. 数据宽度的定义为何采用 byte/wyde/tetra/octa？

**答：** 因为这四个词是 Knuth 在 MMIX 里定义的、按 2 的幂递增的一套名字，比 word/dword/qword 更系统、也没有歧义。

- **对应关系**：`byte` = 8 位、`wyde` = 16 位（2 字节）、`tetra` = 32 位（4 字节）、`octa` = 64 位（8 字节）。
- **系统化**：名字按 2 的幂递增，首字母 `b/w/t/o` 又可以直接做指令后缀（`.b`/`.w`/`.t`/`.o`）。
- **避免 word/long/quad 的歧义**：`word` 随架构变（x86 的 word 是 16 位，很多 RISC 的 word 是 32 位）；`long` 随数据模型变（LP64 下 64 位、ILP32 下 32 位）；`quad` 也依赖 word 的大小。byte/wyde/tetra/octa 不依赖这些约定。
- **`octa` 在汇编里另有 128 位含义**：有些汇编器的 `.octa` 伪指令是 16 字节（128 位）；本 ISA 明确把 `octa` 定义为 64 位，不能望文生义。
- **`byte` 的历史**：早期 byte 不一定是 8 位（有 6/7/9 位等）；ISO/IEC 2382-1:1993 记录了 8 位字节这一事实标准，IEC 80000-13:2008 进一步把 byte 明确为 8 位，之后不再有歧义。
- **`b` 不会和 bit 混**：虽然 bit/byte 都以 b 开头，但在数据宽度命名和指令后缀（`.b`）里，`b` 明确指 byte（8 位），不是 bit。
- **与"以 8 为单位"自洽**：8 → 16 = 2×8 → 32 = 4×8 → 64 = 8×8，正好是统一的 8 位节奏。

## 5. DADAO 的设计目标与非目标是什么？

**答：** 目标是把"可实现、可验证、可教学"放在第一位；非目标是商用性能、生态兼容和指令数最少。

- **目标：教学与实验载体**——能完整跑起来、能观察、能改；从编码到汇编器、模拟器、FPGA 都能在一门课里走通。
- **目标：可实现**——模拟器和 FPGA 能实现，性能可接受；"可接受"是底线，不是"领先"。
- **目标：可验证**——每一层都能用独立事实核对（规范、汇编/反汇编、模拟器、RTL），而不是只靠实现自洽。
- **目标：简单且实用**——清晰简洁的内部设计与接口逻辑；不为了"看起来先进"增加隐藏机制。
- **非目标：商用性能/面积/功耗的最优**——不刻意追求高性能，也不参与商用 ISA 的生态竞争。
- **非目标：历史兼容**——不背 x86/ARM 的二进制兼容包袱；可以重新决定指令长度、寄存器分组、标志位。
- **非目标：指令数最少**——不追求 RISC 意义上的"极小指令集"；宁可留白，也不堆很少用到的功能组合。
- **非目标：16 位压缩**——不做 16 位指令扩展，不为它预留位域和长度前缀。

## 6. DADAO 的主要设计取舍有哪些？

**答：** 每个选择都是"取一个好处、舍一个代价"，下面是最关键的几组。

- **定长 32 位 vs 变长**：取译码简单、流水线友好；舍代码密度。
- **值条件（-1/0/1）vs 标志位**：取无隐藏状态、无假依赖；舍每条条件指令多一个寄存器操作数。
- **寄存器分组 vs 统一**：取地址/数据分离、等效更多寄存器；舍跨组搬运要多一条指令。
- **硬件 RAS vs 软件栈**：取省访存、防跑飞；舍 RAS 状态（`RACNT`/`MRPTR`）与溢出处理。
- **立即数拼接 vs 常量池**：取无访存、无 cache 污染；舍大常数要多条指令。
- **大端 vs 小端**：取可读性、网络序一致；舍与 x86/ARM 的默认字节序兼容。
- **LR/SC vs AMO**：取一套机制覆盖所有 RMW；舍可能失败、要重试循环。
- **四组 × 64 个寄存器 vs 32 个**：取寄存器压力小；舍每个操作数要 6 位、组由 `opc` 区分。

## 背景知识

### 术语与概念

- **ISA（指令系统体系结构）**：软件看到的指令、寄存器、寻址与异常模型；同一 ISA 可以有多种微架构实现。
- **RISC / CISC**：精简/复杂指令集；前者强调定长、规整、load/store，后者强调单条指令完成更多工作。
- **微架构（microarchitecture）**：同一 ISA 的具体实现（流水线级数、乱序窗口、cache 大小等）；ISA 是软件接口，微架构是实现。
- **ABI（应用二进制接口）**：寄存器使用、参数传递、数据对齐等约定。
- **64 位 ISA**：寄存器/地址宽度为 64 位；它与"指令编码长度"是两件事——AArch64 是 64 位 ISA，但指令固定 32 位；x86-64 是 64 位 ISA，但指令变长。

### 对照

**先分清两个"位"**：

- **寄存器/地址宽度**：决定它是 32 位还是 64 位 ISA（x86-64、AArch64、RV64、MIPS64、SPARC V9、PowerPC64 都是 64 位）。
- **指令编码长度**：决定一条指令占几个字节（定长 32 位、16 位压缩、1–15 字节变长等）。

**指令数量（大致，按助记符估算）**：

- **通用（32/64 合并）**：
  - x86-64：约 1,000 条（基础整数/系统）；含 SIMD 约 2,000–3,000。
  - ARM：AArch64 约 600–900；AArch32 约 500–700。
  - RISC-V：G 去掉 F/D = 78 条（RV64I 52 + M 8 + A 11 + Zicsr 6 + Zifencei 1）。
  - MIPS：约 100–150（MIPS32 基础；MIPS64 另加 64 位指令）。
  - SPARC：约 150–200（V9）。
  - PowerPC：约 200–300（32/64 基础）。
  - SimRISC：200 条（266 − 66 FP）。
- **浮点**：
  - x86-64：x87 约 80 + SSE/AVX 浮点约 300–500。
  - ARM：VFP 约 100 + NEON/SVE 浮点约 300–500。
  - RISC-V：F 26 + D 26 = 52 条。
  - MIPS：COP1 约 30–40。
  - SPARC：F/P 约 40–50。
  - PowerPC：FP 约 50–60。
  - SimRISC：66 条。
- **扩展（向量 + 位操作 + 加解密）**：
  - x86：约 15–20 套，指令约 1,000–2,000。
  - ARM：约 5–10 套，指令约 500–1,000。
  - RISC-V：约 5–10 套，指令约 200–400。
  - MIPS：MDMX、MSA、DSP ASE 等，数套。
  - SPARC：VIS（可视化指令集）。
  - PowerPC：Altivec（VMX）、VSX 等。
  - SimRISC：0 套（只有通用 + 浮点）。

> x86/ARM/MIPS/SPARC/PowerPC 没有权威的指令条数口径，以上为按助记符的估算；RISC-V 与 SimRISC 为精确数。

## 专题：产业界 ISA 比较

- **x86-64**（Intel / AMD）
  - 定位：PC / 服务器的事实标准；CISC；变长指令（1–15 字节）；向后兼容 16/32 位。
  - 优势：生态最大、软件最全；劣势：译码复杂、功耗与面积代价高。
- **ARM64**（ARM）
  - 定位：移动 / 嵌入式 / 服务器；RISC；定长 32 位；IP 授权模式。
  - 优势：能效高、授权灵活；劣势：AArch32/AArch64 双状态的历史包袱。
- **RISC-V**
  - 定位：开放标准；模块化扩展；嵌入式 / 研究 / 新兴市场。
  - 优势：无历史包袱、可定制；劣势：生态仍在成长、碎片化风险。
- **MIPS**
  - 定位：曾经的嵌入式 / 网络主力；RISC；定长 32 位；分支延迟槽。
  - 现状：影响力下降，公司几经易手。
- **SPARC**
  - 定位：Sun / Oracle 的服务器 RISC；寄存器窗口；大端。
  - 现状：服务器市场萎缩，OpenSPARC 开源。
- **PowerPC / POWER**
  - 定位：IBM 的 RISC；嵌入式、超算（POWER）；OpenPOWER 开放。
  - 优势：高性能、VSX 向量；劣势：生态规模小于 x86/ARM。
- **IBM Z（z/Architecture）**
  - 定位：IBM 大型机；64 位 CISC；金融/银行核心系统的主力。
  - 特点：支持 24/31/64 位三种寻址模式（31 位沿用 ESA/390，上限 2 GB；64 位上限 16 EB）；生态封闭但极稳定。
- **IA-64（Itanium）**
  - 定位：Intel / HP 的 64 位 EPIC/VLIW；2001 年推出，商业上失败，2021 年停产。
  - 特点：编译器负担重；与 x86 不兼容。
- **Alpha**
  - 定位：DEC 的 64 位 RISC；1992 年推出，性能领先；后被 Compaq/HP 收购并停产。
  - 特点：无 32 位形态；对后来的 64 位 RISC 影响大。
- **PA-RISC**
  - 定位：HP 的 RISC；32 位（1.1）/ 64 位（2.0）。
  - 特点：早期商用 RISC 之一。
- **SuperH**
  - 定位：Hitachi / Renesas 的 32 位嵌入式 RISC；汽车/家电常见。
  - 特点：J-core 是其开源实现；有 GCC/binutils/QEMU 支持。
- **LoongArch**
  - 定位：龙芯的 64 位（LoongArch64）/ 32 位 ISA；国产化桌面/服务器。
  - 特点：自主生态；与 MIPS 有历史渊源。

**另有**：8/16 位微控制器（AVR、MSP430、PIC）与可配置嵌入式核（ARC、Xtensa、TriCore），不在 64 位比较范围内。

**一句话对比**：x86-64 靠生态与兼容，ARM64 靠能效与授权，RISC-V 靠开放与可定制；MIPS/SPARC/PowerPC 是曾经的强者，今天更多在细分市场与开源社区。

## 专题：其他开放/教学 ISA

- **MMIX**
  - 历史：Knuth 为《计算机程序设计艺术》设计，用来取代 1960 年代的 MIX；1999 年随 MMIXware 发布，2011 年冻结为 Version 1。
  - 特点：64 位；256 个 64 位 GPR + 32 个特殊寄存器；32 位定长指令；256 个 opcode；big-endian；64 位地址空间；目标是机器语言简单、优雅、易学。
  - 工具：`mmixal` 汇编器、`mmix` 模拟器；GCC/binutils 有 `mmix` 目标；另有 MMIXVD 可视化调试器。
- **DLX**
  - 历史：Hennessy 与 Patterson 在《Computer Organization and Design》中提出的教学 RISC（1990 年代）。
  - 特点：32 位；32 个 GPR；32 位定长；load/store；5 级流水线；用于讲流水线、冒险与 cache。
  - 工具：DLXsim 模拟器 + 汇编器；有第三方 C 编译器，无主流完整工具链。
- **OpenRISC**
  - 历史：OpenCores 社区 1999/2000 年前后发起；代表实现是 OR1200。
  - 特点：规范 32/64 位，但实际只有 32 位实现（无 64 位硬件/模拟器/工具链）；32 位定长；32 个 GPR；可配置 cache/TLB；可选 FPU/DSP；有 Linux 移植。
  - 工具：GCC/binutils/QEMU/or1ksim；规范最后更新 1.4（2022-02-20）。
- **J-core（SuperH 开源实现）**
  - 历史：SuperH（SH-2）ISA 的开源实现，由开源硬件社区维护，用于 FPGA 与嵌入式项目。
  - 特点：32 位 RISC；16 位定长指令；有分支延迟槽。
  - 工具：GCC/binutils/QEMU 的 SH 目标；J-core 提供 FPGA 核。
- **OpenSPARC**
  - 历史：Sun 2005/2008 年开放 SPARC T1/T2 的 RTL 与规范。
  - 特点：SPARC V9，64 位；32 位定长；寄存器窗口；芯片多线程（CMT）。
  - 工具：GCC/binutils 的 SPARC 目标；OpenSPARC 模拟器。
- **OpenPOWER**
  - 历史：IBM 2013 年发起的开放生态，围绕 POWER8/POWER9。
  - 特点：64 位；32 位定长；32 个 GPR；VSX 向量；可配置大小端；Microwatt 是开源软核。
  - 工具：GCC/LLVM/QEMU。
- **CHERI**
  - 历史：剑桥大学与 UC Berkeley 在 2010 年代提出。
  - 特点：在 64 位 ISA 上增加带标签的能力寄存器与内存保护，防止指针越界/伪造；实现包括 CHERI-MIPS、CHERI-RISC-V、ARM Morello。
  - 工具：CHERI LLVM、QEMU；研究性强，尚未成为主流商用 ISA。
