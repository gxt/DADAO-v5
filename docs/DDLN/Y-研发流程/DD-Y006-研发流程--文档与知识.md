# 研发流程 -- 文档与知识

**本册要点**

- 文档按**读者**三分：技术规范（实现依据）、工程流程（怎么做）、结论口径（自己看）。
- 新增文档前先问三问：能机械判吗、与既有重复吗、只服务当前任务吗。
- 同一事实只能有一个权威落点，其它地方是**指针**。
- **被引用的材料不能只放可删目录**，否则清理时引用悬空。
- 台账要克制：状态、问题、教训各一份，细节留给任务与日志。
- 生成物必须能"重派生并逐字节比对"，否则会悄悄漂移。

## 1. 为什么文档要按读者三分？

**答：** 因为三类读者的诉求相反：实现者要"能机械校验的精确描述"，协作者要"能照做的流程"，决策者要"结论与理由"。混在一份文档里，必然对某一方不适配。

- **技术规范**：面向实现与工具，允许精确到字段，要求可机械校验。
- **工程流程**：面向做事的人，要求步骤可执行、检查点明确。
- **结论口径**：面向维护者，记录"为什么这么定、放弃了什么"。
- **判据**："这份文档写砸了会害谁？"答案不同，写法就不同。
- **代价**：同一主题可能出现在多处；靠"指针 + 单一真源"避免重复。

**各家做法**：

- **标准组织**：规范与实施指南分开写（规范可测、指南可读）。
- **开源项目**：贡献指南、设计文档、代码注释三分离。
- **企业**：流程手册、架构文档、决策记录分离。
- **学术**：论文（结论）与代码库（实现）分离。
- **反例**：一份"万能文档"既当规范又当教程，最后两边都不好用。

**是统一标准吗**：不是。

## 2. 为什么新增文档前要问三个问题？

**答：** 因为文档的边际成本在维护，不在创建：多一份文档就多一处会过期的地方。三问是"能不能不写"的过滤器。

- **① 能机械判吗**：能写成检查的，就不要写成文档——检查不会过期。
- **② 与既有重复吗**：重复就改既有，别新增第二真源。
- **③ 只服务当前任务吗**：是就放可删目录，任务结束随之消失。
- **三问皆否**才落到长期知识区，并且要有明确读者。
- **代价**：判断成本；换来的是文档总量可控。

**各家做法**：

- **严格项目**：文档变更需评审，新增需说明读者与维护者。
- **开源项目**：以"代码即文档"为原则，减少独立文档。
- **企业**：文档模板强制填写"读者/维护者/更新时机"。
- **一般团队**：文档随需求膨胀，过期后无人敢删。
- **本研究仓**：三问 + 台账克制。

**是统一标准吗**：不是。

## 3. 为什么被引用的材料不能只放可删目录？

**答：** 因为"引用"意味着它会被别人当成依据；一旦所在目录被清理，引用就悬空，而悬空通常不会报错——直到有人去查。

- **可删目录**：过程产物、构建中间物、临时脚本。
- **非易失位置**：被引用的数据、生成器、证据、快照。
- **悬空引用的危害**：结论无法复核，等于失去可追溯性。
- **机械检查**：被引用路径必须存在、且未被忽略规则排除。
- **判据**："半年后有人查这条结论，能不能找到原文？"

**各家做法**：

- **标准组织**：引用必须指向稳定编号的文档。
- **学术**：引用需可长期访问（存档副本、DOI）。
- **企业**：引用指向文档管理系统，不指向个人目录。
- **一般项目**：引用常指向临时链接，几个月后失效。
- **本研究仓**：悬空引用门控。

**是统一标准吗**：不是。

## 4. 为什么台账要克制？

**答：** 因为台账一旦膨胀就会失真：同一个事实被抄到三处，改一处漏两处，最后没人知道哪份可信。克制不是少记，而是"每类事实只有一处"。

- **三份台账**：状态（现在到哪）、问题（已知缺陷与风险）、教训（判据与反例）。
- **细节归处**：任务书、日志、证据；台账只留索引与判据。
- **禁止复制**：台账不复述细节，只写指针与结论。
- **判据**："这条信息变了，要改几处？"超过一处就是重复。
- **代价**：查细节要跳转；换来的是台账可信。

**各家做法**：

- **开源项目**：议题库 + 变更日志 + 设计文档三处，边界清晰。
- **企业**：需求/缺陷/风险三套系统，靠编号互链。
- **小团队**：一个表格包打天下，半年后没人维护。
- **本研究仓**：状态/问题/教训分列，禁止复制细节。

**是统一标准吗**：不是。

## 5. 为什么生成物必须能重派生比对？

**答：** 因为生成物（表、清单、别名、期望值）会随输入悄悄变化：输入改了但没人重新生成，或生成器版本变了没人发现。能重派生并逐字节比对，才能把"漂移"变成可判定的失败。

- **要求**：生成器提供"重新生成 + 比对"模式；产物带来源与版本信息。
- **进门控**：比对必须自动跑，否则等于没有。
- **差异报告**：指出第一处差异的位置，而不是只说"不一致"。
- **生成器与被生成物同仓**：避免"生成器在别处、产物在这里"。
- **代价**：生成要可重复（顺序、时间戳、路径都要固定）。

**各家做法**：

- **编译器**：表生成后比对，防止手改生成物。
- **协议项目**：从 schema 生成代码，CI 校验生成结果无差异。
- **文档站**：目录与索引自动生成，漂移即报。
- **一般项目**：生成物手工维护，漂移长期存在。
- **本研究仓**：生成器 `--check` + 门控。

**是统一标准吗**：不是。

## 6. 为什么讲义与规范的写法不同？

**答：** 因为两者服务的目标相反：规范要"可机械校验、无歧义"，讲义要"可读、可教、能建立直觉"。用规范体写讲义会难读，用讲义体写规范会不可校验。

- **规范**：精确定义、边界穷举、术语一致；允许枯燥。
- **讲义**：先给一句话答案，再展开；允许类比与反例；示例优先。
- **共享部分**：术语与事实必须一致（否则读者被教错）。
- **做法**：讲义引用规范时只讲"结论与直觉"，把可校验细节留给规范。
- **反例**：讲义里写死具体编码数字，规范一改就全错。

**各家做法**：

- **标准组织**：规范 + 教程 + 实施指南三件套。
- **教材**：以直觉与示例为主，规范细节给指针。
- **厂商文档**：手册 + 应用笔记分离。
- **研究**：论文讲思想，代码讲细节。
- **本研究仓**：讲义不写死易变数字。

**是统一标准吗**：不是。

## 7. 实例：生成器有自检，但不在门控里

**现象**：生成的期望值悄悄变了，没人发现；某天门控突然大面积变红，定位发现是生成物先漂移。

**根因**：生成器提供了"重派生比对"能力，但没有接入任何门控——能力存在但没被使用。

**规矩**：凡入库的生成物，生成器必须支持重派生比对，且比对要进门控。

**机械防**：
- 门控跑"重新生成 → 逐字节比对"，不一致即红。
- 产物头部记录生成器版本与输入哈希。
- 差异报告定位到第一处不同，便于快速归因。

## 8. 实例：引用的材料只在临时区

**现象**：半年后追一条结论的依据，发现原文只在已被清理的目录里，只能重做实验。

**根因**：把"一次性使用"误当成"可以不保留"，忽略了"被引用"这个属性。

**规矩**：被引用的材料必须有非易失落点；临时目录只放过程产物。

**机械防**：
- 引用检查：被引用路径必须存在且未被忽略规则排除，悬空即红。
- 引用登记：结论类文档必须登记所依据材料的落点。
- 清理前扫描引用，命中即拒绝清理。

## 背景知识

### 术语与概念

- **三分界**：按读者划分文档落点（规范 / 流程 / 结论）。
- **单一真源**：同一事实只有一处权威描述。
- **指针**：指向真源的引用，不复制内容。
- **悬空引用**：指向不存在位置的引用。
- **台账**：状态、问题、教训三类索引。
- **重派生**：由输入与生成器重新产出内容。
- **漂移**：产物与输入/生成器不一致。
- **可删目录**：过程产物所在位置，允许随时清理。

### 对照

**文档分层**

- **标准组织**：规范 / 指南 / 教程。
- **开源项目**：贡献指南 / 设计文档 / 变更日志。
- **企业**：流程手册 / 架构文档 / 决策记录。
- **本研究仓**：规范 / 流程 / 结论三分界。

**台账规模**

- **克制**：三类各一份，细节外链。
- **膨胀**：事实多处复制，过期后不可信。
- **判据**：一处变动需要改几处。

**生成物管理**

- **强**：生成器 + 比对门控 + 差异定位。
- **中**：生成器存在但不入门控。
- **弱**：手工维护生成物。
