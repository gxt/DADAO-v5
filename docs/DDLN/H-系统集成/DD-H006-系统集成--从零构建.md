# 系统集成 -- 从零构建

**本册要点**

- 从零构建的核心是**自举链**：先用宿主工具造出目标工具链，再用目标工具链造系统。
- 分阶段 + 检查点是唯一可行的推进方式：每阶段结束要有"能验证的产物"。
- 最大敌人是**宿主泄漏**：宿主头文件、库、工具悄悄参与构建。
- 可复现要求：固定版本、固定选项、固定顺序、记录哈希。
- 成本很高（小时级到天级），所以要先能"只重建失败的那一段"。

## 1. 自举链为什么必须分两段？

**答：** 因为一开始没有目标编译器：只能用宿主工具先造出一个"能生成目标代码"的编译器，再用它重新编译所有东西（包括它自己），否则产物里会残留宿主假设。

- **第一段**：宿主工具 + 目标描述 → 初始交叉工具链。
- **第二段**：用初始工具链重建工具链（自编译），消除宿主影响。
- **为什么必须重建**：第一段产物可能链接了宿主库、用了宿主默认参数。
- **判据**：用第二段工具链重建出的东西，与第一段的产物不同（说明第一段不干净）。

## 2. 阶段怎么划分？

**答：** 按"依赖方向"划：工具链 → C 库 → 基础工具 → shell → 系统服务 → 应用；每阶段有明确的输入输出。

- **阶段一**：交叉工具链（能在宿主生成目标代码）。
- **阶段二**：C 库（没有它，什么都链接不了）。
- **阶段三**：基础工具与 shell（能执行脚本）。
- **阶段四**：init 与系统服务（能启动）。
- **阶段五**：应用与数据。
- **规则**：每阶段结束做检查点（产物 + 哈希 + 最小验证）。

## 3. 宿主泄漏怎么发现？

**答：** 看构建日志里的路径：出现宿主路径即泄漏；另外用"干净环境"和"最小 sysroot"来验证。

- **日志审查**：搜索宿主根路径、宿主库路径。
- **干净环境**：在容器或纯净变量（清空路径与标志）里重建。
- **最小 sysroot**：只放目标的东西，缺少就报错，而不是悄悄回落到宿主。
- **差分验证**：两段工具链产物比对。
- **判据**：换一台没有宿主开发包的机器，仍能构建成功。

## 4. 可复现要固定什么？

**答：** 四固定一记录：版本、配置、顺序、环境；记录产物哈希与完整命令。

- **版本**：每个包的源码版本与补丁。
- **配置**：编译选项、功能开关。
- **顺序**：阶段与包顺序固定，不做并行不确定调度。
- **环境**：路径、时间戳（构建产物内不要时间戳）、用户与主机名。
- **记录**：最终镜像/包的哈希 + 构建脚本版本。

## 5. 成本怎么控制？

**答：** 分层缓存 + 断点续建：工具链与库不常变，缓存它们；只重建变化的部分。

- **缓存**：按阶段缓存产物，输入不变则跳过。
- **断点**：失败后从该阶段继续，不从头再来。
- **并行**：只在不影响确定性的前提下并行。
- **裁剪**：只为目标用途构建必要组件。
- **判据**：改一行脚本不应导致全量重建。

## 6. 常见坑有哪些？

**答：** 路径污染（宿主优先）、宿主库泄漏、工具链未自编译、时间戳进入产物、并行导致不确定顺序。

- **路径污染**：环境变量里宿主路径在前。
- **库泄漏**：链接时搜到宿主库。
- **未自编译**：只用第一段工具链，产物带宿主假设。
- **时间戳**：产物内含构建时间，哈希不可复现。
- **并行不确定**：链接顺序变化导致产物差异。

## 背景知识

### 术语与概念

- **自举链**：用宿主工具造目标工具的链条。
- **自编译**：用目标编译器重建它自己。
- **阶段检查点**：每阶段的产物与验证。
- **宿主泄漏**：宿主资源参与目标构建。
- **可复现构建**：同输入同产物。
- **sysroot**：目标根，限制搜索范围。

### 对照

**构建路线**

- **完全自举**：可控、慢、教学价值高。
- **现成发行版**：快、不透明。
- **混合**：关键件自建、其余用包。

**成本控制**

- **阶段缓存**：主流做法。
- **全量重建**：可靠但慢。
- **判据**：改一处是否触发全量。
