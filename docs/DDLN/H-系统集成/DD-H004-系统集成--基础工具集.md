# 系统集成 -- 基础工具集

**本册要点**

- 一个系统"能用"的标志之一是：有 shell、能看文件、能看进程——这靠基础工具集。
- **单体多调用**（一个二进制、多个入口）是嵌入式与小系统的主流做法：省空间、部署简单。
- 裁剪不是删功能，而是**按用途选功能**；选多了只是占空间，选少了连脚本都跑不起来。
- shell 是工具集的灵魂：没有它，启动脚本与排障都无从谈起。
- 静态链接的工具集最省心（无解释器依赖），代价是体积与升级方式。

## 1. 为什么需要基础工具集？

**答：** 因为系统启动后要做的事都是"用工具做工具"：挂载、建目录、起服务、看日志、改配置；没有 shell 与基本命令，系统只能跑单个程序。

- **最小集合**：shell、文件操作（ls/cp/mv/rm）、文本（cat/grep/sed）、进程（ps/kill）、挂载与管理。
- **启动脚本**：由 shell 解释执行，因此 shell 是必需的。
- **排障**：没有工具，现场只能靠"重烧镜像"。
- **判据**：能否在不重新构建的情况下定位一个启动问题。

## 2. 为什么用"单体多调用"？

**答：** 因为几十个小工具各带一份库与启动代码会占大量空间；把入口合并到一个二进制，按调用名分派，空间与部署成本都大幅下降。

- **机制**：一个可执行文件，按 argv[0] 或第一个参数选择功能。
- **收益**：体积小、符号表小、部署简单。
- **代价**：单点故障（一个二进制坏了全坏）、调试不如独立工具方便。
- **取舍**：小系统用单体；通用发行版用独立包。
- **注意**：功能必须真的等价，不能"看起来有、跑起来缺"。

## 3. 裁剪按什么标准？

**答：** 按"启动必需 + 排障必需 + 应用必需"三层选；不确定的先用全量，跑通后再按实际使用情况裁。

- **启动必需**：挂载、建目录、起 init、网络（若需要）。
- **排障必需**：shell、查看文件与进程、日志工具。
- **应用必需**：由目标应用决定。
- **方法**：先全量跑通 → 记录实际调用的命令 → 再裁。
- **陷阱**：按"印象"裁剪，结果启动脚本里少一个命令就卡住。

## 4. shell 怎么选？

**答：** 优先选与工具集配套、功能够用的那个：启动脚本需要的语法（条件、循环、函数、变量展开）必须支持。

- **最小**：只支持基本语法，脚本要写得朴素。
- **完整**：语法齐全、交互友好，体积大。
- **配套**：与工具集同一来源可减少兼容问题。
- **判据**：启动脚本与运维脚本能否不经修改地跑。
- **陷阱**：用完整 shell 写脚本，换成最小 shell 后全崩。

## 5. 静态还是动态？

**答：** 小系统优先静态：没有解释器依赖，拷贝即用；通用系统用动态：共享库、升级方便。

- **静态**：单文件可用、无加载器问题；体积大、每个工具各带一份库。
- **动态**：共享库省空间；依赖解释器与搜索路径。
- **混合**：核心工具静态、其余动态。
- **判据**：是否能保证解释器与库一定存在。
- **常见故障**：动态工具在最小根文件系统里找不到库。

## 背景知识

### 术语与概念

- **单体多调用**：一个二进制提供多个命令入口。
- **applet**：单体程序里的一个命令实现。
- **裁剪**：按用途选择编译进来的功能。
- **启动脚本**：初始化时执行的脚本。
- **静态链接**：把库打进可执行文件。

### 对照

**工具集形态**

- **单体**：小、省空间、单点故障。
- **独立包**：灵活、体积大、依赖多。
- **混合**：核心单体 + 扩展独立。

**shell 选择**

- **最小**：脚本朴素、体积小。
- **完整**：语法齐全、体积大。
- **判据**：启动脚本可否直接运行。
