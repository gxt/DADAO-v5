# 系统集成 -- C 库与运行时

**本册要点**

- 选型先看**环境约束**：裸机没有内核，只能用带桩的嵌入式库；有 Linux 才能用 musl/glibc。
- 在可行集合内，按体积、许可、动态链接、线程与本地化、维护成本取舍。
- 动态链接器与加载路径决定"程序能不能被装载"，比库本身更容易出错。
- 启动代码与构造器决定"程序跑起来前发生了什么"。
- 静态 / 动态 / PIE 是三种形态，选择会反向影响工具链与测试。
- 选型结论必须带前提，否则会变成教条。

## 1. 为什么选型要先看环境约束？

**答：** 因为库依赖内核：嵌入式库靠桩函数提供 I/O 与内存，Linux 库靠系统调用；选错了不是"不好用"，而是根本跑不起来。

- **裸机/RTOS**：无内核 ⇒ 只能选提供桩接口的嵌入式库。
- **Linux 用户态/完整系统**：有系统调用 ⇒ musl / glibc 一类。
- **约束来源**：目标有没有内核、有没有内存管理单元、镜像大小限制。
- **结论**：先由环境圈定可行集合，再谈偏好。

## 2. 四个常见候选怎么取舍？

**答：** 按六个维度打分：体积、许可、动态链接能力、功能完整度（线程/本地化/名字服务）、系统调用依赖、维护与生态。

- **嵌入式精简库**（picolibc 一类）：体积小、静态为主、I/O 靠钩子、无动态链接。
- **传统嵌入式库**（newlib 一类）：历史久、桩接口清晰、教学常用。
- **轻量 Linux 库**（musl 一类）：许可宽松、静态友好、体积小；功能上比 glibc 少。
- **完整 Linux 库**（glibc 一类）：功能最全、ABI 稳定、动态链接成熟；体积大、许可约束强。
- **取舍原则**：先排除不可行的，再按"最缺的那一项"决定。

## 3. 动态链接器与加载路径为什么关键？

**答：** 因为程序启动第一步就是找解释器：路径错、搜索路径错、版本错，都会表现为"程序根本起不来"，而错误信息往往很晦涩。

- **解释器路径**：写在可执行文件里，必须存在于目标根。
- **搜索路径**：库目录配置（配置文件或环境变量）。
- **版本与符号**：同名库不同版本可能导致解析失败。
- **排查**：先看解释器是否存在，再看依赖能否全部解析。
- **反例**：静态链接能跑、动态链接起不来——问题几乎都在这一层。

## 4. 启动代码与构造器做什么？

**答：** 启动代码负责"把 C 运行环境搭起来"（栈、数据段、清零段、参数、构造器），然后调入口；构造器负责在 `main` 前初始化全局对象与库状态。

- **启动代码**：设栈、搬数据段、清零段、传参数、调构造器、进 `main`。
- **构造器**：按表执行初始化函数；顺序与依赖有关。
- **退出路径**：`main` 返回后走退出流程（刷新缓冲、调退出钩子）。
- **裸机差异**：没有内核，退出靠半主机或停机指令。
- **常见缺陷**：漏清零段 ⇒ 全局变量初值随机；构造器未跑 ⇒ 库状态未初始化。

## 5. 静态、动态、PIE 怎么选？

**答：** 静态最简单（无加载器）、动态最省空间（共享库）、PIE 最安全（地址随机化）；三者对工具链与库的构建方式要求不同。

- **静态**：单文件、部署简单；体积大、升级要整体替换。
- **动态**：共享库、升级方便；依赖解释器与搜索路径。
- **PIE**：位置无关、可随机化；要求库也用位置无关方式构建。
- **约束**：静态 PIE 需要"位置无关的静态库"。
- **判据**：部署环境是否可控、是否要求安全加固。

## 6. 选型结论怎么写？

**答：** 必须写成"在什么前提下选什么、放弃了什么、代价是什么"，而不是"某库最好"。

- **前提**：目标环境、内存/镜像限制、是否需要动态链接、许可要求。
- **取舍**：选它的理由，以及被放弃方案的理由。
- **代价**：功能缺口（如本地化、名字服务）、调试难度、维护成本。
- **复核**：环境变化时重新评估（例如从裸机转到 Linux）。
- **反例**：把"某库体积小"当成普遍结论，忽略它缺功能。

## 背景知识

### 术语与概念

- **C 库**：提供标准函数与系统调用封装的运行库。
- **动态链接器**：装载程序并解析共享库。
- **启动代码**：进入 `main` 前的初始化代码。
- **构造器**：`main` 之前执行的初始化函数。
- **PIE**：位置无关可执行文件。
- **sysroot**：目标的根，供编译器查找头与库。

### 对照

**库的定位**

- **嵌入式精简**：裸机、RTOS，静态为主。
- **轻量 Linux**：静态友好、体积小。
- **完整 Linux**：功能全、动态成熟。
- **专用**（如移动平台）：与通用 Linux 不兼容。

**链接形态**

- **静态**：部署简单、体积大。
- **动态**：共享、依赖解释器。
- **PIE**：安全加固、要求库配套。
