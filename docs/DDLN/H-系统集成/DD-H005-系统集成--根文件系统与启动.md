# 系统集成 -- 根文件系统与启动

**本册要点**

- 根文件系统是"系统启动时挂载的第一个文件系统"，它的布局与内容决定系统能否起来。
- 目录布局遵循通用约定（可执行、配置、设备、临时、用户数据分区）。
- **init** 是第一个用户态进程：启动服务、回收孤儿进程、处理关机。
- 设备节点与伪文件系统（进程信息、内核参数）必须就位，否则很多工具直接失败。
- 启动失败大多集中在四处：挂载、init 路径、设备节点、权限。

## 1. 根文件系统要放什么？

**答：** 按用途分目录：可执行文件、库、配置、设备节点、运行时数据、用户数据；关键是"启动时需要的都在里面"。

- **可执行与库**：工具集、C 库、动态链接器。
- **配置**：启动脚本、服务配置、网络配置。
- **设备**：设备节点或由内核自动生成。
- **运行时**：临时目录、锁目录、日志目录。
- **用户数据**：家目录、应用数据。
- **判据**：把镜像挂到另一台机器上，能否看出"这是一个系统"。

## 2. init 该做什么？

**答：** 三件事：启动系统服务（按依赖顺序）、回收孤儿进程、处理关机与重启；它是所有用户态进程的祖先。

- **顺序**：先挂载与基础服务，再网络与应用。
- **依赖**：服务之间有先后，顺序错会"看起来起来了但功能不可用"。
- **回收**：孤儿进程必须被回收，否则进程表泄漏。
- **关机**：通知服务停止、刷缓存、卸载文件系统。
- **陷阱**：把 init 写成一个大脚本，出错后无法定位。

## 3. 设备节点与伪文件系统怎么处理？

**答：** 优先让内核自动生成设备节点（设备文件系统），并挂载进程信息与内核参数伪文件系统；只有内核不生成时才用静态节点。

- **自动生成**：内核挂载设备文件系统，节点随设备出现。
- **伪文件系统**：进程信息、内核参数、调试信息。
- **静态节点**：仅在无自动生成能力时使用，需固定主次设备号。
- **权限**：节点权限错会导致"设备在但打不开"。
- **判据**：`/dev` 下的节点与真实设备一致。

## 4. 启动脚本怎么组织？

**答：** 分层：基础（挂载、时区、主机名）→ 服务（按依赖）→ 应用；每步失败要能看出是哪一步。

- **分层**：基础层失败通常意味着"系统起不来"；应用层失败只影响功能。
- **日志**：每一步打印标记，便于定位卡在哪。
- **幂等**：重复执行不产生副作用。
- **超时**：长时间无响应的步骤要能中断，否则看起来"卡死"。
- **陷阱**：脚本里用了裁剪时被去掉的命令。

## 5. 启动失败怎么定位？

**答：** 按顺序排查四层：引导加载器 → 内核 → 挂载根文件系统 → init；每层都有典型症状。

- **引导层**：无任何输出 ⇒ 加载器或镜像问题。
- **内核层**：有内核日志但停住 ⇒ 缺驱动或参数错。
- **根文件系统**：提示找不到 init 或挂载失败 ⇒ 路径/格式/权限。
- **init 层**：起来了但服务不全 ⇒ 脚本或依赖。
- **手段**：串口早期输出、内核命令行、最小 init（只打印）逐层缩小范围。

## 背景知识

### 术语与概念

- **根文件系统**：启动时挂载的第一个文件系统。
- **init**：第一个用户态进程。
- **设备节点**：代表设备的特殊文件。
- **伪文件系统**：由内核提供、不占磁盘的文件系统。
- **启动脚本**：初始化阶段执行的脚本集合。
- **挂载**：把文件系统接到目录树上。

### 对照

**init 形态**

- **脚本型**：简单、可控，依赖顺序手工维护。
- **服务管理器**：依赖声明、并行启动，复杂。
- **单一二进制 init**：与工具集同源，体积小。

**设备节点**

- **自动生成**：主流，随设备出现。
- **静态节点**：无自动生成能力时使用。
- **判据**：节点与真实设备是否一致。
