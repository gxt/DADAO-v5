# 系统集成 -- 交叉工具链与 sysroot

**本册要点**

- 交叉编译的本质是"**目标 ≠ 宿主**"：编译器跑在宿主，产物跑在目标。
- **sysroot** 是目标的根：头文件、库、启动文件、动态链接器都在里面；它必须**不含宿主的东西**。
- 最容易出的错不是编译失败，而是**宿主泄漏**：宿主头文件或库悄悄参与了构建，产物在目标上跑不起来。
- 三方必须配套：编译器、头文件、库——版本错配的症状往往延迟到运行期。
- 验证配套只需一个**最小程序**：编译 → 链接 → 在目标上运行并退出。

## 1. 为什么必须用交叉工具链？

**答：** 因为目标机器跑不了编译器（性能、架构、甚至还没有系统），而宿主编译器产出的代码不能直接在目标上执行。交叉工具链把"在哪编译"和"在哪运行"分开。

- **宿主**：开发机，负责编译。
- **目标**：要跑程序的环境（模拟器或实机）。
- **前缀命名**：`<arch>-<vendor>-<os>-<abi>` 一类，表明产物面向谁。
- **判据**：产物能否在目标上执行，而不是在宿主上"看起来对"。

## 2. sysroot 是什么，该放什么？

**答：** 是"目标系统的根"，用来定位头文件、库、启动文件与动态链接器；它只应包含目标的东西，宿主的东西一律不该进来。

- **头文件**：目标的 C 库头与内核头。
- **库**：静态库、共享库、启动文件（`crt0` 一类）。
- **动态链接器**：目标上的解释器路径。
- **不放**：宿主 `/usr/include`、宿主库、宿主工具。
- **检查**：编译器应报告实际使用的 sysroot 路径，构建日志应能核对。

## 3. 三方配套错配有什么后果？

**答：** 症状延迟且隐蔽：编译能过、链接能过，运行期才崩（结构体布局不同、符号版本不匹配、启动文件不匹配）。

- **编译器与头文件错配**：类型宽度、对齐、宏定义不一致。
- **头文件与库错配**：函数签名或符号版本不一致，链接期或运行期失败。
- **库与动态链接器错配**：加载失败或解析到错误版本。
- **共同根因**：某个环节偷偷用了宿主的副本。
- **判据**：三方必须来自同一套构建，且版本可核对。

## 4. 怎么验证配套是对的？

**答：** 一个最小程序走完整链路：编译、链接、在目标上运行并正常退出；同时检查它实际链接的库与解释器路径。

- **最小程序**：打印一行、调用一次库函数、返回 0。
- **检查解释器**：产物里记录的解释器路径必须存在于目标根。
- **检查依赖**：列出动态依赖，确认都来自目标 sysroot。
- **运行验证**：在模拟器或实机上跑一次，退出码为 0。
- **价值**：一次验证能挡住大部分错配。

## 5. 宿主泄漏怎么防？

**答：** 三条：显式指定 sysroot、禁用宿主默认搜索路径、审查构建日志里出现的宿主路径。

- **显式 sysroot**：编译与链接都传，不依赖默认值。
- **禁用默认路径**：头文件与库搜索只指向目标根（必要时加"不搜标准路径"）。
- **日志审查**：构建日志里出现宿主路径即视为可疑。
- **环境隔离**：干净环境（容器或纯净变量）能显著降低泄漏概率。
- **反例**：本机能过、换机器就挂——典型泄漏症状。

## 6. 多目标、多版本怎么并存？

**答：** 按"前缀 + 目标三元组"分目录，每个组合一套独立的安装根与 sysroot；切换靠环境文件或显式路径，不靠修改全局配置。

- **目录**：每个目标一套前缀，互不覆盖。
- **环境**：用脚本设置路径与 sysroot，可复现。
- **默认值**：不设全局默认，避免"忘了切"。
- **记录**：构建配置里写明用的哪套。
- **判据**：同时装三套工具链时不会互相污染。

## 背景知识

### 术语与概念

- **交叉编译**：在宿主生成目标代码。
- **sysroot**：目标的根目录，供编译器查找头与库。
- **宿主泄漏**：构建过程中误用宿主资源。
- **启动文件**：程序入口与运行环境初始化代码。
- **目标三元组**：描述目标架构/系统/ABI 的标识。

### 对照

**工具链组织**

- **前缀分目录**：多目标并存的标准做法。
- **容器隔离**：彻底但重。
- **全局安装**：最省事、冲突最多。

**常见错配**

- **编译器/头文件**：类型与宏不一致。
- **头文件/库**：符号与签名不一致。
- **库/解释器**：加载失败。
