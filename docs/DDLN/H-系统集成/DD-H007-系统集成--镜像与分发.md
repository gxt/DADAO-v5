# 系统集成 -- 镜像与分发

**本册要点**

- 镜像 = 内核 + 根文件系统 + 引导方式；三者必须匹配。
- 先问"**要交给谁、在哪跑**"：模拟器镜像、实机镜像、容器镜像，三者不是一回事。
- ISO 只在"有可引导固件 + 可引导内核"时才有意义；没有稳定内核时它是空壳。
- 镜像必须可**从零重建**：同输入同哈希，否则分发的是不可审计的黑盒。
- 交付物要带版本清单与哈希，且不含运行产物。

## 1. 镜像由哪几部分组成？

**答：** 三部分：引导链（加载器与参数）、内核（含驱动最小集）、根文件系统（库、工具、init）；三者版本必须互相匹配。

- **引导链**：谁把内核放进内存、传什么参数、根文件系统在哪。
- **内核**：能不能挂载目标文件系统、有没有必需驱动。
- **根文件系统**：能否启动到 init、库是否齐全。
- **匹配性**：内核版本与库/工具链的 ABI 必须一致。
- **判据**：换掉任一部分还能起来吗？不能说明耦合没理清。

## 2. 交付形态怎么选？

**答：** 按使用场景：模拟器用的镜像（磁盘/内存盘）、实机用的镜像（可写介质/网络引导）、开发环境用的容器镜像；三者内容与构建方式不同。

- **模拟器镜像**：打包成模拟器能直接加载的形式，启动快。
- **实机镜像**：考虑可写介质、分区表、引导固件要求。
- **容器镜像**：装的是开发环境，不是目标系统（属运行平台册）。
- **判据**：接收方拿到后"下一步做什么"是否明确。
- **反例**：把模拟器镜像直接烧到实机，几乎必然起不来。

## 3. ISO 什么时候才有意义？

**答：** 当目标有标准可引导固件、且有能引导的内核时。若内核还不能稳定启动到用户态，ISO 只是"装有镜像的容器"，没有实际价值。

- **前提一**：可引导固件（BIOS/UEFI 或目标平台等价物）。
- **前提二**：内核能在该固件下加载并启动。
- **前提三**：根文件系统能被内核挂载（内置或外部）。
- **现状判断**：没有稳定内核 ⇒ 先做模拟器镜像，不做 ISO。
- **替代**：需要"给别人一个能跑的系统"时，模拟器镜像 + 启动脚本更实用。

## 4. 镜像怎么保证可复现？

**答：** 固定输入（版本、配置、顺序）、去除时间戳与随机性、记录哈希；构建两次比对。

- **固定**：源码版本、构建脚本、工具链版本。
- **去随机**：文件时间戳、用户/主机名、文件顺序。
- **哈希**：镜像级哈希 + 关键文件清单。
- **验证**：同输入构建两次，哈希一致。
- **判据**：别人拿到清单能否重建同一镜像。

## 5. 分发时带什么、不带什么？

**答：** 带：镜像、版本清单、哈希、启动说明、最小验证用例；不带：运行产物、调试临时文件、大体积日志。

- **带**：镜像本体、清单（组件与版本）、哈希、启动命令、已知限制。
- **不带**：测试运行结果、构建中间物、编辑器与个人配置。
- **体积**：镜像通常以百 MB 到 GB 计，先量再发。
- **可审计**：清单能对应到版本锁。
- **判据**：接收方能否独立验证"这个镜像就是我说的那个"。

## 6. 为什么镜像不能当"正确性证据"？

**答：** 因为镜像只证明"这套组合能跑起来"，不证明"行为符合规范"；正确性要靠判据与测试，而不是"我这儿能启动"。

- **能跑 ≠ 正确**：启动成功只覆盖极少数路径。
- **判据归属**：语义归指令测试，接口归系统测试，性能归评测。
- **镜像的角色**：被测对象与交付物，不是判据。
- **写作要求**：文档里不得用"镜像能启动"代替"验证通过"。

## 背景知识

### 术语与概念

- **镜像**：内核 + 根文件系统 + 引导数据的打包产物。
- **引导链**：从固件到内核的加载过程。
- **可复现镜像**：同输入同哈希。
- **分区表**：介质上的分区描述。
- **版本清单**：镜像内各组件的版本记录。

### 对照

**镜像形态**

- **模拟器镜像**：加载快、便于测试。
- **实机镜像**：受固件与介质限制。
- **容器镜像**：开发环境，不是目标系统。
- **ISO**：需要可引导固件与内核。

**可复现要素**

- **固定输入**：版本、脚本、选项。
- **去随机**：时间戳、顺序、用户名。
- **验证**：两次构建哈希一致。
