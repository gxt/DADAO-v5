# 参考模型 -- 导论

> 状态说明：本册是 B 系列的**导论**——讲为什么需要参考模型、有哪几种形态、与相邻系列怎么分工、各分册查哪里。细论证在 B002–B005，本册不复述。

**本册要点**

- 参考模型存在的唯一理由：**判据必须独立于被测实现**，否则测的只是"两处一致"。
- 四种形态：手写黄金模型、可执行模拟器、形式可执行规范、从厂商文档生成；各有代价。
- 四类用途：仿真、判据、文档、测试生成（外加形式证明入口）。
- 差分能治"实现错"，**治不了"规范错"**——这是本系列最重要的分工。
- 独立性必须能机械检查，不能靠自觉。

## 1. 为什么必须有独立于实现的参考模型？

**答：** 因为用实现（编译器、模拟器、硬件）的输出当期望值，测出来的只是"两处一致"：两处同错时全绿，而这恰恰是最危险的情形。判据必须来自**规范**，且派生路径不能经过被测对象。

- **污染的三条路径**：用被测实现生成期望值；参考模型与实现共享代码或公式；参考模型跟着实现改（"以实现为准"）。
- **独立的判据**：期望值能追溯到规范条款；派生脚本不引用被测实现的产物；模型版本与规范版本绑定。
- **多实现一致仍有价值**：能抓单实现看不见的盲区（对齐、保留编码、返回地址维护等边角）。
- **但不是充分条件**：多实现可能共享同一处误读，一致地错。

**各家做法**：

- **x86-64**：无公开形式语义，业界以"文档伪代码 + 多家实现交叉"为准。
- **ARM64**：架构规范以机器可读描述发布，可直接生成模型。
- **RISC-V**：官方采用形式可执行规范（Sail），另有参考模拟器。
- **MIPS**：无官方形式模型，工程上靠模拟器与硬件对照。
- **SPARC**：无已知形式模型（**待核**）。
- **PowerPC**：IBM 以 XML 描述语义，可机械转换。

**是统一标准吗**：不是。是否有官方形式模型，各家差异极大。

## 2. 四种形态怎么选？

**答：** 看要防哪一类错：防"实现错"，手写模型或模拟器就够；防"规范错"，非形式模型或人工复核不可。

- **手写黄金模型**：最容易起步、最容易被"照抄实现"污染。
- **可执行模拟器**：最接近真实运行，本身也是大型软件，会有 bug。
- **形式可执行规范**：一份定义可产出仿真器、文档、覆盖与测试；成本最高。
- **从厂商文档生成**：上游提供机器可读语义时最不容易漂移；上游不提供就无从谈起。
- **组合**：手写 + 模拟器两路就能覆盖多数工程场景；再加形式模型是"向上游证明规范"的需求。

## 3. 五个分册各管什么（本册为导论，另五册见下）

- **B002 ISA 语义模型**：以 Sail 为例，讲"语义怎么写成可执行形式"、"能换来什么"、"内存与外设为什么要留在 harness"。
- **B003 可执行模型作判据**：黄金模型、参考模拟器、形式模型生成物三者的定位与陷阱（版本、自身 bug、弃权）。
- **B004 判据派生与差分**：期望值的四种来源；生成器重派生比对；签名设计与代价；差分统计与盲区。
- **B005 并发与内存模型**：为什么内存模型不能用指令级期望值表达；litmus 形态；本项目暂不做的代价与最小路径。
- **B006 系统接口与二进制模型**：链接/加载语义判据、系统调用的允许集合与副作用、二进制层分层判据；与链接器册、操作系统册按"实现 / 判据"分界。

## 4. 出问题该查哪一册

- 期望值是怎么来的、能不能追溯到规范 → **B004**。
- 要不要写形式模型、写了能换来什么 → **B002**。
- 模拟器与我的实现不一致，谁错 → **B003**。
- `fence`/原子操作"允许什么结果"，说法不一 → **B005**。
- 系统调用或链接产物"算不算对"，判据怎么定 → **B006**。
- 判据本身是否被实现污染 → **B004**（独立性检查）与 **B001**（污染路径）。

## 5. 与相邻系列的分工

- **测试体系**：管"判据怎么用"（分层、覆盖、门控、统计）；本系列管"判据从哪来、怎么保证独立"。
- **编译工具**：编译器的正确性由判据评判；本系列不讨论编译器怎么实现。
- **资源管理 / 操作系统**：它们定义"机器做什么"；本系列讨论"怎么证明机器确实这么做"。

## 背景知识

### 术语与概念

- **参考模型**：独立于被测实现的语义来源，用于派生判据。
- **黄金模型**：用脚本或高级语言按规范实现的语义模型。
- **形式可执行规范**：用形式语言写成的语义，可被工具执行与检查。
- **判据（oracle）**：判断结果对错的依据。
- **差分测试**：多实现跑同一向量并比较结果。
- **签名**：把最终状态压缩成可比较字符串。
- **弃权（abstain）**：环境或工具不支持，结果未判定。
- **规格覆盖**：模型中被用例走到的语义规则比例。

### 对照

**官方形式模型的可得性**

- **ARM64**：有（架构规范以机器可读描述发布）。
- **RISC-V**：有（Sail 被官方采纳）。
- **PowerPC**：有（由 XML 生成）。
- **x86-64**：无官方模型，有研究性手写模型。
- **MIPS**：无通用形式模型（CHERI 变体有）。
- **SPARC**：无已知形式模型（待核）。
- **共同点**：越靠近"需要对外认证"的生态，越倾向投入形式模型。
