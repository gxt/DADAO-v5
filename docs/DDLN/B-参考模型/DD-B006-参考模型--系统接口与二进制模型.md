# 参考模型 -- 系统接口与二进制模型

**本册要点**

- ISA 判据只管"一条指令算什么"；**程序能不能被正确装载、系统调用是否符合约定**，需要另一层模型。
- 链接/加载层的判据是"产物是否符合规范"：符号、重定位、段属性、可见性。
- 系统接口层的判据不是"返回什么值"，而是"**允许/禁止哪些行为**"——因为接口本身允许非确定性。
- 二进制层把三层串起来：指令语义 → 程序语义 → 系统调用语义。
- 与"链接器册""操作系统册"的分界：那两册讲**怎么实现**，本册讲**怎么判它对不对**。
- 成本集中在"接口面太大"，所以要选**少数高价值接口**先建模。

## 1. 为什么 ISA 判据不够？

**答：** 因为程序出错常常不在单条指令：符号解析错、重定位算错、系统调用语义理解错，都能让"每条指令都对"的程序产生错误结果。判据必须覆盖这三层之间的接缝。

- **接缝一：装载**：ELF 段被放到哪、重定位应用顺序、符号可见性。
- **接缝二：调用**：参数与返回值约定、错误码、副作用。
- **接缝三：资源**：文件、目录、进程状态被改成什么样。
- **为什么不能靠"跑通就算对"**：跑通只说明没崩，不说明行为符合规范。
- **代价**：需要为每一层单独建判据，工作量比 ISA 层更大。

**各家做法**：

- **编译器生态**：以"生成的程序能跑 + 标准测试套件通过"为主要判据。
- **操作系统生态**：以系统调用测试套件（如内核自测）为主要判据。
- **形式方法**：为链接与文件系统单独建语义模型。
- **硬件验证**：只覆盖 ISA 层，系统层交给软件测试。
- **本项目**：ISA 层已有判据思路，系统层尚未成体系。

**是统一标准吗**：不是。

## 2. 链接/加载的参考模型解决什么问题？

**答：** 解决"产物是否符合规范"这一判断：符号该不该被导出、重定位算出来的值对不对、段属性与可见性是否如声明。它把"链接器实现"与"链接语义"分开。

- **判据对象**：ELF 结构（段/节/符号表/重定位表）、重定位后的值、符号可见性与绑定。
- **可判定的问题**：同一份输入，链接结果是否唯一；某符号是否按规则被解析到目标定义。
- **为什么需要模型**：链接器实现互相参照会"一致地错"；语义模型能给出独立判据。
- **形态**：形式化的链接语义（可执行），或"结构化断言 + 期望产物"。
- **难点**：链接语义涉及大量细节（弱符号、公共符号、重定位配对），面很宽。

**各家做法**：

- **研究项目**：有形式化的链接/加载语义模型，可对 ELF 链接做推理。
- **编译器项目**：以"产物 + 断言 + 端到端运行"为主，无形式模型。
- **发行版**：靠 ABI 稳定性测试与大规模重建验证。
- **嵌入式**：靠链接脚本断言与目标板实测。
- **本项目**：以端到端运行 + 产物检查为主。

**是统一标准吗**：不是（ELF 有标准，链接语义的实现自由度很大）。

## 3. 系统调用 oracle 为什么不能只比返回值？

**答：** 因为系统调用的效果大量体现在**副作用**上：文件内容、目录结构、文件描述符状态、进程属性。只比返回值，等于只看"报没报错"，不看"做对没做对"。

- **副作用维度**：文件系统状态、打开的文件、进程状态、信号与退出状态。
- **非确定性**：接口允许"实现自由"（如返回顺序、时间戳精度），判据必须是"允许/禁止的行为集合"，不能是单一期望值。
- **可观测性**：要让行为可比较，需要把副作用序列化成可比的状态摘要。
- **错误路径**：错误码与"出错后状态是否被改动"同样要判。
- **代价**：需要一套"状态快照 + 允许集合"的框架。

**各家做法**：

- **文件系统 oracle**：用"允许的操作序列与结果集合"判定实现，而不是单一返回值。
- **内核自测**：断言返回值 + 关键副作用（有的覆盖较全，有的只测返回值）。
- **POSIX 合规测试**：以行为集合为主，覆盖面广但维护重。
- **一般项目**：只比返回值与"没崩"。
- **本项目**：尚无系统调用 oracle。

**是统一标准吗**：部分统一（POSIX 定义行为，但测试形态各家自定）。

## 4. 二进制层的判据怎么建？

**答：** 把"指令语义"当原子，往上叠"程序语义"（调用约定、栈布局、异常展开），再叠"系统调用语义"；每层都给判据，层间用可观测状态衔接。

- **层次**：单指令 → 函数（调用约定、栈帧）→ 程序（装载、初始化）→ 系统（调用与资源）。
- **判据衔接**：下层输出（寄存器/内存）成为上层输入；每层只判自己那一段。
- **可观测点**：函数入口/出口状态、系统调用前后的状态摘要。
- **为什么分层**：出错时能定位到"哪一层的判据红了"，而不是只看到"程序结果不对"。
- **代价**：每层都要独立的期望值来源。

**各家做法**：

- **编译器测试**：函数级（IR → 汇编）+ 程序级（运行结果）两层。
- **ABI 测试**：函数调用约定专项，逐条参数组合。
- **内核测试**：系统调用级，断言返回值 + 副作用。
- **硬件验证**：只到指令级。
- **本项目**：函数级与程序级已有，系统级缺。

**是统一标准吗**：不是。

## 5. 与链接器册、操作系统册的边界在哪？

**答：** 那两册讲"怎么实现"（链接器怎么做、内核怎么用机制）；本册讲"怎么判它对不对"（用什么判据、判据从哪来、允许集合怎么定）。

- **链接器册**：ELF 结构、重定位类型、链接脚本、动态链接——**实现与机制**。
- **操作系统册**：系统调用表、进程、页表、异常、驱动——**用法与策略**。
- **本册**：链接语义判据、系统调用行为集合、二进制层分层判据——**判据与模型**。
- **判据**："这段话是在说'怎么做'还是'怎么判'？"后者归本册。
- **反例**：把 `readelf` 的输出当"判据"——那只是观测手段，判据要说明"什么样的输出才算对"。

**各家做法**：

- **研究项目**：模型与实现分属不同论文/仓库。
- **工业项目**：测试与实现同仓，边界靠目录与命名区分。
- **标准组织**：规范（怎么算对）与实现（怎么做）分离。
- **本项目**：按"实现 / 判据"分册。

**是统一标准吗**：不是。

## 6. 成本与最小路径是什么？

**答：** 成本在"接口面太大"：系统调用数百个、链接语义细节极多。最小路径是只挑**高价值接口**（文件读写、进程创建退出、内存映射）与**高价值链接语义**（符号解析、常用重定位），先建判据再扩。

- **第一步：选面**：系统调用选 5–10 个最常用；链接选"符号解析 + 常用重定位 + 可见性"。
- **第二步：定判据**：返回值 + 状态摘要 + 允许集合（允许非确定性的部分）。
- **第三步：建观测**：状态摘要算法固定（否则跨版本不可比）。
- **第四步：接门控**：与 ISA 判据分开统计，避免混在一起看不出层次。
- **代价**：只覆盖一部分；但比"全覆盖但不可判定"更有价值。

**各家做法**：

- **内核测试**：按子系统逐步覆盖。
- **文件系统 oracle**：先覆盖核心操作，再扩展。
- **链接器测试**：按重定位类型逐类覆盖。
- **一般项目**：只做端到端，出问题靠人查。
- **本项目**：尚未开始。

**是统一标准吗**：不是。

## 7. 实例：系统调用只比返回值

**现象**：系统调用测试全绿，但文件内容不对、目录多出残留、文件描述符泄漏；这些问题都在返回值里看不出来。

**根因**：判据只覆盖返回值，未覆盖副作用；"成功"被定义成"没报错"。

**规矩**：系统调用判据必须包含"返回值 + 状态摘要"，错误路径还要判"状态是否被改动"。

**机械防**：
- 每条用例声明观测点（返回码、文件内容摘要、目录项集合、描述符表）。
- 缺观测点的用例不得入库。
- 审查时改坏一处副作用，确认用例会红。

## 8. 实例：链接产物"能跑"就当对了

**现象**：链接产物能运行，但符号可见性不符合声明（内部符号被导出、弱符号解析顺序错）；换一种链接方式后行为变了。

**根因**：判据只有"能跑"，没有"符号与重定位是否符合规范"。

**规矩**：链接层判据要看结构（符号表、重定位结果、段属性），不能只看运行结果。

**机械防**：
- 产物检查作为固定环节：符号可见性、未定义符号、重定位配对。
- 对同一输入做"链接两次结果一致"的确定性检查。
- 把结构检查与运行测试分开统计，避免运行通过掩盖结构错误。

## 背景知识

### 术语与概念

- **链接语义**：符号解析、重定位、可见性等规则的总和。
- **加载语义**：把可执行映像放入地址空间并转移控制的过程。
- **系统调用 oracle**：判定系统调用行为是否合规的参考实现。
- **允许集合**：接口规范允许出现的多种行为。
- **状态摘要**：把文件/目录/进程状态序列化成可比较的值。
- **副作用**：调用在返回值之外造成的状态变化。
- **二进制层**：从指令到程序、再到系统接口的层次划分。

### 对照

**链接判据**

- **结构检查**：符号表、重定位结果、段属性。
- **运行测试**：端到端跑通，粒度粗。
- **形式语义**：研究项目，可推理但成本高。

**系统调用判据**

- **仅返回值**：最弱，漏副作用。
- **返回值 + 状态**：主流。
- **允许集合**：适合有非确定性的接口（文件系统、时间）。

**分层覆盖**

- **指令级**：硬件验证与 ISA 合规。
- **函数级**：ABI 与编译器测试。
- **程序级**：端到端测试。
- **系统级**：内核自测与接口 oracle。
