# 大道至简——浮点运算

**本册要点**

- IEEE 754 默认模型：异常只置状态位，不陷入。
- 状态位 NV/DZ/OF/UF/NX；舍入模式 RNE/RTZ/RDN/RUP。
- min/max 采用 `minimumNumber`/`maximumNumber`（NaN 不传播）。
- FMA：`a×b+c` 只舍入一次。
- 格式转换（`ft2fo`/`fo2ft`、int↔float）：`orri` 块操作，1–63 条，源/目的不重叠。
- 算术/取整/平方根/scaleB：`ftadd`…、`ftrnd`/`fornd`、`ftroot`/`foroot`、`ftsclb`/`fosclb`。
- 比较/分类/符号位：`ftqcmp`/`ftscmp`、`ftcls`/`focls`、`ftsgnj`/`ftsgnn`。
- 除零：浮点返回 ±Inf/qNaN 并置 DZ/NV；整数返回定值，不陷入。
- `rf0` 既是 qNaN 又是 FCSR；可作源/目的，不可作浮点运算目的。
- 保存 `rf0`–`rf63` 即保存 FCSR。

## 1. 为什么浮点不引发异常，而只是设置异常状态位？

**答：** 因为采用 IEEE 754 的"默认（非停止）"模型：异常只按 IEEE 754 累积到状态位，由软件在需要时检查，硬件不逐条陷入。

- **IEEE 754 的模型**：IEEE 754 把除零、无效、溢出、下溢、不精确定义为"异常信号"，实现可以选择"默认返回结果 + 置状态位"或"陷入"；SimRISC 选前者。
- **结果确定**：任何浮点运算都按 IEEE 754 返回确定结果（NaN/Inf/0 等），不改变控制流；软件通过读 `rf0[4:0]`（NV/DZ/OF/UF/NX）判断是否发生过异常。
- **实现简单**：精确的浮点陷阱在流水线里很难做（结果产生晚、要保证精确异常）；改成"粘滞状态位 + 软件检查"就不需要为浮点单独设计陷阱与精确异常路径。
- **对乱序/推测友好**：浮点指令没有控制流副作用，可以自由推测执行；状态位是粘滞的（accrued），一旦置位就保持，直到软件清除。
- **软件粒度更灵活**：可以在一个计算块结束后统一检查标志，而不是每条指令都陷入；C 的浮点环境（fenv）也是这种"读/清标志"的模型。
- **代价**：不检查就不知道出过异常；状态位需要软件主动读取和清除。
- **标准**：IEEE 754-2019 把异常定义为"信号"，实现可选"默认值 + 状态位"或"陷入"；本 ISA 选前者。
- **各家做法**：x86 SSE 默认屏蔽、MXCSR 标志，解除屏蔽才 `#XM`；ARM64 FPCR/FPSR，默认不陷入；RISC-V `fcsr.fflags`，不陷入；MIPS/SPARC/PowerPC 用 FCSR/FSR/FPSCR，陷阱可选。
- **为什么 SimRISC 不陷入**：精确浮点陷阱在流水线里代价高；状态位 + 软件检查更适合乱序/推测。

## 2. 为什么 min/max 指令是 minimumNumber/maximumNumber，而不是 minimum/maximum？

**答：** 因为选的是"NaN 不传播、返回另一个数"的语义；`ftmin`/`ftmax`、`fomin`/`fomax` 对应 IEEE 754-2019 的 `minimumNumber`/`maximumNumber`，而 `minimum`/`maximum` 是 NaN 传播版。

- **两个函数的区别**：`minimumNumber(x, NaN) = x`、`maximumNumber(x, NaN) = x`（单 NaN 返回数字；双 NaN 返回 canonical qNaN）；`minimum(x, NaN) = NaN`、`maximum(x, NaN) = NaN`（任一 NaN 就传播）。
- **为什么选 Number 版**：min/max 的常见用途是"在一组数里挑最小/最大"，NaN 通常表示"这个位置没有有效值"；返回有效数字比让整个结果变成 NaN 更有用。
- **与 RISC-V 一致**：RISC-V 的 FMIN/FMAX 与 2019 的 `minimumNumber`/`maximumNumber` 逐条一致（单 NaN 返回数字、双 NaN 返回 canonical qNaN、`−0 < +0`）。
- **NaN 传播版可以软件合成**：需要 `minimum`/`maximum` 时，用本族加一个显式 NaN 判断即可；反过来（硬件只提供传播版）要合成 Number 版更麻烦。所以硬件选常用的一版。
- **边界**：`−0 < +0`（`min(+0, −0) = −0`、`max = +0`）；单 NaN 返回数字（sNaN 置 NV）；双 NaN 返回 canonical qNaN；不涉舍入、不置 NX。
- **标准**：IEEE 754-2019 §9.6 定义 `minimumNumber`/`maximumNumber`（单 NaN 返回数字）与 `minimum`/`maximum`（NaN 传播）。
- **各家做法**：RISC-V FMIN/FMAX 用 Number 版；x86 `minss`/`maxss` 是 legacy 的"返回第二源"语义，不符合 2019；ARM64 分两组——`FMIN`/`FMAX` 是 NaN 传播版（任一 NaN 返回 qNaN），`FMINNM`/`FMAXNM` 是 Number 版（单 qNaN 返回数字）；MIPS/SPARC/PowerPC 用比较 + 选择。
- **为什么 SimRISC 选 Number 版**：min/max 的常见语义是"挑有效值"，NaN 表示缺失；传播版可软件合成。

## 3. 为什么需要 fused multiply-add 指令？

**答：** 因为 `a × b + c` 只舍入一次，比"先乘再舍入、再加再舍入"更准，也更省指令。

- **指令**：`ftfma rfHA, rfHB, rfHC, rfHD` / `fofma …`——四个寄存器槽（一个目的、三个源），计算 `rfHB × rfHC + rfHD`，不使用花括号。
- **单次舍入**：FMA 用乘法的**精确积**直接与加数相加，只在最后舍入一次；普通 `mul` + `add` 在乘法结果处多舍入一次，可能得到不同结果。
- **精度**：反例——`a = 1 + 2⁻²³`、`b = 1 − 2⁻²³`、`c = −1`，精确积是 `1 − 2⁻⁴⁶`；FMA 得 `−2⁻⁴⁶`，而先乘后加会把积舍入成 1、再加得 0。
- **避免中间溢出/下溢**：精确积不先舍入，中间结果不会因为"乘法溢出/下溢"而丢失；只有最终结果才按格式舍入。
- **性能**：一条指令完成两次运算，减少指令数、寄存器压力和一次舍入。
- **典型用途**：点积、矩阵乘、多项式求值（Horner）、复数运算等数值内核。
- **代价**：硬件需要更宽的内部乘积/累加通路，面积和时序成本更高。
- **标准**：IEEE 754-2019 §7.2 定义 `fusedMultiplyAdd`。
- **各家做法**：x86 FMA3/FMA4（`VFMADD*`）；ARM64 `FMADD`/`FMSUB`；RISC-V `fmadd.s/d`；SPARC/PowerPC 也有 FMA；MIPS 的部分版本有 `MADD.S`/`MSUB.S`。
- **为什么 SimRISC 只设 FMA**：`a×b+c` 最常用；`a×b−c` 用 `sgnn` 对 `c` 取负再加，逐位一致、不额外舍入。

## 4. 为什么 rf0 参与浮点运算时是 qNaN？（换言之，qNaN 作为源操作数有什么用？）

**答：** 因为 rf0 的位型被固定成 qNaN（单精/双精各一段），按浮点读出来就是一个安静 NaN；这样它既是 FCSR，又是合法的浮点值。

- **位型固定**：rf0 的高位段和低位段分别是 fo/ft 的 qNaN 编码，所以按浮点读永远是 NaN；它与复位值同源。
- **FCSR 位藏在 NaN 的 payload 里**：舍入模式 `[33:32]`、异常状态 `[4:0]` 都落在 NaN 的 payload 区域内（对 ft 而言舍入模式还在 32 位之外），改这些位不会改变"它是 qNaN"的事实。所以无论 FCSR 处于什么状态，读 `rf0` 都是 qNaN——用户误用时只会得到 NaN，不会拿到一个看似合法的数。
- **作源安全**：qNaN 作输入不会置 NV（只有 sNaN 才会），所以用 rf0 作源不会误报无效运算。
- **`abs`/`-abs` 的特例**：`ftsgnj`/`fosgnj` 配 `rfHD = rf0` 实现 `abs(rfHC)`（rf0 符号位为 0，`copySign` 就是清符号位）；`ftsgnn`/`fosgnn` 配 `rfHD = rf0` 实现 `-abs(rfHC)`。
- **毒值/哨兵**：把 qNaN 作源会让结果变成 NaN，程序误用 rf0 时结果可追溯；也可以用来占位或强制产生 NaN。
- **省掉一个 NaN 寄存器**：rf0 本身就是规范 qNaN，不需要再单独放一个"常数 NaN"。
- **各家做法**：x86 没有固定 NaN 寄存器（NaN 由指令/内存产生）；ARM64 有默认 NaN（FPCR.DN）；RISC-V 有 canonical NaN（`0x7FC00000`/`0x7FF8000000000000`）；SimRISC 用 `rf0` 兼作 qNaN。
- **为什么用 rf0**：0 号槽承载 FCSR；位型固定为 qNaN，误用也只得到 NaN。

## 5. 为什么把 rf0 当作 FCSR，而不是设一个独立的浮点状态寄存器？

**答：** 因为 `rf0` 既是浮点格式（qNaN），又是 FCSR；非 FCSR 部分按设计忽略写入，所以它能像普通 `rf` 一样作源/目的，现场保存恢复也更简洁。

- **一条寄存器读写状态**：`rf0[33:32]` 是舍入模式（RNE/RTZ/RDN/RUP），`rf0[4:0]` 是异常状态（NV/DZ/OF/UF/NX）；读写用普通浮点寄存器操作即可，不必新增 CSR 或专用指令。
- **`rf0` 是合法浮点格式**：它既是单精 qNaN 又是双精 qNaN，可作浮点源操作数。
- **可作源/目的**：`set.w`（立即数赋值）、`rd2rf`/`rf2rd`（寄存器复制）、`ld`/`st`（取数存数）都允许 `rf0` 作源或目的；写入只更新 FCSR 相关位，其余位按设计忽略。
- **现场保存/恢复简洁**：保存 `rf0`–`rf63` 就把 FCSR 一起保存了，恢复同理，不需要单独保存/恢复 FCSR。
- **不能作浮点运算目的**：浮点运算会更新状态位，所以 `rf0` 不可作浮点运算的目的；这也能防止手写汇编时把 `rf0` 误当普通目的寄存器。

## 6. 浮点格式转换怎么分类？

**答：** 按"源/目的"分四类：浮点↔浮点、整数→浮点、浮点→整数，以及同格式搬移；都是 `orri` 块操作，`immu6` 指定连续寄存器个数（1–63）。

- **浮点↔浮点**：`ft2fo`（单→双）、`fo2ft`（双→单）、`ft2ft`/`fo2fo`（同格式搬移）。
- **整数→浮点**：`it2ft`/`it2fo`（32 位有符号）、`io2ft`/`io2fo`（64 位有符号）、`ut2ft`/`ut2fo`（32 位无符号）、`uo2ft`/`uo2fo`（64 位无符号）。
- **浮点→整数**：`ft2it`/`ft2io`/`ft2ut`/`ft2uo`、`fo2it`/`fo2io`/`fo2ut`/`fo2uo`。
- **块操作**：`immu6` = 1–63；源/目的范围不可有交集（含完全重合），否则 ILLI；按序号递增逐对、先读后写。
- **边界**：浮点→整数遇 NaN/Inf/超出范围返回整型饱和值并置 NV；浮点→浮点溢出返回 ±Inf（OF）、下溢 tiny+inexact 置 UF（同时 NX）；整数→浮点可能 inexact。
- **各家做法**：x86 `cvtsi2ss`/`cvttss2si`（截断）；ARM64 `SCVTF`/`FCVTZS`（可指定舍入）；RISC-V `fcvt.*`（动态舍入）；MIPS `cvt.*`；SPARC/PowerPC 的转换。
- **为什么 SimRISC 用块操作**：`immu6` 一次转换多个寄存器；源/目的不重叠，硬件简单。

## 7. 浮点算术、取整、平方根、scaleB 各是什么？

**答：** 它们覆盖 IEEE 754 的常用运算：加减乘除余、取整、平方根、scaleB；除 min/max/FMA 外都在这里。

- **加减乘除**：`ftadd`/`ftsub`/`ftmul`/`ftdiv` 与 `foadd`/`fosub`/`fomul`/`fodiv`。
- **余数**：`ftrem`/`forem` 是 IEEE 754 remainder（`x − n×y`，n 为最接近 `x/y` 的整数，平局取偶）。
- **scaleB**：`ftsclb`/`fosclb` 计算 `x × 2^n`（n 取整数值），舍入模式由 `rf0` 控制。
- **平方根**：`ftroot`/`foroot` 实现 `rootn(x, n)`，目前仅 n=2；其他 n 触发 ILLI；`rootn(-0, 2)` 不做要求。
- **取整**：`ftrnd`/`fornd` 把浮点取整为整数值（仍是浮点），`immu6` 是 6 档 one-hot 取整模式；5 个静态档不受 `rf0` 影响、不置 NX；只有 `0x20`（动态档）在结果 ≠ 输入时置 NX。
- **共同规则**：结果格式与输入相同；`rf0` 不可作目的；sNaN 置 NV、返回 qNaN；qNaN 返回 canonical qNaN。
- **标准**：`ftrem` = IEEE 754 remainder；`ftsclb` = scaleB；`ftroot` = rootn；`ftrnd` = roundToIntegral 六档。
- **各家做法**：x86 有 `roundss`/`roundsd`、`sqrtss`、`fprem`/`fprem1`；ARM64 有 `FRINT*`、`FSQRT`；RISC-V 有 `fsqrt`，round/scaleB/rootn 用软件合成；MIPS/SPARC/PowerPC 各有取舍。
- **为什么 SimRISC 提供 round/root/scaleB**：这些是 IEEE 754 的常用操作，一条指令比软件合成省事。

## 8. 浮点比较怎么处理 NaN？

**答：** 比较结果写 `rd`：1（大于）、0（等于）、-1（小于）、NaN（unordered）；`q` 版返回 qNaN，`s` 版返回 sNaN。

- **指令**：`ftqcmp`/`ftscmp`（单精）、`foqcmp`/`foscmp`（双精）。
- **结果**：`rfHC > rfHD` → 1；`=` → 0；`<` → -1；unordered → NaN（q 版 qNaN、s 版 sNaN，符号位为 0）。
- **为什么用 `rd`**：结果写到数据寄存器，后续用 `cs.*`/`br.*` 的六种条件判断；NaN 按整型看是正数，所以"等于/不等/小于/不小于/小于等于/大于"可以用零/负数条件直接判，而"unordered vs greater"要再判结果是否为 1。
- **与 min/max 的区别**：比较只给关系，不选值；min/max 是 `minimumNumber`/`maximumNumber`。
- **标准**：IEEE 754-2019 §5.6 的 `compareQuiet*`/`compareSignaling*`；NaN 为 unordered。
- **各家做法**：x86 `ucomiss`/`comiss`（quiet/signaling）；ARM64 `FCMP`；RISC-V `feq`/`flt`/`fle`（quiet）；MIPS `c.cond`；SPARC/PowerPC 的 FP compare。
- **为什么 SimRISC 写 `rd`**：结果可保存/复用；NaN 按整型正数，便于用零/负条件分流。

## 9. 浮点分类指令怎么用？

**答：** `ftcls`/`focls` 把一个浮点数归入 10 个 IEEE 754 类别之一，结果写 `rd` 的 10 个位（其余位清零）。

- **类别位**：0 sNaN、1 qNaN、2 −Inf、3 负正规、4 负次正规、5 −0、6 +0、7 正次正规、8 正正规、9 +Inf。
- **块操作**：`immu6` 指定连续分类的寄存器个数（1–63）；目的 `rd`、源 `rf`，分属不同组，不会重叠。
- **用途**：实现 `isnan`/`isinf`/`signbit`/`fpclassify` 等分类；一条指令给出全部类别。
- **限制**：`immu6 = 0` 或起始+计数 > 64 → ILLI。
- **标准**：IEEE 754-2019 §5.7.2 的 `class` 10 类。
- **各家做法**：RISC-V `fclass.s/d` 也是 10 位；x86 用 `ucomiss` + 位操作/`fpclassify`；ARM64 用 `FCMP` + 位操作；MIPS/SPARC/PowerPC 各有分类/比较。
- **为什么 SimRISC 用 10 位**：与 IEEE 754 `class` 对齐，一条指令覆盖 `isnan`/`isinf`/`signbit`/`fpclassify`。

## 10. 浮点异常标志的精确口径是什么？

**答：** 五个标志（NV/DZ/OF/UF/NX）都是 sticky；`UF` 只在结果 tiny **且** inexact 时置位，`NX` 与 `UF` 独立，tininess 检测点在舍入后。

- **sticky**：置位后保持为 1，直到软件写 `rf0` 清零。
- **UF**：结果 tiny **且** inexact 才置位；tiny 但可精确表示不置 UF、也不置 NX；`UF` 置位时 `NX` 必同时置位。
- **NX**：inexact 但非 tiny 只置 NX；`NX` 与 `UF` 相互独立。
- **tininess**：检测点在舍入后（按目标格式舍入后再判是否小于最小正规数）。
- **NV**：无效运算（sNaN 输入、0×Inf、Inf−Inf 等）；`DZ` 除零；`OF` 溢出返回 ±Inf；`UF` 下溢返回次正规/±0。
- **不陷入**：浮点指令只累积状态位，不改变控制流；软件读 `rf0[4:0]` 检查。
- **标准**：IEEE 754-2019 §7.5 定义 NV/DZ/OF/UF/NX；UF 只在 tiny+inexact 时置位，tininess 检测点在舍入后。
- **各家做法**：x86 MXCSR；ARM64 FPSR；RISC-V `fcsr.fflags`；MIPS FCSR；SPARC FSR；PowerPC FPSCR；SimRISC `rf0`。
- **为什么都 sticky**：IEEE 754 要求累积，软件可在计算块结束后统一检查。

## 11. 浮点符号位操作有哪些？

**答：** `ftsgnj`/`fosgnj` 做 copySign，`ftsgnn`/`fosgnn` 做符号取反；配 `rf0` 或自身可以实现 abs/-abs/copy/negate。

- **copySign**：`ftsgnj rfHB, rfHC, rfHD` = 取 `rfHC` 的数值位 + `rfHD` 的符号位。
- **符号取反**：`ftsgnn` = 取 `rfHC` 的数值位 + `~rfHD` 的符号位。
- **特例**：`rfHD = rf0` → `abs(rfHC)`（sgnj）/ `-abs(rfHC)`（sgnn）；`rfHC = rfHD` → `copy(rfHC)`（sgnj）/ `negate(rfHC)`（sgnn）。
- **用途**：不涉舍入、逐位精确；FMA 的 `a×b−c` 可以先用 `sgnn` 对 `c` 取负再 `fma`。
- **标准**：IEEE 754-2019 §5.5.1 的 `copySign`/`negate`。
- **各家做法**：x86 用 `andps`/`xorpd` 等位操作；ARM64 用 `FABS`/`FNEG` + 位操作；RISC-V `fsgnj`/`fsgnjn`/`fsgnjx`；MIPS/SPARC/PowerPC 的符号操作。
- **为什么 SimRISC 用 sgnj/sgnn**：一条指令完成 copySign/符号取反，不涉舍入；abs/-abs 用 `rf0` 作符号源。

## 12. 浮点除零会怎样？和整数除零有什么不同？

**答：** 浮点除零有统一标准（IEEE 754-2019）：有限非零 ÷ ±0 → ±Inf + DZ，0/0 → qNaN + NV；各 ISA 的差异主要在"是否陷入、标志放哪"，而整数除零没有统一标准，各家方案不同。

- **IEEE 754-2019（统一）**：有限非零 ÷ ±0 → ±Inf（符号 = 被除数 XOR 除数），置 DZ；0/0 → qNaN，置 NV；Inf/Inf → qNaN，NV；有限/Inf → ±0；Inf/有限 → ±Inf；NaN 传播，sNaN 置 NV。
- **x86-64（SSE）**：默认屏蔽异常（不陷入），MXCSR 的 ZE/IE 标志；解除屏蔽才 `#XM`。
- **ARM64**：FPCR/FPSR；默认不陷入，异常陷入由 FPCR 的 enable 位控制。
- **RISC-V**：`fcsr` 的 `fflags`（DZ/NV）；不陷入。
- **MIPS / SPARC / PowerPC**：FCSR/FSR/FPSCR 标志；是否陷入由控制寄存器/陷阱使能决定。
- **SimRISC**：`rf0[4:0]` 的 DZ/NV；不陷入，sticky。
- **整数除零（对比）**：x86 `#DE`、ARM64 返回 0、RISC-V 全 1、MIPS 未定义、SimRISC 定值；没有统一标准。
- **为什么浮点能统一**：IEEE 754 定义了 Inf/NaN 作为可表示值，除零有明确的"值 + 标志"；整数没有 Inf/NaN，只能由 ISA 约定。
- **为什么陷入策略不同**：x86 默认屏蔽是为了性能/兼容；RISC 风格倾向"标志 + 软件检查"；嵌入式可选陷入以便调试。

## 背景知识

### 术语与概念

- **IEEE 754**：浮点格式、舍入、异常与 NaN 的标准；1985 年首版，2008/2019 修订。
- **单精 / 双精（single/double）**：32 位/64 位二进制浮点格式；SimRISC 用 `ft`/`fo` 后缀区分（tetra/octa）。
- **舍入模式**：RNE（就近偶数）、RTZ（向零）、RDN（向下）、RUP（向上）；由 `rf0[33:32]` 选择。
- **异常状态位**：NV（无效）、DZ（除零）、OF（溢出）、UF（下溢）、NX（不精确），粘滞累积。
- **qNaN / sNaN**：安静 NaN / 信号 NaN；IEEE 754-1985 用尾数最高位区分（1 = qNaN，0 = sNaN）；qNaN 用于传播，sNaN 用于触发无效运算（NV）。
- **canonical NaN**：规范 NaN，一种特定的 qNaN 位型；双 NaN 的 min/max 返回它。
- **FMA（fused multiply-add）**：`a×b+c` 只舍入一次。
- **fenv**：C 的浮点环境接口（`feclearexcept`/`fetestexcept`/`fesetround` 等），对应"读/清状态位 + 设舍入模式"。

### 对照

**浮点状态寄存器**

- **x86-64**：**独立**——SSE 用 MXCSR、x87 用状态/控制字；指令 `stmxcsr`/`ldmxcsr`、`fnstsw`/`fldcw`。
- **ARM64**：**独立**——FPCR（控制）/FPSR（状态）两个系统寄存器；指令 `MRS`/`MSR`。
- **RISC-V**：**独立**——`fcsr` 是一个 CSR（含舍入模式 `frm` 与异常标志 `fflags`）；指令 `csrrw`/`csrrs`/`csrrc`（伪指令 `frcsr`/`fscsr`/`fsrm`/`fsflags`）。
- **SimRISC**：**不独立**——就是 `rf0`（浮点寄存器组的 0 号），同时是 qNaN；写用 `set.w rf0, wp2/wp0`，读用 `rf2rd`，运算时可直接作源。

**min/max 的 NaN 语义**

- **IEEE 754-2008**：`minNum`/`maxNum`（单 NaN 返回数字）。
- **IEEE 754-2019**：改为 `minimum`/`maximum`（NaN 传播）与 `minimumNumber`/`maximumNumber`（单 NaN 返回数字）。
- **RISC-V**：FMIN/FMAX 采用 `minimumNumber`/`maximumNumber`。
- **SimRISC**：`ftmin`/`ftmax`、`fomin`/`fomax` 采用 `minimumNumber`/`maximumNumber`。

**浮点寄存器与宽度**

- **x86-64**：x87 8×80 位栈式寄存器；SSE 16×128 位（AVX-512 32×512 位）。
- **ARM64**：32×128 位 V 寄存器（可作 32×64 位 D / 32×32 位 S）。
- **RISC-V**：32×64 位 f 寄存器（D 扩展），F 扩展用低 32 位。
- **MIPS**：32×64 位 FP 寄存器（MIPS64）。
- **SPARC**：32×64 位（V9）。
- **PowerPC**：32×64 位 FPR。
- **SimRISC**：64×64 位 `rf`，单精用低 32 位（`ft`），双精用 64 位（`fo`）。
