> **状态**：**草案（Draft）**——**仅供讨论，不作判据真源**（定稿后再议是否升为正式册、是否纳入只读锁）。

## 1. 分层（自上而下）

| 层 | 名称 | 候选 / 现状 | 决策点（要点） |
|---|---|---|---|
| **L1** | **C 库与链接形态** | `picolibc`（**现状**，**静态**）；`musl`（候选）；**动态形态**（`.so`/`-fPIC`/`-shared` = **产物形态**） | 静态优先；**动态链接独立后置**（不与 pk 混）；**本层只记"形态/用它与否"**，**loader 能力归 L3**（裁定 2026-10-12） |
| **L2** | **系统调用接口** | **semihosting**（`trap <any cfxha>, 0x3FF00`；**现状**）；真 syscall（syscall 号 + 执行者） | **谁执行**：平台/模拟器 responder（现状）↔ 内核 syscall 表 |
| **L3** | **资源管理 / 内核行为** | **无内核**（**现状**）；`pk`（proxy kernel：加载 ELF + trap/异常/syscall 转发）；Linux kernel | 何时引入；`pk` 与动态链接**分层不混**（用户 2026-10-11 原话） |
| **L4** | **平台（machine）** | `qemu`（**现状**：`dadao-m1`）；`gem5`；`verilator`；`fpga` | **暂不分类**（用户 2026-10-12 裁定）⇒ 以 **「平台 × 能力」矩阵**表达（维度/真源见 §3 #4） |

**现状（M7）= L1 `picolibc`（静态）+ L2 semihosting + L3 无内核 + L4 `qemu`。**

**本册边界（裁定 2026-10-12）**：**只写「层与选择」**（分层定义 / 层间约束 / 各层"候选·现状·决策点"）；**任何具体值一律指针**到 `spec/Machine-01`（内存映射、semihosting 25 服务、加载/退出等）与 `.tao/contracts/contract-*` ⇒ **不重复、不漂移**。

## 2. 层间约束（讨论要点）

- **L1 × L3（裁定 2026-10-12）**：**L1 只记"库形态"**（静态/动态**产物**：`-fPIC`/`-shared`/`.so`）；**loader 能力**（`ld.so`/`PT_INTERP`/`.dynamic`/GOT/PLT 解析）归 **L3** ⇒ **"能不能动态"由 L3 决定，L1 只表达"用它与否"**；这正是"**pk 与动态链接不混**"的由来（不同层，可分别后置）；
- **L2 × L3**：L2 的"谁执行"由 L3 决定——**无内核 ⇒ 只能由平台/模拟器代答**（semihosting）；**有内核 ⇒ 由内核 syscall 表执行**（semihosting 退为 bootstrap/调试通道）；
- **L2 × L4**：L4 决定 L2 的可用形态——模拟器可提供 responder；`fpga`/真实硬件**没有** responder ⇒ 需要替代（串口协议、bootrom 服务、或先在 L3 引入最小内核）；
- **L1 × L4**：库的构建/链接形态受平台约束（如无 MMU/无动态加载 ⇒ 只能静态）。
- **各层后置顺序（本册承载的决策；用户 2026-10-12 裁定「**不立 ADR，只写在册里**」）**：
  - **L1**：**静态优先**；**动态链接独立后置**（不与 pk 混）；
  - **L2**：先 **semihosting**；**真 syscall 随 L3 内核**引入（届时 semihosting 退为 bootstrap/调试通道）；
  - **L3**：现"**无内核**"；**`pk`** 与 **Linux kernel** 各自后置；**`musl`** 亦后置（M7 = picolibc）；
  - **L4**：**暂不分类**；以「平台 × 能力」矩阵表达（**人工填表 + 每条标注依据**）。

**组合规律（待验证）**：
- **要"能否跑"** ⇒ 取决于 L4 是否有 **semihosting responder**（无 ⇒ 需 L3 内核或替代通道）；
- **要"跑得多久/多准"** ⇒ 取决于 **时序精度**（`qemu` 非周期精确 ⇒ 计时类基准宜上 `gem5`/`fpga`）；
- **要"语义对不对"** ⇒ 与平台无关的**独立 oracle**（`spec`/向量/lit）优先，平台只作**执行载体**。

### 5.1 套件接入要点（Embench-IoT → DADAO）

> 逐条要点提炼自 `embench-analysis.md`（原文已归档 `.tao/archive/M7/notes/embench-analysis.md`，含逐基准证据/脚本索引）；此处只留**接入判据**，不复述证据。

- **平台接入面极窄**：Embench 只要求平台实现 **3 个 `void` 函数** `initialise_board` / `start_trigger` / `stop_trigger`（`support/support.h`）；**无** `uart_*`/`timer_*`/`power_*`/`exit` 钩子；计时为平台自选。
- **无需 OS / varargs / libc malloc**：freestanding；所有 `printf/puts` 均在调试宏内（默认不编译）；堆 = BEEBS 自带静态 bump 堆（≤ 8 KiB）；停机由 crt0 走 semihosting `SYS_EXIT`。
- **pass 判据 = 进程退出码 0**：`support/main.c` 返回 `!correct`（`verify_benchmark` 非 0 = 正确）⇒ **不靠打印 "correct"**；"可跑 + 语义对"由 L3 执行门控承载（见 §4 能力矩阵 / §5 表）。
- **最小运行时 + 端序坑**：需 `memcpy/memset/memmove/memcmp` + `strlen/strchr` + ctype + 一个 double `sqrt`（`wikisort`）；DADAO **大端** ⇒ 仅 `md5sum` 用小端 `uint32_t*` 重解释（**唯一端序坑**，大端下 verify 失败），其余与端序无关。
- **内存与工具链**：单最大基准 ≈ 64 KiB（`xgboost` 静态 43 KB + 栈 ≤13 KB + 堆 ≤8 KB），全 19 个常驻 ≈ 268 KiB ⇒ 现行 16 MiB RAM 余量 ≥ 250×；C 源码接入需 **clang DADAO `TargetInfo`**（接入时缺失，后已补）。
