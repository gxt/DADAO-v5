# AI 编程：DADAO-0628

> 本课介绍 **DADAO-0628**——一次用 AI Agent 从零实现 DADAO 软件栈的实践。

## 贡献者

**隋岩**。

## 一句话

DADAO-0628 是一个 **greenfield（从零）实现**的 DADAO 软件栈：不从历史实现复制代码，而是从一个**按 commit 锁定的规范合约**出发，由 AI Agent 逐步实现，并用**多路独立实现的交叉验证**保证正确性。

## 它做了什么

### 1. 从规范出发，而不是从代码出发

- 规范来自 DADAO wiki（`gxt/DADAO.wiki`），**按 commit 锁定**（SimRISC 0.4.1；AEE-ABI 0.9.2 / SEE-SBI 0.7.1 / HEE-HBI 0.1.2）。
- 历史实现只作「**仓库编排 + 工程教训**」参考，**不回植**（non-reuse rule）。

### 2. 四路 ISA 验证链（最有特色的部分）

同一套 M1 指令集（**87 条**）由**四个独立实现**分别完成，都只从规范派生，再用**同一份测试向量**交叉验证：

```
                 spec 合约（唯一权威）
      ┌──────────────┬──────────────┬──────────────┐
      ▼              ▼              ▼              ▼
  Python 黄金模型    QEMU          gem5           Sail
  （独立 oracle）  （功能模拟）  （周期级模拟）  （形式化可执行规范）
      └──────────────┴──────────────┴──────────────┘
                 四路差分：AGREE = 198，DIVERGE = 0
```

> 一个实现有 bug → 四路不一致 → 被定位出来。这是「**独立 oracle**」原则的工程化。

### 3. 里程碑

- **M0 可复现基础**：仓库检查、SPEC/组件按精确 commit 锁定、向量 schema。
- **M1 MC + CPU 核心**：QEMU 在 MMU-off 裸机模式执行标量程序；LLVM MC 汇编/反汇编同一批向量；非法编码与立即数边界一致拒绝。
- **M2 Basic CodeGen**：LLVM 把标量整数/指针函数降为指令（算术/比较/控制流/调用/RAS/栈数组/全局量……）。
- **M2.5 clang 前端 + libc MVP**：`clang hello.c -o hello` 产出真实 DADAO ELF；libc 分阶段 picolibc → musl。
- **内核 bring-up**：进行中（前身曾三次尝试，均未到稳定用户态）。

### 4. 组件（按精确 commit 锁定）

LLVM、QEMU、gem5、llvm-test-suite、embench、musl、linux。

## 与「前身」的关系

DADAO-0628 之前，还有一个 **meta-repo（`gxt/DADAO`，version 202406）**：用传统方式（gcc / binutils / qemu / chipyard / linux）搭建 DADAO 工具链与 SoC，是 0628 的**前身**。

| | 前身 `DADAO`（202406） | DADAO-0628 |
| --- | --- | --- |
| 方式 | 传统（人工 + 既有工具链） | **AI Agent 驱动** |
| 编译器 | gcc（`TCH-gcc`） | LLVM（MC + CodeGen + clang） |
| 规范 | wiki（持续演进） | wiki **按 commit 锁定** |
| 验证 | 单条指令测试向量 | **四路独立实现交叉验证** |

> 0628 对前身只作「失败考古 + 工程教训」参考，不复制实现。

## 为什么重要（对课程）

1. **「Agent 写代码、人写约束」**：本项目开发方式的来源——人写规范/合约/任务书（约束），AI Agent 写实现。
2. **独立验证的威力**：多路实现交叉验证，能发现单测/单实现看不见的盲区（如 `ldo` 对齐、reserved→UNDI、PC 基址寄存器未维护）。
3. **教训**：单模块各自过 ≠ 组合正确；验证必须**独立于被测实现**。
