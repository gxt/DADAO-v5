# `docs/TestReports/` — 测试报告（人读结论 + 里程碑快照）

> **定位**：本目录收**给人看的测试结论**与**里程碑快照**。原始数据、日志、生成器**不在**本目录（见 §2）。
> **上位依据**：`docs/README.md`（三分界）、`docs/Process-08`（运行产物与日志）、`docs/Process-09`（测试组织）。
> **状态**：生效（2026-11-10，用户裁定「人读结论放 `docs/`，加子目录；原始数据不入库」）。

## 1. 命名（必须）

`<里程碑>-<主题>.md`，主题用能独立看懂的中文短语；同一份报告的附属文件加后缀：

| 文件 | 含义 |
| --- | --- |
| `M11-三平台一致矩阵.md` | 里程碑快照（现场生成） |
| `M11-三平台一致矩阵-凡例.md` | 该快照的口径 / 复现方式 |
| `M13-三平台差分-qemu-gem5.md` | 阶段性差分结论 |

- 文件名**不带日期**（日期写册头），保证同一里程碑只有一份「当前版」。
- 快照类文件**首行必须**写 `<!-- 现场生成，勿手改 -->`。

## 2. 收什么 / 不收什么（必须）

- **收**：跨平台一致性结论、差异归因、里程碑矩阵快照、复现命令。
- **不收**：逐例 JSON、driver 日志、`m5out/`、生成器脚本、基线原文——这些落运行期目录（`.dadao/tests/` 或任务运行期目录），**不入库**。
- 一条结论要能回溯到证据：写清「来源任务 / 快照文件名 / 机器指纹」。

## 3. 每册必备四项（必须）

1. **生成时间**（本地时间，UTC 另注）
2. **数据来源**（哪个任务、哪份 JSON / 哪次运行）
3. **机器指纹**（CPU 型号、源码 tree hash 或补丁集版本、工具 md5 作诊断）
4. **复现命令**（只写 `make` 目标 / 脚本名 / 环境变量）

## 4. 禁止项（必须）

- **禁止**写运行期绝对路径：`/tmp/**`、`/home/**`、仓库内 `.work/**` 具体路径。
- **禁止**手改快照数值——数据变了就重跑生成器覆盖。
- **禁止**新增二级主题子目录（本目录不再嵌套，主题靠文件名区分）。
- **禁止**把本目录当任务书或知识库用：判定口径归 `.tao/knowledge/`，任务过程归任务书。

## 5. 索引

新册加入后，在 `docs/README.md` 的索引表补一行（文件 → 一句话）。历史册（M11 及以前）不追溯改写，只补链接。
