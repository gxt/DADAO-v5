- **2026-11-15 `m14-linux-004`**

- **2026-11-16 `m14-linux-006`**
  - 摘要：**K2：supv 同步异常成为正式通道（全 GPR 帧 + 11 项 cause 分派 + 退出码按事件性质分段）**。`kernel/k1_trap.S` 退役，新增 `kernel/trap.S`：入口在第一条指令前捕获 `rd1-rd63`/`rb1-rb63`（`rd0` 硬连零、`rb0` 只读 IP，二者不入帧），借用 `rb3`/`rd2`/`rd3` 前先把它们经 `cfx_smon` cg6 暂存寄存器（`§3.7`，`scratch_regs_num ≥ 2`）保住，帧落静态 `.bss`（故障 SP 可能不可用），再按 `stm.o`/`ldm.o` 的合法区间分块搬运；`rb3` 最后用 `ld.o rb3, [rb3, slot]` 自址恢复。C 侧 `dadao_trap_handler()` 按 `spec/DADAO-13 §2` 的 11 项表分派：注册的探针（`dadao_trap_probe_register()`，`mm/k1_pt.c` 首次使用）按策略返回 `escape …, {0,4}`，其余走 `dadao_die()` 具名打印 + `spec/Machine-v5 §7.1` **monitor 段**退出码（`0xC0|mode<<4|bit`，supv ⇒ `0xE1` 类）；表外原因为不可编码事件，落 guest 段自检码。退出码按事件性质重分段：自检失败 `0x01-0x7F`（`head.S` 0x01-0x03、`setup.c` 0x04-0x08、`k1_pt.c` 0x09-0x0c、`trap.S` 0x0d、`traps.c` 0x0e/0x0f），`dadao_die()` 的异常终止编成 `spec/Machine-v5 §7.1` 的两种段：`CFXTRAP`/`CFXESC` 走「其它 cfx」段 `0x80|cfxHA`（K2 期 `cfx_smon` ⇒ `0x82`，cfxHA 由 `cg4 rc0` 现场读出），其余 cause 走 monitor 段 `0xC0|(mode<<4)|(__ffs(cause)&0xF)`（mode 从帧 `excp_prev_run_mode` 读）——**表外 cause 也走这条**（不再落 guest 段，否则与失败点序号不可区分），控制台仍打印原始 `cause=0x…`。旧 `0xE1-0xED` 一并用作自检失败的语义误标已消除。探针新增 `redirect`（先写 `cg5 rc3` 再 `escape …,0` 落到新 ip，验证返回 IP 可软件改写）与重入保护判据。K2 启动边界翻转：`defconfig` 去掉 `CONFIG_DADAO_K1_EARLY_STOP`（符号与钩子保留，默认改 n），新增 `CONFIG_DADAO_K2_EARLY_STOP`（默认 n，defconfig 开）= `setup_arch()` 末尾停在 K2 边界；`head.S` 的 `dadao_jump_on_stack()` 在内核入口把 SP 切到 init task 栈（`current` 由 SP 推导，静态 early stack 无 thread_info，否则 printk 取 `current` 即空指针）。`defconfig` 新增 `CONFIG_DADAO_K2_TRAP_SELFTEST`（默认 n）+ `CONFIG_DADAO_K2_SELFTEST_UNKNOWN`（探针用，映射表外 cause）。工具侧：`make_defconfig.py` 增显式配置切片入口（`--extra-config` / `apply_config_lines()`），`check_k0.py`/`check_k1.py` 构建前各自落自己的切片（不再依赖上一次谁配过）；`check_k1.py`/`k1_pt_probe.py`/`k1_boot_probe.py` 同步新退出码；新增 `tools/linux/k2_trap_probe.py`（C0-C9：plain/probe/unknown 三镜像、P1-P5、4 路注入）。

- **2026-11-16 `m14-linux-007`**
  - 摘要：**K2：`cfx_time` + `cfx_hart` TIMER → jiffies（最小时间框架 + 两条 mask 轴）**。新增 `kernel/time.c`：读数/编程/确认收敛成 `dadao_time_freq()`/`dadao_read_time()`/`dadao_timer_arm()`/`dadao_timer_stop()`/`dadao_timer_status()`（`cfx_time` `cg10 rc0/rc1`、`cfx_hart` `cg8 rc4/rc5`），单点 `dadao_timer_interrupt()` 做 `jiffies_64 += 1` + 按「本次采样 + period」重挂（7.2.10 已无 `xtime_update`；`do_timer()` 的 jiffies 半边即此，负载均值半边要每 CPU 运行队列，K4 才具备）；`period = freq / HZ` 于 `time_init()` 现场派生并打印（`freq/hz/period/n_ticks/first`），**不写死**。新增 `kernel/async_trap.S`：`cfx_hart` 的 supv 异步向量（contract-see §6.3），GPR 保存/恢复宏提出到 `include/asm/entry.h`（`trap.S` 同步入口同用，行为不变），`escape cfx_hart, [excp_cause_ip, 0]`（异步帧 `cause_ip` 已是下一条）；表外 cause/`info≠0` 具名打印后按 §7.1 monitor 段（`0xc0|mode<<4|__ffs(cause)&0xf`）退出。新增 `kernel/irq.c::init_IRQ()`：先写 `cfx_hart` `cg2 rc10` 并回读（回读同时是 4 字节对齐检查）再开 mask；`cg2 rc8` 必须为 `2`；两条 mask 轴 = `cfx_smon` supv `rc4` 与该 mode 的 `global_cfx_intr_mask`（`cg8 rc1`），位索引取 `cfx_hart` `cg4 rc0` 现场值——**并且源轴要写两行**（`cfx_smon` 与 `cfx_hart`）：`escape` 只恢复运行模式（§5.3，帧无 prev_cfx），首次投递后内核的 `inner_cfx_code` 就是 `cfx_hart`，只开 `cfx_smon` 一行只能收到 1 个 tick（`tools/testcases/arch/min_rom_probe_integ051t.py` 记同一约定）。Kconfig 新增 `DADAO_K2_TIME_STOP`（默认 n，defconfig 开 = K2 时间边界：`time_init` → 向量 → 两轴 → N tick → 停表校验 → `SYS_EXIT(0)`）与 `DADAO_K2_TIME_CASE`（0 生产 / 1 IMASK / 2/3 单轴），`defconfig` 加 `CONFIG_HZ_100`（10 ms 周期，让「半个 period」的间隔余量容得下宿主抖动）。固件 `tests/shared/bootrom/k0/hmon.S`：`OPEN_SUPV_REGS` 的源位由 `{2}` 放宽到 `{2,15}`，新增 `cfx_hart`/`cfx_time` 两个目标（`K2_TIME_PERM=0` 为门控的负例变体）。工具 `tools/linux/k2_time_probe.py`（C0–C8：契约 freq、`.config` HZ、period、tick 序列/单调/jiffies、间隔余量与实测分布、停表、IMASK 挂起与释放、两轴各一次、固件未放行的 CFXPERM 负例；`--selfcheck` 14 组翻转 + `--inject` 6 路）。`check_k0`/`check_k1`/`k2_trap_probe` 的配置切片各补 `DADAO_K2_TIME_STOP=n`。
