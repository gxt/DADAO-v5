# busybox 组件（busybox）

DADAO Linux 的**用户态最小外壳**（M14 `K6`：`ADR-0052` 于 2026-11-17 就地修订，M14 出口扩到「busybox 启动」）。上游基线与补丁序列由 `manifests/components.lock.toml` 锁定（`shallow_ref = "1_38_0"`，精确 commit `fc71374d…`）；工作树由 `make fetch` + `make apply-series --component busybox` 在 `.work/source/busybox` 建立（浅裸镜像 `.cache/busybox.git`）。

## 版本与来源（2026-11-18 实测）

- **版本 = `1.38.0`**（用户 2026-11-17 指定）；身份只认 40 字符 commit，tag 仅作 `shallow_ref`。
- **`repository` = `https://git.busybox.net/busybox`**（官方上游）。任务书原写 `github.com/mirror/busybox.git`，实测该镜像**陈旧**：GitHub API 的 tags 列表最新只到 `1_36_1`（其 `1_36_0` = `70f77e46…`，即 chipyard 子模块锁的那一支），**根本没有 `1_38_0`**；直连 github.com 的 `git clone` 也在 133 s 后失败（"Couldn't connect to server"）。官方站 `ls-remote` 立即应答 `1_38_0 -> fc71374d`，`--depth 1 --branch 1_38_0` 裸镜像克隆 86 s 完成。

## 补丁集

- 形态：**树形补丁集**（`patches/<上游相对路径>.patch`，一文件一补丁），清单见 `series`；规范 `docs/Process-01-组件补丁组织与构建编排.md`。
- 当前 **2 个**补丁（都是「`#` 在 DADAO 汇编里不是注释符」这一条根因的两个落点，`spec/Toolchain-01 §2.2`）：
  - `libbb/const_hack.c.patch`：上游 clang 屏障 `asm volatile("# forget …" : "=r"(pp) : "0"(p))` 的模板注释在 DADAO 上被当作语句起点 ⇒ 编译失败。改为**空模板**（约束本身就是屏障），对任何后端都合法。
  - `libbb/Kbuild.src.patch`：`hash_sha{1,256}_*_x86-*.S` 的手写 x86 汇编在非 x86 上其**正文**被 `#if` 去掉，但生成器的 `### Generated by … ###` 头行仍是 `#` 注释 ⇒ 汇编失败。改为**只在 x86 目标**编译这 5 个对象（`$(ARCH)` ∈ x86_64/amd64/i386/i686/x86）。

## 最小 config（`config.min`，K6 首版）

- **口径**：只开 `sh`（ash）+ `ls/cat/echo/mkdir/rm/cp/mv/grep/ps` + 多调用分发器本身（`CONFIG_BUSYBOX`，`busybox sh`/`--list`/`--version` 需要）+ `CONFIG_STATIC`。**关**掉 PAM、行编辑（`FEATURE_EDITING`/补全）、NFS 等无关项；首版**不做 `/proc`、不做作业控制**。
- **生成方式**：`make allnoconfig` → 按 `config.min` 逐条打开 → `make silentoldconfig` 解析 `select`/依赖 → **再断言**每个符号仍为 `y`（依赖不满足时 busybox 会把符号悄悄关掉，那必须显式失败）。`config.min` 是唯一真源，`.config` 是运行期产物；**是否复用 `.config` 是双向判定**：产物目录记录生成时的受管符号集（`.dadao-busybox-fragment`），与当前 `config.min` **不相等就重生成**——**删掉一个符号同样算变更**（单向 subset 会让收缩后的真源失效，reviewer 第 1 轮 I-B 反例）。`build_busybox.py --check-config` 可单独查询该判定（rc=0 当前 / rc=1 需重生成，并打印 added/removed 明细）。

## 构建与验证

```
make fetch                                            # .work/source/busybox @ 锁定 commit
python3 tools/infra/apply_series.py --component busybox
make build-busybox                                    # = tools/linux/build_busybox.py
```

- **交叉链接口径**：DADAO clang 驱动是 **freestanding**（不隐式链 libc），且 `.dadao/dadao-unknown-elf` 这个 target sysroot 装的是 **picolibc/newlib 头**（有 `sys/features.h`、没有 musl 的 `features.h`）。所以构建脚本生成 `CC` wrapper：编译用 `-nostdinc` + musl 源树的 7 个 include 目录（与 `tools/testcases/run_suite.py` 同一口径），**最终链接**再显式追加 musl 的 `lib/crt1.o` + `lib/libc.a`（`-r` 可重定位链接不追加）；`STRIP` 必须是 `llvm-strip`（宿主 binutils 的 `strip` 读不了 DADAO ELF）；`ARCH=dadao`（busybox 默认取 `uname -m` = 宿主，会误编 x86 汇编）。
- **可复现**：`SOURCE_DATE_EPOCH` = 锁定 commit 的提交时间 ⇒ `AUTOCONF_TIMESTAMP`（被 `libbb/messages.c` 编进 banner）不再随构建时刻变化，**clean 重建哈希逐位一致**。**陈旧对象守卫**：构建产物目录里的 stamp（工具链三件套 size/mtime + `crt1.o`/`libc.a` 内容 + `config.min` + wrapper）与上次不同即自动 `make clean`（与 `build-musl` 同一口径），避免「换了工具链却链上旧对象」的假绿。
- **产物**：`.work/build/busybox/` 下三件——`busybox`（源树内同名副本同哈希）、`.config`（生成快照）、`applets.txt`（applet 清单，来自 `include/applet_tables.h`，供 `m14-linux-031` 建 applet 链接）。ELF：`ELF64 / MSB / machine 0xDA0 / ET_EXEC`，**无 `PT_INTERP`/`PT_DYNAMIC`**。
- **运行证据**（`qemu-dadao` 用户态）：`--version` → `BusyBox v1.38.0 (…)`；`--list` = `ash cat cp echo grep ls mkdir mv ps rm sh`（11 个，现场派生）；`echo/mkdir/ls/sh -c/grep/cat/cp/mv/rm` 全部 rc=0。

## 已知边界

- **`ps`**：首版无 `/proc` 语义；在 `qemu-dadao`（宿主 FS 直通）下会列出**宿主** `/proc`，进内核后（K6）按任务书退化为自身/空表——口径由 `m14-linux-032` 收口。
- **无作业控制 / 无行编辑 / 无 `/proc` applet**：见 `config.min` 的取舍；交互体验不是 K6 出口条件。
- **K6 的运行验收**（内核 + initramfs + semihosting 控制台）不在本组件内，属 `m14-linux-031/032/033/034`。
