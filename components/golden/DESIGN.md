# M1 与 FP golden 设计说明

完整逐条定义见 [逐条指令 golden 说明](INSTRUCTION_REFERENCE.md)：按当前指令身份逐项说明操作数、计算步骤、异常、算例和依据。

本文说明当前 `dadao_interp_v5.py`、`fp_ref.py` 和向量运行器的实际设计。它不复制整份 ISA，也不把旧版本的临时解释当作新规范。这里的“M1”指原标量工作范围，另加当前合约明确的 66 条 `scope: fp` 指令；它**不等于当前编码表中所有 `scope: m1` 指令**。

## 1. 模型要回答什么

给定一条 32 位指令和执行前的寄存器、内存、PC，回答两件事：

- 指令能否执行；若不能，架构规定的异常是什么？
- 若执行成功，哪些状态改变，结果是什么，下一条指令在哪里？

输入和输出都是架构可见状态。模型不模拟流水线、周期、缓存、并发内存序，也不从内存自动取下一条指令。多步执行由调用者依次提供指令字。

### 依据与独立性

| 内容 | 依据 |
| --- | --- |
| 指令编码、字段位置、身份 | `contracts/opcodes.yaml` |
| 寄存器、整数、访存、控制流语义 | `.tao/contracts/contract-isa.md` 与其引用的 `spec/SimRISC-00` 至 `10` 相应章节 |
| 当前零号寄存器规则、RACNT、64 位控制流 | 上述规范及 `.tao/adr/adr-0012-*`、`adr-0015-*` 中已经确认的规则 |
| YAML 字段、内存预置宽度、默认测试地址 | `tests/inst/schema.md` |

执行器不读取 LLVM、QEMU 或向量生成器。测试期望从规范和独立整数运算推导。编码表由模型与向量共用，因此回放能检查二者是否一致，**不能独立证明编码表本身无错**。

出现冲突时先核对规范正文及已确认裁定。既不按“多数文件这么写”表决，也不因旧向量能通过就保留旧语义；无法消除的矛盾明确阻断，等待用户裁定。

## 2. 实现范围

| 类别 | 本模型处理 |
| --- | --- |
| RD 定宽整数加减乘除余、比较、逻辑、移位、扩展 | 执行当前仍定义的变体 |
| 双目的 128 位加减乘 | 执行；`sub.uo` 按 ADR-0049 返回借位 0/1 |
| RB 地址加减、比较、自增 | 完整 64 位；包含当前规范的 `sub.o RD,RB,RB` |
| RD/RB/RA 单次和多寄存器 load/store | 执行，检查对齐和寄存器范围 |
| RD/RB/RA 块传送、RD/RB wyde 立即数、条件赋值 | 执行 |
| 分支、jump、call、ret、RegRAS/MemRAS | 执行 |
| `swym` | 只推进 PC，不模拟等待周期 |
| 浮点运算、RF 访存/传送/FCSR 指令语义 | 66 条已执行；有限值采用独立整数/有理数 oracle，NaN/Inf、舍入和累积标志按 `contract-fp.md` |
| 特权、trap/escape、原子、fence | `Unsupported` |
| 未定义/已删除编码，包括全零指令字 | `UNDI` |

`is_supported(record)` 查询的是指令族是否在模型范围内，不保证每种输入都不存在规范歧义。指令数量从当前表现场统计，不用历史“178 条”作为完成证明。`sub.o RD,RB,RB` 虽在表中标 `m3`，仍属用户确认的地址整数运算；特权指令即使标 `m1`，也不因此纳入本模型。

### 浮点 oracle 的确定性边界

`fp_ref.py` 只用符号位、指数、尾数和 `Fraction` 表示 finite 值。每次算术先读完所有源，再用整数商余实现 RNE、RTZ、RDN、RUP 四种舍入，最后按目标格式重新编码；因此宿主机的 `float`、LLVM 和 QEMU 都不会提供期望值。binary32 存在于 RF 低 32 位，binary64 使用完整 64 位。

结果的 NV、DZ、OF、UF、NX 以位或方式累积到 `rf0[4:0]`；写 `rf0` 只改 `[33:32]` 和 `[4:0]`。NaN 的 quiet/signaling 位和 payload 由位模式处理，分类、sign injection、RF 存取和块传送不把 RF 位模式转换成宿主数值。

以下情况是合约开放点，不输出自行选择的值：`rootn(-0,2)` 的结果、`ftsclb/fosclb` 的 NaN/Inf/溢出/下溢边界。f2i 的 finite inexact 已按新规范置 NX。模型对这些输入抛出 `SpecificationGap`；这不是架构异常，也不计作执行通过。

取整、最小/最大值与融合乘加分别按 `contract-fp.md` §18–§20 执行：`ftrnd/fornd` 的 `immu6` 是 one-hot selector，只有 `0x20` 读取 `rf0` 方向并可能置 NX；`ftmin/ftmax/fomin/fomax` 实现严格 `minimumNumber/maximumNumber`（单 NaN 返回数、双 NaN 返回规范 qNaN、sNaN 置 NV、`−0 < +0`）；`ftfma/fofma` 用精确积与加数相加后只舍入一次。

## 3. 状态和单步执行

### 寄存器与 PC

RD、RB、RA、RF 各保留 64 个 64 位槽。RF 保存浮点位模式和 FCSR；66 条浮点/RF 指令由独立位级 oracle 执行。

- `rd0` 永远读出 0；是否合法写入，由具体指令检查，不能用“丢弃写入”代替非法目的检查。
- `rb0` 在执行时保存当前控制流值；显式写 `rb0` 非法。指令成功后由模型更新它。
- `ra0[53:48]` 是 `RACNT`，`ra0[47:0]` 是 `MRPTR`；写 `ra0` 时 `[63:54]` 的 SBZ 位不成为可写状态。
- `pc` 是低 48 位取指地址；`rb0` 保留 64 位值。二者低 48 位必须一致。

成功后的 `pc`、`pc_next` 均为下一条取指地址；`rb0` 为对应的完整控制流值。这样可以把返回状态直接交给下一次 `run(state=...)`。默认地址 `0xFC0000000000` 只是当前测试向量的执行位置。

### 执行顺序

1. 检查输入与当前 PC 对齐；未对齐取指返回 `IALIGN`。
2. 译码，确认模型是否支持该指令。
3. 检查编码中能确定的合法性，例如目的寄存器、寄存器区间、立即数范围。
4. 在输入状态的副本上执行；检查动态对齐、移位量、返回栈等条件。
5. 成功才返回新状态；架构异常则返回原状态。输入对象不被修改。

因此，load/store 或 call/ret 执行到一半才发现异常，也不能留下部分寄存器或内存修改。本模型只返回异常名称，不模拟异常入口、异常级别或处理程序。

## 4. 整数运算：先明确位宽，再明确写回

`b/w/t/o` 分别为 8/16/32/64 位。令 `W` 为运算位宽，`M = 2^W - 1`。

### 算术、除余和比较

- 定宽加减乘：先取源的低 W 位，计算后取结果低 W 位；有符号变体符号扩展到 64 位，无符号变体零扩展到 64 位。
- 有符号除法：向零截断。例如 `-7 / 3 = -2`，余数 `-1`。不能直接用 Python 的负数 `//` 或 `%` 代替。
- 除数按位宽截断后为零：`div.u` 返回 `M`，`div.s` 返回全 64 位的 `-1`；`rem` 返回按符号规则扩展后的被除数。**不报 ILLI。**
- 有符号 `INT_MIN / -1`：商为该位宽的 `INT_MIN`，余数为 0，再符号扩展；**不报 ILLI。**
- 比较：按有符号或无符号解释截断后的源，产生 -1/0/+1，再按后缀扩展。例：`cmp.ub(1,2)` 得 `0xFF`；`cmp.sb(1,2)` 得 `0xFFFFFFFFFFFFFFFF`。

依据：contract-isa §6.1、§6.2、§10–12 与 SimRISC-04/08/09/10。

### 双目的和别名

`add.so`/`sub.so`/`mul.*` 的两个目的分别存放高、低部分；`add.uo`/`sub.uo` 的 `rdha` 存放进位/借位、`rdhb` 存放 64 位结果。先读取所有源，再写两个目的，源与目的同号不会读到本条指令刚写入的值。

允许一个目的为 `rd0`，表示丢弃该部分；两个目的同时为 `rd0`，或两个目的为同一个非零寄存器，均为 ILLI。

### 移位、扩展与逻辑

- 当前窄位宽移位采用“完整值写回”：无符号变体零扩展，有符号右移符号扩展，**不保留目的旧高位**。
- 寄存器形式先取移位量寄存器的低 6 位，再检查是否超过 `W-1`；立即数形式检查 `immu6 <= W-1`。超出范围是 ILLI，不能把非法量再按 W 取模。
- 当前 ext 只保留 64 位形式；起始位表示“保留源的第 0 至第 k 位，再符号或零扩展”。
- 当前三寄存器逻辑运算只保留 64 位形式。旧窄逻辑/ext 编码不再作为旧指令继续执行。

依据：contract-isa §6.3–6.4、§10–12；当前 opcodes 表。

### 条件赋值

`cs.n/cs.z/cs.p` 根据第一个源的符号、是否为零或是否为正，在另外两个源之间二选一并写入目的。`cs.eq/cs.ne` 比较前两个源，条件成立才写入第三个寄存器，条件不成立则保留它原来的值。条件和选中的源都在写入前读取，目的与源同号时不会因本条写入改变判断。

### 地址寄存器算术

RB 加减、自增和比较使用完整 64 位，结果按 64 位回绕；仅实际访存和取指时使用低 48 位。两个 RB 的低 48 位相同但高 16 位不同，`cmp.uo RD,RB,RB` 仍可能不相等。

## 5. 访存与寄存器传送

### 访存

内存按字节、大端存储。单次地址为 `RB基址 + 有符号立即数`；多次地址为 `RB基址 + RD索引 + i×元素字节数`，有效地址取低 48 位。

- load 将内存值按指令规定符号或零扩展；store 只写源的低 W 位。
- 2/4/8 字节访问要求相应自然对齐；不对齐报 MALIGN。
- 多寄存器操作在开始前保存基址和索引，避免加载覆盖地址寄存器后改变后续地址。
- 个数只能为 1–63，起始寄存器加个数不能超过 64。
- `ld/ldm` 不能以 `rd0/rb0` 为目的；`st/stm` **可以**从它们读取：`rd0=0`，`rb0=当前指令控制流值`。

内存预置 `{address, value}` 按该指令的访问宽度写入 **value 的低 N 字节**；可用 `width: 1/2/4/8` 显式指定测试预置宽度。例如 byte 访问的 `value=0x1234` 在该地址写入 `0x34`。这与 schema 中的预置 store 约定一致。

### 块传送与立即数

RD/RB/RA 之间的块传送按整 64 位位模式搬运（写 ra0 时应用其字段规则）。同组 `rd2rd`、`rb2rb` 的源、目的区间不能重叠，完全相同也报 ILLI；不同寄存器组中相同编号不属于重叠。

`set.zw` 将选中 16 位填为立即数，其余清零；RD 的 `set.ow` 其余位填一。`or.w/andn.w` 仅修改选中的 16 位，其余位保留。`wp0` 到 `wp3` 对应从低到高的四段。

依据：contract-isa §3–5，SimRISC-00/01/02/03。

## 6. 分支、调用和返回地址栈

相对分支/跳转地址为 `rb0 + (有符号立即数 << 2)`，基准是当前指令，不是下一条。寄存器跳转为 `RB + RD + (有符号立即数 << 2)`。计算保留 64 位，写回 rb0；下一次取指使用低 48 位。未跳转时顺序增加 4。

`call` 把下一条地址的低 48 位作为返回地址压栈。`ret` 从栈中取地址并按立即数设置返回值寄存器；`ret rd0, 0` 合法，`ret rd0, 非零` 为 ILLI。目标未对齐在下一次取指时产生 IALIGN，不提前伪造目标指令的执行。

### RACNT 与 MemRAS

`RACNT` 是寄存器返回栈中有效条目的个数，不能通过扫描条目是否为零来推断。每条有效记录由 16 位递归计数和 48 位返回地址组成，`ra63` 是栈顶。

| 操作 | 处理规则 |
| --- | --- |
| 空栈 call | 建立计数为 1 的新栈顶，RACNT 变 1 |
| 返回地址与栈顶相同、递归计数未满 | 递归计数加 1，RACNT 不变 |
| 其余 call、RACNT < 63 | 推入新记录，RACNT 加 1 |
| 其余 call、RACNT = 63 | MRPTR 为 0 则 RASOF；否则向 MemRAS 溢出一个条目，RACNT 保持 63 |
| ret、有效栈顶计数为 0 | RASUF |
| ret、栈顶计数 > 1 | 计数减 1，RACNT 不变 |
| ret、栈顶计数 = 1 | 弹出条目，RACNT 减 1 |
| ret、RACNT = 0 | MRPTR 为 0 则 RASUF；否则读取 MemRAS 条目，按其计数处理 |

MemRAS 条目计数为 0 是 RASUF；大于 1 时，保留减一后的记录到寄存器栈。MRPTR 是指针，**没有旧模型中的 MemRAS 总计数**。模型检查 MemRAS 对齐，但不检测 OS 分配的栈容量或地址权限。

依据：contract-isa §1.3.4、§8；SimRISC-00 返回地址栈流程。

## 7. 验证器如何避免“假通过”

1. 校验输入结构、数值范围、指令身份和编码；错字段、错身份不能靠“碰巧结果相同”通过。
2. `encoding` 只检查译码和静态合法性，单独计数，不执行零初值下的动态语义。
3. `semantic/boundary/overlap` 执行并比较显式期望；没有任何结果或 PC 断言时不能通过。`swym` 的空期望表示除 PC 外整份状态不变，会实际检查。
4. 异常用例不仅核对异常名称，还比较全部寄存器、内存和 PC，确认没有部分提交。
5. `deferred` 必须明确标状态和理由；`active` 附带理由不能偷偷跳过。模型范围外和机器层异常另列 SKIP。
6. 所有用例都跳过、文件为空、YAML 错误均非零退出。FAIL 不会被跳过计数抵消。

测试分为两层：`test_interp_v5.py` 检查从规范推导的语义与边界；`test_validator_v5.py` 故意篡改期望结果、身份、PC、异常后的状态等，检查验证器能否抓住错误。`check_golden.py` 再在临时副本中修改真实模型/向量，验证失败路径和原文件未污染。

## 8. 审查发现与当前边界

已修复的旧设计包括废弃指令身份、窄运算写回、除余异常值、RB 比较截断、控制流截断、零号存数源误拒绝、块重叠误允许、旧 RAS 计数、ret 合法性和单步状态推进。模型缺少实现时不会再自动沿用测试机 ILLI。

### `sub.uo` 的借位语义

`sub.uo` 的 `rdHA` 已由 `ADR-0049` 冻结为借位（`rdHC < rdHD` 时 1，否则 0），`rdHB = (rdHC − rdHD) mod 2^64`；不再抛 `SpecificationGap`。原“128 位高半”与“借位 0/1”的表述冲突已同步修正规范/合约。QEMU 原本已按借位实现；向量生成器与 golden 已对齐。

### 仓库向量已同步

合并远端 `origin/master` 后，原先把 `rd0/rb0` 存数源判为 ILLI 的 10 条向量已按现行零号源规则更新。全量回放 730 条：编码通过 173、执行通过 500、FAIL 0、跳过 57（5 deferred + 4 scope + 48 machine），退出码 0。若后续重新引入旧期望，应按规范重写断言，而不是把模型改回旧语义或无条件跳过。

### 当前已知不足

- **f2i**：finite inexact 已置 NX，不再抛 `FPGap`；NaN/Inf/越界按当前实现饱和 + NV，但 NaN 符号位与无符号 `-Inf` 的饱和方向仍缺独立向量。
- **scaleB**：第三源已改为 `rdHD` signed 64 位整数（`rd0=0`），`tests/inst/fp/scaleb.yaml` 可回放；旧 `rfHD` 路径不再接受。
- **FP 向量**：`tests/inst/fp/` 只有 scaleb；fma/rnd/minmax 仍只有单测和 C 探针，没有共享 YAML。
- **门控**：已新增 `check-golden`（单测 + `tests/inst` 回放 + `check_golden` + 生成器 `--check`），纳入 `make check`。
- **注入/审计**：`check_golden.py` 的模型注入只覆盖标量算术；`009t-audit.py` 对 `ctrl-br`、`ldm.o`、`shl.*` 有既存偏差。
- **L2**：依赖已配置，但 LLVM 构建在 clang 链接阶段被 OOM 杀掉，尚未跑通。

### 面向 i128/i256 的扩展

`sub.uo` 的借位和 `add.uo` 的进位是 64 位多字运算的基元；i128/i256 应由多条 64 位加减链组合，不改变单条 `sub.uo` 的借位语义。`cmp` 结果写满 64 位也便于宽比较。

### 不能由本次验证推出的结论

- 未覆盖全部 32 位指令字和所有 64 位操作数组合。
- 未穷举全部浮点输入；特权、原子、内存序以及机器地址权限仍未验证。
- 未验证编码表本身的独立正确性。
- 仓库向量通过只说明其断言成立，不能代替全部语义证明。
