## M11

- **2026-11-07 GEM5-026t**
  - 摘要：**gem5 SE 线程（clone CLONE_THREAD）、futex 与 TLS 落地**。一个线程 = 同一 `Process` 的第二个 `ThreadContext`：地址空间/fd 表/信号 disposition 共享，栈、`rb3`(TP) 与每线程 Linux 状态（`ThreadState`：阻塞掩码、pending、备用栈、clear-tid、robust list、tid）私有；`clone` 的 `CLONE_SETTLS` 把 `tls` 参数写进子线程 `rb3`（QEMU `cpu_set_tls` 等价，不另造 TLS 模型、不分配 TLS block）。`futex`(98) 的 `WAIT`/`WAIT_BITSET`/`WAKE`/`WAKE_BITSET`/`REQUEUE`/`CMP_REQUEUE`/`LOCK_PI`/`UNLOCK_PI`/`TRYLOCK_PI`：等待线程 `suspend()` 进模拟器自己的等待队列（键 = 进程 + 地址 + bitset），唤醒/超时把结果写回 `rd8` 再 `activate()`，超时用 gem5 事件队列上的 `AutoDelete` 事件——**不忙等、不重执行 trap**；`set_robust_list`/`get_robust_list` 与线程退出时的 `exit_robust_list()` 走链（标 `FUTEX_OWNER_DIED` 并 wake）。`SYS_exit` 只结束本线程（最后一个线程结束进程），退出时清 clear-tid 字并 wake（musl `__tl_lock` 依赖它），`exit_group`/致命信号仍结束进程。信号改为**每线程**（掩码/pending/备用栈），并支持在**指令边界**投递（`ISA::pendingSignal` 每指令一次 bool 检查），使纯用户态自旋的线程也能被 `pthread_cancel`；`rt_sigreturn` 改用投递时记录的帧栈而非只信 `rb1`（musl 取消处理器返回 trampoline 时 SP 可以不是帧基址）。另修 **LR/SC 跨 hart 失效**：任何 hart 的 store 清掉另一 hart 对「同一精确地址 + 同一宽度」的保留标记（contract-isa §LR-SC；没有它 musl 的 `a_cas` 在多线程下会丢更新，`sem_init` 直接失败）。`se.py --num-threads` 默认 8→64（11 个活动线程的 `pthread_cond-smasher` 与上百个短命 fork 子进程需要）。验收：独立 guest 探针 4 组（线程/TLS 独立性、raw clone SETTLS 写 rb3、futex 语义含超时与争用、robust list + clear-tid）各 3 轮一致且 fails=0；static 基线 threads/futex 桶 blocked 归零；`tls_align`/`tls_init`/`tls_local_exec` 与 19/20 例 threads/futex 代表实测 pass。**已知限制**：`raise-race`（100 次 fork + 1000 次信号）超 120 s 预算归 time budget；`CLONE_VM` 非线程 fork 仍复制地址空间；`FUTEX_WAKE_OP`/`FUTEX_FD` 未建模（显式 `ENOSYS`）。
  - 执行者：engineer

- **2026-11-07 GEM5-025t**
  - 摘要：**gem5 SE IPC（pipe/socket）与多进程（clone/execve/wait4）落地**。`se_workload.cc` 新增 `pipe2`(59)（`O_CLOEXEC`/`O_NONBLOCK`）、`socket`(198)/`socketpair`(199)/`bind`(200)/`listen`(201)/`accept`(202)/`accept4`(242)/`connect`(203)/`getsockname`(204)/`getpeername`(205)/`sendto`(206)/`recvfrom`(207)/`setsockopt`(208)/`getsockopt`(209)/`shutdown`(210)、`chdir`(49)、`clone`(220)、`execve`(221)、`wait4`(260)。pipe 是 **guest 对象**（`DadaoPipeFDEntry`：64 KiB 缓冲 + 两端计数，`dup`/`fork` 共享同一 open file description；短读、`EOF`、`EPIPE`+挂起 `SIGPIPE`），宿主 pipe 会阻塞模拟器故不用；阻塞语义统一为 `SyscallRetryFault`（空 pipe/写满 pipe/未退出的 `wait4`/无连接可取的 `accept`、`recvfrom` 让 CPU 重执行 trap，`inst.cc` 读 `SEWorkload::syscallRetry`）。socket 只透传 `AF_UNIX`/`AF_INET`/`AF_INET6`（sockaddr 的 `sa_family` 与 `SO_RCVTIMEO`/`SO_SNDTIMEO` 的 `timeval` 逐字段换序），其余族 `EAFNOSUPPORT`。多进程：一进程 = 一个 gem5 `Process` + 一个 `ThreadContext`（`se.py --num-threads`，默认 8，`system.multi_thread`），`clone` 复制地址空间/fd 表（真共享时识别 `CLONE_FILES`）、子进程 `rb1=newsp`/`rd8=0`，`CLONE_VFORK` 挂起父进程到子进程 exec/exit；`execve` 重建映像（argv/envp/auxv 仍由 `initState` 同一套栈构造，`advance()` 落在新 entry），保留 pid/ppid/子进程表/`RLIMIT_*`/信号屏蔽与 `SIG_IGN`、按 `FD_CLOEXEC` 关 fd，非 DADAO 可执行返回 `ENOEXEC`；`wait4` 返回原始 wait status（`WIFEXITED`/`WEXITSTATUS`/`WIFSIGNALED`/`WTERMSIG`）+ `WNOHANG` + `ECHILD`，最后一个进程退出才结束仿真。另补 `RLIMIT_NPROC` 强制（`EAGAIN`）与 guest 侧 `fcntl` 记录锁表（宿主同一进程无法区分 guest 进程，`F_GETLK`/`F_SETLK`/`F_SETLKW` 不再透传）。验收：独立 guest 探针 59/59（pipe 阻塞读/写、EOF、EPIPE、默认 `SIGPIPE` 终止、fork/wait status、`WNOHANG`、`ECHILD`、DADAO `execve`），代表例 ×3 一致；static 基线 IPC/socket/pipe 与 process creation/exec 两桶 blocked 归零（`qemu_only_fail` 0）。**已知限制**：`CLONE_THREAD` 仍 `fatal`（`GEM5-026t`）；`functional/popen`/`spawn`/`vfork`/`regression/execle-env` 需 guest 根内 DADAO `/bin/sh`、`echo`（语料没有）⇒ 转真实 `ENOEXEC` 失败，QEMU 之所以过是它把宿主 x86-64 二进制交给宿主内核执行。
