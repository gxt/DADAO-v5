| 检查 | 实际结果 |
|---|---|
| tag 解引用 | `c8222cc67a399bfc01e8658dd14b30d5bfd634f9`，等于组件锁 |
| `make manifest-check` | 退出 0 |
| `python3 tools/infra/check_patch_tree.py` | 退出 0；总计 5 个组件、124 个补丁 |

反例：篡改锁的 tag 或完整 SHA，`fetch.py` 非零退出；干净树上额外两次提交也非零退出；破坏补丁 hunk 时 `git apply --check` 非零退出。审阅发现并修复了初版 `fetch.py` 误接受任意干净后代的缺陷。

上游 `src/SConscript` 对 `sim/tags.cc` 使用 `AlwaysBuild`，因此重复 SCons 执行会生成版本标签并重新链接；本次没有重复编译 C++。原始构建与门控日志保存在运行产物目录，持久结论以本页为准。
