## 实现范围

- 单核 `AtomicSimpleCPU` 使用唯一 RAM `0xFC0000000000`/16 MiB 与 boot ROM
  `0xFFFFFFFF0000`/64 KiB，从复位向量装载 raw ROM。
- loader 只接受 ELF64、大端、`EM_DADAO=0x0DA0`、`e_flags=1`，按 VA=PA
  装载 RAM 内 `PT_LOAD` 并处理 BSS；错误头、越界段和入口显式失败。
- cfx0/1/2/3/63 寄存器、模式移交、指令 mask、trap/同步异常计数、
  规范 cg5 现场、一般/跨 cfx escape 和已配置向量内 fault 路由。
- semihosting 按 `rd16/rb16/rd8`、64 位大端参数块实现完整 25 服务；
  tagged trap 与 `cfxha` 无关，退出状态经 gem5 exit event 传播。

## 反例与修复

首次执行中，trap/同步异常计数保持 0，且屏蔽 `cfx63→cfx0` 的 trap 后仍
进入向量。根因是计数未在异常进入时更新，权限检查误读目标 cfx 的整个
mask 寄存器。修复后按目标 cfx 的指令 mask 判权，并记录 trap cause-info。

自主复核又发现 cg5 现场寄存器错位：旧实现把 cause IP 写入 rc0
（规范为 prev run mode），且 escape 读取不可见隐藏副本并拒绝跨 cfx 参数。
修复后 rc0–rc4 分别保存 prev mode/mask、cause ID/IP/info，escape 从可写
现场恢复并按当前 cfx 的 escape mask 检查目标；新增 RO 写、非法 rc、
跨 cfx 允许/拒绝及当前 cfx 断言，均由 FAIL 转 PASS。

独立反例把 ELF 启动后 `rd4` 的期望从 `0x55` 改为 `0xdead`，门控明确失败
并返回 1；还原后机器门控 47/47。另把真实 ELF 退出期望 42 改为 43，
工具链集成门控退出 1；还原后 1/1。
