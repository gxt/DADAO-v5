# lecnote — 讲义（课件）梳理

从「**课程定义**」与「**项目**」出发，梳理一套**面向本科生**的讲义。核心原则是**讲清楚道理**，而非罗列文档；允许与项目文件重复，或直接引用其章节。

## 输入

- **课程定义**：名称、面向对象、总范围与路线、课时预估。
- **项目**：规范 / 合约 / 决策 / 任务 / 踩坑（项目知识库与源码）。
- **读者约束**：语言、深度、已具备的理论。

## 原则

1. **一条主线**：课程必须有贯穿主线（如「规范 → 实现 → 验证」），否则会变成文档堆砌。
2. **术语随用随释**：**不在开头罗列概念**；术语**首次出现处**用「**定义块**」（见下）就地解释，含权威来源。同一术语只解释一次，后文直接用。
3. **以项目为实例**：用项目的真实片段讲道理（可引用、可复制），出处写清。
4. **坑即案例**：把项目真实踩坑写成「现象 → 根因 → 修复 → 教训」。
5. **不按课时切内容**：按主线/问题叙述，最后再映射课时。
6. **贯穿线**：方法论（Spec-first / 合约 / 独立 oracle / ADR）与 **Agent 协作**逐节点出。
7. **先出一稿再讨论**：先完成一篇代表性讲义，与用户讨论后再批量推进。

## 流程

1. **定主线**：确定贯穿主线与分节（公共核心 + 分支路线）。
2. **按主线叙述**：每节按下面的讲义模板写；术语随用随释。
3. **映射课时**：产出「章节 ↔ 课时」表。
4. **一稿先出、再讨论**。

## 讲义模板

```markdown
# <标题>

> <一句话：本课讲什么、为什么>

## 学习目标
- 学完能……（可验证的行为，2–4 条）

## <正文：按主线/问题展开>
<以叙述为主；术语首次出现处用「定义块」；用项目真实片段讲道理并标出处>

## 动手 / 实验
<可操作步骤或观察>

## 坑案例
**现象** → **根因** → **修复** → **教训**

## 小结与延伸阅读
```

## 定义块（术语随用随释的专用格式）

术语**首次出现处**用如下块就地解释；后文直接使用，不再重复。

```markdown
> **〔术语〕<中文名>（<English>）**
> <一句话定义>。
> 来源：<权威出处：标准/手册/教材/官方文档/项目章节>。
```

- 一个定义块只讲一个术语；定义用**一句话**讲清。
- 来源要**可核验**：标准名/版本、教材名/作者、官方文档，或项目章节号（如 `§N`）。

## 注意

- 讲义**不依赖任何具体仓库路径**（便于迁移）；课程与素材的对应写在正文的「项目实例」处。
- 面向本科生：**先直觉与例子，再形式化**；避免直接抛内部术语。
- 中文撰写；术语可保留英文原名。
