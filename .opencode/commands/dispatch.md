# /dispatch $ARGUMENTS — 下发任务给实现子代理

根据 $ARGUMENTS 找到任务文件，判断执行环境，调起实现子代理执行。

## 执行步骤

### 0. 定位交互目录

按 `.tao/README.md`「交互目录 `$TAO_ROOT` 定位」确定 `$TAO_ROOT`。

### 1. 查找任务文件

在 `$TAO_ROOT/tasks/` 中递归搜索匹配 `$ARGUMENTS` 的文件：
- 搜索模式：`$TAO_ROOT/tasks/**/$ARGUMENTS*.md`（任务按模块分目录）
- 找到多个时列出让用户选择
- 找不到时提示用户先创建任务文件

### 2. 读取任务文件，提取关键字段

- **任务状态**：检查 `**状态**` 字段（四态状态机，见 `.opencode/agents/architect.md`「任务状态机」）：
  - `待开始` → 正常下发执行
  - `待返工` → 允许下发，但任务描述中**必须注明**"此任务为返工任务，先处理审查者 Needs Revision 意见（见审阅记录 → 最新一轮 reviewer 验收）"
  - `待验收` / `已验证` → 不重复下发，提示用户先 `/complete` 或确认是否真的要重做
  - `k` 后缀 → 启动任务由 `/plan` 处理，不通过 `/dispatch` 下发
  - `m` 后缀 → 里程碑标记文件，不下发，提示用户这是里程碑标记

- **依赖检查**：读取 `**依赖**` 字段；所列前置任务（可跨模块）若未全部 `已验证`，拒绝下发并提示缺失项

- **执行环境**：判断目标执行位置
  - `本地` → 本地执行，无需同步
  - `远端 * · <节点/仓库名>`（如 `远端 21 · <repo-name>`）→ 需同步到远端机器

- **知识库引用检查**：引用格式应为 `§章节号`（如 §20.10），行号会变不要要求。
  若引用完全缺失章节号则提醒补充。

### 2.5 下发前预检（强制）

下发前四项预检，结论写进下发说明：① **任务书内部一致性**（目标/范围/约束/验收不矛盾，教训 `QEMU-014t`）；② **本任务验证手段**所需全部前置（含跨任务指令/工具）实际可用（依赖「已验证」≠能力具备，教训 `QEMU-005t`）；③ **验收可执行性**——逐条标「现在可跑 / BLOCKED（原因 + 替代证据）」，不可跑者须写明替代验证（最小 ROM 探针 / 独立 oracle / 仓库向量回放）；④ 指令范围/编码/期望值来源与 `contracts/`、`tests/vectors/` 一致。

并发约束：**同时在跑的子代理 ≤ 8**；**同改共享文件**（`contracts/`、`Makefile`、`tests/vectors/`、`spec/SimRISC-0x` 等）的任务**一律串行**；长构建受 `JOBS=8`、禁全核（见 `AGENTS.md`「并行任务上限」「长任务」）。

### 3. 远端任务：同步到远端机器

若 `执行环境` 含 `远端`，**先查阅知识库中的 `registry.md`（若存在）**，
在路由规则表中找到匹配的行，**直接使用表中记录的传输命令**同步任务文件；
**若该文件不存在，请用户提供传输命令，不要自行假设**：

路由表示例（若 `$TAO_ROOT/knowledge/registry.md` 存在，实际值以其为准；不存在则由用户提供）：
```
| `远端 21 · <repo>` | `scp <file> user@host-21:~/<repo>/.tao/tasks/<module>/` | 远端执行智能体 |
| `远端 152 · <repo>` | `scp -P 22005 <file> user@host-152:~/<repo>/.tao/tasks/<module>/` | 远端执行智能体 |
```

将 `<file>` 替换为本地任务文件实际路径，执行传输命令。确认成功后再继续。

> **不要**假设一律用 `rsync`，传输命令以路由表为准（可能是 scp / scp -P / rsync）。

### 4. 调起实现子代理

用 `task` 工具调起 `engineer` 子代理执行该任务文件：

- **subagent_type**：`engineer`（定义见 `.opencode/agents/engineer.md`）
- **任务描述**：让子代理读取 `$TAO_ROOT/tasks/<module>/<完整文件名>.md` 并按其执行，遵守其 agent 规则
- 子代理执行完成后返回结果（完成区内容、自审结论、遗留问题）

**远端任务**：远端由对应机器上的协作智能体执行（见路由表执行方）。本命令只负责同步任务文件到远端。

**空返回容错**：若 engineer 子代理返回**空结果**或明显异常（未含完成区/验收结论），**立即停止**，向用户汇报异常，不继续当作执行完成；**不自行重试**。

### 5. 收尾（本地任务立即 /complete）

- **分支—提交—push**（**单一真源**）：见 `AGENTS.md`「任务收尾·分支—提交—push」——本任务在**开工分支内**提交，architect 在**每次 engineer / reviewer 返回后** commit，主会话在 `/complete` 后 `merge --squash` 落地 `master` + `push`(FF)。
- **本地任务**：工程师返回后（状态已 `待验收`），**不要停在汇报**——先调起 `architect` 执行「提交 + 文件集审核」（见 `.opencode/agents/architect.md`；Accepted ⇒ 正常提交，否则 `WIP:`；**不 push**），**再**进入 `/complete <任务编号>` 收尾（reviewer 验收 → architect 复核 → memory/知识库更新；完整步骤见 `.opencode/commands/complete.md`），收尾报告即汇报。
- **远端任务**：确认任务文件已同步到远端，提示用户：**远端执行完成后，将含完成区的任务文件回传本地**（用路由表传输命令反向 pull，或远端 push 回本地），再运行 `/complete` 收尾。

### 6. 子代理硬约束（下发提示必带）

每次 `/dispatch` 提示**必须内联** `AGENTS.md`「子代理硬约束」的 11 条最小清单（临时目录、不提交 git、完成区对齐真实输出、只动任务范围、失败即停、补丁导出、日志留存、一键证据脚本、用户裁定落盘、提交权归 architect、还原纪律）。引用既有规则，不重复定义。

## 注意

- 下发目标（本地 / 远端）必须与任务文件 `执行环境` 字段一致
- 路由规则从知识库的 `registry.md` 读取（若存在）；不存在时请用户提供，不要硬编码主机地址
- 知识库引用用章节号（§4.5），不要要求行号
- 传输失败时报错，不要继续
