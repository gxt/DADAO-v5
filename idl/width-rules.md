# IDL 宽度与符号派生规则表

> **用途**：M17 的 Python 前端/执行器（`m17-idl-002`/`m17-idl-003`）做类型推导与求值时，
> 宽度、符号、写宽的**唯一依据**。每条规则都标出处；本仓规范查不到出处的一律进
> §7 未定义清单，**不自行裁定**（用户 2026-11-20 口径）。
> **机械校验**：`python3 idl/subset_stats.py --check` 逐条把出处钉到**具体章节的正文锚点**
> （节号写错、换到不定义该规则的章节 ⇒ 红）。构造盘点见 [`syntax-subset.md`](syntax-subset.md)。

## 1. 口径

- **出处只认三处**：`spec/SimRISC-0x-*.md`（指令散文）、
  `spec/IDL-ISA语义描述语言与语义库.md`（语言与语义库）、`.tao/contracts/contract-*.md`（合约）。
- `.idl` 注释、`idl/diff-vs-udb.md`、任务书、UDB 文档**都不是**出处：它们只能解释，不能裁定。
- 规则行格式为三列 `ID | 规则 | 出处`（出处写 `path` §N）；`--check` 校验 ① 该文件存在 ② 该节存在
  ③ 该节正文含该规则的锚点语句（弱锚点不放行）。
- 「未定义」不是「随实现定」：执行器遇到这些构造必须先取裁定（见 §7）。

## 2. 类型与字面量

| ID | 规则 | 出处 |
| --- | --- | --- |
| W01 | `Bits<N>` 是无符号位向量，`N` 编译期已知；无符号域内 `+ - *` 不改符号解释 | `spec/IDL-ISA语义描述语言与语义库.md` §1 |
| W02 | `U32` = `Bits<32>` 别名（库函数形参 `U32 width_bits` 用它） | `spec/IDL-ISA语义描述语言与语义库.md` §1 |
| W03 | `Boolean` 是独立类型：`if`/`for` 条件必须是 `Boolean`，整数不隐式转布尔 | `spec/IDL-ISA语义描述语言与语义库.md` §1 |
| W04 | 赋值/二元运算的宽度扩展：有符号操作数**符号扩展**、无符号**零扩展** | `spec/IDL-ISA语义描述语言与语义库.md` §1 |
| W05 | `$signed(x)` = 有符号视图：位模式不变，只改「如何解释符号」（比较/右移/除法由此分叉） | `spec/IDL-ISA语义描述语言与语义库.md` §1 |
| W28 | 解码变量的位宽与符号由命名约定给出：`imms12` 12 位有符号、`immu18` 18 位无符号 | `spec/IDL-ISA语义描述语言与语义库.md` §2 |

- 宽度的**唯一来源**是声明处的 `Bits<N>`；没有全局「默认 64 位」规则。
- `W04` 只给**扩展方向**；「普通二元运算的结果宽度」与「赋值到更窄 `Bits<N>` 时的截断」由
  语言规范 §1.1 定义（`U10`）：结果宽 = 两操作数较宽者、赋值取低 N 位。`.idl` 大量依赖该口径
  （如 `Bits<16> sum = $signed(src1) + $signed(src2);` 取低 16 位）。
- `W05` 只改解释：`$signed(rd[rdHC]) >>> n` 与 `rd[rdHC] >> n` 的位结果不同，但都是同一组位。
- `W28` 只给**解码变量**的位宽（来自编码字段），不是指令语义；扩展规则仍按 `W04`。

## 3. 寄存器组、写宽与窄位宽

| ID | 规则 | 出处 |
| --- | --- | --- |
| W09 | 四组寄存器各 64 个、每寄存器 64 位；`fo`/`ft` 是 `rf` 的两个数据视图（同一存储） | `spec/IDL-ISA语义描述语言与语义库.md` §3 |
| W10 | 写宽度：`rd`/`rb`/`ra`/`rf`/`fo` 整 64 位；`ft` 只写低 32 位；按 wyde 写 = 切片赋值（其余位保持） | `spec/IDL-ISA语义描述语言与语义库.md` §3 |
| W13 | 寄存器模型（合约口径）：4 组 × 64 个，每寄存器 64 位 = 机器字长 | `.tao/contracts/contract-isa.md` §1.1 |
| W21 | 数据宽度后缀：`.b` 8 位、`.w` 16 位、`.t` 32 位、`.o` 64 位 | `.tao/contracts/contract-isa.md` §2.5 |
| W22 | ft 结果**只写目的低 32 位、高 32 位保持原值**（不符号扩展、不零填）；64 位整搬移是例外 | `spec/SimRISC-00-指令系统设计.md` §2.3 |
| W26 | 窄位宽（8/16/32）运算：只有 size 内低位参与、溢出静默丢弃，结果再按 `.s`/`.u` 符号/零扩展至 64 | `spec/SimRISC-08-32位数据运算.md` §1.1 |
| W27 | `lr` 窄读（`.t`/`.w`/`.b`）只写低 32/16/8 位、rd 高位保持（既不零扩展也不符号扩展） | `spec/SimRISC-12-其它指令.md` §1.1 |

- 六个数组（`rd`/`rb`/`rf`/`ra`/`fo`/`ft`）里只有 `ft` 是 32 位元素；`fo` 与 `rf` 是同一存储的
  两种 64 位读法（`W09`）。
- **写宽 ≠ 数据宽度**：`.t` 存储（`W21`）写 `rd` 时是「整寄存器写」；真正「只改部分位」的只有
  三类：wyde 写（`W10`，切片赋值）、`lr` 窄读（`W27`）、`ft` 结果（`W22`）。
- `.idl` 里「只改一个 wyde」按**切片赋值**写（`rd[rdHB][31:16] = …`，共 69 行切片赋值），
  其余位天然保持（`W10`）。

## 4. 运算符宽度

| ID | 规则 | 出处 |
| --- | --- | --- |
| W06 | 加宽加 `` `+ ``：结果宽 = 两操作数最大宽 + 1，精确保留进位（64+64 用 `Bits<65>` 接） | `spec/IDL-ISA语义描述语言与语义库.md` §1 |
| W07 | 加宽左移 `` `<< ``：移位量须为编译期常量（`SimRISC-07` 用 40 把 32 位尾数对齐到 bit63） | `spec/IDL-ISA语义描述语言与语义库.md` §1 |
| W08 | 加宽乘 `` `* ``：用于 64×64→128 的精确乘积（`fo_mul` 用它求 106 位积） | `spec/IDL-ISA语义描述语言与语义库.md` §4.7 |
| W23 | 比较结果 −1/0/+1 **写满 64 位**（全 1 / 0 / 1）；有符号与无符号视图分别比较 | `spec/SimRISC-04-64位数据运算.md` §1.3 |
| W24 | 算术右移 `>>>` 高位补符号位（`shr.s`）；逻辑右移 `>>` 高位补零（`shr.u`） | `spec/SimRISC-04-64位数据运算.md` §2.2 |
| W25 | 逻辑左移 `<<` 低位补零；移位量取 `hd` 低位，`shamt > N` 触发 ILLI（N=63 ⇒ 0..63 全合法） | `spec/SimRISC-04-64位数据运算.md` §2.2 |

- 三个加宽运算符的出处不同：`` `+ ``/`` `<< `` 在语言规范 §1，`` `* `` 只在 §4.7 被提到
  「用于 106 位精确积」；`` `* `` 的结果宽 = 两操作数位宽之和（`U06`，语言规范 §1.1）。
- 普通 `+ - *` 的结果宽 = 两操作数较宽者（`U10`，语言规范 §1.1），落盘宽度由赋值处的 `Bits<N>` 决定
  （更窄则取低 N 位）；需要进位/128 位积时必须显式加宽，`.idl` 就是这么写的（`Bits<65>`/`Bits<128>`）。
- 移位量统一取低 6 位（`immu6` 或 `rd[..][5:0]`），`shamt > 63` 不会发生（`W25`）；
  算术右移的符号位来自**视图**（`$signed`，`W05`），不是指令后缀的副作用。

## 5. 特殊寄存器

| ID | 规则 | 出处 |
| --- | --- | --- |
| W14 | `rd0` 固定为 0、只读；作目的时按格式判定（双目的允许丢弃一半；其余目的 rd0 ⇒ ILLI） | `.tao/contracts/contract-isa.md` §1.3.1 |
| W15 | `rb0` 读出 = 当前指令地址（IP，整 64 位）；指令不得把 `rb0` 当普通目的（⇒ ILLI），写 `rb0` 只经 `jump()` | `.tao/contracts/contract-isa.md` §1.3.2 |
| W16 | `rf0` = FCSR：`[33:32]` 舍入模式、`[4:0]` 异常标志（sticky）；写 rf0 只更新这两个位域 | `.tao/contracts/contract-isa.md` §1.3.3 |
| W17 | `ra0` = `{SBZ, RACNT[53:48], MRPTR[47:0]}`；`ra1`–`ra63` = 递归计数 + 返回地址，`ra63` 为栈顶 | `.tao/contracts/contract-isa.md` §1.3.4 |

- `.idl` 里 0 号的特殊行为由**模型不变量**保证（存储视图是数组），operation 只写「本条指令对
  0 号的非法判定」：`if (rdHB == 6'd0) { raise(...); }`。
- `rb0` 的写通道只有 `jump()`（`W15` + 语言规范 §4.3）；`rd0` 的读写丢弃是模型行为，
  不写进 operation。
- `ra0` 的 `[63:54]` 是 SBZ（写无效）⇒ `.idl` 写 `ra[6'd0][53:0]` 而不是整寄存器（`W17`）。

## 6. 地址与访存

| ID | 规则 | 出处 |
| --- | --- | --- |
| W11 | 访存按**大端**：最低地址的字节是最高有效字节（`read_memory`/`write_memory`） | `spec/IDL-ISA语义描述语言与语义库.md` §4.4 |
| W12 | `read_memory(width, ea)` 返回 64 位、结果**零扩展**至 64；符号扩展由各指令自己做 | `spec/IDL-ISA语义描述语言与语义库.md` §4.4 |
| W18 | 基础数据类型 8/16/32/64 位：byte / wyde / tetra / octa | `.tao/contracts/contract-isa.md` §1.4 |
| W19 | 有效虚拟地址 48 位：访存基址取 `rb[47:0]`；控制流地址按 64 位全宽计算、取指取低 48 位 | `.tao/contracts/contract-isa.md` §1.5（`rb[47:0]`）；取指取低 48 位另见 `spec/IDL-ISA语义描述语言与语义库.md` §4.3 |
| W20 | 存储端序：指令字与数据同为**大端序** | `.tao/contracts/contract-isa.md` §1.6 |

- 访存三步：`Bits<64> ea64 = rb[rbHB] + $signed(imms12);` → `Bits<48> ea = ea64[47:0];`
  → `read_memory(width, ea)`。**截断发生在 48 位处**（`W19`），不是 64 位。
- `read_memory` 已零扩展（`W12`），所以 `.ub/.uw/.ut` 直接写目的；`.sb/.sw/.st` 在指令里
  自己用复制式符号扩展（`{{56{v[7]}}, v}`）。
- 大端（`W11`/`W20`）只影响「字节 ↔ 位」的映射，不影响寄存器内的位序（`.idl` 用 `[msb:lsb]`
  直接切片，不需要按字节换序）。
