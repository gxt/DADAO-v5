# SPEC-012k: 版本更新启动（0.5.3 → 0.5.4）

**模块**：spec
**项目里程碑**：M2
**依赖**：无
**状态**：已验证

## 问题根源

当前 SimRISC 规范（0.5.3）的指令文档按寄存器类型分类（数据类/地址类/浮点类/系统类），但 `docs/assembly-list.md` 中的指令表已按数据宽度和操作类型重新分类。这种分类不一致导致：
1. 查找指令时需要跨多个文档
2. 新分类更符合实际使用场景（按数据宽度组织）
3. 需要为 M2（Basic CodeGen）提供更清晰的规范结构

## 目的

将 SimRISC 规范从 0.5.3 升级到 0.5.4，核心是指令文档的分类重组：
1. 按 `docs/assembly-list.md` 的 12 个分类重新组织指令文档（01-12）
2. 保持 SimRISC-00（指令系统设计）独立，更新版本号和交叉引用
3. 存档 0.5.3 文档，创建新分类文档
4. 语义变更（st 指令零寄存器、寄存器复制范围限制、swym 编码）在 opcodes.yaml 之前完成
5. 更新下游合约、引用和工具脚本

## spec/ 只读策略（0.5.4）

`spec/` 在 0.5.3 中标注为只读。**0.5.4 起**，策略调整为：**只有 spec 模块的任务才能修改 `spec/` 下的文件**。非 spec 模块任务若需修改 spec 文件，必须通过 spec 模块任务进行。

## 关键决策

- **QFC 编码表**：保持原样不重排。
- **跨分类内容处置**：抽取到公共章节（扩 `SimRISC-00`），分类文档**交叉引用**而非复制。
- **deferred 内容**：浮点和待定**单独成文**并保留 `deferred` 标记。
- **第一版约束**：文档重组时尽量保持 0.5.3 的内容，不要自行发挥。
- **语义变更时机**：先重组文档 → 语义变更 → 再更新 opcodes.yaml。
- **opcodes.yaml 字段调整**：待 spec 基本调整好后再专门讨论方案。
