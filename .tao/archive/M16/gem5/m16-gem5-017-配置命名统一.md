# m16-gem5-017: gem5 配置命名统一（`se.py` + `--cpu-type`，删 `se_timing.py`）

**模块**：gem5

**依赖**：`m16-gem5-006`（Timing 访存实现）；与 `m16-gem5-015` **并行**（它改 `fs.py`，本任务改 `se.py` + `compare_chipyard.py`，零文件重叠）

## 背景（用户 2026-11-19 裁定）

现命名把**执行模式**（SE/FS）与 **CPU 类型**（atomic/timing）压进文件名：

```
se.py / se_timing.py / fs.py / fs_timing.py(拟)
```

gem5 上游的做法是：**脚本按模式命名，CPU 类型走 `--cpu-type {atomic,timing,minor,o3}`**（`configs/example/{se,fs}.py`）。DADAO 采用同构：

```
configs/dadao/se.py  --profile user                --cpu-type {atomic,timing}
configs/dadao/fs.py  --profile {tiny,vast}         --cpu-type {atomic,timing}
```

## 要做

1. **`se.py` 加 `--cpu-type {atomic,timing}`**，默认 `atomic`（行为不变）；
2. **把 `se_timing.py` 的实现并入 `se.py` 的 `timing` 分支**（`DadaoTimingSimpleCPU` + `NoncoherentXBar` + `SimpleMemory` + `--wuming-cycles` 的接线），然后 **删除 `configs/dadao/se_timing.py`**；
3. **改引用点**：`tools/gem5/compare_chipyard.py`（`CONFIG` 指向 `se.py`，命令行补 `--cpu-type timing`）、`components/gem5/README.md`、`Makefile` 帮助、相关任务书；
4. **`--profile` 在 SE 侧**：SE 只有 `user` 机型，`--profile user` 可省略（默认即 user），但要能接受该参数（与 `fs.py` 一致）；
5. 不碰 `fs.py`（归 `m16-gem5-015`）。
