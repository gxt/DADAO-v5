# m17-idl-009: 阶段一收口——`pending` 清零与四方零红

**模块**：idl
**项目里程碑**：M17
**依赖**：`m17-idl-005`、`006`、`007`、`008`
**可并行分片**：否
**预估**：1–2 h
**档位**：中改（复核 ≤40 min）
**状态**：已验证

## 背景

阶段一 = 非 FP 的 222 个 `tests/inst` 镜像（272 − `07-floating-point` 50），四方（IDL/QEMU/gem5/chipyard）签名槽 + 退出码一致。本任务只做收口审计，不补语义。

## 要做

1. `idl/idl_exec_cases.toml` 的 `pending` 段清零；主清单集合 == 现场派生集合（脚本断言，禁写死 222）；若仍有「id 已注册但不在主清单」的镜像，本任务负责加入并跑绿（**不补语义**）；
2. 全量四方（含 gem5/chipyard）跑一遍：**默认在主控机**（222 例约 2 min，属 <5 min 冒烟）；若期间有组件重建或仿真器 md5 变化，改派节点复跑并记录节点与耗时。逐例记录槽数与退出码；红例逐条归因（spec/IDL/QEMU/gem5/RTL/资产）后修复或登记；
3. 检查 `check-idl` 的 L2 强度：耗时、并发安全（`GATE_LOCKED_TARGETS`）、缺安装根时 ERROR；
4. 更新 `idl/README.md`：四方用法、`pending` 归零、门控说明、逐指令 trace 的「仅归因」定位；
5. 抽样（不进判据）：picolibc `--stage fast` 与 embench 子集各跑 ≥1 例，各平台的通过/失败如实记录。

## 不做

- 不改已通过 id 的语义（发现缺陷 ⇒ 登记 issue 或另立任务，不在本任务修）；
- 不碰 FP（阶段二，等 `N26` 裁定）；
- 不改 `tests/inst` 载体与 `expected.tsv`。

## 约束

- 独立 `git worktree`；不提交 git；术语「寄存器组」；
- 报告落运行期证据目录，仓库内只改 `idl/README.md` 与本任务书；
- 计数现场派生；完成区 ≤30 行、不写运行期路径。

## 验证

1. `pending` = 0 且集合断言通过；222 例四方全绿，贴现场计数；
2. **可达 FAIL ≥2**：① 往 `pending` 加回一条 ⇒ 集合断言红；② 把某册镜像从主清单删一条 ⇒ 集合断言红；`cp`+md5 还原后回绿；
3. `make check-idl`（L2）rc=0，贴耗时；`check-idl-parse`/`check-idl-sync`/`check-knowledge-refs` rc=0；
4. 抽样两套的真实结果（通过/失败例名）记录在完成区，不写成判据。

## 完成区

**测试结果**：证据脚本（运行期证据目录内 `run.sh`）**rc=0 / PASS=17 FAIL=0**；注入两路均可达 FAIL（pending 加回 ⇒ rc=2「同一镜像同时在主清单与 pending」；主清单删一条 ⇒ rc=2「主清单缺 1 个应纳入镜像」），`git diff` 非空 + `cp` 还原后 md5 相等、单例回绿。
**修改文件**：`idl/README.md`（新增「四方差分与门控」节）；本任务书。
**验收结果**：现场派生 **main 222 = derived 222 / pending 0 / FP 排除 50**；`make check-idl` **rc=0，19.6 s，222/222（IDL+QEMU）**；全四方 `--platforms qemu,gem5,chipyard --jobs 62` **rc=0，101.3 s，222/222，槽 3552，`[FAIL]`=0**（222 行均 `parties=4`、四方 rc 全 0）。二进制 md5 与 `008` 记录相同（qemu `a9ca4aec…`、gem5 `b9db6a94…`、chipyard `6d699cc3…`），故按任务书在主控机跑、未改派节点。`check-idl-parse` rc=0、`check-idl-sync` rc=0。L2 接线：`_locked-check-modules` 前置含 `check-idl`，`GATE_LOCKED_TARGETS` 含 `check-idl`/`check-modules`；缺 QEMU 安装根 ⇒ `check-idl: ERROR … not found` 非零；持 `gate.lock` 时 `GATE_LOCK_FAILFAST=1 make check-idl` ⇒ 日志 `rc=75` 拒绝。ExecError 审计：`contracts/opcodes.yaml` **263** 条 / `SEMANTICS` **213** / 未注册 **50**，未注册集与 `07-floating-point` 50 个镜像 stem **完全相等**，**非 FP 缺 0**（无新增 ExecError id）。抽样（不进判据）：picolibc `--stage fast` 的 `test-hello`/`test-printf`/`semihost-clock` **3/3 pass**（40.8 s）；embench static `-O0` 的 `aha-mont64`/`crc32`/`matmult-int` **3/3 pass**（27.1 s）。
**新发现/坑**：① `make -n check-modules` 不可作接线证据——`gate-locked` 规则带 `+`，`-n` 会真实执行整条 L2（Process-07 §1），改用 Makefile 文本机械解析 + 实跑持锁拒绝取证。② `check-knowledge-refs` 当前 rc=2（1 条悬空），但 `git archive HEAD` 基线树**逐行相同**（`.tao/knowledge/milestones-m18.md:39` 引用未创建的 `ADR-0059`，属 `m18-linux-013` 在飞工作），本任务零改动，按 KNOWN-RED 处理。③ FP scope 共 65 个 id，但只有 50 个有 `tests/inst` 镜像，故 `213 + 50 = 263` 而非 `213 + 65`。
**遗留问题**：① `check-knowledge-refs` KNOWN-RED（见上，需 `m18-linux-013`/ADR-0059 创建后自愈，本任务不修）；② 无其它未完成项、无缺陷登记。
