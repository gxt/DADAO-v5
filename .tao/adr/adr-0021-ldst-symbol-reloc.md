# ADR-0021: `ld/st` 符号偏移 reloc 体系（`REL12` + `ABS12` + 专用类型）

**状态**：Accepted（rev. 2026-10-09：`D1` 由「引入 `REL12`」扩展为「引入 `REL12` + `ABS12` 双类型」，见 `## 修订`）
**日期**：2026-10-08
**决策者**：用户（逐条确认，见 `INTEG-023k §A #8/#9 + §B`；`SPEC-122t` 完成区 Q4 ②）
**关联**：`ADR-0019`（DADAO M4 重定位类型；本 ADR 为其**扩展**，新增编号 4/5 两类型 `REL12`/`ABS12`）、`ADR-0003`（Object ABI：`e_flags[7:0]=1` namespace）、`contract-elf.md §2–§4`（重定位正文，正文落点归 `SPEC-123t`）、`ISS-151`、`ISS-161`、`INTEG-023k §A #8/#9、§B`、`SPEC-123t`（正文）、`LLVM-065t`（实现）、`TESTCASES-036t`

## Context（背景）

- `ADR-0019` 冻结 M4 reloc 集：`ABS48`(0) / `REL26`(1) / `REL20`(2) / `REL14`(3) / `NUM`(4)，覆盖绝对地址与分支/调用相对寻址；**未含 load/store 访存的符号偏移**。
- `LLVM-052t` / `LLVM-054t` reviewer 判（`ISS-161` / `ISS-151`）：
  - `ld/st ..., [rb1, sym]` 的**访存符号偏移**需 `R_DADAO_REL12`——`spec/SimRISC-01 §存取类指令`：单 load/store 的地址 = `rb + imms12`（12 位立即数）；用户允准 M4 之后补，**须 ADR 逐条确认**（属新增第 5 类）。
  - 现 `DADAOMCCodeEmitter` 对访存符号偏移走**默认分支**落 `R_DADAO_REL20`——`REL20` 服务 `br.n/nn/z/nz/p/np`（`riii`，18 位立即数、有效 20 位），与 `ld/st` 的 `imms12`（12 位、有效 14 位）**字段与语义均不同**，复用即**错编码**（既有缺陷，非本 ADR 引入）。
- `INTEG-023k §A #8/#9`（用户 2026-10-08 逐条裁定）：「`REL12`（#8）与 `ISS-151`（#9）**合并**为 `ld/st` 符号偏移 reloc 体系」；`ISS-151` = **新增专用类型、不复用 `REL20`**，且**必须覆盖超出 `REL12` 的情形**。
- 约束：reloc 类型在 **`e_flags[7:0]=1`** namespace 内独立编号（`contract-elf §2`），不沿用 legacy `Dadao.def`；v5 相对类公式**无 `-4`**（`rb0` 读出为当前指令地址，`ADR-0019 D3`）。

**承载位置**：本 ADR **只记决策/理由/被否方案/指向规范章节的引用**；reloc 类型的**规范正文**（类型名 / 编号 / 位宽 / 编码字段 / 公式 / 溢出 / 松弛）归 `contract-elf.md §2–§4`，由 `SPEC-123t` 落笔（`spec/Process-03-ADR编写规范.md`「ADR 不承载规范正文」）。

## Decision（决策）

**D1 — 引入 `REL12`（load/store 相对寻址）**
为 `ld/st` 的符号偏移（`ld/st ..., [rb, sym]`，编码字段 `imms12`）引入**新的相对寻址 reloc**（用户确认名 `REL12`；namespace 内符号名以 `SPEC-123t` 正文为准），作为 `ADR-0019` reloc 集的**第 5 类扩展**。**公式**（含是否 `>>2`、减数基准 P 的定义）属规范正文，归 `SPEC-123t`；本 ADR 不定公式。

> **D1 扩展（rev. 2026-10-09，用户逐条确认）**：引入的类型由 `REL12` **单一扩展为两个类型**——**`REL12`**（基址 **`rb0`**，PC 相对，`field = S + A − P`，`P` = 该访存指令地址 = `rb0` 读出值）+ **`ABS12`**（基址 **`rb1–rb63`**，基址相对，`field = S + A`）；两者**字段宽度同为 `imms12`（字节）、公式不同**。因 ELF `RELA` 记录**无「基址寄存器」字段**，**由汇编器按访存基址寄存器自动选型**（`rb0` ⇒ `REL12`；否则 ⇒ `ABS12`），**必须明确区分**（否则 PC 相对与基址相对混淆 ⇒ 静默错值）；**linker 只看类型、不解码指令**。原「引入 `REL12`」决策**不改**，本条为其扩展。**注**：公式/编号/字段/越界**规范正文**仍归 `SPEC-123t`（`contract-elf.md §2–§4`）。

**D2 — `ld/st` 符号偏移用专用类型，不复用 `REL20`**
`ld/st` 符号偏移**必须**使用本体系的专用类型，**不得复用 `R_DADAO_REL20`**——`REL20` 服务分支相对类（18 位立即数、有效 20 位、`riii`），与 `ld/st` 的 `imms12`（12 位、有效 14 位）字段与语义不同，复用会产出错误编码。`ISS-151` 记录的「走 emitter 默认分支落 `REL20`」是**既有缺陷**，本决策予以纠正。

**D3 — 必须覆盖超出 `REL12` 的情形**
本体系**必须覆盖符号偏移超出 `REL12` 有效范围（±2 KiB）的情形**——不得静默截断、误编码或静默出 0。其**具体机制**（是否另设更宽专用类型 / 序列化 / 越界报错）属规范正文，归 `SPEC-123t` 裁定；本 ADR 只确定「**必须覆盖**」这一决策。

## Rationale（理由）

- **引入 `REL12`（D1）**：`ld/st` 的地址 = `rb + imms12`（`spec/SimRISC-01`），符号偏移天然落在 12 位立即数字段；`ADR-0019` 未覆盖该场景 ⇒ 需新增（`ISS-161`）。
- **不复用 `REL20`（D2）**：`REL20` 是分支相对类（有效 20 位、`riii` 字偏移），与访存的 12 位**字节**偏移字段不匹配；复用会把访存偏移按分支语义编码 ⇒ 静默错误。此为 `ISS-151` 登记的既有缺陷。
- **覆盖超出 `REL12`（D3）**：12 位有符号立即数范围有限（±2 KiB）；符号偏移超出时须有确定行为，不得截断/静默 0——与 `ADR-0019 D6`（越界 ⇒ link-time error）同源的「越界须显式失败」原则。
- **合并为单一体系（#8+#9）**：`REL12` 与 `ISS-151` 是同一场景（访存符号偏移）的两个面（引入类型 + 纠正错用），合并记录避免决策分散。

## Consequences（影响）

- **LLVM MC/ELF**：`DADAOFixupKinds` / `MCCodeEmitter` / `getRelocType` 增 `REL12`，并让 `ld/st` 符号偏移走专用分支（**不再落 `REL20`**）；`llvm/include/llvm/BinaryFormat/ELF.h` 增对应 `R_DADAO_*` 枚举（最终符号名/编号以 `SPEC-123t` 正文为准）。实现归 `LLVM-065t`（在 `SPEC-123t` 正文之后）。
- **LLD**：`lld/ELF/Arch/DADAO.cpp` 增 `REL12` 的 `relocate`；超出 `REL12` 的行为按 `D3`（机制待 `SPEC-123t` 定）。
- **spec**：`contract-elf.md §2–§4` 补 `REL12`（编号/公式/溢出）及「超出 `REL12`」的正文（`SPEC-123t`）；本 ADR 不含正文。
- **下游**：`LLVM-065t` 依本 ADR + `SPEC-123t` 正文实现；`TESTCASES-036t` 覆盖 `ld/st` 符号偏移（含超出 `REL12`）向量。
- **不引入新 ISA**：本体系仅扩展 reloc 类型，不改 ISA 指令/编码（`ld/st` 的 `imms12` 字段不变）。

## 被否方案（记录）

- **复用 `R_DADAO_REL20`**（现状 emitter 默认分支）：否决——字段宽度与语义均不符（有效 20 位分支 vs 12 位访存），静默错误（`ISS-151`）。
- **不引入 `REL12`**（`ld/st` 符号偏移不发 reloc）：否决——与 `ISS-161` 的 `FK_Data_*` 静默出 0 同类缺陷，禁止静默。
- **只做 `REL12`、不定义超出情形**：否决——超出范围须有确定行为，不得静默截断（`D3`）。
- **在 ADR 内定类型名/编号/位宽/编码**：否决——规范正文归 `spec/`（`Process-03`「ADR 不承载规范正文」）。

## 修订

**rev. 2026-10-09（用户 2026-10-09 逐条确认；`SPEC-123t`）**：`D1` 由「引入 `REL12`（单一类型）」**扩展为「引入 `REL12`（`rb0`，PC 相对）+ `ABS12`（`rb1–rb63`，基址相对）两个类型」**；原 `D1`/`D2`/`D3` 的 Accepted 决策**不删**，只追加/澄清。

- **① 两个类型（区分依据 = 基址寄存器）**：`REL12` 服务 **`rb0` 基址**（`ld/st rd, [rb0, sym]`），`rb0` 读出为当前指令地址 ⇒ PC 相对，公式 `field = S + A − P`；`ABS12` 服务 **`rb1–rb63` 基址**（`ld/st rd, [rbN, sym]`），基址为通用基址寄存器 ⇒ 基址相对，公式 `field = S + A`。两者**字段宽度同为 `imms12`（字节）、公式不同**。
- **② 自动选型**：ELF `RELA` 记录**无「基址寄存器」字段** ⇒ **由汇编器按访存基址寄存器自动选择类型**（`rb0` ⇒ `REL12`；否则 ⇒ `ABS12`）；**不得**只用一个类型承载两种公式。**linker 只看类型、不解码指令**。
- **③ 越界**：两类型越出 `imms12` 有符号 12 位（`−2048..+2047`）一律 **link-time error**（不截断/wrap/静默 0；不另设更宽类型）。
- **④ `rb0` 危险（规范只记危险）**：`ld/st` 基址可为 `rb0`，而 `rb0` 读出为当前指令地址、随取指推进 ⇒ 多指令形态（`ADR-0018 §C7 D4` 形态②③④）中以 `rb0` 为基址会**漂移**；**如何规避（先 `rb2rb` 拷出并做 ±k×4 修正、或避开 `rb0` 作基址）由 LLVM 依实际情形决定**，规范**不指定、不硬性禁止**。
- **⑤ 四形态归属**：访存偏移用哪一形态（`ADR-0018 §C7 D4` 四形态）**由 LLVM 依实际情形选择**，规范**不指定**；reloc 层**不新增更宽类型、不做 relaxation**，`REL12`/`ABS12` 只服务「编译器选择**形态①**（单条访存、`imms12` 就地补丁）」的情形。
- **用户原话（2026-10-09，原样留痕）**：(1)「四个方案是让 llvm 根据实际情况选择，没让你来选」；(2)「ld/st 指令用到的基址寄存器可以是 rb0，所以，动态运行过程中，需要考虑 rb0 自己的递增」；(3)「两种情况是并存的，rb0 表示相对地址，rb1-rb63 则是绝对地址；真实使用的时候是不是需要明确区分」；(4)「两种类型：REL12 和 ABS12」。
- **变更范围**：`**状态**` 行 rev 日期、标题、`## Decision` 的 `D1` 扩展注记、本 `## 修订` 条目、`## 状态说明` 补记。**不变**：`D2`/`D3` 及其余全部 decision。
- **流程说明**：本次为经用户逐条确认的**就地修订**（`Process-03` 一般规则为「决策变更时新增 ADR 或标注 `Superseded`，不直接改写已 `Accepted` 的决策」，此处为经授权的例外）。
- **规范正文落点**：`contract-elf.md §2–§4`（`SPEC-123t` 落笔）；实现归 `LLVM-065t`。
