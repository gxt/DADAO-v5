## Context（背景）

- **缺口（`ISS-230`，契约可满足性缺口）**：现状 GOT 取址 = **单条** `ld.o rdX, [rb0, imm12]`（`R_DADAO_REL12` = `imms12` 有符号**字节**偏移，`−2048..+2047`，`contract-elf.md §2.2`/`§3.1`）⇒ **±2 KiB**。而 `.got` 与 `.text` 默认相隔一整页：`-shared` 走**默认布局**时链接期报 `R_DADAO_REL12 out of range: 65596 is not in [-2048, 2047]`（rc=1）；量级实测 **65552 / 65588 / 65596 B**（`-z max-page-size=0x1000` ⇒ 4112 B，仍越界）⇒ **任何分段布局下单指令访问均不可达**。
- **根因（前置不可满足）**：`ADR-0026 D5` 给出的兜底 = 「超 ±2 KiB ⇒ `R_DADAO_ABS48` 序列 + `ldm.o_rrri_rb` 两段式」，但该路径在**现有 ABI 下不可实现**——① `ldm.o` 的**偏移域只能是 `rd`**（`ld.o` 只有 `imms12` 立即数形式）；② **链接器无可用 `rd`**：`spec/DADAO-21` 寄存器表中 `rd0` 零、`rd1` `rderrno`、**`rd2`–`rd3` = 「调试/测试保留，编译器不得分配使用」**、`rd4+` 归编译器（函数体内可能活跃）；③ ISA 侧唯一宽范围 PC 相对通道（`REL26` 字偏移 / `add.si` 的 `imms18`）**无匹配重定位类型**，且 `ABS48` 是**绝对地址**而非 PC 相对 ⇒ 「契约（不固定 GOT 基址 + 超范围两段式）」与「可用通道」**不闭合**。
- **现状 PLT 形态**（依据 = `lld/ELF/Arch/DADAO.cpp::writePlt`，源码检出 `.work/source/llvm-project/**`；字节级实测 `libtest.so`：`.plt@0x1B0`、其中 `ldm.o` 于 `0x1B4`、条目内嵌 8 字节常量 = `0x134` = `0x2E8 − 0x1B4` ✓）：每条目 = **8 字节数据槽**（条目 `+16`）+ `ld.o rd5,[rb0,16]` + `ldm.o {rb4},[rb0,rd5]` + `jump [rb4,rd0,0]`；`pltEntrySize = 24`、`pltDataOffset = 16`、`pltHeaderSize = 0`（eager）。⇒ 每次调用多一次访存，且 24 B 条目 + `+16` 处数据槽**跨 cache line** ⇒ dcache 不友好。
- **已核事实基线**（逐条带依据）：
  1. `R_DADAO_ABS48` **已有「指令 wyde 切片」编码**：`set.zw`/`or.w`/`andn.w`，每指令 1 个 16 位 wyde、按 `wp`（= `hb[5:4]`，`bits[17:16]`）选片，opcode 与寄存器域保留（`DADAO.cpp` 文件头 + `relocate` 的 `R_DADAO_ABS48` 分支）⇒ **机制现成**，缺的只是 **PC 相对 + 有符号** 变体。
  2. `set.zw` 清其余 48 位、`set.ow` 置其余 48 位为 1（`spec/SimRISC-03 §3.1`）⇒ 2 条配对**必须按 `disp` 符号选形**：**≥0** = `set.zw` + `or.w`；**<0** = `set.ow` + `andn.w`（**两条都换**，理由见 `D2`）——`or.w` = `rd[wp] | imm`（只置位），故只在「其余位已为 0」（`set.zw`）时可得目标值；`set.ow` 下其余位（含 `wp0`）已全 1，该 wyde 只能用 `andn.w` = `rd[wp] & ~imm` 清出目标值（`spec/SimRISC-03 §3.1`、`.tao/contracts/contract-isa.md` 指令语义表）。`or.w-rd = 0x48` / `andn.w-rd = 0x49` / `set.zw-rd = 0x4C` / `set.ow-rd = 0x4D` **同在** `spec/SimRISC-00` 的 **`0100-1xxx` 行**（`SimRISC-00 §SimRISC QFC`；编码表 `.tao/contracts/contract-isa.md`）⇒ opcode 改写便宜。
  3. `set.rd rd, <disp>`（偏移地址）= **有符号数、不限指令数**；「固定 3 片 + `R_DADAO_ABS48`」**仅**适用**地址**操作数 `set.rb`（`spec/Toolchain-01 §6.1`，2026-10-16 已订正）。
  4. **先例**：`R_DADAO_REL26` 落点为 `call-iiii`（`0x74`）时**改写为 `jump-iiii`（`0x70`）**（`.tao/contracts/contract-elf.md §3.2`）⇒ 「重定位按符号改写 opcode」在本项目**已有先例**。
  5. `rb0` 读出**当前指令**地址（**无 `-4`** 流水偏移）⇒ 偏移基准 = **执行取数的那条 `ldm.o`** 的地址（`ADR-0019 D3`、`contract-elf.md §3.1`）。

## Decision（决策）— **提案**（每条 = 决定 / 理由 / 被否方案）

**D1 — 新增重定位类型 `R_DADAO_REL32`：PC 相对 32 位有符号偏移（落点 = 配对两条指令的 wyde 切片）**
- **决定**：新增重定位类型 **`R_DADAO_REL32`**（**用户 2026-10-16 定名**，原话「`REL32`，甲」），语义 `disp = S + A − P`（**PC 相对、有符号、32 位、单位字节**），落点为**配对序列**（**非负形** = `set.zw rdX, wp1, hi16` + `or.w rdX, wp0, lo16`；**负形** = `set.ow rdX, wp1, hi16` + `andn.w rdX, wp0, ~lo16`，见 `D2`；首条 = `disp[31:16]`、次条 = `disp[15:0]`）；编号取 **`14`**、`R_DADAO_NUM` 由 **`14` 顺延为 `15`**（沿用 `ADR-0019 D10`「终端计数、密集无空档」口径）；**记录形态 = (甲)**（一个类型 + 两条记录 + addend 补偿，见「记录形态」节）。
- **定名与值类（用户 2026-10-16 确认）**：
  - **值类 = 偏移类**（**有符号 / 补码，32 位**）✓ —— 与 `ADR-0019 D10`(b) **值类规则一致**（**偏移类** ⇒ **补码（有符号）加法**；**基址 / 绝对地址类** ⇒ **无符号 48 位**；并注「**命名后缀与值类解耦**」，`48` 后缀**仅** `ABS48` 一名），**明确归入「偏移类」** ✓；
  - **不适用**「有效位宽 = 立即数位宽 + 2」的字偏移换算 ✓ —— 与 **`REL12` 同款例外**（单位 = **字节**、非字；「+2」规则见 `contract-elf.md §2`，其 `REL12`/`ABS12` 例外见 `§2.2` 末 + `ADR-0019 D2` 命名）。**同构句**：`REL12` = 字段 **12 位** / **字节**偏移 / 有效 **12** 位；`REL32` = 字段 **2×16 位**（两 wyde）/ **字节**偏移 / 有效 **32** 位 ✓（名中数字 = **有效位宽**，与 `REL26`/`REL20`/`REL14` 同族命名口径 ✓）；
  - **取名理由**：族前缀 **`REL`** = **相对类**（`ADR-0019 D2` 命名：「相对类用 `REL`，PPC64 风格，不用 `PC`」）⇒ **值类自证** ✓（见名即知「偏移类 / 补码」，无须额外标注）。
- **理由**：`ldm.o` 的偏移域是 **`rd`（64 位）** ⇒ 寄存器内**任意可达**；PC 相对 ⇒ PIC/PIE 下偏移是**链接期常量**、与装载基址 `B` 无关；复用 `rwii`（每指令 1 wyde）与 `ABS48` 的 **wyde 切片既有机制**，只加「PC 相对 + 有符号」语义。
- **被否**：(a) 沿用 `ABS48`（绝对地址）+ 借 `rd3` 作偏移寄存器 ⇒ 须改 `spec/DADAO-21` 寄存器表，且 `ABS48` 是**绝对**地址、与 `rb0` 相对语义冲突；(b) 新增 **48 位** PC 相对类型（3 片）⇒ 无必要（32 位够，`D6`）；(c) **命名 `DISP32`**（**用户早先提案**，2026-10-16 被 **`REL32`** 取代）⇒ 无 `REL` 族前缀、**不体现相对族 / 值类**（`disp` 是可正可负的**相对量**，名须自证偏移族）；(d) **记录形态 (乙)**（两个类型 hi/lo）⇒ 见「记录形态」节与 `## 被否方案（记录）`。

**D2 — 缺省非负：链接期按 `disp` 符号改写配对两条（`≥0` ⇒ `set.zw`+`or.w`；`<0` ⇒ `set.ow`+`andn.w`）**
- **决定**：汇编器 / 编译器**一律**发射**非负形** = `set.zw rdX, wp1, hi16` + `or.w rdX, wp0, lo16`（`set.zw` 清其余 48 位 = **零扩展**示义）；链接期若 `disp < 0` ⇒ **同时改写两条**：① 首条 opcode `set.zw-rd`（`0x4C`）→ `set.ow-rd`（`0x4D`），立即数仍取 `disp[31:16]`；② 次条 opcode `or.w-rd`（`0x48`）→ `andn.w-rd`（`0x49`），**立即数改为 `~disp[15:0]`**（`andn.w` 语义 = `rd[wp] & ~imm` ⇒ 取 `imm = ~lo16` 才得 `lo16`）。寄存器 / `wp` 域不变。
- **理由（为何负值必须同改两条）**：`set.ow` 把**其余 48 位全置 1（含 `wp0`）**（`spec/SimRISC-03 §3.1`）⇒ `wp0` 已是 `0xFFFF`，而 `or.w` 只做 `rd[wp] | imm`——**只能置位、不能清零** ✗ ⇒ 若次条仍留 `or.w`，`wp0` 恒为 `0xFFFF`（静默错值、不可归因）。必须换 `andn.w`（`rd[wp] & ~imm`）：从全 1 中清出目标 wyde，`imm = ~lo16` ⇒ `0xFFFF & lo16 = lo16` ✓。**非负形不受影响**：`set.zw` 将其余位清 0 ⇒ `wp0` 初值 `0x0000` ⇒ `or.w` 得 `lo16` ✓。**改写仍然便宜**：四个 opcode 同在 `SimRISC-00` 的 `0100-1xxx` 行（`or.w-rd = 0x48` / `andn.w-rd = 0x49` / `set.zw-rd = 0x4C` / `set.ow-rd = 0x4D`）⇒ 各只动 8 位 opcode；**先例** = `R_DADAO_REL26` 把 `call-iiii`(`0x74`) 改写为 `jump-iiii`(`0x70`)（`contract-elf.md §3.2`）。用户建议、主会话同意。

| `disp` 符号 | 首条（`disp[31:16]`） | 次条（`disp[15:0]`） | 其余 48 位 → 结果 |
|---|---|---|---|
| `disp ≥ 0` | `set.zw rdX, wp1, hi16`（`0x4C`） | `or.w rdX, wp0, lo16`（`0x48`） | 清 0 ⇒ `wp0` 初值 `0x0000` ⇒ `or.w` 得 `lo16` ✓ |
| `disp < 0` | `set.ow rdX, wp1, hi16`（`0x4D`） | `andn.w rdX, wp0, ~lo16`（`0x49`） | 全 1（含 `wp0 = 0xFFFF`）⇒ 只能 `andn.w` 清得 `lo16` ✓（`wp3`/`wp2` = 1 = 符号扩展 ✓） |

- **被否**：(i) **只改首条 opcode**（负值下 `wp0` 恒为 `0xFFFF` ⇒ 静默错值 ✗）；(ii) **布局保证 `disp` 恒正**（免 opcode 改写）⇒ 多一条**布局义务**、对大映像不可保证（正是 `ISS-230` 的老路）✗。

**D3 — 失败要响亮：落点形态不符 / 溢出 ⇒ link-time error**
- **决定**：落点**必须**是配对序列的**首条**——opcode = `set.zw-rd`/`set.ow-rd`、预期 `wp`、且**紧随**一条**同 `rd`** 的**配对次条**（首条 `set.zw-rd` ⇒ 次条 `or.w-rd`；首条 `set.ow-rd` ⇒ 次条 `andn.w-rd`，见 `D2`）；不符 ⇒ **link-time error**（沿 `contract-elf.md §3.2`「越界/不合法即错」风格），**禁**静默放行。`disp` 超出 32 位有符号范围 ⇒ 同为 **link-time error**（不截断、不 wrap；`ADR-0019 D6`）。
- **理由**：负值若按 `set.zw` 静默处理，结果会静默偏 **`+2³²`**（静默错值，不可归因）；形态校验把「发射侧与链接侧的约定」变成**可机械判定**的链接期断言。
- **被否**：静默放行 / 按无符号截断 / 越界时自动改走别的路径（不可判、不透明）。

**D4 — 不引入「配对重定位」机制：单条 reloc + addend `A = −8`**
- **决定**：**一个**重定位记录挂在**首条指令**上（`P` = 首条地址），addend 固定 **`A = −8`** ⇒ `disp = S + A − P = S − (P + 8)`，而 `P + 8` = 紧随其后的 `ldm.o` 指令地址 = `rb0` 读出值 ⇒ **等价于「相对 `ldm.o`」**（`rb0` 无 `-4`，事实基线 5）。跨两条指令的 2 个 wyde 切片由**同一条** reloc 写入。
- **理由**：`ADR-0019 D5` 的「逐指令挂 reloc」对本类型不够用（两条指令写的是**同一个值**的两半）⇒ 单条 reloc 更简、**不新增公式**（`S + A − P` 原样可用，`A` 把「相对 `ldm.o`」编码进去）；也免去两程序列在链接期的**配对查找**。
- **被否**：两条独立 reloc（须成对校验，任一条被单独误用即静默错值）；把 reloc 挪到 `ldm.o` 上（`ldm.o` 的**偏移域是 `rd`**、无 wyde 立即数域，挂不上）。
- **⚠️ 实现前置（未验证）**：**「单条 reloc 覆盖两条指令的 wyde 切片」在 lld 侧无既有实现**（`ABS48` 指令路径是「一指令一 reloc」）⇒ 须在实现阶段确认可行（通道：reloc 记录自带 `offset`、链接器可读相邻指令）。**列为待验证项** ✗。

**D5 — 固定 2 片（不按值变长）；不解禁 relaxation**
- **决定**：`disp` 一律 **2 片**（32 位有符号）；**不**按值缩短 / 加长；`ADR-0019 D7`（禁 relaxation）**维持不变**。
- **理由**：`set.rd rd, <disp>`「有符号、不限指令数」（`spec/Toolchain-01 §6.1`）只对**汇编期已知常量**成立；**可重定位** disp 链接期才知，而重定位**只改定长指令的立即数域、链接器插不了指令** ⇒ 发射侧必须**固定**片数。
- **被否**：按值变长（链接期不可实现）；3 片（48 位，浪费、且与 `D6` 范围过剩）。

**D6 — 可达 ±2 GiB；不保留任何寄存器**
- **决定**：可达范围 = 32 位有符号字节偏移 = **±2 GiB**（与 RISC-V `AUIPC+ADDI` 同量级）；临时寄存器取自**调用者保存**族（`rd4–rd7` / `rd16–rd31`；PLT 内联形式沿用现状的 `rd5`）；**不使用** `rd2`/`rd3`（`spec/DADAO-21` 保留给调试/测试）。
- **理由**：偏移在 `rd`（64 位）里 ⇒ 可达性彻底解决；**不引入固定基址寄存器**、**不保留专用寄存器** ⇒ 与 `ADR-0026 D5`（不占 GP）一致，且**无需改动 `spec/` 寄存器表**。
- **被否**：`rd2`/`rd3` 改「链接器保留」（须改 `spec/`，需用户原话授权）；固定 GOT 基址寄存器（`ADR-0018 C6` / `ADR-0026 D5` 已否）；`rb2`(`rbgp`) 式固定基址（须改 ABI 语义 + GOT 须落 `rb2 ± 2 KiB`）。

**D7 — PLT 改为内联形式（去 8 字节数据槽；`pltEntrySize` 24 → 16）**
- **决定**：PLT 条目 = **配对序列**（同 `D2` 两形：`disp ≥ 0` ⇒ `set.zw`+`or.w`；`disp < 0` ⇒ `set.ow`+`andn.w`；条目内**无** opcode 改写环节）+ `ldm.o {rb4}, [rb0, rdX]` + `jump [rb4, rd0, 0]`（**3 条指令、无数据槽、无 padding**）；`pltEntrySize` **24 → 16**、`pltDataOffset` 取消；`disp = S − (ldm.o 地址)`。**PLT 由链接器合成**（`lld/ELF/Arch/DADAO.cpp::writePlt` 直接 `write32be` 自产编码，**不走重定位改写**）⇒ 它**自己按符号**直接选配对（`set.zw`+`or.w` 或 `set.ow`+`andn.w`）⇒ **无需 opcode 改写** ✓——`D2` 的改写机制**只服务**「编译器发射、链接期才知符号」的 GOT 路径。
- **理由**：去槽 ⇒ 每次调用**少一次访存**；条目由 24 B → 16 B（对齐仍满足，`ld.o` 的「槽在条目 `+16`」需求消失）⇒ **dcache 友好**（用户原话「这个 disp 放在一个函数后面，对 dcache 的影响很大」）。
- **被否**：**(E) 保留数据槽**（多一次访存 + 条目 `+16` 处数据槽跨 cache line ✗）；条目内联 **3 片**（48 位，无必要）。

**D8 — GOT 访问改为同法（3 条/次）；取消「`.got` 必须贴 `±2 KiB`」的布局义务**
- **决定**：编译器发射的 GOT 取址 = `set.zw/or.w rdX, disp`（2 条）+ `ldm.o {rbT}, [rb0, rdX]`（1 条）= **3 条/次**（现状 1 条）；`disp = S − (ldm.o 地址)`，由 `D1` 的类型承载；`tests/scripts/dadao-dyn.lds` 的「`.got` 紧跟 `.text`（±2 KiB 内）」**布局义务取消**。
- **理由**：单指令 `R_DADAO_REL12`（`imms12` = ±2 KiB）在**任何**分段布局下都不可达（实测 65552 / 65588 / 65596 / 4112 B）⇒ 该布局义务是**不可满足**的补丁（`ISS-230` 候选 (c)）；治根 = 让访问本身可达，而非把 `.got` 搬到近处。
- **被否**：老式**单条** `ld.o [rb0, imm12]`（±2 KiB，**不可行** ✗）；`ADR-0026 D5` 的 `ABS48` 两段式（在现有 ABI 下**不可实现**，`ISS-230`）；`rb2`(`rbgp`) 固定 GOT 基址。

**D9 — 落地方式（提案 / 待用户裁定）**

- **待用户裁定**：采用「**就地修订既有 ADR**」还是「**另立新 ADR**（`Superseded` / 并存）」；以及是否需 `spec/` 授权（**本提案主张无需**：不改 ISA、不动 `rd2`/`rd3`）。

- **被否（备选，非否决）**：新增独立 ADR 承载全部 10 条 ⇒ 与 `ADR-0019` / `ADR-0026` 三处并置、口径易分叉。

## 记录形态（**已定**：**(甲)** 一个类型 + 两条记录 + addend 补偿）

- **决定（甲）**：**一个**类型（`R_DADAO_REL32`，`D1`）+ **两条**记录，两条**各带补偿 addend**：**hi 记录 `A − 8`**、**lo 记录 `A − 4`** ⇒ 两条**各自算得的 `V` 相同** ✓；**不引入配对机制** ✓。

- **既有先例（实测 ✓）**：`set.rb rb1, ext2` ⇒ 产出 **3 条 `R_DADAO_ABS48` 记录**。实测命令与输出（本机现有构建，`llvm-mc` + `llvm-readobj`，非重建）：

## Rationale（理由）

- **为何「PC 相对 + 32 位有符号」这一族**：它同时满足三条硬约束——① **不引入固定基址寄存器 / 不占专用寄存器**（`ADR-0018 C6`、`ADR-0026 D5`）；② **不新增 / 不改 ISA、不改 `spec/` 寄存器表**（复用 `set.zw/or.w` + `ldm.o` 既有编码）；③ **不依赖 `.text`/`.got` 链接布局**（治 `ISS-230` 的根因，而非打补丁）。
- **与 `ADR-0026 D5` 的关系**：本提案**替代**该条的兜底路径（`ABS48` 序列 + `ldm.o_rrri_rb` 两段式在现有 ABI 下不可实现），而非叠加；`D5` 中「不固定 GOT 基址、PC 相对、不占 GP」的原则**保持不变**。
- **代价可接受**：GOT 访问由 **1 条 → 3 条**、PLT 条目 **24 → 16 B**（且**少一次访存**）；换来**任意可达**与**布局自由**——`ISS-230` 中「改已验收对象形态 / 改 ISA·ABI / 改布局义务」三候选里，本提案**只动发射形态**，代价最小。

## Consequences（影响）

- **待办（须先经用户逐条确认；落纸与实现均为后续任务）**：① `contract-elf.md`：新类型 **`R_DADAO_REL32`**（编号 `14`、公式、落点 / 越界；**记录形态 (甲)** = 两条记录 + addend 补偿 `A − 8` / `A − 4`）；② `contract-dynlink.md §3`：GOT/PLT 形态、**布局义务取消**；③ `ADR-0019` `D11` + `ADR-0026` `D5`/`D7` 就地修订（**本草案不做**）+ **`D10` 核查结论 / 记录形态 (甲)** 的落纸（**本草案不做**；`REL12`（4）**必须存在**、**不删号、不改号**）；④ **lld**：新类型 `relocate` + `writePlt` 重写（去槽、16 B）+ `DADAO.def` 编号；⑤ **LLVM CodeGen**：GOT 取址 3 条形态 + fixup / reloc 发射；⑥ `tests/scripts/dadao-dyn.lds` 布局义务解除（`INFRA-085t` 消费侧）；⑦ **向量 / 产物排查**：写死 `pltEntrySize = 24`、旧 PLT 字节码、类型号 `14`/`NUM = 14` 的测试与文档。
- **`spec/` 零改动**（前提 = 不动 `rd2`/`rd3`、不新增 ISA 指令）⇒ **无需 `spec/` 授权**（若 `D9` 裁定改寄存器语义，则该前提失效）。
- **与既有编号方案的耦合**：`NUM` `14 → 15` 属**改号**，影响面同 `ADR-0019 D10`(d)（`DADAO.def` / 契约 / 产物排查）。
- **回归风险**：PLT 条目尺寸与字节内容变更 ⇒ 既有 PLT 字节级断言与 golden 必须同步（否则假绿）。

## 被否方案（记录）

- **保留 PLT 数据槽**（现状）：多一次访存 + 条目跨 cache line（dcache 不友好）。
- **负值只改首条 opcode（`set.ow` + 留 `or.w`）**：`set.ow` 已把 `wp0` 置全 1，`or.w` 只能置位、不能清零 ⇒ 静默错值（见 `D2`）。
- **布局保证 `disp` 恒正 / `.got` 贴 `.text`**：多一条**不可满足**的布局义务（实测 65552–65596 B；`ISS-230` 候选 (c)）。
- **老式单条 `ld.o [rb0, imm12]`**：±2 KiB，不可行。
- **`ABS48` + `rd3` 作偏移寄存器**：须改 `spec/DADAO-21` 寄存器表（`rd2`/`rd3` 保留），且 `ABS48` 是**绝对**地址、与 `rb0` 相对语义冲突。
- **`rb2`(`rbgp`) 固定 GOT 基址**：须改 ABI 语义，且 GOT 须落 `rb2 ± 2 KiB`（仍受 ±2 KiB 约束）。
- **按值变长 / 启用 relaxation**：链接器插不了指令（`ADR-0019 D7` 不变）。
- **两条「须配对校验」的 reloc**（各自**无补偿 addend** ⇒ 须回查 hi/lo 配对）：须成对校验，任一条被单独误用即静默错值。**注**：与 (甲) 的「两条记录」**不同** —— (甲) 两条**各带补偿 addend**、**各自独立可判** ⇒ **无需配对** ✓。
- **命名 `DISP32`**（**用户 2026-10-16 早先提案**，后被 **`REL32`** 取代）：无 `REL` 族前缀 ⇒ **不体现「相对族」与值类**（`disp` 是可正可负的**相对量**，名须自证偏移族；`ADR-0019 D2` 命名口径「相对类用 `REL`」）。
