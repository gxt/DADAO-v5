## Context（背景）

### 现状与缺口

- **缺口（`ISS-230`，`open`）**：现状 PIC/PIE 的 GOT 取址 = **单条** `ld.o rdX, [rb0, imm12]`（`R_DADAO_REL12` = `imms12` 有符号**字节**偏移、`−2048..+2047`、±2 KiB；`contract-elf.md §2.2`/`§3.1`）。而 `.text` 与 `.got` 之间在**任何分段布局**下都隔了一整页以上（实测 `65552` / `65588` / `65596` / `4112` B，均 rc=1）⇒ 单指令访问**不可达**；`ADR-0026 D5` 的兜底（`R_DADAO_ABS48` 序列 + `ldm.o_rrri_rb` 两段式）在**现有 ABI 下不可实现**（`ld.o` 的偏移域只有 `imms12`；`ldm.o` 的偏移域只能是 `rd`，而**链接器无可用 `rd`**——`rd0` 零 / `rd1` `rderrno` / `rd2`–`rd3` 调试测试保留 / `rd4+` 可能活跃）。
- **`REL32` 路线已撤**：`ADR-0028`（GOT/PLT 远距离取址 = `R_DADAO_REL32` 配对两条 + `set.zw`/`or.w` opcode 改写）同日转 **`Superseded`**（用户裁定改线 `rela.si`）；`ADR-0019 D11` 已加「**已撤**」注记（`R_DADAO_NUM` 回 `14`）、`ADR-0026 D5`/`D7` 已加「**本次改线**」注记，`.tao/contracts/contract-elf.md` / `contract-dynlink.md` 的 `REL32` 条款**已回退**（现行 = `NUM` `14`、远距离取址通道标「待后继 ADR 定」）。**本 ADR = 该后继 ADR**。

### 事实基线（逐条带依据）

1. **`rela.si` 旧口径与删除**：`ADR-0003` 登记 `rela.si`（`riii`，`imms18 << 12`）=「`imms18` **直接 `<< 12`**（12 位偏移，得 30 位有符号数）；**PC 低 12 位清零**得 **4 KB 对齐**（**与页无关**）、**无 `<<2`**」；**2026-09-30 由 `ADR-0012 D5` 删除**：`rela.si`（`riii`，`rbha, imms18`）→ **UNDI**、编码 `0x5A` **保留但不再指派**、指令总数 `254 → 253`、M1 身份集 `177 → 176`（关联任务 `SPEC-057t`）。
2. **`rb0` 语义（本 ADR 的 `P` 基准）**：`rb0` 读出为**当前指令的地址**（**非下一条**）、只读、**任何指令以 `rb0` 为显式目的 ⇒ ILLI**（`spec/SimRISC-00:62`；`contract-isa.md §1.3.2`；`ADR-0019 D3`）⇒ v5 **无 `−4` 也无 `+4` 修正**（与 `DADAO-0628` 的「`rb0` = `PC + 4`」口径**不同** ✗，见下「0628 对照」）。
3. **`riii` 格式现成**：`add.si` 的 `rd` 目的形（`op = 0x59`）/ `rb` 目的形（`op = 0x5B`）= `op8` + `ha[23:18]` + `imms18[17:0]`（`contracts/opcodes.yaml:1532-1573`）⇒ `0x5A` 落在同族空位（`rela.si` 删除后**未指派**；`contracts/opcodes.yaml` 中**无** `0x5A` 条目 ✓）⇒ **恢复不占新编码位** ✓。
4. **`dst_rb0` 规则的既有先例**：`add.si` 的 `rb` 目的形即带 `dst_rb0`（`spec/SimRISC-05:25`）；`ld.o`/`ldm.o` 的 `rbHA = rb0` ⇒ ILLI（`spec/SimRISC-01:149`）⇒ 「`rela.si` 目的 `rb0` ⇒ ILLI」与既有规则**同形** ✓。
5. **现状 PLT 形态**（依据 = `ADR-0028` Context 的字节级实测，`lld/ELF/Arch/DADAO.cpp::writePlt`）：每条目 = **8 字节数据槽**（条目 `+16`）+ `ld.o rd5,[rb0,16]` + `ldm.o {rb4},[rb0,rd5]` + `jump [rb4,rd0,0]`；`pltEntrySize = 24`（eager）⇒ 每次调用多一次访存、常量槽**跨 cache line**。
6. **`.got` 布局义务现状**：`tests/scripts/dadao-dyn.lds` 的「`.got` 紧跟 `.text`（±2 KiB 内）」是**对已知不可满足约束的补丁**（`ISS-230` 候选 (c)），消费侧 = `INFRA-085t`。

### 0628 对照（**内容溯源，非执行必需** ✗；只读 `.cache/refs/**`，不复制代码、**不得作执行依赖**）

- **0628 做法**：`rela`（`riii`；`DADAO-0628` 编码 `0x48`，**与 v5 的 `0x5A` 不同**）= `rbHA = (rb0[47:0] & ~0xFFF) + (sign_extend(imms18) << 12)`（**PC 低 12 位清零 + `<<12`、无 `<<2`**）（`.cache/refs/DADAO-0628/sail/dadao_insts.sail:534-541`）；取址 = **两个**类型 **`R_DADAO_RELA_PAGE`(4) + `R_DADAO_RELA_LO`(5)**（hi/lo 配对，参 RISC-V `%pcrel_hi`/`%pcrel_lo`）（`.cache/refs/DADAO-0628/components/llvm/patches/0014-…patch`、`0015-…patch`；`code-agent/tasks/DL-061b-codegen-globals.md`，**内容溯源，非执行必需**）。
- **本项目差异**：① **PC 不清低位**（用户裁定「参照 `auipc`」）⇒ 低段由「页内偏移」改为「**有符号 4 KB 余量**」（见 `D2`），这是能复用 `ld.o` 的 `imms12`（**有符号**）的关键；② `P` = **`rela.si` 自身地址**（v5 `rb0` 无 `+4`/`−4`，事实基线 2）⇒ 与 0628 的 `PC + 4` 基准不同；③ 编码 `0x5A`（`ADR-0012 D5` 保留位）vs 0628 的 `0x48`。
- **建议落点**：「**两个类型 hi/lo**」的形态与 0628 **同向**（本 ADR `D2`）；差异项（PC 不页对齐 / `rb0` 基准 / 编码）落本 ADR `D1`/`D2`，**不引 0628 文件为执行依据**（`AGENTS.md`「参考来源与任务自包含」）。

## Decision（决策）（每条 = 决定 / 理由 / 被否方案；`D1`–`D8` **已由用户逐条确认** ✓，见 `## 状态说明`「逐条确认表」+「确认记录」）

**D1 — 恢复指令 `rela.si rbHA, imms18`（`riii`、编码 `0x5A`、`auipc` 式语义）**
- **决定**：恢复 `rela.si` —— 格式 **`riii`**（`op8 = 0x5A` + `ha[23:18]` + `imms18[17:0]` = **8 + 6 + 18 = 32 位** ✓，与 `add.si` 同格式同字段位）；编码 **`0x5A`**（`ADR-0012 D5`「保留但不再指派」⇒ **不占新编码位** ✓；`rela.si` 删除前即此编码）；语义 **`rbHA = PC + (sign_extend(imms18) << 12)`**（`<< 12` = 4 KB 块、**无 `<< 2`**）；其中 **`PC` = `rela.si` 指令自身地址**（= `rb0` 读出值；事实基线 2）；**PC 低位不清零** ✓（= RISC-V `auipc` 式；**明确取代** `ADR-0003`/`ADR-0012 D5` 前身的「**PC 低 12 位清零 / 4 KB 页对齐**」口径 ✗）；`imms18` **有符号** ✓；`ha = rb0`（目的 `rb0`）⇒ **ILLI** ✓（与 `dst_rb0` 规则同形；事实基线 4）。
- **理由**：用户裁定「完全复用 RISC-V 方案、**仅用一个 `rb`** 即可、且该 `rb` 正好可复用为取出的地址所用寄存器」+「含义参照 `auipc`、编码 `0x5A`」；`riii` 与 `0x5A` **现成** ⇒ 只恢复一条指令、不动 opcode 空间；语义与 `rb0` 既有定义**自洽**（`rb0` = 当前指令地址 ⇒ `PC` 无需修正项）。
- **被否** ✗：**保持删除** `rela.si`（能力「可覆盖」但**寄存器成本未被覆盖**，见「被否方案（记录）」）；**保留旧页对齐语义**（⇒ 低段必须是「页内偏移」，与「PC 相对有符号余量」互斥，见「被否方案（记录）」）；**另择新 opcode**（占用空白编码、无必要）；**保留 `−4`/`+4` 修正**（v5 `rb0` 无流水偏移，加修正项与既有契约冲突）。

**D2 — 配对 hi/lo 重定位（复用 RISC-V `%pcrel_hi` / `%pcrel_lo`）；两个新类型**
- **决定**：新增 **两个**静态重定位类型（PC 相对、`rela.si` + `ld.o` 配对使用）：
  - **高段**（落点 = `rela.si` 的 **`imms18` 字段**）：`value = ((S + A − P) + 0x800) >> 12`（**`+0x800` 后下移** = **舍入到最近的 4 KB 倍数**、**非截断** ✗）；`P` = **`rela.si` 指令地址**（= `rb0` 读出值）；`S` = **目标地址**（GOT 槽 / 符号 / PLT 目标）、`A` = addend。
  - **低段**（落点 = 后续 **`ld.o rbX, [rbX, imms12]`** 的 **`imms12` 字段**）：`value = (S + A − P) − (高段值 << 12)`（**有符号**）；**由高段舍入保证** `|value| ≤ 2048` ⇒ 余量 ∈ `[−2048, +2047]`，**恰落在 `imms12` 的有符号 12 位域内** ✓（若用**截断** ⇒ 余量可达 `+4095`，**越出** 12 位有符号域 ✗ ⇒ 这是「必须舍入」的直接理由）。
  - **配对（已定：(甲) 显式配对）** ✓：低段记录**须携带「配对信息」指回 `rela.si` 站点**（= RISC-V `%pcrel_lo(label)` 形态：以站点标签 / addend 指回 hi 指令）⇒ 链接器据此取回 / 重算**该站点已定的高段值**，使两段自洽；**两段共用同一个 `P`**（= `rela.si` 站点地址），而**不是**各自指令地址（后者会让两段算出不同的 `V` ✗）。**用户裁定（甲）** = 引用原话「**1、复用RISC-V方案**」（见「确认记录」）⇒ **否** (乙) 刚性邻接 ✗。
  - **编号与命名（已定）** ✓：编号取 **`14` / `15`**、`R_DADAO_NUM` **`14 → 16`**（`ADR-0019 D10`(e)「类型号密集无空档」）；**命名 = `R_DADAO_PCREL_HI`（`14`） / `R_DADAO_PCREL_LO`（`15`）**（用户裁定原话「**2、PCREL_HI/LO**」，见「确认记录」；`_HI`/`_LO` = RISC-V `%pcrel_hi`/`%pcrel_lo` 同形；**不带数字后缀**以免与既有 `R_DADAO_REL12`(4) 撞名）。起草笔的建议名 `R_DADAO_RELA_HI`/`_LO` **已按用户裁定订正为 `PCREL_HI`/`PCREL_LO`** ✓（**仅命名订正、决策实质不变** ✗）。
- **理由**：`rela.si` 给出高段（`<<12` 块偏移），后续 `ld.o` 的 `imms12` 给出低段 ⇒ **两条指令算出同一个地址**，且**不需要任何临时寄存器**；与 RISC-V `auipc + addi/ld` 的 hi/lo 方案**同形** ⇒ 期望值可**独立派生自 ELF gABI + RISC-V golden**（`ADR-0025 D7` 精神），不从 v5 实现反推。
- **被否** ✗：**单条类型 + addend 补偿**（`ADR-0028` 的 (甲) 形态：靠 `A − 8`/`A − 4` 令两条各自算出同一个 `V`）⇒ 依赖「两指令相邻且间距固定」的隐含约定，且**低段无法据「已发出的高段值」自洽**（`rela.si` 的 `imms18` 与 `ld.o` 的 `imms12` 字段宽度/语义不同 ⇒ 没有配对准据）；**两个类型但不带配对信息**（链接器无法定位 hi 站点 ⇒ 只能重复计算、与已发值可能不一致）；**复用既有 `R_DADAO_REL12`(4) 承载低段**（其公式 `S + A − P` 的 `P` = `ld.o` 自身地址、且语义是「访存符号偏移」⇒ 混用即**静默错值** ✗）。

**D3 — 范围与失败：±512 MiB、无布局义务、越界即 link-time error**
- **决定**：可达范围 = `imms18` 有符号 18 位 × 4 KB = **±2¹⁷ × 2¹² = ±2²⁹ = ±512 MiB** ✓；**不引入任何布局义务** ✓（**不要求** `.got` 贴近 `.text`；`tests/scripts/dadao-dyn.lds` 的 ±2 KiB 布局义务**取消**）；**越界**（`S + A − P` 超出 ±512 MiB，或高段 / 低段落不进各自字段、低段越出 12 位有符号域）⇒ **link-time error** ✓（`ADR-0019 D6` 精神：**不截断、不 wrap、不静默**）；**落点形态不符**（高段不在 `rela.si` 的 `imms18` / 低段不在配对 `ld.o` 的 `imms12`；配对信息悬空或指错站点）⇒ 同为 **link-time error** ✓。
- **理由**：与 RISC-V 同口径（`auipc`+`hi20`/`lo12` 溢出由链接器报错）⇒ 失败**响亮**、可归因；±512 MiB 覆盖「`.text` ↔ `.got` / PLT 目标」的实际量级（现状实测 ≈ 64 KB 级），代价 = 相对 `REL32` 的 ±2 GiB 少 2 位（**用户裁定的取舍** ✓）。
- **被否** ✗：静默截断 / 按无符号 wrap；越界自动改走别的通道（不透明、不可判）；保留 `.got` 布局义务（**不可满足**的补丁，`ISS-230` 候选 (c)）。

**D4 — GOT 取址：零额外寄存器（同一个 `rb` 既作载体又作目的）**
- **决定**：GOT 取址 = `rela.si rbX, hi` + `ld.o rbX, [rbX, lo]` ⇒ **2 条 / 次**（现状 **1 条**、`REL32` 提案 **3 条**）✓；**零额外寄存器** ✓ —— **同一个 `rb` 既承载 `rela.si` 的结果、又作 `ld.o` 的基址、又收 `ld.o` 的结果**；`rbX` 由**分配器**挑（`rb0` 不可作目的 ⇒ 不涉 `rb0`）；语义 = **`rela.si` 先得 `PC + (hi<<12)`，`ld.o` 再从 `PC + (hi<<12) + lo` 取 8 字节** ⇒ `rbX` 收 **GOT 槽内容（= 符号地址）**；`st.o` 同法复用。**不保留 / 不固定任何寄存器** ⇒ 与 `ADR-0026 D5`（不固定 GP）、`ADR-0018 C6`（`rbgp`/`rbtp` 保留不分配）一致 ✓。
- **理由**：**用户原话**「仅用一个 `rb` 寄存器就可以解决全部问题，且该 `rb` 正好可以复用想要取出来的地址所用的寄存器」✓；相较 `REL32`（`set.zw`/`or.w` 落 `rd` + `ldm.o` 落 `rb` = 3 条 + **需 1 个 `rd` 临时**）**少 1 条、少 1 个临时寄存器**。
- **被否** ✗：`REL32` 的「`rd` 偏移 + `ldm.o`」形态（见「被否方案（记录）」）；`ABS48` + `ldm.o_rrri_rb` 两段式（**已废弃**，`ISS-230`）；固定 GOT 基址寄存器（`rb2`(`rbgp`) / 专用寄存器）；为链接器让出 `rd2`/`rd3`（须改 `spec/` 寄存器表，且本方案**不需要** ✓）。

**D5 — PLT：3 条 / 12 B，去 8 字节数据槽**
- **决定**：PLT 条目 = `rela.si rb4, hi` + `ld.o rb4, [rb4, lo]` + `jump [rb4, rd0, 0]` ⇒ **3 条指令 / 12 B** ✓；**取消条目内 8 字节数据槽** ✓（`pltEntrySize` **24 → 12**、`pltDataOffset` 取消；该意图自 `ADR-0028 D7` 沿用 ✓）；**由链接器合成**（现状 `lld/ELF/Arch/DADAO.cpp::writePlt` 直产字节编码）⇒ 链接器**自己**算 hi/lo、**不经重定位记录**（同 `ADR-0028 D7` 口径）。**合成方式为提案** ✗。
- **理由**：去槽 ⇒ 每次调用**少一次访存**、条目内**无跨 cache line 的常量**、条目 `24 → 12 B` ⇒ **dcache 友好**（用户早先原话「这个 disp 放在一个函数后面，对 dcache 的影响很大」）；`rb4` 沿用现状 PLT 的既有选择。
- **被否** ✗：**保留数据槽**（多一次访存 + 跨 cache line ✗）；`REL32` 的 **16 B** 四指令条目（更长）；PLT 内联 `jump` 之外的临时寄存器方案（无必要）。

**D6 — 撤回 `REL32` 路线；编号基线回 `NUM = 14`**
- **决定**：`ADR-0028` 的 **`R_DADAO_REL32`（编号 `14`）** 与 **`R_DADAO_NUM` `14 → 15` 的顺延** **作废** ✓ ⇒ **编号基线 = `R_DADAO_NUM` `14`**（= `ADR-0019 D11` 撤销后的现行值；`.tao/contracts/contract-elf.md §2.2` 与 `contract-dynlink.md §4.3` 现行即此 ✓）；本 ADR 的**两个新类型**由该基线顺延（`D2`）；`ADR-0028` **已 `Superseded`** ✓（其文首已指向后继 ADR = 本文档）；`ADR-0019 D11`「已撤」注记 / `ADR-0026 D5`·`D7`「本次改线」注记**已落纸** ✓ —— **本 ADR 不改它们的已写内容** ✗（只作**指向**）。
- **理由**：`D1`–`D5` 已完整取代 `REL32` 的功能面（且**更省**：2 条 vs 3 条、零 `rd` 临时）⇒ 同一缺口不保留两条并行通道（形态 / 编号双份、**无消费者**）；编号必须**密集无空档**（`ADR-0019 D10`(e)）⇒ 不得留 `15` 空号。
- **被否** ✗：`REL32` 与 `rela.si` **并行保留**（两通道分叉、口径易漂移）；保留 `NUM = 15` 空号（违反密集无空档）。

## Rationale（理由）

- **为何「`auipc` 式 + hi/lo 配对」这一族**：它同时满足四条硬约束 —— ① **零额外寄存器**（同一个 `rb` 承载 + 作基址 + 收结果，`D4`）；② **不固定 / 不保留任何寄存器**（不占 GP、不动 `rd2`/`rd3` ⇒ **无需改 `spec/` 寄存器表**）；③ **不依赖 `.text`/`.got` 链接布局**（治 `ISS-230` 根因而非打补丁，`D3`）；④ **完全复用 RISC-V 方案**（`auipc` + `%pcrel_hi`/`%pcrel_lo` 同形 ⇒ 期望值可从外部权威独立派生）。
- **为何「舍入」而非「截断」**（`D2`）：低段要落进 `imms12` 的**有符号** 12 位域 ⇒ 只有把高段取到**最近的 4 KB 倍数**，余量才 ≤ 2048（半块）；截断会把余量推到 `+4095`，越出该域 ✗。RISC-V 用同一个 `+0x800` 舍入，故「复用 RISC-V」在此**不只是口号**、而是**唯一可行的取整口径**。
- **为何「配对信息指向 `rela.si` 站点」**：两段必须算出**同一个 `V`**，而 `S + A − P` 依赖 `P`；每段各用自己的指令地址会**算出不同的 `V`**（差 4）✗。配对信息令 `P` 统一取 `rela.si` 站点地址，且使低段能对齐**已发出的高段值**（而非平行重算）。
- **代价可接受（相对 `ADR-0028` 的 `REL32`）**：GOT 取址 **3 条 → 2 条**、PLT 条目 **16 B → 12 B**，可达范围 **±2 GiB → ±512 MiB**（对本项目够用）；换来「零 `rd` 临时 + 无 opcode 改写环节 + 与 RISC-V 同形」⇒ `ISS-230` 的候选里，本 ADR 只动**发射形态 + 一条 ISA 恢复**（后者已获用户原话授权）。
- **与 `ADR-0026 D5` 的关系**：本 ADR 填上该条「超 ±2 KiB ⇒ 远距离取址」的**通道空缺**（`ADR-0028` 撤回后留下的空位），**不叠加**；`D5` 中「不固定 GOT 基址、PC 相对、不占 GP」的原则**保持不变** ✓，`D7④`「越界 ⇒ 链接期报错、禁 relaxation、非静默」不变 ✓。

## 被否方案（记录）

- **`REL32` 路线（`ADR-0028`）**：GOT 取址 **3 条/次**（vs 本 ADR **2 条**）+ **需 1 个 `rd` 临时**（`set.zw`/`or.w` 落 `rd`，再 `ldm.o` 落 `rb`）+ 需**链接期 opcode 改写**（负值两条同改）✗ —— 能力可覆盖，但**寄存器 / 指令成本**与「与 RISC-V 同形」两点均未覆盖。
- **加宽访存立即数 `ld.o [rb0, imms18]`**：可达 **±128 KiB**（18 位**字节**偏移 = ±2¹⁷）——比 ±2 KiB 宽，但**仍带布局义务**（`.got` 必须落进该窗；大映像不可保证）✗，且须改 `ld.o` 的字段宽度 ⇒ **动 ISA 编码**（代价高于恢复一条已保留编码的指令）。
- **保持删除 `rela.si`（`ADR-0012 D5` 现状）**：能力上「3 片 `ABS48` / `REL32` 序列」**可覆盖**，但 **寄存器成本未被覆盖** —— `REL32` 需 `rd` 临时、`ABS48` 需 3 片 wyde + `rd`/`rb` 两段式（在现有 ABI 下**不可实现**，`ISS-230`）✗；且**永不与 RISC-V 同形** ⇒ 期望值无法从外部权威直接派生。
- **保留 `rela.si` 旧页对齐语义**（`ADR-0003` / `DADAO-0628` 口径：`base = rb0 & ~0xFFF`、低段 = 页内偏移）：低段必须写成**页内绝对偏移**（无符号 12 位），而 `ld.o` 的 `imms12` 是**有符号**域 ⇒ 只能给「正值 + 负值」两种符号各造一条路径，**不能**用「有符号 4 KB 余量」一条路径收口 ✗；也与用户裁定的「参照 `auipc`」不符。
- **两个类型但不带配对信息**：低段无法定位 hi 站点 ⇒ 只能平行重算 `(S+A−P)`；一旦 hi 站点与 lo 站点的 `P` 理解不一致（各自指令地址 vs 站点地址）即 **静默错值** ✗。
- **单条类型 + addend 补偿**（`ADR-0028` 记录形态 (甲)）：依赖「两指令相邻、间距固定」的隐含约定；两指令字段宽度 / 语义不同 ⇒ **没有配对准据** ✗（`ADR-0028` 的 `A − 8`/`A − 4` 是为「两条 wyde 写同一个值」设计的，与本方案的「高低段字段不同」不同型）。
- **复用 `R_DADAO_REL12`(4) 承载低段**：其公式 `S + A − P` 的 `P` = `ld.o` **自身**地址、语义为「访存符号偏移」⇒ 与本方案「相对 `rela.si` 站点的余量」**同形不同义**，混用即**静默错值** ✗（`ADR-0019 D10`(b) 的值类分列同理）。
- **固定基址寄存器 / 专用寄存器**（`rb2`(`rbgp`) 固定 GOT 基址；或让出 `rd2`/`rd3` 作链接器临时）：前者仍受 ±2 KiB 约束且须改 ABI 语义；后者须改 `spec/` 寄存器表（`rd2`–`rd3` = 调试/测试保留）✗ —— 本方案**不需要**任何保留寄存器 ✓。
- **命名带数字宽度后缀**（如 `R_DADAO_REL30` / `R_DADAO_REL12X`）：与既有 `R_DADAO_REL12`(4) 的「有效位宽 = 立即数位宽」口径**撞名 / 易混** ✗ ⇒ 建议 `_HI`/`_LO`（`D2`）。
