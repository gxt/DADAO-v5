# ADR-0054: `lr`/`sc` 的「另一 hart 同址同宽 store 清保留」在单 hart 机型下不实现

**状态**：Accepted
**日期**：2026-11-15
**关联**：`ISS-440`、`ISS-435`（保留粒度 = 精确地址 + 访问宽度）、`ADR-0034 D6`、`spec/SimRISC-12 §1`、`m13-qemu-014`、`m13-chipyard-002`、`m13-testcases-037`

## Context（背景）

`spec/SimRISC-12 §1` 与 `ADR-0034 D6` 规定：保留标记的清除事件包括「**另一 hart** 对**同一精确地址、相同访问宽度**发起 store」（与同 hart store、异常/中断进入并列）。

现状（三平台）：

- **QEMU**：`m13-qemu-014` 按 `ISS-435`（用户裁定「严格按 spec 来」）删除了整字值 CAS，只剩「记录键 + 另一条 `lr`」；**没有任何路径**表达"另一 hart 的 store 命中同一键"；
- **chipyard**：`WumingTinyConfig` 为**单 hart**配置，无第二个 hart 可发出该事件 ⇒ 无观测载体；
- **gem5**：未实现该清除路径。

即：spec 有语义、**三平台都没有实现路径**；单 hart 机型的架构上该事件**不可观测**（不存在"另一 hart"），补实现也无法被任何测试区分真伪。

## Decision（决策）

- **D1 单 hart 机型不实现**：该清除事件在单 hart 机型下不可观测，**本阶段三平台均不实现**，也不为此造用例。
- **D2 不为它开 GAP 向量**：现有 `lr`/`sc` 向量只覆盖「同 hart store 清保留」「异常/中断进入清保留」（后者见 `ISS-443`），**不新增**"另一 hart"类用例；`ISS-440` 保留为 open，作为该能力的登记点。
- **D3 重开条件**：引入**多 hart 机型**（多 hart chipyard 配置或多 hart QEMU 机器）时，本条与 `ISS-440` 一并重开，按 `SimRISC-12 §1` 实现并补向量。

## Rationale（理由）

- 语义存在不代表必须在无载体时实现：单 hart 下该事件**物理不可观测**，实现与否无法被任何向量区分，反而增加三平台分叉风险；
- 与 `ISS-435` 的口径不冲突：`ISS-435` 定的是"保留粒度 = 精确地址 + 宽度"，本条讲的是"谁来触发清除"，两者正交；
- 把重开条件绑定到"多 hart 机型出现"这一可判定事件，避免该语义被永久遗忘。

## Consequences（影响）

- 三平台保持现状（QEMU 记录键 + 同 hart 清除；chipyard 单 hart；gem5 未实现），**不新增代码与用例**；
- `ISS-440` 继续 open，`status` 与本文互指；
- 多 hart 机型的工作（含 IPI、多 hart 启动）若要落地，必须同时把本条列入范围。

## 状态说明

2026-11-15 由主会话起草；用户先裁定「3、1」（立 ADR、采用"单 hart 不可观测、暂不实现，等多 hart 机型"），随后对 **D1–D3 逐条确认**（原话：「确认，继续」）⇒ 置 `Accepted`。`ISS-440` 保持 open 作为该能力登记点。
