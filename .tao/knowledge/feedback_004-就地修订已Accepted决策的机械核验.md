# feedback_004：核「已 `Accepted` 决策未被静默改写」用「HEAD×工作树按节 diff + 非空校验」；「已标 `Superseded`」须核到节内标记

> 操作规范（"应该这样做 / 不该那样做"）。来源：`SPEC-113t`（`ADR-0020` 新建 + `ADR-0004` 就地修订，2026-10-07）engineer 自审 F2、reviewer 独立注入、architect 交叉复核。

## 背景（触发事件）

`SPEC-113t` 按 `Process-03`「不直接改写已 `Accepted` 的决策」就地修订 `ADR-0004`：新增 `## 修订` 条目（`R1`/`R2`/`R3`）表达取代/覆盖关系，**不得**改动受保护决策 `D1`/`D2.1`/`D3`/`D4`/`D5`/`D6` 正文。工程师原拟用 `git diff` 的 hunk（删除行）判定「未静默改写」，但 hunk 边界**脆弱**：修订条目里**引用** D 项正文措辞（如「覆盖 `D1` 内存映射表…」）会与正文改动**混淆**，产生误判。

## 规律（应固化）

1. **判「受保护决策正文未被改写」用「`git show HEAD:<file>` × 工作树**按节前缀提取**后逐节 `diff`」，**不以 `git diff` hunk 为准**。
   - 做法：写一个按「起始前缀 / 结束前缀」切节的提取器（如 `### D1 `→`### D2 `、`#### D2.1 `→`#### D2.2 `），对 `git show HEAD:<file>` 与工作树各切一次，`diff -q` ⇒ `same` 才算未改。
   - 反例：只凭 `git diff` 看「仅 `**状态**` 行替换、无其它删除行」下结论——语义上正确，但**不稳**（新增条目引用正文措辞会干扰 hunk 判读）。

2. **提取结果须做「非空」校验**（每节 `<行数> > 0`），否则**空提取 ⇒ 两侧都空 ⇒ `same` ⇒ 假 PASS**。
   - 反例：若节前缀写错（如把 `#### D2.1 ` 误写成 `## D2.1 `），提取为空，`diff -q` 仍报 `same`，掩盖真实改动。

3. **「某决策已标 `Superseded`」须核到该节内的 in-place 标记，不得以「修订条目里写了『已标』」为准**。
   - 反例（`SPEC-113t` 观察）：`ADR-0004 R2` 括注称「（`D3` 标 `Superseded`）」，但实测 `D3` 节标题与节内**均无** `Superseded`（全文仅见通用规则行 / 历史 rev 行 / R2 本条）——该「已标」实为**文件级取代声明**（条目即标注），非节内标记。属**措辞不精确**（决策成立：`Process-03`「**新增 ADR** 或标注 `Superseded`」已由新增 `ADR-0020` 满足），但核对时应指出。
   - 做法：`awk '/^### D3 /,/^### D4 /' <file> | grep -c Superseded`（**按节内**计数）为 0 即证「未 in-place 标注」；若要标，给该节标题后加一行 `> **Superseded by ADR-00xx Dn**`，或把括注改为「由本修订条目声明取代」。

4. **独立注入须「非空 → 检出 FAIL → 还原回绿」三步齐证，且还原用 `cp`+`md5`（禁 `git checkout/restore/stash`）**；注入宜在**临时树**（`/tmp/opencode/<任务ID>/`）进行，不碰工作树。
   - 做法：`cp <file> /tmp/opencode/<任务ID>/inj.md` → 改一处 → `diff -q <file> inj.md` 证**非空** → 用被测脚本/同款逻辑复核报 `DIFFERENT`（FAIL）→ 丢弃临时树即可（工作树自始未动）。
