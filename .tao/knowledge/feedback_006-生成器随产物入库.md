# feedback_006：生成器随产物入库（产物入 git ⇒ 生成器不得只留 `.work/`）

**来源**：`LLVM-060t` round1（`DADAOCfxAlias.inc` 已入库，生成器却留在 `.work/`），由 architect 修订允许文件集后 round2 迁入并复现。教训记录见 `lessons.md §7.7`；规则原文见 `AGENTS.md`「临时目录」。

## 规则

1. **判据 = 产物是否入库**：凡产出**被提交（入 git）**的生成器/脚本，必须**随产物**保留在**非易失位置**——优先 `tools/<module>/`（可复用/可审计价值高），否则 `.work/<任务ID>/`；**不得**只留 `/tmp` 或 **`.work/`（被 `.gitignore` 整体忽略 ⇒ 不入库）**。
2. **「一次性」只描述用途，不等于可丢弃**：即使生成器只服务一个任务，只要其产物入库，生成器即须入库。
3. **任务书「允许文件集」须显式含该项**：architect 拆任务时，「无残留/允许文件集」清单须把「随产物入库的生成器」列为允许文件；否则 engineer 为不越界会把生成器留在 `.work/`（`LLVM-060t` round1 即如此）。
4. **入库生成器须「可复现生成」产物**：复用既有投影函数、不另造轮子；可复现性以 **`cmp` 逐字节**证（重跑生成器 → 产物不变 ⇒ 与已入库 patch/产物 `cmp` EXIT=0）。architect 交叉复核时**须自己跑一遍生成器 + `cmp`**，不得采信他人输出。
5. **生成物内 provenance 行**（如 `// Generator: <路径>`）须指向生成器当前路径；落点迁移导致该行失真时，按用户裁定授权改该注释并**重新导出 patch**（只改注释、表数据/编码零变化）。
