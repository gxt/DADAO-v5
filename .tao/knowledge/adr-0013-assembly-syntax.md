# ADR-0013: DADAO 汇编语言语法冻结

**状态**：Accepted
**日期**：2026-09-28
**关联**：`SPEC-035t`、`docs/spec/assembly-language.md`（v1，2026-09-25 用户审核通过）、`ADR-0012 D4`（spec/ 只读策略调整）

## Context（背景）

DADAO M1 的汇编语言语法已在 `docs/spec/assembly-language.md` v1 中定稿并经用户审核通过。该规范定义了词法、地址表达式、寄存器组、条件标记、指令语法、伪指令、指导符等书写形式，是 LLVM MC parser/printer/disassembler 实现的权威依据。

按 `AGENTS.md` ADR 判据，汇编语法属于：
- **外部契约 / 跨模块**：影响 LLVM MC、QEMU、测试用例等多个模块
- **不可逆 / 高代价**：语法一旦冻结，后续修改需同步修改汇编器、反汇编器、所有测试向量和文档
- **有多方案且需记录取舍**：寄存器组、条件标记、地址表达式等均有多种可选方案

本 ADR 正式固化上述语法决策，供后续实现和验收作为约束依据。

## Decision（决策）

### D1：`{...}` 语法的四种用途

**引用**：`assembly-language.md §4`（寄存器组与条件标记）；**双目的用途为本次新增（2026-09-28 用户确认，由 `SPEC-036t` 落地，v1 尚无）**

`{...}` 语法统一用于四种场景，通过上下文消歧：

| 用途 | 语法 | 示例 | 区分标记 | 来源 |
|------|------|------|---------|------|
| 条件寄存器组 | `{reg, …}?` | `{rd3}?`、`{rd8, rd0}?` | `?` 紧跟 `}` | v1 §4 |
| 双目的寄存器对 | `{reg, reg}` | `{rd8, rd9}` | 无 `?`，恰好 2 个 | **本次新增** |
| 多寄存器组（范围） | `{start:end}` | `{rd8:rd11}` | `:` 分隔 | v1 §4 |
| 多寄存器组（单寄存器） | `{reg}` | `{rd8}` | count=1 | v1 §4 |

**已拒绝方案**：
- R1: 用不同括号区分（`()` for 条件、`[]` for 组）→ 增加语法复杂度，且 `[]` 已用于地址表达式（§3），会造成歧义
- R2: 双目的用 `(rdHA, rdHB)` 而非 `{rdHA, rdHB}` → 与条件组风格不一致，增加记忆负担
- R3: 多寄存器组保持旧语法（显式写出 count，如 `ldm.ub rd8, rb0, rd1, 3`）→ 与 `ldm`/`stm` 的组记法不一致，且 count 与起始寄存器的语义关联隐含

### D2：`?` 作为条件标记后缀

**引用**：`assembly-language.md §4.1–§4.2`（寄存器组语法与规则）

- `?` **MUST** 紧跟 `}` 之后，标记「该组寄存器用于条件判断」
- **MUST NOT** 写在寄存器名之后（`rd3?` 会被词法解析为单个标识符，因 `?` 属于标识符字符集——§2.3）
- parser 靠有无 `?` 区分条件组与双目的组（§4.2）

**已拒绝方案**：
- R1: 用 `@cond` 前缀标记（如 `@cond {rd8, rd0}`）→ 与 RISC-V / GNU AS 风格差异大，且引入新关键字
- R2: 不用标记，靠指令语义推断 → `cs.eq {rd8, rd0}, rd9, rd10` 中无法区分条件组（`{rd8, rd0}?`）与双目的组（`{rd8, rd0}`），两种语义的编码不同

### D3：`i` 作为指令字单位后缀

**引用**：`assembly-language.md §2.4`（数字与单位后缀）

- `i` 紧跟立即数之后，表示该立即数以**指令字（4 字节）**为单位
- **MUST** 仅用于「跳转/分支的目标偏移」（`jump`/`call`/`br.*`）
- 其余立即数 **MUST NOT** 加后缀；其单位在 §5 逐族说明（访存偏移 = 字节；`rela.si` = 4 KiB）

**已拒绝方案**：
- R1: 用 `*4` 或 `<<2` 显式乘法（如 `jump [rb0, 2*4]`）→ 语义不清晰，用户不友好，且要求汇编器支持常量折叠表达式中的地址语义
- R2: 所有立即数统一字节单位（不用后缀）→ 跳转偏移以指令字为单位是 ISA 设计决定（`imms24`/`imms18`/`imms12` 的每个单位 = 4 字节），汇编应如实反映而非隐藏

### D4：`[...]` 地址表达式语法

**引用**：`assembly-language.md §3`（地址表达式）

- 访存与跳转/分支目标**共用** `[...]` 记法（§3 开篇）
- 访存：`[rbN, imm]`（偏移单位为字节，`imms12`）
- iiii 跳转：`[rb0, immi]`（偏移单位为指令字，加 `i`；基址 **MUST** 为 `rb0`）
- rrii 跳转：`[rbN, rdN, immi]`（寄存器偏移不加倍；立即数加 `i`）

**已拒绝方案**：
- R1: 访存用 `rbN(imm)`（MIPS 风格，如 `ld.ub rd8, 1(rb2)`）→ 与跳转记法不统一，需两套语法
- R2: 跳转用 `#imm`（ARM 风格，如 `jump #8`）→ `#` 在多数汇编器中是注释符（§2.2 已定义 `#` 为注释），冲突

### D5：源+目的都用组记法（多寄存器指令）

**引用**：`assembly-language.md §4.2`（现有 `ldm`/`stm` 组记法规则）；**块赋值/浮点格式转换的源+目的组记法为本次新增（2026-09-28 用户确认，由 `SPEC-036t` 落地）**

- 当 `immu6` 表示连续寄存器个数时，源和目的**都用** `{start:end}` 范围记法
- 适用于：寄存器复制（`orri` 格式，如 `ra2rd`，8 条）、浮点格式转换（`orri` 格式，20 条）
- 示例：`ra2rd {rd8:rd10}, {ra1:ra3}`
- `ldm` 的组是目的（内存→寄存器），`stm` 的组是源（寄存器→内存）——语义一致
- **注**：v1 §5 的 `rrri` 行（`ldm`/`stm`）已用组记法；本决策将其**推广**至 `orri` 格式的块赋值与浮点格式转换（v1 尚无）

**已拒绝方案**：
- R1: 只有目的用范围，源保持原样（如 `ra2rd {rd8:rd10}, ra1, 3`）→ 语义不对称，`immu6` 同时约束源和目的的寄存器个数，拆开书写会让读者误以为源和目的可以不等长
- R2: 源和目的都用范围但用不同分隔符（`{rd8:rd10}` vs `(ra1:ra3)`）→ 增加语法复杂度，无实际消歧收益

### D6：双目的逗号组与条件组的消歧规则

**引用**：`assembly-language.md §4`（条件组，v1）、§5（`rrrr` 格式类）；**双目的组的消歧为本次新增（2026-09-28 用户确认，由 `SPEC-036t` 落地）**

消歧规则（parser 执行顺序）：

1. 读取 `{...}` 内容
2. 检查 `}` 后是否有 `?`：
   - **有 `?`** → 条件组（如 `{rd8, rd0}?`）
   - **无 `?`** 且恰好 2 个寄存器、用逗号分隔 → 双目的组（如 `{rd8, rd9}`）
   - **无 `?`** 且有 `:` → 范围组（如 `{rd8:rd11}`）
   - **无 `?`** 且 1 个寄存器 → 单寄存器组（如 `{rd8}`）

**已拒绝方案**：
- R1: 限制双目的组只能出现在指令第一个操作数位置 → 无法覆盖未来可能的双目的扩展（如新增指令的目标操作数也用双目的）
- R2: 用关键字标记（如 `dst {rd8, rd9}`）→ 过于冗长，且关键字需保留，与现有标识符字符集冲突风险

### D7：汇编表格落点

**引用**：`assembly-language.md 附`（与上游 `spec/` 的关系）、`ADR-0012 D4`（spec/ 只读策略调整）

- `assembly-list.md` 的分类表格**嵌入**对应 `spec/SimRISC-XX-*.md` 文件（而非独立存放）
- `spec/` 目录**可由 spec 模块任务修改**（ADR-0012 D4 已解除只读限制）
- 旧「spec/ 只读」表述需同步更新——本 ADR 确认该更新已纳入计划（由 `SPEC-036t` 执行）

**已拒绝方案**：
- R1: 表格只放 `docs/assembly-list.md`，spec 文件用链接引用 → 查阅不便，需在两个文件间跳转；且 spec 文件作为独立分发单元时丢失上下文
- R2: 表格放 `docs/spec/`（v5 规范层）→ 与 `spec/`（原始规范）分离，增加维护成本；且 `docs/spec/` 的定位是 v5 扩展规范，不是原始指令表

## Rationale（理由）

上述 7 条决策的核心权衡原则：

1. **统一记法优先**（D1、D4）：`{...}` 和 `[...]` 各自统一一类语义，减少语法碎片
2. **显式标记优先**（D2、D3）：`?` 和 `i` 作为后缀消歧，避免 parser 需要语义推断
3. **对称性优先**（D5）：源和目的用相同记法，反映 `immu6` 的真实语义约束
4. **确定性优先**（D6）：parser 消歧规则简单明确，不依赖指令语义
5. **就近原则**（D7）：表格嵌入 spec 文件，减少跨文件查阅

## Consequences（正面影响）

- 汇编语法有了权威的单一来源（`assembly-language.md`），LLVM MC / QEMU / 测试用例均以此为准
- `{...}` / `[...]` / `?` / `i` / `:` 五种标点覆盖全部 M1 指令的书写需求
- parser 消歧规则明确，可直接映射为递归下降或 PEG 文法

## Consequences（负面影响）

- 新语法与当前 LLVM MC 实现（旧语法）不兼容，需全面重写 parser/printer/disassembler
- `{...}` 四种用途共用一对括号，对人类读者的初见成本略高（需结合上下文理解）
- 单位后缀 `i` 仅限跳转/分支，增加了"何时加何时不加"的记忆负担
