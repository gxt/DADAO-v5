## §1 写码前（规划 / 规范 / 任务书 / 契约）

### 1.1 任务书自包含与参考来源边界
- 任务书须**自包含**：执行所需事实/格式/模板写入任务书或 v5 自身知识，不依赖外部仓库内容；模板以 v5 自身知识为准。
- 参考仓库只读溯源/对照，其文件**不得作执行依赖**；引用须标「**内容溯源，非执行必需**」。
- 规划前可在里程碑/任务书层面检索参考仓库（**只读 `.cache/refs/**`、不写回、不复制代码**），产「参考做法 → 本项差异 → 建议落点」逐条；结论落知识层或任务书，**不新建文档**。

### 1.2 下发前预检第 2 项须核「本任务验证手段的全部前置」
- 第 2 项（依赖链实际可用）**不得窄化**为「任务书 `依赖` 字段指向的任务是否存在」——须把验收命令（如 `make check`）**逐个子门控拆开**，对每个子门控问三问：① 它**读哪些文件**（门控载体）；② 这些文件**由谁产出**（本任务 / 同仓前置 / 跨模块前置）；③ 产者是否已在**本任务之前**且**已验证**。
- 凡「产物须在**同一原子变更**内出现的门控载体」⇒ 必须**并入本任务文件集**或**前置**，不得留在下游任务（否则成环或红）。

### 1.3 门槛前置：路径 / 组合须已被 ADR / 规范定义
- 门槛（里程碑门控）正向用例若把**两条及以上路径 / 组合**并在同一例，须在**立案 / 下发前**逐项核：「该路径 / 组合是否已被 ADR / 规范**定义**？是否已**实现**？」
- **未定义** ⇒ 视为**前置缺口**，**先经用户裁定**（另立任务实现 + ADR 逐条确认 / 调整门槛口径 / 其它），不得默认「组合可用」而把风险留给门槛任务。
- 缺口与选项只**追加**写入相关任务书审阅记录 + `milestones.md`；**不改任务范围、不动 `spec/`、不擅自建任务 / 立 ADR**。

### 1.4 ADR 判据提醒与 decision 逐条确认
- 涉及 ADR 判据（高代价 / 跨模块 / 多方案 / 外部契约 / 结论固化 / 定位）时**主动提醒用户是否生成 ADR**，不擅自决定、不静默略过。ADR **不承载规范正文**（正文归 `spec/` 与 `contract-*`）。
- 写入 ADR 的每个 decision 必须**逐条与用户确认**；任务书 / 文档里已写的 decision 只是**提案**。**不得**把未经逐条确认的 decision 写为 `Accepted`；改已 `Accepted` ADR 的 decision 仍须逐条确认（新增 ADR / 标 `Superseded` / 经授权的就地修订）。

### 1.5 改动清单 × 范围边界 × 事实核实 交叉自检
- 任务书「改动清单」与「范围边界 / 事实核实」两节须**交叉自检**：同一文件不得既在改动清单又标「不动」。
- 标签类括注须与实际字段值一致；引用的 file:line 事实须在**下发前实测**（不得沿用旧任务 / 历史台账的表述）。

### 1.6 反例判据须与门控脚本实际行为对齐
- 反例注入判据须与门控脚本**实际行为**对齐，不得凭文字假设（如门控对某状态「直接 `continue`」、或某计数）；「不变量计数」须下发前实测。

### 1.7 正例 / 反例清单交叉自检、操作数角色
- 同一串不得同时出现在正例与反例清单；操作数角色（目的 / 源、首操作数）须与格式定义一致（如 `orrr`/`orri` 目的为首操作数、`cs.*`-rf 目的位置不同）。

### 1.8 编码类反例示例须选未占用 opx/op
- 反例示例须写明「**注入后构建成功、目标检查 FAIL**」；不得给出会触发 TableGen 解码冲突或构建失败（如与既有记录 `op`/`ha` 撞车）的值。

### 1.9 反例条目须写清「注入什么 → 哪些用例应 FAIL」
- 反例注入条目须写清「**注入什么 → 哪些用例应 FAIL**」，并与括注的证明目的交叉自检，不得自相矛盾（如「T3 仍 PASS」与「证明含完全重合承重」并存）。

### 1.10 唯一 / 仅 / 全部类断言须下发前全量实测
- 任务书「事实源 / 事实核实」段凡出现「**唯一 / 仅 / 全部 / 共 N 个**」类**计数或集合**断言，须在**下发前**对生成物**全量实测**并落纸。
- 规范子句若**限定某子集**（如「cfx 组」），只在该子集内据实书写；子集外同值项**不得混入**（避免扩义或臆断）。
- 判别 `pre-existing` 失败清单亦须全量实测（或引既列清单），回归判据统一取「**与改前基线逐字节一致 / 零新增**」。

### 1.11 softfloat 目标须显式设 `default_nan_pattern`
- 任何新增 / 复制的 softfloat 目标初始化都须**显式设 `default_nan_pattern`**（`memset(st,0,...)` 后为 0 ⇒ invalid 运算走畸形 default-NaN / 断言）。
- 探针须覆盖至少一条 invalid → default-NaN 用例。

### 1.12 id 后缀 bank 签名与工具反解陷阱
- 单目的 `orrr` 指令 id 后缀 = **操作数 bank 签名**（按字段顺序，非单 bank）；工具须**从记录的 src 字段推导 bank**，**不反解 id 末段**。
- 编码类改动须以**跨载体门控**为准：单文件 validator（只比字面 `value`）抓不到 `value = op<<24 | ha<<18` 之类不一致，须跨载体 `validate_vectors` / `check-interface` 兜底。

### 1.13 同一 reloc 类型不得承载两种语义
- `RELA` 记录**不带基址寄存器字段**、linker **只看类型不解码指令** ⇒ 一类型承载两公式必**静默错值**；PC 相对与基址相对须**按基址寄存器分型**（如 `REL12`/`ABS12`，由汇编器自动选型）。

### 1.14 寄存器编号的语义是「调用域相关」的
- 同一号在函数 ABI / 系统调用 / 半托管可承载不同角色，变更须**逐域分类**（按用途「改 / 不改」），**勿跨域全局替换**；重叠区（如返回区与入参区）须显式澄清。

### 1.15 改阈值类参数须连带同步配套阈值 / 正负例边界
- 改阈值（如槽位上限）须连带同步**同族**：主阈值 + 计数检查 + 正例 + 负例阈值 + 派生切换点，**成对出现**；只改主阈值会留自相矛盾边界。
- 证据脚本对**每条**阈值设**独立**断言。

### 1.16 保留集判定须同源；仅写注释的不变式须显式移交
- 保留集随函数条件变化时，「保留判定」（RA）与「使用判定」（PEI）**必须**用**同一**条件；条件输入的求解须在保留集冻结前完成。
- **仅写注释的不变式不算落地**——须移交后续任务并在其范围 / 验收写明。

### 1.17 册内「可机械核对」的计数一律指向真源
- 册内计数须**指向真源**（生成物 / `contracts/`）或**去数字**；确需保留的「冻结 / 示例性」数字须**显式标注依据**（否则被下次清理误伤）。

### 1.18 任务书验收与契约冲突 ⇒ 按契约实现并更正该条
- 任务书验收措辞若与 `contracts/`/ADR 冲突（属任务书缺陷），实现**按 Spec-first 以契约为准**（宁**显式报错**，不静默 0 / 截断），并在**收尾更正**任务书该条为可达表述（附一句更正说明；**只改该条**，不改既有完成区 / 审阅记录），**不留「不可达验收」**。

### 1.19 伪代码为权威：prose 与伪代码张力
- 规范内**伪代码（权威优先级最高）**与 prose 对同一语义有张力时，**以实现伪代码为准**。
- 区分两类：**澄清类**（实现与伪代码一致、仅易误解）⇒ 入本文件，**不立** spec 任务；**覆盖缺口 / 张力类**（prose 与伪代码 / 机制不符，须改上游册）⇒ **登记 issue + 提请授权**，不得静默改。

### 1.20 改 `spec/` 目录须用户事先明确授权
- `spec/` 下任何**新增 / 修改 / 删除**（含 v5 自定册 `Machine-*`/`Process-*` 与 `spec/README.md`）**须用户"事先"明确允许**，授权**原话落盘**；未获授权而拟改 ⇒ **BLOCKED**。
- **上游只读册**（`DADAO-1x/2x`、`SimRISC-00..12`、`Toolchain-01`）只作**只读引用**（引 `§` 章节号，不改一字）；确需修改须先经授权，并在**同一变更**内更新 `manifests/spec-readonly.lock.toml` 的 `sha256`。
- 任务书「输出」不得把上游只读册列为可改对象；需要的新正文一律落 **v5 自定册**。
- **三处固定检查**（下发前预检第 5 项 / reviewer 验收 / architect 提交）均以 `git diff --name-only`（提交前 `--cached`）与 `spec/` 清单交叉；有交集而缺授权证据 ⇒ 阻断。规则正文 `docs/Process-06`。

### 1.21 ADR / 规范点名一类产物须逐字列出、逐项核到底
- ADR / 规范**逐个点名**一类产物时，任务书「范围」与「验收 grep 范围」须把点名项**原样抄入**，逐项给「已落地 / 不适用 / out-of-scope（附证据）」结论；**不得**以概括措辞替代点名清单。
- 核对「门控可执行来源」须从 `make check` 依赖表出发，沿「门控 → 脚本 → 可执行 / 子脚本」调用链**逐跳追**；grep 范围须覆盖**全部被调脚本所在目录**。
- 判「是否门控 / 执行器」须用**调用链证据**（全仓 grep + import/subprocess），不得因「同款写法 / 同目录」类推；判 out-of-scope 须给**调用链反证**并登记遗留。

### 1.22 判 target 是否在 `make check` 依赖链须读 `check:` 依赖行
- 判「某 target 是否随 `make check` 跑」只看 `check:` 目标的**依赖行**（`grep -n '^check:' Makefile`），**不得**以 `.PHONY:` 清单为准；再 `grep -n '^<target>:'` 看目标处注释（常标 `standalone`）。
- 要求另跑 standalone target 时须显式写明「standalone，不在 `make check` 依赖链内」，各自单独跑、各自报 EXIT。**行号引用须逐行核对**。

### 1.23 生成器随产物入库
- **判据 = 产物是否入库**：凡产出**被提交**的生成器 / 脚本，须**随产物**保留在**非易失位置**（优先 `tools/<module>/`，否则 `.work/<任务ID>/`）；**「一次性」只描述用途，不等于可丢弃**。
- 任务书「允许文件集」须**显式含**「随产物入库的生成器」；入库生成器须**可复现生成**产物（`cmp` 逐字节证）；生成物内 provenance 行（如 `// Generator:`）须指向生成器当前路径，落点迁移致失真时按授权改注释并**重新导出 patch**（只改注释、表数据 / 编码零变化）。

### 1.24 re-scope 的双层（生成器 + yaml）与跨任务契约（谁加谁减）
- **生成物改动须「改生成器 + 重跑」**，禁只手改生成物；重跑须 **byte-identical / 幂等**（两跑 md5 相等）并作为验收项。
- **跨任务共享的集合型门控载体**（其内容随某任务的状态改变）⇒ 须在**两个任务的接口**写明「**谁加、谁减**」，并把「本任务应移除 / 加入」列为**接收变更方**的验收项 + 机械核验。

### 1.25 规范以「委派 / 占位」留给任务的决策
- 任务若落地规范「**委派给本任务**」或「**留占位**」的决策，须在**规范正文以外**记明三件事：已落地的**实现口径**、规范对应段落**现状**（占位 / 委派 / 歧义，逐条引 `§`）、**拟改文本**（放任务书完成区 + `issues.yaml`）。
- 实现口径须由**门控断言**固化（使缺口在授权前即可机械核验、实现不依赖未授权 spec 改动）；规范覆盖缺口**一律不改 `spec/` 收口**，登记 issue + 请用户**事先**授权，授权后在**同一变更**内同步该册 `sha256` 锁。
- 区分两类：「实现口径已固化」（登记遗留、不阻塞）vs「规范正文缺口」（提请授权），不得混为一次静默改 `spec/`。

### 1.26 保护范围扩面须四处一致；立案前须实测锁实际包含哪些册
- 立案前凡涉及「**更新**某册锁 / 某清单」的表述，须先**实测**该文件实际包含哪些项——「更新」的前提是「已在锁内」，不在即应为「**新增**」。
- 保护**范围扩面**（如把 v5 自定册纳入原「只保护上游册」的锁）至少同步**四处一致**：① **机制正文**语义；② **锁 / 清单**与计数；③ **门控措辞**（docstring / `--help` / 输出行，**逻辑零改动**）；④ **判据注记**。任一处漏改 ⇒ 规范与机制自相矛盾。
- 授权范围**边界外的相邻措辞不得顺手改**——登记「遗留」并提请**另行授权**；扩面后 `sha256` 须**改毕后实测**并核「既有册 `sha256` 逐条未变」。

### 1.27 「复用上游共享层」须列全接入点清单
- 任务范围若为「**复用**上游共享层」，任务书「输出」须**显式列全接入点清单**：① 钩子实现文件；② **调试地址翻译钩子**（否则回退 NULL ⇒ **SIGSEGV**）；③ **CLI arch mask**（否则 CLI 被拒）；④ **Kconfig `select` + meson `when:` 挂钩**（否则共享层不编入）。任一项漏列 ⇒ 实现期必然「越界」或功能不可达。
- 越界**判据** = 「**是否为本任务复用共享层的必需接线**」，非任务书字面文件清单；超出字面清单的必需接线须**如实披露**、不得裁剪；共享层零改动仍须**实测证**（`git -C <source> diff --stat HEAD -- <share-path>` 为空）。

### 1.28 停机协议迁移（exit-port → semihosting `SYS_EXIT`）
- **约定**：参数为 **64 位大端内存块** `{reason=0x20026, exit_code}`，**块指针在 `rb16`**（非旧寄存器习惯）、服务号 `rd16=0x18`、`trap cfx_umon, 0x30000`（`immu18[17:16]==2'b11` 判定，**与 `cfxha` 取值无关**）；**退出码在内存块第 2 字段**。
- harness 须**显式** `-semihosting-config enable=on,target=native`（否则 `SYS_EXIT` 不可达、host `$?` 不传播）。
- `-d cpu` 观测：`SYS_EXIT` 的 `trap` **不在 trap 前切 TB** ⇒ 若「读观测值的 `ld_o`」与 exit 序列同 TB，会观测到旧值；**修法**：exit 序列**前置一条 no-op `jump-iiii imms24=1`** 强制 TB 边界。
- **迁移类任务**须**先记改前基线**（逐条真实输出）**再对拍**；**范围 / 计数一律脚本枚举**（禁目测抽样）；默认全迁、例外逐条披露并登记 issue。

### 1.29 clang target 上架三处口径
- `TargetInfo` 的 DataLayout 须 `resetDataLayout()` **由 triple 派生**，**禁**写死字面量（clang 以 `err_data_layout_mismatch` 强制与后端一致）。
- 默认 `DefaultABIInfo` 对**所有聚合**走间接；凡 ABI 要求「小聚合入寄存器」须**自建 `ABIInfo`** 并分发。
- clang driver **已自动透传** `-Wl,` / `-Xlinker`，工具内**勿**再重复透传链接参数。

### 1.30 描述 ISA 约束须引用精确形式
- 描述 ISA 约束须引用**精确形式**（如 `start+immu6 ≤ 64`，附 `§` / 数据行指针），**禁**「必须排除 / 必须包含」式笼统表述（会**同时过强与漏约束**）。

### 1.31 手写 CSR / reserved 集合须与生成集合相等
- 自定义后端**手写**的 `getCalleeSavedRegs` / `getReservedRegs` 必须与 TableGen 生成的 `CSR_RegMask` / 保留集**集合相等**；不一致则 RA 视其为 preserved 而 PEI 不保存 ⇒ **静默坏寄存器**。无常量池后端另须 `setOperationAction(ConstantFP, Legal)` + `DAGToDAG` 材料化。

### 1.32 并发 / 可重入的安装步骤须 temp + `rename(2)`
- 同一目标可能被多个 `make` 目标 / 并行任务写的**安装步骤**，须先写**每进程唯一临时名**再 `rename(2)` 原子替换（`cp -aL src dst.tmp.$$ && mv -f dst.tmp.$$ dst`）；**禁**依赖 `cp --remove-destination`（`unlink` + `open(O_EXCL)` 非原子对，并发下 `EEXIST`）。

### 1.33 实现侧与向量侧耦合须同批落地
- 改动若**同时**含「写侧」（实现）与「读侧」（向量 / 期望值），二者须放进**同一任务**或**同批落地**；任一侧单独落地即**红门控**。

### 1.34 量产型生成器须全量覆盖 + 不可判定即中止 + 幂等
- 遍历真源**全部记录**的量产型生成器须：① 逐条覆盖，遇「无法无歧义映射」**中止报错**（禁静默跳过 / 人工挑拣）；② **幂等**——同一真源两跑产物**逐字相等**（md5 对账）作为可验收判据；③ 规模产物**分层**（快档入常驻门控、全量档 opt-in；opt-in 档与真源一致性无常态报警，须登记遗留）。

### 1.35 预检涉及 `enabled` / 构建前置须实测门控硬要求
- 下发前「任务书自洽性」预检若涉及 `enabled` 组件 / `series` / 构建前置等**由门控机械判定**的约束，须先**实跑 / 实读该门控脚本**确认硬要求，再判自洽；**不得**仅凭任务书文字推断「自洽」。

### 1.36 LLVM `setOperationAction` 键
- `SETCC` 按**操作数**类型、`SELECT_CC` 按**结果**类型取 action ⇒ 设 `SELECT_CC MVT::i64 Custom` 会**连带捕获**「FP 比较选整数臂」；lowering 须统一处理 `SETCC` / `SELECT_CC`（含 `FCMP` 源）。`cs.*` 选的臂操作数须用 **i64 类型叶子**（非 `GPRD` 寄存器类叶子），否则常量臂被拒。

### 1.37 目录型安装须 temp staging + 先 `rm -rf` 旧目录 + `rename(2)`
- **目录**的原子替换不能推广**文件**型（`rename(2)` 覆盖**非空**目录会 `ENOTEMPTY`）：须 `rm -rf dst.tmp.$$ && cp -aL src dst.tmp.$$ && rm -rf dst && mv -f …`（staged 副本先完整、再暴露），并由**连跑两次 `EXIT=0`** 证幂等。

### 1.38 后端未处理调用形态：某优化级「正常」≠ 无缺陷
- 不得以「某优化级正常」判其无缺陷——同一根因可在不同优化级表现为**静默 hang** 与**断言 crash** 两态。须以**逐优化级的运行期退出码**（含 `timeout`）为判据、并**归并同根 issue**；对不支持的调用形态须**显式拒绝 / 降级**（不可依赖断言兜底）。

### 1.39 DADAO 分支放宽两坑
- 加分支放宽时：① **勿实现 `reverseBranchCondition`**（会改 CFG 形状、触发既有 lit 回归），放宽只走 BranchRelaxation 跳岛回退路径；② `BrOffset` 是**字节**偏移而 DADAO 分支立即数存**字** ⇒ 判据须**按各分支字段宽度**换算，并加 **4 对齐前置**。

### 1.40 clang 独立静态链接后端库
- 交叉工具链中 `clang` **独立静态链接**后端库：只 `ninja llc`（或 `build-mc-lite`）**不更新 `clang`** ⇒ 同一源码 `clang` 与 `llc` 产物不同，易误判为后端 bug。**验证 `clang` 行为须用完整 `make build-mc`**。

### 1.41 定长 ISA 的 MC `writeNopData` 须精确写 `Count` 字节
- 定长 4B / 无子字指令的 ISA 须**精确写 `Count` 字节**（不足整字尾部用 **0** 补，整字写 NOP）；**不可**向上取整到指令宽度（写超 ⇒ fragment 尺寸崩），**亦不可** `getMinimumNopSize()=4`（relax 死循环）。仅**可执行段**触发。

### 1.42 组件锁 `shallow_ref` 优先引用不可变 tag
- `manifests/*.lock.toml` 中 `shallow=true` 组件的 `shallow_ref` 应取**不可变 tag** 而非可变分支；选 tag 前用 `git ls-remote --tags` 核 `refs/tags/<tag>^{}` 指向锁内 `commit`（注意区分同名 lightweight tag）。

### 1.43 新门控上线后 `.work/` 示例路径须 `<>` 占位
- 引用了 `.work/**` 的门控上线后，任务书 / 记录 / 文档中**举例** `.work/` 路径时**一律写可判定跳过的占位形态**（含 `<>` 或 `*`，如 `.work/log/<模块>/<任务ID>-*.log`），**禁**写具体路径——否则示例本身被当真实引用、门控**自伤**。

### 1.44 待办 / 计划须落任务书或 `milestones.md`
- 「待办 / 计划 / 后续要做」须落**任务书**或 `milestones.md`「规划中」（有人看、被跟踪）；**不得**落 `.work/`（可丢弃、无人提醒）——被丢弃的待办 = 静默漏项。

### 1.45 文档只写位域，派生值由生成器算
- **文档只写位域**（字段位置 / `opx` / `mask`）；**派生值（`value` 等）由生成器算**——作者**不手算、不复写**（例：6 位 `opx` 落 `bits[23:18]` 放进字节需 `<<2`，`0x0C → 0x30`；手算复写照抄即错源）。

## §2 验收与反例

### 2.1 期望值须「独立派生」+ 可复算派生器
- 期望值须**独立派生自 `spec/`**，**禁**由被测实现（LLVM / QEMU）生成或校准。
- 期望值写死时必须交付**可复算的派生器**（内联进探针 / 自检），使「常量 = 派生结果」可独立验证；否则硬编码值与实现形成**自证循环**。

### 2.2 工具交付物 vs 数据交付物应分层验收
- 脚本（工具交付物）的 bug 不应阻断数据交付物的验收——两者**分层验收**，分别给判据。

### 2.3 验证型任务（无实现改动）亦须交付可失败的专证据
- 验证型任务**亦**须交付**可失败的专证据**（内置反例合并注入 ⇒ FAIL ⇒ `cp`+md5 还原 ⇒ **重建** ⇒ 回绿）；且「基线无缺口」结论须有**覆盖面依据**（用例逐条对应任务输出范围），**不得**以 validator 绿灯 / 覆盖脚本充数。

### 2.4 独立 oracle：机械解析 + 披露 + 显式捕获旁路通道
- 期望值的**结构化来源**（契约表格 / 清单）须在独立 oracle 内**机械解析**（逐条），禁复制为硬编码常量（防「契约 → oracle」静默漂移）。
- **语义性**期望值（位编码、规则 → 异常映射、文档化 token）**只能硬编码**时须：带 `contract-*`/`spec` § **引用注释** + 在任务书 / `README` **披露** + 与既有同层 oracle 范式一致。
- 独立 oracle **禁** `subprocess`/`os.system`/`Popen`；其绿灯**只是必要条件**，真实执行语义由 E2E 驱动承担（**覆盖 ≠ 语义**）。
- 执行载体的**旁路输出通道**（如 semihosting 控制台）须**显式**重定向到可比对的位置（`-chardev file,…` + `chardev=…`），禁依赖默认 stderr（与工具告警混淆、不可判定）。

### 2.5 管道退出码陷阱
- `cmd | tee log; echo $?` 取到的是**管道末端 `tee`** 的退出码（恒 0），而非被检命令的退出码。正解：`cmd > log 2>&1; rc=$?; … ; echo "EXIT=$rc"`，或 `${PIPESTATUS[0]}`，或 `set -o pipefail`。

### 2.6 合并反例注入互相抵消
- 一键证据脚本的 `MUST_FAIL` 清单须**逐例标注其对应的唯一注入**；凡一例受 **≥2 注入**影响，须核查是否存在「多注入抵消 → 假绿」路径：改用单一归因用例，或**分轮注入**（每轮只注入一处）。

### 2.7 二进制 sha 随源码 commit 变化
- 二进制内嵌源码 revision ⇒ **跨 commit/amend** 时**不得**以二进制 sha 相等作还原判据——应断言**源码 blob sha**，二进制等价以「**重建后探针回绿**」为证；同 commit / clean 态下二进制 sha 复原为**辅证**（记录基线前须先 normalize 重建对齐 clean commit）。

### 2.8 未重建组件的探针回归判据 = 逐字节一致 / 零新增失败
- 改**仅 MC/codegen**（不重建组件）时，探针产出结构性不变；回归判据取**与改前基线逐字节一致**（`diff -q`），即**零新增失败**。
- **不得**以探针 `rc=0` 为判据——legacy 探针在基线即 `rc=1`（pre-existing），以 `rc` 判定会误报「本任务引入回归」。

### 2.9 注入脚本须含 trap + 完整唯一替换串
- 注入脚本须对**异常退出**设 `EXIT`-trap，自动还原并**重建**（源码还原 ≠ 二进制还原）。
- 注入替换串必须是**完整、唯一可定位**的条件前缀（拼接后仍合法）。

### 2.10 注入 / 验证脆弱点的结构化拦截
- 脆弱点：**行号定位**（变动后失配）、**空注入**（模式未命中静默继续）、**手改污染**、**注入无鉴别力**（断言恒真）。
- 拦截范式：唯一定位（锚点命中计数 = 1）+ sha 断言（改前 / 改后 / 还原一致）+ 要求**被检命令非零退出** + `trap` 复原，**退出码即判决**（勿另造轮子）。

### 2.11 机械生成投影须在两个 drift 门控显式排除
- 机械生成投影入 `contract-*.md` 时，须**同步**加入**两个** drift 门控（`check_spec_drift`、`check_spec_refs`）的排除名单，否则以「无来源头 / 无 § 引用」误报。

### 2.12 路径类 grep / 遍历检查须排除 `__pycache__`
- 路径类 grep / 遍历检查须排除 `__pycache__`（`.pyc` 内嵌旧字符串 ⇒ `binary file matches` 噪声）。

### 2.13 只读清单门控范式：TOML 锁 + `--root` 临时树 + `if errors` fail-closed
- 三要素：① **TOML `[[…]]` 锁 + 复用既有 checker 体例**（manifest 驱动、`--verbose`、`--root` 覆盖、只读、非零退出）；② **`--root DIR`** 使「临时树注入」成为默认自测手段（不触碰真实仓库，还原用 `cp`+md5）；③ **fail-closed 判据用 `if errors:` 而非 `if mismatches:`**——锁**残缺**（缺 `sha256` / `format` / 条目为空）须计入 `errors` 并据以非零退出。
- 反例门控须覆盖「**锁残缺**」类（改册 / 删册 / 改锁值 / 缺 `format` / 空条目 / 缺 `sha256`），不能只测「被锁文件被改」。
- 门控类任务的「变更集」= tracked `git diff` ∪ untracked `git status`，并加 `git -c core.quotePath=false`（否则非 ASCII 路径被转义致集合比较假失败）。

### 2.14 证据脚本对「已提交变更」的断言须带提交范围（`BASE..HEAD`）
- 凡断言「某变更存在 / 某文件被改」的 git 调用，若被测产物**可能已被提交**，**必须带提交范围**：`git diff "$BASE_COMMIT"..HEAD -- <path>`；**禁裸 `git diff`**（比较工作树 vs HEAD，变更已入 HEAD ⇒ 空 ⇒ **假 FAIL**）。
- `BASE_COMMIT` 须可经**环境变量覆盖**（默认基线），以便 `BASE_COMMIT=HEAD` 重放验证该断言**确实可 FAIL**。
- 只有「检测工作树残留」才用 `git status --porcelain`；需在**提交后**仍抓越界则另加 `$BASE_COMMIT..HEAD` 越界断言。
- 证据脚本本身也是**交付物**：须经受「**提交后仍应回绿**」自检；reviewer 须**逐条核 git 调用是否带 range**；engineer 修一处缺陷须**全脚本同类排查**（`grep -nE '\bgit\s+(diff|status|log|show)\b'`）。
- **评审不得因「pre-commit 设计」放行**：凡断言依赖**未提交工作树**而提交后必红 / 必空，reviewer 须判 `Needs Revision`（要求改 `$BASE_COMMIT..HEAD`）。

### 2.15 迁移生成物落点须同一原子落地
- 迁移生成物落点 = **改落点 + 清旧忽略规则 + 同删残留旧产物目录**，三者**同一原子落地**；任务书「输出」须显式列旧目录为**删除目标**，并贴删除前后真实输出。判据：清掉忽略规则后 `git status -uall` 若暴露旧产物，即证必须同删。
- 迁移前须 `grep`/`ls` **实测**旧落点真实路径（可能已被上游任务改变），不以任务书 / 历史描述为准。
- 脚本比对 `git status` 路径须先 `git -c core.quotePath=false`（非 ASCII 路径默认加引号 + 八进制转义 ⇒ **假阳性 FAIL**）。
- 范围判定不得越界：删除目标**只列**任务书明确列出的目录；gitignored 树内其它历史残留**登记为遗留 / 另立任务**。

### 2.16 核「已 Accepted 决策未被静默改写」
- 判「受保护决策正文未被改写」用「`git show HEAD:<file>` × 工作树**按节前缀提取**后逐节 `diff -q` ⇒ `same`」，**不以 `git diff` hunk 为准**（hunk 边界脆弱：修订条目**引用**正文措辞会混淆）。
- 提取结果须做**非空校验**（每节行数 > 0），否则空提取 ⇒ 两侧都空 ⇒ **假 PASS**。
- 「某决策已标 `Superseded`」须核到**该节内**的 in-place 标记，不得以「修订条目里写了『已标』」为准。

### 2.17 门控收口
- 门控 / 证据脚本判「注入反例 ⇒ 应失败」**一律用非零判据**（`-ne 0`），**禁**硬编码 `== 1`——GNU make 对「任一 recipe 失败」以 **`2`** 结束。
- 门控若含「不回归」组成，优先把其载体列为**新门控的 make 前置**（由 make 机械保证）；recipe 内子步骤须**显式捕获 `rc` 并 `exit $$rc`**（`$$?` 紧接子命令，禁经管道）。
- 门控组成**复用其它模块已验收产物**可接受，须同时满足三条件：① 被复用物**已入库且经其原任务验收**；② 该组成**本即原任务的交付断言**；③ **不新增跨模块契约、不改 `spec/`/`components/`**。
- 门控「覆盖计数」类断言须**机器可判**（脚本 `--list`/摘要打 `distinct N`/`required N` + 全量跑断言集合差为空），禁目测抽样。

### 2.18 以寄存器号 / 符号名做 grep 机械扫描须大小写不敏感
- 用 grep 机械枚举 / 分类「某寄存器号或符号出现在哪些行」时须**大小写不敏感**（`grep -i`，或大小写各扫一遍再并集）——否则**仅大写**写法会漏网，致「改一类」不彻底、遗留陈旧口径。

### 2.19 判 `spec/` / 非 ASCII 路径交集须用 `core.quotepath=false`
- 用 `git diff --name-only | grep '<前缀>/'` 判路径交集时，若仓库含**非 ASCII 文件名**，默认 `core.quotepath=true` 会加引号 + 转义 ⇒ 假阴性；须改 `git -c core.quotepath=false diff --name-only`，或 `git diff -z --name-only`（NUL 分隔）解析后再判。

### 2.20 验证正则须自证「确有命中」
- 验收用匹配正则必须**自证对目标样本确有命中**（现场打印逐类命中计数，或断言计数 >0），**不得**仅凭「脚本未报错 / 全绿」判其有效（否则死断言 / 0 次执行仍全绿）；同排同类锚定须一并排查。

### 2.21 验证器须断言「结构」（成对 / 条数）
- 覆盖类验证器在「注记存在才断言」的写法下，**删注记即可静默收缩覆盖仍全绿**；不变量须绑到**必存在的锚**（如指令行）并断言**成对** + **逐文件条数相等**（使删任一注记即 FAIL）。

### 2.22 用「进程退出码」做跨后端值级通道
- ① **值通道只有低 8 位**（`ret i64 300 ⇒ 44`；`& 0xFF`），更宽值须另寻通道；② **信号致负 `returncode`**（如 `-11`）`&0xFF` 会把崩溃静默当值 ⇒ 取 rc 处须判 `rc<0 ⇒ 失败`。
- 宿主 `lli` 对变参模块会 **SIGSEGV** ⇒ 该类模块归 `host-unsupported` 排除并登记，非静默。

### 2.23 里程碑 E2E 须真实语料
- 里程碑 / 门控「编译 E2E」用**小到 `exit=42`** 的程序可全绿却掩盖**整类**未实现能力；「能编译真实 C」须以**真实语料（如 Embench）或覆盖语言惯用形态的大程序**做端到端，**不得**以 trivial 程序通过为由宣称具备编译能力。

### 2.24 真实语料 E2E 判据须含「运行期带超时的退出码」+ 优化级矩阵
- 「编译 + 链接 `rc=0`」**不足以**证明正确——编译器可能在**优化级**产生运行期错误代码（**静默错码**）；判据须含**运行期**（`timeout N`，`124` 判 **FAIL**，不得当「跑完」），且**逐优化级**（`-O0/-O1/-O2`）分别跑，区分「**编译期显式失败 = 缺能力**（可延后立任务）」与「**编译成功而运行错 = 缺陷**（**须优先**）」。

### 2.25 完成区计数须写明口径
- 任务书 / 完成区 / 文档里的计数必须**写明口径**（如「按标签数」而非「按行数」）；统计前先判「一行 = 一个条目？」——两种口径混用即失实。

### 2.26 测试断言须能区分被测属性
- 验证某属性时用例必须对该属性**敏感**——用**交换不变**的合并操作（如 `lo XOR hi`）算期望值会使「次序 / 半字序互换」类缺陷**数学上不可检**（全绿却验不到目标）；须构造**非交换**判别用例（如 `hi - lo`）并断言可区分。

### 2.27 bash 证据脚本 `local` 多赋值在 `set -u`
- `local o=$1 d=$WORK/aha-$o` 在 `set -u` 下会因 `o` 尚未生效报 `o: unbound variable`（退出脚本）；**拆成独立 `local` 赋值**。

### 2.28 反例注入还原须以「clean baseline」为锚
- 注入脚本的还原目标须是**注入前的干净基线**（备份须在确认 workspace clean 时生成，或脚本**先校验 / 断言 clean 态、否则拒绝运行**）；若以「运行时现场」为锚，则在**已注入态**重跑时还原会回到**已注入态**（`md5` 虽一致但基线已脏、检查仍红）。

### 2.29 新增 lit/IR 结构测试后必须实跑 L3 闭划分门控
- 按「目录扫描 + 闭划分（`include ∪ exclude` 须恰等于磁盘集）」维护的语料清单，其门控**只在 L3 跑**：新增 `*.ll` lit 结构测试**未同步登记**即静默 `unclassified` ⇒ **必须实跑 L3**（`test-m6`/`diff_ir_lli`）。
- **只靠 L1/L2 会漏**——二者不扫该语料目录，新增文件在 L1/L2 全绿时仍为 `unclassified`。

### 2.30 报告 / 验收中的定性陈述亦须逐条有实验依据
- 「计数 / 唯一 / 仅 / 全部」之外的**定性陈述**（某源是否被预处理掉、某符号是否发出、某路径是否可用）亦须**逐条**有本轮实测依据。
- **措辞的来源不构成依据**——含上游文档、既有台账、乃至**验收方自己给出的处方原话**；照抄即可能把错误定性带入报告，须**独立复现**后方可采用。

## §3 收尾与提交

### 3.1 收尾检查
- 收尾（在知识沉淀**之前**）须过四项，任一不过即**停下报告**：① 门控按改动类型**全绿**（门控范围类改跑 `make check`，纯文档 / 台账跑 `check-no-residue`）；② 仓库**无临时残留**（`git status --untracked-files=all` 干净，禁 `*_tmp*`/`_gate*`/`*.orig`/`*.rej`）；③ 证据留**非易失位置**；④ **无未提交**的任务结果。

### 3.2 还原方式禁用清单
- **禁用** `git checkout` / `git restore` / `git stash` **及 `git show <commit>:<path> > <path>`** 还原注入或临时改动——它们把文件**覆盖为「提交中的版本」**，在**工作树有未提交改动**时**静默丢弃**。
- 还原一律 **`cp` 备份 + `md5` 对账**，或**优先在临时树**（`/tmp/opencode/<任务ID>/`）注入；**`git status`/`git diff` 干净不作「已还原」证据**；「还原须含重建」（源码还原 ≠ 二进制还原）。

### 3.3 子代理的用户裁定须原样落盘
- 子代理**取得用户裁定后，须把用户原话（或问答摘要）原样写入任务书**（完成区 / 审阅记录）——**子会话问答对父会话不可见**。
- 主会话**不得**仅因「父会话无记录」就否定子代理报告的用户裁定、反复回问同一问题（除非有**相反证据**）；涉及用户裁定的结论须可追溯到**具体原话**。

### 3.4 「失败」不再即停
- **「失败」不再是停止条件**——失败须**保留现场**（命令 / 完整输出 / 退出码 / 日志路径），**但继续推进**：自行处置（当场派修 / 绕行 / **按需重试并记录次数** / 登记后跳过）；**只在需要用户语义裁定（新决策 / 需授权）时才留问**。
- **重试须有据、须记录次数、须保留现场，不得以重试掩盖根因**；失败与处置须写入任务书 / `.work/log/` / `issues.yaml`。

### 3.5 子代理异常返回：重试 1 次后拆分
- `task` 异常返回（`Task cancelled` / 空结果）先核对完成区与 `git status`：已落盘 ⇒ 视为完成；**确未落盘 ⇒ 重试同一任务一次**（附失败现场）。
- **第 1 次重试后仍异常 / 未落盘** ⇒ **立即停止重试**（**不耗满 3 次、不盲目再重试**），**与用户商定把该任务拆分为多个小任务**（缩小单次下发粒度、要求分段落盘）。
- 每次异常与重试须登记（task_id、异常类型 / 次数、重试结果、**任务拆分决议**）。

### 3.6 子代理异常返回须逐项扫描残留
- 子代理异常返回但产出**部分落盘**时，门控绿灯**不覆盖正文**——须**逐项扫描残留**（**不能只看「文件已改」**）；主会话核对 `git status`/`grep` 后按 §3.5 处置。

### 3.7 验证命令产物不得落入仓库测试目录
- 证据 / 验证命令一律在 `.work/<任务ID>/` 或 `/tmp/opencode/<任务ID>/` 下运行，产物**勿落仓库源 / 测试目录**；收尾须核 `git status --untracked-files=all` 干净。

### 3.8 同一工作树内禁止并发会切分支 / 写工作树的子代理
- 同一工作树内**禁止并发**会切分支 / 写工作树的子代理（共享 `HEAD` / 索引 / 工作树 ⇒ 互相污染）；需并行就各自开独立 `git worktree` 或**串行**；同一工作树只允许**只读**并发。

### 3.9 任务开工分支必须从最新 `master` 拉
- 建分支前先对齐 `master`（`git fetch` 后 `git switch -c <任务号> master`）；**不**从过期提交切分支（否则已落地的配置 / 规则改动被从工作树撤掉）。

### 3.10 长构建须脱离 opencode 工作区生命周期
- 长构建 / 夜跑须 `setsid nohup …` **脱离工作区服务**（opencode 按活跃度回收 location ⇒ 会杀未脱离子进程）；**禁**「会话内后台等待器」当唤醒机制（随工作区被回收）——改为**落盘完成标记 + 定时巡检**。日志须含**独立完成标记**（`XXX_EXIT=$rc`），**禁**以「无 `FAILED`」推断成功。

### 3.11 复合命令禁用 `cmd | tail`/`| tee` 接 `&&` 串联
- 复合 shell 命令**禁**以 `cmd | tail`（或 `| tee`）**结尾再 `&&` 串联**后续——管道后 `$?` 是末端 `tail`/`tee`（恒 0），**失败仍继续**；须用 `; rc=$?`（或 `${PIPESTATUS[0]}`/`set -o pipefail`）**显式判 rc**。

### 3.12 子代理结束判定以完成通知为准
- 判定子代理是否已结束，**以完成通知为准**；无通知时须核对至**无并发写者**（文件 mtime 稳定 / 无相关进程）——「无构建进程 + `状态=待验收`」会误判。

### 3.13 `push` 独立执行；squash/rebase 的 base
- **`git push` 必须独立执行**，前置步骤（rebase / squash / 校验）**失败即止**——不得用 `;`（或 `&&` 之外的无条件串接）让失败后仍 push；**先判 `rc` 再 push**。
- `git rebase -i <base>` 的 `<base>` 必须是**目标提交的父**（base 取成目标提交本身会得「`fixup` 没有前驱」）。

### 3.14 每任务一分支
- 每任务**开工前建分支**（名 = 任务号前缀）；该任务 **WIP / 返工 / reviewer 修改**一律提交在**该分支**，**完全确定后一次性落地 `master`**（`git merge --squash <branch> && git commit`，或 FF）并**删除该分支** ⇒ `master` 只接受「一次性落地」、**永不改写已推送历史**；`push` 仍由主会话 `/complete` 后执行（FF、无需 force）。**不追溯**既有历史。

### 3.15 历史改写的锚点用 `.work/log/` 记 SHA
- 改写历史前需留锚点时，**记 SHA 到 `.work/log/`**（+ `git reflog` 兜底），**不建 `backup/*` 锚点分支**（分支制落地后该需求消失）。

### 3.16 被引用的材料一律不得只放 `.work/`
- **凡被引用的材料（文档 / 证据 / 结论），一律不得只放 `.work/`**——`.work/` 被整体 gitignore、只在本机存在 ⇒ 引用会**悬空**、不可复现。被引用的 `.work/` 材料须**升格**到 `.tao/knowledge/`（或结论摘要 + 指针），由 `check-knowledge-refs` 机械保证（悬空即红）。

### 3.17 判定「用户裁定是否真实」唯一依据 = 向用户求证
- 判定「用户裁定是否真实」**唯一可靠依据 = 向用户求证**；**禁**以「父会话上下文无记录」为据定性 / 否定（子会话问答对父会话**不可见** = 已知局限，见 §3.3）。
- **实例**：2026-10-12 `LLVM-082t`，主会话据此误判真实裁定为编造。

### 3.18 越界 ask 来自 `external_directory`；判 deny 是否生效只能靠用户观察
- 越界 `cd`（绝对 / `~` / `..`）的 ask 来自 **`external_directory` 动作**（**非 `shell`**）、且**先于** `shell` 检查 ⇒ fail-fast 只能写该动作 deny（`shell` deny 无效）。
- `permission.rejected` 的 `message` **不能**区分真 `deny` 与 `ask` + 人工 reject（人工 reject 同样返回 `message="Permission denied: external_directory"`）⇒ **判「deny 是否生效」唯一可靠依据 = 用户观察是否弹询问**；**子代理无该视角、不得就此下结论**。
- 改项目/agent 级配置后 `POST /api/location/reload` 通常令其生效（**本任务实测未见效，待复验**）；**全局配置文件改动不在重载范围 ⇒ 需重启服务**。
- `experimental.policies` 在 v2.0.22 **不被 schema 接受**（`Experimental.Policy.action` 枚举仅 `provider.use`）⇒ **不要用它做 deny**。
- **单向判据（2026-10-13 补）**：`message` **含人工输入文本**（如用户 reject 时点评「是我点的」）⇒ **必为 `ask` + 人工介入** ✓；但**系统固定文案不可反推**（人工 reject 与规则 `deny` 可产同一 `message`）⇒ **判 `deny` 是否生效仍须用户观察**（重启后复验口径：越界 `cd /mnt/tao` **不弹询问、无人工即 reject = 生效**；`cd ~` **仍 ask = 已知局限**，靠 `AGENTS.md` 禁 `cd ~*` 规则层兜底）。

### 3.19 `.cache/` 放裸仓库 + 下载原件；组件源 / 构建树归 `.work/`
- **目录分工**：`.cache/` 放**裸仓库**（+ `refs/` 只读工作树）与**下载原件（tarball / 签名）**；**源码检出**、**构建产物 / 环境**分放 `.work/source`、`.work/build`。
- 构建树 / conda 环境放错位置会与「**可幂等重建**」的清理契约冲突（清 `.cache/` 时连构建成果一并删），且大体积产物污染持久对象库。
- **源码检出直接以组件名落地**（`.work/source/<name>/`），**不再套同名 / 分类包装层**。**反例**：为「整齐」多套一层目录（如 `source/<分类>/<name>/`）⇒ 按 `source/<name>` 定位的门控与脚本全部失配，且易被误当「未解包」重做；同一物**只存一份**（下载原件归 `.cache/`，组件源归 `.work/source`）。
- **组件源一律 git 基线**：`.cache/<name>.git` 裸仓库 + `.work/source/<name>/` = **可 `git diff` 的干净检出** ⇒ 任何改动随时可产 patch/diff。**tarball 只作校验物 / 下载原件，不得作组件源**——解包树无 git 元数据，改动**产不出 diff**（要产 patch 时才发现，返工代价高）。`patchless`（无 v5 补丁集）与「源码形态」**正交**：tarball 源同样必须落 `.work/source/<name>/`，只是仍需可 diff。

### 3.20 切分支 / 提交前须核当前分支与工作树
- 任何 `git switch` / `commit` **之前**必须核 `git branch --show-current` + `git status --porcelain -uall`；**脏树 / 共享工作树上禁 `switch -c`**——否则 `switch` 把未提交改动一并带过去、提交**误落兄弟分支**（实例：并发子代理共用同一工作树，**提交误落兄弟分支**）。
- 大任务优先**独立 `git worktree`**，从源头消除共享工作树的串扰（同 §3.8）。

### 3.21 跨分支并行取号须在合并侧复核唯一性
- **跨分支并行时全局编号（issue / 任务号）会撞号**——各分支各自 `max+1` 只保证**分支内**递增，不保证**全仓**唯一 ⇒ 取号须在**合并侧复核**或**串行取号**；**merge 前须核对全仓编号唯一性**。

## §4 里程碑与归档

### 4.1 历史快照旧路径保留、不回溯更新
- 归档 / 历史快照（旧路径、`changelog` 历史行、已验收任务书、`.tao/archive/**`）中的旧路径 / 旧计数**保留、不回溯更新**（by design）；如需全仓一致另行裁定。

### 4.2 归档 `git mv`（含自归档）的 rename 检测
- 归档移动一律 `git mv`（保**路径变更**记录）；rename **检测**（`R` 渲染）是 `git diff`/`git log` 时按阈值即算，**不是提交时固化**的。
- 含**自归档**（或移动后内容继续大幅增长）的归档：相似度**逐段下降** ⇒ 验收 / 交叉复核的 rename 计数**必须在记录齐全的最终态重算**并**注明所用阈值**；报告须说明默认阈值下呈 **`A`+`D`** 属**内容体量的技术性结果、非移动错误**；**不得**以 interim 提交（如 `WIP`）的 rename 计数冒充最终态。

### 4.3 归档 `§4.4`（closed 计数）判据值随流程步骤动态变化
- 「`resolved_by` 提交日 ≤ 达成日的 `closed` 项」的**合格计数 = 任务书「实测基线」+ 本轮边界拆分新增的条目**；任务书预期值只是**执行前**快照。
- 归档产物与完成区**须注记差值来源**；复核者遇「实测 > 预期」**先查是否新增条目**，**禁**仅凭数字不等即判偏差。

### 4.4 成就 / 清单类条目条数 = 「独立成果数」
- 列举成就 / 成果 / 清单时，**条数 = 独立成果个数**（「某类测试全绿 / 某门控绿 / 某文件改造」属**证据**，归入对应成果、**不单开一条**）；**区间（如「3–7」）是上界不是配额**，**宁少勿多**——按上限填满即**膨胀病**。

### 4.5 立项须做「规划中 / 推迟项 → 任务表」的机械收口核对
- 里程碑立项（`k`）后，须把 `milestones.md`「规划中」与「M* 遗留」中所有标「推迟到本里程碑 / 跨里程碑」的条目**逐条**对照任务分解表（条目 → 覆盖任务号 / 未覆盖），产出**对照表**落该 `k`；**未覆盖**：小者**并入**最相关任务书、大者**补任务**，候选 / 有据推迟者标「**保持登记**」。细节不丢弃、但要「**归批**」。

### 4.6 「不得置里程碑」只针对未处置的跨模块影响
- 里程碑纪律「存在未处置项 ⇒ 不得置里程碑」**仅针对未处置的*跨模块*影响**；**本模块内的 open backlog**（规范完备性 / 覆盖缺口等待裁定项）**不构成阻断**——误将模块内 backlog 列为跨模块影响会导致误阻断（实例：模块内「规范是否补记防御分支」待裁定项曾被误当跨模块影响而阻断该模块里程碑 + 项目里程碑；其实现行为安全、本批 0 例暴露）。
