# lessons — 已关闭 issue 里可复用的教训（只记「下次怎么做」，不复述过程）

> 本文件是 `ISS-*` 关闭项的经验沉淀（用户 2026-11-25 裁定：事故/流程类 issue 写一句话进知识库后关闭，不再当待办跟踪）。
> 每条给「原 issue → 一句话结论」。过程细节留在 `.tao/archive/M*/issues-closed.md` 与任务书。

- `ISS-377`（收尾未做「修改文件 ↔ git 对账」导致交付丢失）→ 收尾必须脚本化比对「完成区清单 vs `git status -uall`」的**文件集合**（不只数量），并抽查内容。
- `ISS-393`（把「仍在跑」写成「全部跑完」）→ 判「跑完」只看 `*_EXIT`/进程不存在 + 计数闭环，不看日志尾部像不像结束。
- `ISS-395`（改变差分参照的任务与使用该参照验收的任务并行）→ 「参照物」的变更与「用参照验收」的任务**必须串行**；并发前先看谁在改参照。
- `ISS-445`（子代理 `Task cancelled`）→ 取消后先核盘上事实（工作树/任务书/`.EXIT`），按「保留现场 + 续派」处理，不重来。
- `ISS-458`（证据脚本基线取 `HEAD`，提交后变自比假绿）→ 基线必须取**分叉点**（`head..HEAD` 或固定 commit），禁取「当前 HEAD」。
- `ISS-466`/`ISS-478`（provider 报错/阻断）→ 同 session 重试 3 次仍失败即停，核盘上无残留后换会话；不得以「重试」掩盖 provider 侧问题。
- `ISS-483`（固定基线三坑）→ 新 clone 无 `master` 时不得静默回退 `HEAD~1`；基线不可得就**显式 SKIP 并打印原因**。
- `ISS-442`（`sweep_expect.bin` 的 md5 已非任何门控判据）→ 退役门控的产物 md5 不应再出现在判据/文档里；清理时连引用一起删。
- `ISS-446`（引用已关闭的 `ISS-193`）→ 关闭 issue 时全仓 grep 其 id，把仍引用它的文档/报告一并改指。
- `ISS-411`（`st.o rb0` 未造例）→ 属**已知限制**（期望值随链接布局变化），不是缺口；写进载体的限制段即可，不必造例。
