# m12-chipyard-006: 多周期状态机设计分析（推荐方案，待用户裁定）

**模块**：chipyard
**项目里程碑**：M12
**依赖**：`m12-chipyard-005`（整数核第一步已落地）
**可并行分片**：否（设计分析，单写者）
**状态**：已验证

## 用户裁定（原话）

「ldm/stm，要做。多周期的状态机设计，应该提前进行；应该通过分析各条指令的实际运行情况，给出一个推荐方案，我来裁定；内部运算的逻辑，可以1到2个周期完成，ld/st类的，都需要存储接口的交互，这部分原本就应该多周期」（2026-11-09）

**补充澄清（同日）**：「1–2 周期」是**举例**，3、5 周期也都可以——**周期数怎么合适怎么来**，不要被「单周期核」的名字绑住。

## 用户裁定（2026-11-09，同日补充）

- **Tiny 上 hmon**：Tiny 实现 `cfx_power`（cfx63）+ `cfx3 hmon`；hmon SRAM 复用 `0x0fff_0000_0000`（64 KiB）；**无 PTW/页表**。
- **同步异常不经 `trap` 指令**，直接进 hmon 向量；与 semihosting 的 `trap` **无冲突**。
- **三平台 Tiny 的 semihosting `trap` 统一写 `trap cfx_hmon`**（实现上仍只看 `immu18`，不判断 cfxha）。
- `trap` 判定：`immu18 ∈ 0x3FF00–0x3FFFF` ⇒ semihosting；`cfxha=3`（hmon）+ 其它 `immu18` ⇒ 进 hmon。

## 目标

**只做分析与推荐，不实现**。产出「每类指令的周期划分 + 状态机结构」的方案，供用户裁定。

**必须包含 Tiny 的 hmon/power**：
- `cfx_power`（cfx63）启动移交 → hmon（cfx3）
- 同步异常（ILLI/UNDI/`CFXMEM`/`MALIGN`/`IALIGN`）进 hmon 向量的状态与时机
- semihosting `trap`（`immu18 0x3FF00+op`）与 `trap cfx3` 的区分，以及它们在状态机中的路径
- IALIGN 时 **IP 停留在非法地址**（`DADAO-12 §5`）：触发指令的正常写回（如 `call` 的 RA 压栈）照常完成，但 `ip` 不推进到「非法地址之后的合法地址」；`causeIp` 取非法地址本身

1. **逐类分析**（按执行特性，不是按指令册）：
   - 纯寄存器运算（算术/逻辑/移位/比较/位操作）：**周期数由分析决定**（用户 2026-11-09：1–2 是举例，3、5 周期也都可以，「怎么合适怎么来」）；权衡可仿真性、面积、时序
   - 内部多周期运算：乘法、除法、`clmul`、FP 除法/开方（迭代）
   - 访存：`ld`/`st` 各宽度（**存储接口交互，天然多周期**）；对齐/越界检查放在哪个状态
   - 多寄存器：**`ldm`/`stm`**（N 个寄存器，逐拍还是突发）
   - 控制流：条件分支、`jump`、`call`/`ret`（返回地址计算与 RAS 交互）
   - 原子：`lr`/`sc`（总线交互 + 保留标记）
   - semihosting `trap`：等宿主应答（变长）
2. **推荐方案**：
   - 状态机划分（取指 / 译码 / 执行 / 访存 / 写回 / 特殊），每状态的职责
   - 每类指令的**周期数**（含最坏情况）与状态转移
   - **存储接口握手**：与 TL 的 `valid/ready` 交互、请求挂起与重试
   - `ldm`/`stm` 的实现方式（逐寄存器 vs 突发）与中断/异常点的处理
   - 与现有 `WumingCore` 状态机（005 已实现取指/执行）的衔接：改哪些、保留哪些
3. **备选方案 + 取舍**：至少给 2 个方案（如「统一多周期状态机」vs「快路径 1 周期 + 慢路径状态机」），列优缺点。
