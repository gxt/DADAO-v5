# m18-qemu-010: QEMU 异步进入的模式上限（`cg15 rc14`）

**模块**：qemu
**项目里程碑**：M18
**依赖**：`m18-spec-009`（模式上限）
**可并行分片**：否
**预估**：1–2 h
**档位**：小改
**状态**：已验证

## 目标

`dadao_async_allowed()` 增加 `env->inner_run_mode <= a->switch_run_mode`（`cg15 rc14`）；不满足 ⇒ 不进入、pending 保留。默认 rc14=2 ⇒ hypv 不被异步打断；rc14=3 时可打断 hypv。

## 验收

探针：supv 下 hypv 场景（rc14=2）不进入；rc14=3 时进入并可用 `escape cfx_hart` 返回；两路注入（删上限、改成 `<`）可红；`check-patch-tree` qemu 0、forms/changelog/knowledge rc=0；`cp`+md5。

## 完成区

**测试结果**：证据脚本 20/20 通过（`build-qemu` rc=0；探针 19 例 / 157 断言 rc=0；`--self-test` 19 例全断言可达 FAIL；门控 5 项 rc=0；注入①删上限 ⇒ 探针 rc=1（`async_mode_cap_hypv_block_supv_enter` 红）、`cp`+md5 `a1cbda6d…` 还原重建回绿；注入②`>`→`>=` ⇒ 6 例红（`async_pending_survives`/`async_mask_gate`/`multi_source`/`source_mask_gate` + 两例 cap）、还原重建回绿）。
**修改文件**：`components/qemu/patches/target/dadao/helper.c.patch`（`make_patch.py qemu` 重导，1 写 68 略）、`components/qemu/changelog.md`、`tools/testcases/arch/min_rom_probe_m18qemu009.py`、`tools/testcases/arch/README.md`、`tests/arch/vast-arch-inventory.md`、本任务书。
**验收结果**：`dadao_async_allowed()` 在 `!a` 之后加 `inner_run_mode > a->switch_run_mode ⇒ return 0`（`cg15 rc14`，复位 2）；不进入时源 pending/`cg15 rc5` 保留、无异常。探针新例：hypv/rc14=2 下 TIMER pending 保留（`excp_async_num=0`、`cg16 rc17=1`、`rc5=1<<15`），`escape` 到 supv 后同一边界进入（`rc0=supv`、`rc1=smon`、`rc4=1<<15`、handler ack、`escape cfx_hart` 回 supv/smon）；rc14=3 时 hypv 进入（`rc0=hypv`）并返回 hypv/hmon。`check-patch-tree` 全仓 rc=0（qemu 69 patches）、`check-qemu-forms`/`check-component-changelog`/`check-knowledge-refs`/`check-tests-index` 各 rc=0。
**新发现/坑**：上限不满足时若强行进入且目标模式为 supv（rc14=2），`escape` 返回 hypv 会触发升权 `CFXESC`——这正是“默认不打断 hypv”的原因；探针观测须在离开 hypv 前完成，supv 下访问非自身 cfx 会被 `cfxreg` 行拒绝，故 handler 观测写 GPR、`escape` 后用已知块（`OFF_AFTER`）退出。源码树 `.work/source/qemu` 为 gitignored 独立仓库，注入落地校验用 `git -C .work/source/qemu diff` 而非主仓 `git diff`。
**遗留问题**：无。`m18qemu008` 的 `case_async_escalation` 仍按“rc14=2 从 hypv 进入”构造，本任务后语义过期，但其载体已在 `m18-testcases-005` 的 KNOWN-RED 清单（旧槽位迁移），未改它。
