# m13-qemu-013: 单精写入宽度（`ld.t`/`ldm.t` 不扩展 + ft 结果只写低 32 位）

**模块**：qemu
**项目里程碑**：M13
**依赖**：无（spec 已裁定：`SimRISC-01 §4` 注 + `SimRISC-07` 单精写宽 + `contract-fp §1`）
**可并行分片**：否（qemu 组件单写者）
**预估**：2–3 h
**状态**：待开始

## 背景（用户 2026-11-14 裁定）

1. **`ld.t`/`ldm.t` 只写低 32 位，高 32 位保持原值**（不符号扩展、不零填）；
2. 写 `rf0` 时低 32 位里只有 `[4:0]` 可写 ⇒ `[33:32]`/`[31:22]`/`[21:5]` 全部保持原值；
3. **凡以 ft 寄存器为目的的指令只写低 32 位**（含 `ft2ft`）；`fo2fo` 与跨组复制 `rd2rf`/`rf2rd` 按 64 位二进制搬移。

QEMU 现状（实测）：`trans_fp.c.inc` 的 `ld.t` 用 `MO_BESL`（**符号扩展**）→ `store_rf()` 对 `rf≠0` 写整个 64 位 ⇒ `ld.t rf0 ← 0xFFFF_FFFF` 得 `0x7FF8_0003_7FC0_001F`。按裁定应为 `0x7FF8_0000_7FC0_001F`。

## 目标

1. `ld.t`/`ldm.t` 改为**无符号扩展的 32 位装载**（`MO_UL`/等价），并且只写 `rf[idx][31:0]`。
2. 其余产生 ft 结果的指令同样只写低 32 位；逐条列出受影响的指令族与改动。
3. **`ft2ft` 也按本裁定改**：只搬低 32 位、目的高 32 位保持原值。`fo2fo`、跨组复制 `rd2rf`/`rf2rd`、`ld.o`/`ldm.o`/`st.*` 的 64 位通路行为不变。

## 验收

1. 三平台探针（节点 `server207`，同一 ELF）：
   - `ld.t rf0 ← 0xFFFF_FFFF` ⇒ `0x7FF8_0000_7FC0_001F`；
   - `ld.t rf5 ← 0xFFFF_FFFF` 后 `rf2rd` 读回：高 32 位 == 写前值；
   - `ld.t ← 0x7FFF_FFFF`、`ld.t ← 0`、`ldm.t {rf0:rf1}`；
   - `ftadd` 产 ft 结果后 `rf2rd` 高半保持；
   - `ft2ft` 只搬低 32 位、目的高 32 位保持写前值（反向对照：`fo2fo`/`rd2rf`/`rf2rd` 仍 64 位不变）。
2. 回归：`01-load-store`、`05-arith-addr`、`06-control-flow`、`07-floating-point` 四册三平台全绿。
3. 门控：`check-inst` 红集不变（除既有 `divrem.yaml[23]`）、`check_qemu_trans 264/264`、`check_patch_tree` qemu 段 0 问题、`--source-state` qemu OK、`check-component-changelog` rc=0、安装根==构建树（**串行窗口内测**，先确认无其它写者）。
