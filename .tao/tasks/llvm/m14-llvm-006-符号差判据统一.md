# m14-llvm-006: 符号差判据统一（分支/地址操作数）+ 放行 `.set` 绝对值符号（`ISS-430` 同域）

**模块**：llvm
**项目里程碑**：M14
**依赖**：`m14-llvm-005`（已合入：`parseImmediate` 的符号差诊断 + ABS48 wyde 写回）
**可并行分片**：否（单一组件补丁集 + 单一构建树/安装根）
**预估**：3–5 h（增量 `build-mc` ≈10–20 min、必要时 `install-host`，启动前申报）
**状态**：已验证

## 背景（两处实测缺口）

1. **分支/地址操作数未覆盖**（`m14-llvm-005` 复核确认）：`jump [rb1, L1 - _start]`、`br.z rb1, [rb0, L1 - _start]` 仍 **rc=0**，并发出 `R_DADAO_REL26` / `R_DADAO_REL20` **绑定到符号 0（空/未定义）**、addend 为差值。这是比「静默 0」更隐蔽的错值：链接期会落到错误地址。
   - 对应代码路径：`DADAOAsmParser::parseAddressExpr` / `parseBranchAddress`（与 `parseImmediate` 三条独立）。
2. **`.set` 绝对值符号被误拒**（`ISS-430`）：`.set VD, L1-L0` 后 `set.zw rbX, wpN, VD` 由「静默 0」变为**报错**；`VD` 此时已是 Absolute 符号、可编码。

## 目标

1. 统一判据：**汇编期不可解析的符号差**在 `parseImmediate` / `parseAddressExpr` / `parseBranchAddress` **三处**都不得静默通过（报错或生成正确重定位），诊断文案一致。
2. **不得破坏既有可用行为**：`ld.o [rb2, L1-L0]`（同段可解析差 ⇒ 编码 `22 10 20 04`）必须保持可用且逐字节不变。
3. **放行 `.set` 后的绝对值符号**：`.set VD, L1-L0` + 以 `VD` 作立即数 ⇒ rc=0 且编码为 4；`VD` 在不可解析时仍须报错。
4. 文案不得把单符号操作数称作 symbol difference。

## 验收

1. 三条反例（`jump [rb1, L1-_start]`、`br.z rb1, [rb0, L1-_start]`、不可解析的 `.set`）：改后 **rc≠0** 或**正确重定位**（二选一，写清理由），并贴 stderr；若选重定位，必须证明链接后地址正确（不必真跑，可用 `llvm-readobj -r` + 手算）。
2. 不回归：`ld.o [rb2, L1-L0]`、`br.*` 的数值偏移、`ENTRY + 常量`、裸符号、`%pcrel_hi/lo` 五类对象 md5 与改前**逐字节相同**（去 `.comment` 口径）+ 反汇编 md5 相同；`tests/inst/**/*.S` 全量对象 md5 **116/116 不变**（现场统计）。
3. `.set` 绝对值符号：`rc=0` 且编码 4（贴 `llvm-mc -show-encoding`）；不可解析版本仍报错。
4. lit 新增覆盖上述两边（报错/放行/不回归），`make check-lit` rc=0（计数现场统计）。
5. 门控：`check-isa-coverage`、`check-component-changelog`、`check_patch_tree` llvm 段 0 问题、`--source-state` llvm OK、`check_install_tools --sha-tools clang,llc,llvm-mc`、安装根 == 构建树。
6. ≥2 路注入可达 FAIL + `cp`+md5 还原。
7. 完成区 ≤30 行、无运行期路径；「修改文件」与 `git status -uall` 对账。

**验收结果**：
1. 判据选择 = **报错**：ELF 重定位只能携带「一个符号 + 常量 addend」，`A - B` 在链接期不可还原；同段差在 fixup 求值时被折成常量后，PC 相对形态已丢失目标地址符号（就地解析会跳错地址，链接期只能落到符号 0）。三处（`parseImmediate`/`parseAddressExpr`/`parseBranchAddress`）统一在 `DADAOAsmBackend::evaluateFixup`（唯一有 layout、能判断差是否已折的层）判定；解析期无 layout 不做误判。
2. 反例实测（改后 rc=1 + stderr）：`jump [rb1, L1 - _start]`、`br.z rb1, [rb0, L1 - _start]` → `cannot use a symbol difference ('A - B') as a branch/jump target: there is no relocation form for it; use a single symbol or an absolute constant`。跨段差另覆盖 `ld.o`（rb0 ⇒ PC 相对地址偏移、rb2 ⇒ 基址相对位移）与 `.set VD, L1 - other`（点名 `'VD' (its value is a symbol difference …)`）。改前：前两条 rc=0 且 `R_DADAO_REL26/REL20` 绑到符号 0、addend=差值。
3. `.set` 放行：`.set VD, L1-L0` + `set.zw rb9, wp0, VD` rc=0，对象编码 `4e 24 00 04`（=4；手算 `0x4e|ha(rb9)=0x24|wp0<<16|0x0004` 相符）；`ld.o rb5, [rb2, VD2]` = `22 14 20 04`；两者均无重定位；不可解析版本 rc=1。
4. 不回归：`ld.o rb4, [rb2, L1-L0]` = `22 10 20 04`；五类（同段差位移 / 数值分支偏移 / `ENTRY + 常量` / 裸符号 / `%pcrel_hi,lo`）对象与反汇编 `cmp` 逐字节同改前；116/116 对象+反汇编 md5 全同（llvm-mc 对象无 `.comment`，md5 即「去 .comment」口径）。
5. lit：新增 err 覆盖 6 场景（jump/br 同段差、REL12 同段差、跨段 jump、跨段 ABS12、等值符号）、ok 覆盖 5 编码 + `REL-NOT: R_DADAO`；85/85 通过（83 旧 + 2 新）。
6. 门控：`check-isa-coverage`、`check-component-changelog`、`check_lit_bytes`（259 patterns）、`validate_mc_vectors` rc=0；`check_patch_tree` llvm 段 0 问题；`--source-state` `llvm-project: OK`（base+1、clean）；`check_install_tools --sha-tools clang,llc,llvm-mc` rc=0；安装根 == 构建树（llvm-mc md5 `c111b5b5…`）。
7. 注入：A 关掉 fixup 层判据 ⇒ 跨段/同段 PC-rel 诊断 5→0、rc 1→0；B 恢复「单符号差也拒绝」⇒ `.set` 编码用例 rc 0→1；均 `cp`+md5 还原 + 重建回绿，末态 llvm-mc md5 == 注入前。
8. 完成区 19 行（≤30）、无运行期路径；`-show-encoding` 在 `.set VD` 上只打印 `[0x4e,0x24,A,A]`+fixup 记录（asm streamer 无 assembler/layout、符号无 fragment），故「编码 4」证据取对象反汇编（见 3）。

**新发现/坑**：① 同段 PC-rel 差根因在 `MCAssembler::evaluateFixup`：差先折成绝对常量（`AddSym=null`）→ DADAO hook 返回 `nullopt` → `IsResolved=false` ⇒ 发出符号 0 重定位；判据必须放在 hook 里区分「已折常量」与「单符号」。② `.set` 的等值差在解析期不可求值（MCExpr 折同段差依赖 `MCAssembler`），只能放行到 fixup 层；`-show-encoding` 因此无法显示折后值。③ `hasFinalLayout()` 门必要：只有写对象那一轮 layout 定型，靠 `.p2align` 才能算出的差仍能折（现场 rc=0、ABS12=8）。

**遗留问题**：① `.dd`/`.quad` 数据指令的跨段符号差不在本任务范围（任务书限三处指令算子），仍走既有 `maybeAddReloc`。② `check-temp-dirs` 报 4 个他任务空目录（INFRA-102t/106t/LLVM-130t/TESTCASES-085t，0 B），非本任务产物，未代删。
