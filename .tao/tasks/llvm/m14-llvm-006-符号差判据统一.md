# m14-llvm-006: 符号差判据统一（分支/地址操作数）+ 放行 `.set` 绝对值符号（`ISS-430` 同域）

**模块**：llvm
**项目里程碑**：M14
**依赖**：`m14-llvm-005`（已合入：`parseImmediate` 的符号差诊断 + ABS48 wyde 写回）
**可并行分片**：否（单一组件补丁集 + 单一构建树/安装根）
**预估**：3–5 h（增量 `build-mc` ≈10–20 min、必要时 `install-host`，启动前申报）
**状态**：待开始

## 背景（两处实测缺口）

1. **分支/地址操作数未覆盖**（`m14-llvm-005` 复核确认）：`jump [rb1, L1 - _start]`、`br.z rb1, [rb0, L1 - _start]` 仍 **rc=0**，并发出 `R_DADAO_REL26` / `R_DADAO_REL20` **绑定到符号 0（空/未定义）**、addend 为差值。这是比「静默 0」更隐蔽的错值：链接期会落到错误地址。
   - 对应代码路径：`DADAOAsmParser::parseAddressExpr` / `parseBranchAddress`（与 `parseImmediate` 三条独立）。
2. **`.set` 绝对值符号被误拒**（`ISS-430`）：`.set VD, L1-L0` 后 `set.zw rbX, wpN, VD` 由「静默 0」变为**报错**；`VD` 此时已是 Absolute 符号、可编码。

## 目标

1. 统一判据：**汇编期不可解析的符号差**在 `parseImmediate` / `parseAddressExpr` / `parseBranchAddress` **三处**都不得静默通过（报错或生成正确重定位），诊断文案一致。
2. **不得破坏既有可用行为**：`ld.o [rb2, L1-L0]`（同段可解析差 ⇒ 编码 `22 10 20 04`）必须保持可用且逐字节不变。
3. **放行 `.set` 后的绝对值符号**：`.set VD, L1-L0` + 以 `VD` 作立即数 ⇒ rc=0 且编码为 4；`VD` 在不可解析时仍须报错。
4. 文案不得把单符号操作数称作 symbol difference。

## 验收

1. 三条反例（`jump [rb1, L1-_start]`、`br.z rb1, [rb0, L1-_start]`、不可解析的 `.set`）：改后 **rc≠0** 或**正确重定位**（二选一，写清理由），并贴 stderr；若选重定位，必须证明链接后地址正确（不必真跑，可用 `llvm-readobj -r` + 手算）。
2. 不回归：`ld.o [rb2, L1-L0]`、`br.*` 的数值偏移、`ENTRY + 常量`、裸符号、`%pcrel_hi/lo` 五类对象 md5 与改前**逐字节相同**（去 `.comment` 口径）+ 反汇编 md5 相同；`tests/inst/**/*.S` 全量对象 md5 **116/116 不变**（现场统计）。
3. `.set` 绝对值符号：`rc=0` 且编码 4（贴 `llvm-mc -show-encoding`）；不可解析版本仍报错。
4. lit 新增覆盖上述两边（报错/放行/不回归），`make check-lit` rc=0（计数现场统计）。
5. 门控：`check-isa-coverage`、`check-component-changelog`、`check_patch_tree` llvm 段 0 问题、`--source-state` llvm OK、`check_install_tools --sha-tools clang,llc,llvm-mc`、安装根 == 构建树。
6. ≥2 路注入可达 FAIL + `cp`+md5 还原。
7. 完成区 ≤30 行、无运行期路径；「修改文件」与 `git status -uall` 对账。
