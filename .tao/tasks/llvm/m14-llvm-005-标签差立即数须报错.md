## 背景（实测事实，`ISS-424`）

- `m13-testcases-019` 实测：`llvm-mc`/`clang` 把**标签差**作文**指令立即数**时**静默折成 0**、无诊断：

  ```
  aip.si rbX, . - _start        # 期望「当前 IP − 入口」，实际 imm = 0
  set.zw rbX, L1 - L0
  ```

  同现象在 `__LI` 宏与 `set.zw` 上均复现。风险：`.S` 期望值静默得到 0（假绿），内核/测试作者难察觉。
- 该行为只在**汇编期不可解析为常量**的符号差上出现；同段内已定义标签的差在必要时可用绝对常量绕过（`019` 的绕法：`ENTRY + 字面偏移`）。
- 参考实现基线：宿主 x86 `clang` 对「不可解析的重定位表达式作立即数」会给出明确诊断或生成重定位，不会静默写 0——**本任务要求 DADAO 侧至少做到「不静默」**。

## 目标

1. `llvm-mc -triple=dadao-unknown-elf` 遇到「标签差（`A - B`）作为指令立即数、且汇编期不可解析」时：**报错退出**（首选）或**生成重定位**；**禁止静默写 0**。
2. 该行为对 `clang -c`（内联汇编）同样成立。
3. 可解析的常量表达式（同段已定义标签差、`ENTRY + 常量`、纯数字表达式）**行为不变**，输出逐字节一致。
4. 诊断文案须指出「不能把符号差用作该指令的立即数」，并给出可行替代（例如「用绝对常量或运行期 `aip.si`/`rb2rb` 取 IP」）。

## 验收

1. 最小复现三条（`aip.si rb1, . - _start`、`set.zw rb1, L1 - L0`、`add.si rb1, rb1, . - _start`）在 `llvm-mc` 与 `clang -c` 上均 **rc≠0 且 stderr 有诊断**；贴原始输出。
2. 反例（必须仍 rc=0 且输出与改前逐字节一致）：纯数字立即数、`ENTRY + 0x10` 形式、同段已解析标签差（若原本可用）。
3. lit：新增 `lit/MC/DADAO/` 用例覆盖「报错」与「不回归」两类；`make check-lit` rc=0（计数现场统计）。
4. 关闭态不变：用改动前的对象作基线（`-c` 固定源，去 `.comment` 后 md5 相等），并贴反汇编 md5。
5. 门控：`check-patch-tree` llvm 段 0 问题、`--source-state` llvm OK、`check-component-changelog` rc=0、`check_isa_coverage` rc=0、`check_install_tools --sha-tools clang,llc,llvm-mc` rc=0、安装根 == 构建树。

**新发现/坑**：① 静默 0 的确切落点 = `DADAOAsmBackend::applyFixup` 的 ABS48 分支：同段标签差被 `MCAssembler::evaluateFixup` 折成绝对常量（`IsResolved=true`）后该分支直接 `return`（字段留 0、且不产生重定位）；现按指令 `wp`（`hb[5:4]`）写回 16 位 wyde（与 lld `R_DADAO_ABS48` exec 路径同口径），>48 位值改报错。② 第二处静默失败是 `add.si` 这类「无符号操作数设计」指令的 `report_fatal_error`（rc=134），parse 期统一拒绝后消失。③ 验收 1 后两条复现字面量本身语法不合法（`set.zw` 少 wyde、`add.si` 多一个寄存器），改前它们失败的原因与标签差无关。④ 另一会话并发 `make install-host` 把注入窗口内的二进制装进了共享安装根（`af6125…`），已重建 + 装回还原（`fec66e82…`），证据脚本改为**全程持仓库 gate lock**。⑤ 节点 staging 首次用 `cp` 覆盖安装根 `bin/llvm-mc` 符号链接会**沿链接写穿节点安装根**，已用节点自身构建树原件还原（md5 `b2446951…`）并改为 `rm` + 真实文件 staging。

**遗留问题**：① 待裁定项的 `[...]` 形式（`parseBranchAddress`/`parseAddressExpr`）未改，与 `parseImmediate` 统一判据须同时保住 `ld.o [rb2, L1-L0]` 的既有可用行为 ⇒ 建议单独立项。② 全局 `check_patch_tree` rc=1 的 20 条全在 gem5 16 / qemu 2 / chipyard 2（并发会话的共享组件补丁集未重导出，其 `--source-state` 均 clean/base+1），llvm 段 0。③ 节点 suite 用本轮新 `llvm-mc` + 节点既有 `ld.lld`（本轮未改链接器、对象格式不变）；节点安装根未替换（staging 树内只覆盖 `llvm-mc` 一枚）。
