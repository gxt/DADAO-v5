## 问题根源

M5（SEE/HEE 运行环境 + semihosting）已于 **2026-10-08** 达成（门槛 `make test-semihost` EXIT=0；见 `milestones.md`）。达成过程中形成了一批**明确登记、但不属 M5 门槛**的待办与遗留（见 `milestones.md`「M6 待办」条、`issues.yaml` 的 `ISS-163`–`ISS-169` 及一批 `M5`-scope 项），它们需要一个**下一里程碑**承接：

- 「`-bios` bootrom + ELF 应用」**组合加载/入口语义**未定义（`QEMU-047t` 选 raw-bin path B；ELF 分支忽略 `-bios`、`dadao_load_regions[]` 未含 RAM@0）⇒ `ISS-168`。
- RAM 基址改全 0 的 **C1 step2**（旧向量/harness/`crt0`/e2e 迁 `0` + 删旧 RAM 段 + 收紧断言）未做 ⇒ `ISS-165`。
- 一批 M5-scope `open` 项（完整调用约定、golden model、上游只读册旧口径、cfx mask 可观测性、6 探针 exit-port 等）需按 M6 主题决定去向。
- 用户点名需要一个 **「完整 LLVM」任务**（与「elf 加载」一并），但其**内涵未说明**。

⇒ 需要一个 **M6 规划 `k`**（本文件）先澄清目标、再分解；**本文件现阶段只出候选草案**。

## M6 候选范围（草案，**每条待用户裁定是否纳入 + 归属**）

> 每条格式：**一句话范围** ｜ **依据** ｜ **需用户裁定点**。**均标注「草案，待裁定」**。

### ① ELF 加载与「`-bios` + ELF」组合（`ISS-168`）

- **一句话范围**：定义「`-bios` bootrom + ELF 应用」的**组合加载/入口语义**（复位 PC = `0xffff_ffff_0000` → bootrom 初始化 → 跳 ELF `e_entry`，须定 **`e_entry` 传递方式**）；扩 **ELF loader**（`hw/dadao/dadao-machine.c` 的 `dadao_load_regions[]` 现仅含旧 RAM 段 + ROM，**未含 RAM@0** ⇒ 组合路径需扩表 + 验证）；并同步 M4 `test-elf`（path A，仅 ELF、无 bootrom）的关系。
- **依据**：用户 2026-10-08 裁定「elf 加载放在 M6，与完整 LLVM 的任务一起」（原话逐字见 `INTEG-019k` §第 8 轮）；`ISS-168`；`milestones.md`「M6 待办」；`INTEG-020t` 审阅记录「architect 前置风险评估」（选项 A/B/C 评估）。
- **需用户裁定点**：
  1. 是否**承认**「`-bios`+ELF」组合为 M6 范围（vs 维持 raw-bin 即可）；
  2. **组合加载/入口语义的 ADR 决策逐条确认**（属加载模型/外部契约变更 ⇒ 须 ADR；`AGENTS.md`「ADR decision 逐条确认」；**M5 阶段未立 ADR**，推迟至 M6）；
  3. `e_entry` 传递方式（寄存器 / 内存约定 / bootrom 内置符号）；
  4. 「ELF 应用是否也可不经 bootrom」（M4 path A 保留 vs 组合统一）。

### ② RAM@0 step2（C1，`ISS-165`）

- **一句话范围**：把**旧向量/harness/`crt0`/e2e 迁到 `0`** + **删旧 RAM 段**（`0xffff_0000_0000`）+ **收紧 `check-interface` 断言**；连带处置「既有 `EA=0 ⇒ unmapped 0x87` 向量/探针在 R3 下失效」（`tests/vectors/**`、`tools/qemu/*.py`）。
- **依据**：用户 2026-10-08 裁定「step2 随 M6」；`ISS-165`（`scope` 已 `M5→M6`）；`ADR-0004 R3` / `ADR-0020 D15`；`milestones.md`「M6 待办」。
- **需用户裁定点**：① 是否与①组合**一并**做（删旧段时点）；② 跨模块范围（`testcases`/`qemu`/`integ`/`infra`）与是否**跨模块串行**；③ 是否顺带处置 `ISS-165` 附带项（harness `FAULT_NAMES` 未扩、`0x81` 复用冻结表）。

### ③ 上游只读册 / 规范遗留（`ISS-163`、`ISS-164`、`ISS-167`、`ISS-169`）

- **一句话范围（逐条）**：
  - **`ISS-163`**：`spec/Toolchain-01 §5/§11/§13` 三处旧口径与 `contracts/opcodes.yaml` 的 `scope` 事实不符 ⇒ 须**用户授权**改上游只读册 + 同步 `sha256` 锁（`spec/Process-06`）。
  - **`ISS-164`**：cfx mask（inner/global/指令类型）与 `excp_cause_mask` 的**屏蔽路径当前不可观测**（monitor cause 全不可屏蔽）⇒ 当后续实现**带可屏蔽 cause 的 cfx**（ptw/tlb/cache/timer/uart）后须补验步骤 3/4/5。
  - **`ISS-167`**：`spec/DADAO-12 §5`（上游只读册）异常退出流程 **prose 与伪代码在「跨 cfx escape」上的措辞张力**（判据：伪代码为权威，实现按伪代码）⇒ 建议另立 spec 任务，**须用户授权** + 锁同步。
  - **`ISS-169`**：`TESTCASES-034t` 披露的 **6 个 M1/M2 期 QEMU 探针**（`006t`/`008t`/`009t`/`010t`/`012t`/`013t`）仍以 exit-port 为退出通道，未随迁 `SYS_EXIT`（退出与手算 PC 偏移交错）⇒ 重写后可移除例外。
- **依据**：`ISS-163`（用户 2026-10-08「暂登记遗留」）、`ISS-164`（`QEMU-044t` 遗留）、`ISS-167`（`QEMU-045t` 新发现②，`lessons §7.18`/`§8.12`）、`ISS-169`（`TESTCASES-034t` 披露）；`spec/Process-06`（改 `spec/` 须用户**事先**授权）。
- **需用户裁定点**：① 四项**是否纳入 M6**（或另立 / 更晚里程碑）；② **是否授权**改上游只读册（`Toolchain-01`、`DADAO-12`）——**未授权则 BLOCKED**；③ `ISS-164` 的补验是否以「实现带可屏蔽 cause 的 cfx」为前提（M6 是否含该实现）。
