## 背景

`m20-spec-001` 决定重排 cfx 的 cg/rc、删除/迁移部分 cfx，并统一每 cfx 五种原因。三方实现（QEMU/gem5/RTL）容易出现“某一方实现了某 cfx/cg/rc，另外两方没有”的静默缺口。本任务在 W1 **只从 spec/契约派生预期矩阵**，先定义“什么叫覆盖一致”，不运行引擎。

## 目标

1. 产出 cfx/cg/rc **覆盖矩阵**（数据文件 + 人类可读索引）：
   - cfxha / cfx 名 / cg / rc / 寄存器名 / 访问属性 / 复位/语义类别；
   - 平台适用性：Tiny / Vast（以及是否需要 QEMU user）；
   - 预期状态：`implemented` / `reserved` / `not applicable`。
2. 规则：
   - 某平台有实现时，其它适用平台必须实现；否则必须有 spec/契约的显式 `not applicable` 依据；
   - reserved 访问应一致报 `CFXREG`；
   - 平台专属（如 Tiny 无 PTW/cache）必须写适用性，不当作缺口。
3. 提供静态检查器骨架：矩阵覆盖所有非 reserved cfx 的 cg/rc；注入“某平台缺一行”⇒ 可判红；不依赖引擎。

## 验收

1. 矩阵行数/覆盖现场派生（不用写死）；每个 cfx/cg/rc 有唯一归属；reserved/not applicable 有依据。
2. 静态检查器 rc=0；注入“缺平台行/错状态”⇒ rc=1，`cp`+md5 还原后回绿。
3. 不改 `spec/`/契约正文、引擎源码；矩阵/检查器落点写入任务书，不写具体构建/临时路径。
4. 证据落运行期证据目录内 `run.sh`。
