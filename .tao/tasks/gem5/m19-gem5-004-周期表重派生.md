# m19-gem5-004: 重派生 `wuming_cycles.cc` 周期表（消 ISS-541）

**模块**：gem5
**项目里程碑**：M19

**可并行分片**：否

**档位**：小改
**状态**：已验证

## 背景

`m19-chipyard-003` 把 `docs/core-wuming-cycle-model.md` 与 `contracts/wuming-cycles.yaml` 同步为 `swym` 的 `1+N`，并让 `tools/gem5/gen_wuming_cycles.py --check`（yaml↔文档）通过。但 gem5 源树里**生成的** `src/arch/dadao/wuming_cycles.cc` 第 272 行 `swym` 仍是 `1u`，导致 `make check-wuming-cycles` 的 `artifact-up-to-date` 红（`ISS-541`）。

实际时延由 `wuming_latency.hh` 的 `swymCycles()` 覆盖，行为正确；本任务只把**生成物与补丁集**对齐。

## 目标

1. 用 `tools/gem5/gen_wuming_cycles.py` 重派生 `wuming_cycles.cc`（以现文档为准），确认 `swym` 行为 `1+N`、`dynamic: N`。
2. `make_patch.py gem5` 重导出该文件的补丁；`series` 数不变（不新增补丁文件）。
3. 重建 gem5，`make check-wuming-cycles` rc=0；`make check-gem5-decode` 不回归。
4. 更新 `components/gem5/changelog.md` 一条（承 `m19-chipyard-003`）。

## 验收（逐条贴真实 rc）

1. `make check-wuming-cycles` rc=0（不再只是 yaml↔文档一致）。
2. `make build-gem5` rc=0；`make check-gem5-decode` rc=0。
3. `check-patch-tree` gem5 段 0 problem；`check-component-changelog` rc=0。
4. 生成物可复现：重跑生成器后 `git -C .work/source/gem5 status` 无新增脏文件（`--check` 幂等）。
5. **可达 FAIL ≥1 路**：把 `wuming_cycles.cc` 的 swym 行改回 `1` ⇒ `check-wuming-cycles` 红；`cp`+md5 还原回绿。
6. 不改 gem5 行为代码（`wuming_latency.hh`/`isa.cc`）；版本号未升。

## 约束

独立 `git worktree`；**不提交 git**；只动 `components/gem5/**`（生成物补丁 + changelog）；共享源树按 `apply_series.py --component gem5` 重放；不接板；完成区不写具体 `.work/**` 路径。
