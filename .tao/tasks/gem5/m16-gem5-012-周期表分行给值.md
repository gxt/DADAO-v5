# m16-gem5-012: C/D 类周期表按 ld/st/ldm/stm 分行给值

**模块**：gem5
**项目里程碑**：M16
**依赖**：`m16-chipyard-004`（实测确认 `stm` 偏置与 N 无关）
**可并行分片**：否（单组件写者）
**预估**：2–3 h
**档位**：中改
**状态**：待开始

## 背景（用户 2026-11-18 裁定 + 实测确认）

用户原话：「**表格把 ld/st/ldm/stm 分为不同的行即可，不要加列。不要把简单的事情做复杂。**」

`m16-chipyard-004` 实测（362 样本、48 个 (指令,N) 格、66 个 (指令,N,beats) 格、每格方差 0）确认：**`stm` 的 +1 是每指令固定偏置、与 N 无关**；`ldm` 恒 +0。

现状（`contracts/wuming-cycles.yaml` 由 `docs/core-wuming-cycle-model.md` 生成）：C 类四行共用 `cycles: '9–10'` 区间、D 类共用 `per_element: 1 / per_beat: 8`，模型用 D 公式在 N=1 处求值得到 9（load 与 store 同值）。

## 目标（四项，按用户裁定）

1. **`ld.*` 行**：`cycles: '9'`（单值，去掉 `9–10` 区间）。
2. **`st.*` 行**：`cycles: '10'`。
3. **`ldm.*` 行**：保持 `per_element: 1` / `per_beat: 8`（N=8 → 72）。
4. **`stm.*` 行**：同系数 + **启用表内已有字段 `n_base: 1`**（常数项，N=8 → 73、N=1 → 10）。**不新增字段/列**。
5. **模型**：`wuming_latency.hh` 的 C 分支改为**直接取值**（不再用 `multiElementCycles(row, 1)`）；D 分支加 `n_base` 常数项。
6. **探针**：C/D 类容差 **±1 → 0**。

## 实现路径（按项目规范）

- 真源 = `docs/core-wuming-cycle-model.md`（§2/§3/§5）：先把 C 行改成 `9`（ld）/`10`（st），D 行补 `stm` 的 `+1` 实测注记（来源写 `实测`，引 `m16-chipyard-004`）。
- 生成器 `tools/gem5/gen_wuming_cycles.py`：C 类按 mnemonic 前缀 `ld`/`st` 取不同值；D 类把 `n_base` 从 §5 的实测图解析出来。
- 重跑生成器 ⇒ `contracts/wuming-cycles.yaml` + gem5 C++ 表（`components/gem5/patches/src/arch/dadao/wuming_cycles.{hh,cc}.patch`）。
- `wuming_latency.hh` 改 C 分支与 D 分支（`n_base` 常数项）。
- 探针（`m16-gem5-004`/`008` 一类）的 C/D 容差改 0。
