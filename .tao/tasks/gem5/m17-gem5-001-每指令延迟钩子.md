## 目标

在 gem5 加一个**默认 0** 的每指令额外延迟钩子，并证明其余行为不变。

## 范围

- `ISA::extraExecLatency(const StaticInst*)` 虚函数，默认返回 0（`src/cpu/isa.hh/.cc`）
- `TimingSimpleCPU` 非访存完成路径改为 `clockCycle(1 + isa->extraExecLatency(...))`（仅 1 行改动）
- **不得**改 `advanceInst`/取指/访存路径；`AtomicSimpleCPU` 完全不动

## 硬约束（用户 2026-11-13 裁定）

- **保留 gem5 `TimingSimpleCPU` 原汁原味**：允许在（a）钩子声明（实测落在 `src/arch/generic/isa.hh`）、（b）`timing.cc` 的**单个 hunk**（`advanceInst()` 尾部：默认 0 时走原 `fetch()` 分支 ⇒ 行为逐字节不变）、（c）`src/arch/dadao/**` 三处新增逻辑；不得改取指/访存路径的其它逻辑。
- 钩子**默认 0**：其他 ISA 与现有 DADAO 功能跑批行为必须逐字节不变。
- `AtomicSimpleCPU` 完全不动；它只作零成本基线。
- 延迟表**由 `docs/core-wuming-cycle-model.md` 现场解析生成**，手抄常量即错源。
- 参考材料只读（`.cache/refs/**`），不复制其实现。

## 待裁定

1. **钩子声明位置**：任务书写 `src/cpu/isa.hh`/`isa.cc`，gem5 v25.1.0.1 无这两个文件——`BaseISA` 在 `src/arch/generic/isa.hh`（纯头文件、无 `.cc`）。**自决**：声明放 `src/arch/generic/isa.hh`（属硬约束 (a)「钩子声明」），不新增 `.cc`。
2. **「timing.cc 仅 1 行」与「禁改 advanceInst」互斥**（需裁定）：`completeIfetch()` 非访存分支末尾调 `advanceInst()`，而 `advanceInst()` 在**同一 tick 内直接 `fetch()`**（不 `schedule`）；全文件唯一的「下一次取指」调度点就是 `advanceInst()` 末尾。**自决（临时）**：`-        fetch();` → `+ if (extra > 0) reschedule(fetchEvent, clockEdge(extra), true); else fetch();`（1 删 6 增、单 hunk；默认 0 走原 `fetch()` 分支 ⇒ 行为逐字节不变）。未采用：① 无条件 `reschedule`（字面 1 行，但默认 0 也把取指推迟 1 拍 ⇒ 违反「默认 0 行为不变」）；② `completeIfetch` 前置 `_status = IcacheWaitResponse` 再 `advanceInst`（可凑 1 行，但篡改 CPU 状态语义）。**建议**：接受该位置；若要恢复字面「1 行」，需授权后续任务在 `timing.hh` 加专用 stall 原语。
3. **钩子对访存指令也生效**：`advanceInst()` 同时被访存完成路径（`completeDataAccess`）调用。**自决**：钩子文档注明「延迟已由内存系统承载的 `ld/st` 应返回 0」；默认 0 当前无影响，m17-gem5-002 起建表时落实。
4. **Timing 侧跑不了真实 ELF**：`TimingSimpleCPU` 未实现 `readMem()`（`src/cpu/simple/base.hh` panic），DADAO `ld/st` 仍走 `xc->readMem` ⇒ 访存时序属 m17-gem5-006。**自决**：Timing 侧用无访存 guest 循环（`probe_nomem.S`）证明 numCycles 不变/注入变大；真实 ELF 的逐字节一致用 SE `AtomicSimpleCPU` 证明。

**新发现/坑**：
1. gem5 v25.1 的 `TimingSimpleCPU` 非访存完成路径**没有** `schedule(fetchEvent)`——下一次取指只在 `advanceInst()` 末尾 `fetch()`；给 TimingSimpleCPU 计拍必须改这一处（或另加 stall 原语）。
2. `TimingSimpleCPU` 未实现 `readMem()`，DADAO `ld/st` 在其上直接 panic ⇒ M17 的「访存时序」是执行模型问题（需 `initiateAcc`/`completeAcc` 拆分），不是配置问题。
3. `curStaticInst` 是 `StaticInstPtr` ⇒ 钩子形参 `const StaticInst*` 要传 `.get()`。
4. `isCpuDrained()` 含 `!fetchEvent.scheduled()` ⇒ 用 `reschedule(fetchEvent, …)` 延迟取指时 CPU 自然「未 drained」，drain/checkpoint 语义自洽。
5. 改 `src/arch/generic/isa.hh`（内联 virtual 的体）会连带 SCons 重生成 `python/_m5/param_*`；ccache 下增量重建 2.5–3 min。
