## 背景（用户 2026-11-20 裁定）

M14 做过「内核实现 vs `arch/riscv`/`arch/arm64`」的差异盘点；M16 对 gem5 做同构的事——**把我们的 DADAO gem5 实现与其它 ISA 在 gem5 中的实现逐项对比**，找出「别人有我们没有 / 我们有但做法不同 / 我们漏掉的通用机制」。

**用户明确要求**：**两个 CPU 型号（`atomic` / `timing`）× 两个机型（`tiny` / `vast`）= 4 种组合都要做**。

## 对照物（用户 2026-11-20 指定：**其它 ISA 在 gem5 中的实现**）

- **主参照**：`gem5/src/arch/riscv/**`（与 DADAO 同为 64 位、同为 RISC 形态）
- **强参照**：`gem5/src/arch/arm/**`
- **补参照**：`gem5/src/arch/x86/**`（复杂特权的做法）、`mips`/`power`/`sparc`（轻量参照）
- **不比对 chipyard RTL**（那是 `m16-chipyard-011` 三方差分的活）

## 范围

`gem5/src/arch/dadao/**`（ISA 描述、decoder、fault/interrupt、MMU/TLB、workload、stats）+ `gem5/configs/dadao/**`（`se.py`/`fs.py`），**4 组配置**（`--cpu-type {atomic,timing}` × `--profile {tiny,vast}`）。

## 要做（**只读**）

按「同类机制」逐项对照，四类差异：
1. **缺失实现**：其它 ISA 有、我们没有（如 debug、多核、SMT、`m5ops`、semihosting 的某些路径）；
2. **语义不符**：有但行为不同（异常码、TLB 失效、fault 优先级、`pstate`/`status` 处理）；
3. **旁路 / 折衷**：我们为省事走的近路（如「PTW 走查 0 延迟」「数据侧 functional」），上游是完整实现；
4. **配置缺口**：`configs/dadao` 相对 `configs/example/{se,fs}.py` 缺的通用开关（caches、checkpoint、stats 格式、`--param` 等）。

**4 组配置的差异**要单列：`atomic` 与 `timing` 在访存时序上的实现差异、`tiny` 与 `vast` 在 MMU/TLB/机型参数上的实现差异，**哪一组是「共用代码 + 参数」、哪一组是「两套代码」**。
