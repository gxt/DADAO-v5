## 待裁定

> 每条 = 事实 / 选项 / 建议 / **自决的临时处置**（不代裁，返回主会话问用户）。

1. **SE 模式补 semihosting（本任务新增的 gem5 能力）**
   - 事实：`trap cfx<any>, 0x3FFxx` 原先只在 FS 分支短路（`inst.cc` 判 `fs &&`），SE 下必然落到
     `exec/b6.cc` 的 `panic("DADAO B6: trap … SEE vector model not implemented")`；而
     Machine-v5-Tiny 应用**只能**经 semihosting 触达宿主（`spec/Machine-v5 §5`，`minimal_crt0`
     的 `SYS_EXIT` 就是 `trap cfx0, 0x3FF00`）。⇒ 「同 ELF 双跑 chipyard / gem5 se_timing」
     在没有 SE semihosting 时不可达（chipyard 只有 `WumingSemi`，gem5 SE 只有 `trap cfx0,0` 的
     SBI syscall，两者不是同一种出口）。
   - 选项：(a) 给 `DadaoSEWorkload` 加 `semihosting` 参数（默认 `NULL`）、`inst.cc` 把短路条件
     放宽为「工作负载带 responder 即可」；(b) 改用 gem5 **FS** Tiny（`fs.py`，已有 semihosting）
     做对比引擎，放弃 `se_timing` 命名；(c) 放弃「同 ELF」，改为「同程序两种 runtime」两跑。
   - 建议：(a)。默认 `NULL` 时 SE 逐字节不变（`trap` 仍到执行核 panic），FS `--semihost=off`
     仍 ILLI，属「新增可选能力」而非改语义；改动全在任务书允许的 (a)(c) 两处。
   - **自决临时处置：已实现 (a)**（`DadaoSEWorkload.py` + `se_workload.hh` + `inst.cc` 三处），
     并在 `se_timing.py` 用 `--semihost on` 显式打开；默认关。若用户选 (b)/(c)，这三处可整体回退。

2. **gem5 SE 装载 Tiny ELF 的口径（`--mem-base` + `--max-stack`）**
   - 事实：Tiny 应用链接在 SRAM `0xffff_ff00_0000`（8 MiB），而 SE 的内存范围默认 `[0, 256MiB)`；
     gem5 的栈预留固定在 `StackBase = 0x0000_FFFF_FFFF_0000`（`process.cc` 常量，`--max-stack`
     决定下界）。⇒ 要么给出 `--mem-base`（内存范围到 `StackBase`），要么改 `StackBase`（改 SE 语义）。
   - 建议：加 `--mem-base`（默认 0 = 行为不变），栈的大小由**源码里的 `StackBase` 与 profile 的 SP**
     现场推出（`max_stack = StackBase − (SP & ~0xFFFF)`），不写死。
   - **自决临时处置：已按建议实现**；代价：gem5 侧的 flat memory 比 Tiny SRAM 多出 8 MiB
     地址空间（`[SRAM+8MiB, StackBase)`），只服务 gem5 自己的 argv/env 栈，guest 不触碰 ——
     报告的「机器画像」段如实写出 `mem … 至 StackBase`。

3. **「比值」的方向**
   - 事实：任务书写「比值」未定方向。gem5 `TimingSimpleCPU` 无 icache，每条指令一次
     SimpleMemory 往返（`7+1` 拍），因此 **gem5 周期普遍是硬件实测的 1.4–7.5 倍**（比值 >1.5 是常态）。
   - **自决临时处置**：主口径 = **gem5 / chipyard（模型 / 实测）**，>1.5 的例在 §3 给归因；
     同时把 chipyard/gem5 的倒数关系写在同表（`Δ` 列），双向可读。

4. **「模型之外」的取指分量单列，不摊进逐族**
   - 事实：chipyard 的逐指令拍差**已含**取指摊销（8-beat 缓冲，跨 beat p50=1）；gem5 侧的取指
     代价在 `hooks off` 的周期里（每条指令 8 拍），无法按族拆分。
   - 建议：`gem5 模型部分 = on − off`（实测差值）与 `gem5 取指/基础 = off`（实测）分列；
     归因表把它作为独立来源项，并在正文说明「硬件侧无对应项」。
   - **自决临时处置：已按建议**；`m16-gem5-006` 已披露「取指 8-beat 二期细化」，本任务把它量化。

5. **逐族口径 = §2 的类**
   - **自决临时处置**：报告按周期模型的类（A/A2/A3/A4/B*/C/D/D′/F/G1/G2）归并；助记符级明细
     （前 12 个）留在 `compare.json` 的 `mnemonics` 字段，不入正文表格（避免逐族表过长）。
