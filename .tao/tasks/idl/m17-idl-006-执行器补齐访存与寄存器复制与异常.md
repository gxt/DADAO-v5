# m17-idl-006: 执行器补齐——访存 / 寄存器复制 / 控制流 / 异常

**模块**：idl
**项目里程碑**：M17
**依赖**：`m17-idl-005`（四方驱动与清单机制）
**可并行分片**：否（同改 `idl/idl_exec.py`，与 `007`/`008` 串行）
**预估**：2–3 h
**档位**：中改（复核 ≤40 min）
**状态**：已验证

## 背景

`idl/idl_exec.py` 现按 id 手写语义（`@sem` 注册，现场统计为 61 个），未注册一律显式 `ExecError`；不是通用 AST 求值器。本任务补本组四册全部镜像所需的 id。

范围（2026-11-22 实测缺失数；执行时用脚本重算，不采信本文数字）：
- `tests/inst/01-load-store`：28 个缺失 id；
- `tests/inst/02-reg-copy`：9 个；
- `tests/inst/05-arith-addr`：2 个；
- `tests/inst/06-control-flow`：1 个；
- `tests/inst/11-cfx`：1 个；
- `tests/inst/00-isa-design`：7 个 `pseudo_set.*` + `undi_reserved`（`set.ft`/`set.fo` 只是位写入，不属 FP 运算）。

**覆盖口径 = 上述目录的全部镜像**（含其 id 已注册但尚未进主清单的）；只补缺失 id 不够，本组 `pending` 必须清零。

## 要做

1. 按 `.idl` 正文逐 id 实现语义，函数上方注明 id 与出处册（沿用 `m17-idl-003` 风格）；
2. 本组镜像从 `pending` 移入主清单，逐例四方签名槽 + 退出码零红；
3. 覆盖四类写法：普通值、写回宽度/掩码、RAS 压弹栈、同步异常（`UNDI`/`CFXMEM` 等）；
4. 每条新增 id 复用 `tests/inst` 已有载体，不新造向量。

## 不做

- 不改已通过 id 的语义（必要修改须在完成区逐条列证据）；
- 不改 `tests/inst`、`.idl` 源、`spec/`/`contracts/`、QEMU/gem5/RTL；
- 不做 FP（阶段二）、不做 8/16 位 ALU（归 `008`）、不做 `04`/`12` 册（归 `007`）。

## 约束

- 独立 `git worktree`；不提交 git；术语「寄存器组」；
- `U04`–`U10`（`N34` 未裁）无法按正文判定的 id ⇒ 写进「待裁定」段并保持 `ExecError`，不得按 UDB/RISC-V 猜；
- 只动 `idl/idl_exec.py`、`idl/idl_exec_cases.toml`、`idl/README.md`（如需）、本任务书；
- 计数现场派生；完成区 ≤30 行。

## 验证

1. 本组全部镜像四方一致（贴例数与槽数，现场派生）；
2. 其余组无回归（`005` 的 28 例基线仍绿）；
3. **可达 FAIL ≥2**：① 改一条写回宽度（如 `rd` 高半未清零）⇒ 对应用例红；② 删一个 `@sem` 注册 ⇒ 该镜像 `ExecError` 红；`cp`+md5 还原后回绿；
4. `make check-idl` rc=0、`check-idl-parse` rc=0、`check-inst-sig` 结果不变。
