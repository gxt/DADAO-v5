**模块**：idl

**执行环境**：本地

## 背景

`m18-testcases-003` 发现 IDL 执行器仍按 ADR-0060 建模 cg9：`_op_escape`/`Machine.escape` 使用 `async_cause_id`/`saved_global`、宏 cause 17/18、cg9 五掩码；而 ADR-0061 已改为：

- 源索引 = cfxha（15/32），取消 17/18；
- cg9 七槽：`prev_run_mode/prev_cfx/cause_ip/src_frame/src_pending/vector/switch_mode`，`src_frame`/`src_pending` HW/RO；
- 掩码在 `cfx0–3 cg8 rc1`（`async_intr_mask`），按当前运行模式求值；
- 一帧多源；`cg9` 是**捕获缓冲**（每次异步进入整体覆盖、无帧活动期、无 `frame_valid`），`src_frame` 只是最近一次进入的快照、**不作有效判据**；`escape imms18=2` ⇒ 当前 cfx 的 `CFXESC`（不返回、不改 cfx/模式/cg9、不清 `src_frame`）；无 `cause_info`。

目前 IDL 侧与 spec 不一致，L2 的 IDL 比对可能假绿。

## 目标

1. `idl/tools/idl_exec.py`：`Cfx.cg9` 改七槽；异步进入写 `src_frame/src_pending`（位=源 cfxha）；一帧多源；`escape imms18=2` **恒**为当前 cfx 的 `CFXESC`（不返回、不改 cfx/模式/cg9）；mask 从当前 mode monitor `cg8 rc1` 读；删除 17/18 与 saved_global。
2. `spec/IDL-ISA… §4.6` `cfx_escape_enter`/相关语义同步 ADR-0061（cg9 七槽、src 位、mask monitor、一帧多源、escape 释放）。
3. 更新 `idl/data/exec_anchor.toml`/`idl/.manifests.toml`/`spec/.manifests.toml`（IDL-ISA）；IDL 渲染只改相关块。
4. 用 `m18-testcases-003` 的探针/向量做交叉验证；IDL 与 QEMU 对 escape/cg9 行为一致。

## 验收（逐条贴真实 rc）

1. `check-idl-sync`/`-parse`/`-exec-anchor`、`check-spec-codeblocks`、`check-contracts-*`、`check-manifests-guard` 全 rc=0。
2. `idl_exec --self-test` 覆盖：src_frame/src_pending 位 15/32、一帧多源、mask 从 monitor、无嵌套、`escape imms18=2` ⇒ CFXESC（**不**释放帧）、`3`/SBZ ⇒ ILLI；全 PASS。
3. `check-idl`（四方差分）与 QEMU 结果一致；无旧 17/18/saved_global 残留。
4. **可达 FAIL ≥2 路**：① 用旧 17/18 位 ⇒ 自检/向量红；② 把 `escape imms18=2` 实现成「返回并清 `src_frame`」⇒ 向量红；还原后回绿。
5. `make check` 与基线逐行相同；版本不变。
6. 完成区 ≤30 行；状态 → `待验收`。
