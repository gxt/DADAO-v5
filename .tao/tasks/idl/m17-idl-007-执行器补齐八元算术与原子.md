# m17-idl-007: 执行器补齐——八元算术与杂项（原子 / 位计数）

**模块**：idl
**项目里程碑**：M17
**依赖**：`m17-idl-005`（四方驱动与清单机制）；与 `006` 串行
**可并行分片**：否（同改 `idl/idl_exec.py`，与 `006`/`008` 串行）
**预估**：3–4 h
**档位**：大改（复核 ≤60 min）
**状态**：已验证

## 背景

本组覆盖 64 位算术/位操作与原子/位计数，语义分散在 `SimRISC-04`（八元逻辑、移位、乘除、`cmp`、`ext`）与 `SimRISC-12`（`ctlz`/`cttz`/`ctpop`、`lr`/`sc`、`swym`）。

范围（2026-11-22 实测缺失数；执行时用脚本重算，不采信本文数字）：
- `tests/inst/04-arith-logic-octa`：23 个缺失 id（其中 `ext.uo_orri_rd` 已由 `006` 注册 ⇒ 本任务剩 22）；
- `tests/inst/12-misc`：27 个（`lr.*` 15、`sc.*` 12、`ctlz`/`cttz`/`ctpop`/`swym` 已在其中按现场统计）；
- `tests/inst/00-isa-design/atomic_rmw`（非 id 载体，用 `lr`/`sc` + 算术）。

本任务合计 **49 个 id**（现场重算；`006` 已注册 `ext.uo_orri_rd`，**禁重复注册**）。

**覆盖口径 = 上述目录的全部镜像**（含其 id 已注册但尚未进主清单的）；本组 `pending` 必须清零。

## 要做

1. 按 `.idl` 正文逐 id 实现；函数上方注明 id 与出处册；
2. 本组镜像从 `pending` 移入主清单，逐例四方零红；
3. 原子语义按 `SimRISC-12 §1`：`lr`/`sc` 的 an/ar/nn/nr 四变体、8/16/32/64 位宽、窄读保留高位、保留清除事件按单 hart 口径；`clmul` 双目的与 `cmp` 三值按 `SimRISC-04`；
4. 位计数按 64 位 `hd` 上界；`swym` 为流水线提示（无架构副作用）。

## 不做

- 不改已通过 id 的语义；不改 `tests/inst`、`.idl` 源、QEMU/gem5/RTL；
- 不做 FP、不做 8/16 位 ALU（`008`）、不碰 `01`/`02`/`05`/`06`/`11` 册（`006`）。

## 约束

- 独立 `git worktree`；不提交 git；术语「寄存器组」；
- `ISS-440`/`ISS-443` 的保留清除事件三平台均未实现 ⇒ 本任务按「单 hart 最小可跑」口径，不扩平台差异；不一致处逐条记「待裁定」；
- `U04`–`U10` 无法按正文判定的 id ⇒ 待裁定段 + 保持 `ExecError`；
- 只动 `idl/idl_exec.py`、`idl/idl_exec_cases.toml`、`idl/README.md`（如需）、本任务书；计数现场派生；完成区 ≤30 行。

## 验证

1. 本组全部镜像四方一致（例数/槽数现场派生）；
2. 其余组无回归；
3. **可达 FAIL ≥2**：① `cmp` 三值改成 0/1 ⇒ 相关例红；② `sc` 失败不返回 0 ⇒ 相关例红；`cp`+md5 还原后回绿；
4. `make check-idl` rc=0、`check-idl-parse` rc=0。

**修改文件**：`idl/idl_exec.py`（+392/−0：49 个 id 语义 + `Machine` 保留标记三原语 + `take_exception` 清标记；已通过 id 与既有函数签名未改）；`idl/idl_exec_cases.toml`（04 整册 25 + 12-misc 26 + `atomic_rmw` 1 = 54 个镜像从 pending 迁入主清单，pending 121→67，余下全是 008 的 03/08/09/10 册）；`idl/README.md`（一段覆盖说明）；本任务书。
**验收结果**：证据脚本 = 运行期证据目录的 `run.sh`（`PLATFORMS=qemu,gem5,chipyard GATE=1`）→ `run.sh: PASS（全部检查通过）`。逐项 rc：`manifest_set`（main=155 group=62 group_ids=61 group_pending=0 sem=152）→0；`manifest_inject_reachable`（临时清单少一条）→2；`four_way` 155/155 →0；`make_check_idl` 155/155 →0；注入 A（`cmp.si` 三值改 0/1）→ rc=1 红 1 例 → `cp`+md5 还原 →0；B（`sc` 失败返回 0）→ rc=1 红 2 例 →0；C（`lr` 窄读改整寄存器写）→ rc=1 红 3 例 →0；D（删「异常进入清保留」）→ rc=1 红 1 例 →0；源码 md5 全程 `7beaadcfad63ce65598b7c5cb91c4d33`。
**新发现/坑**：① worktree 无 `.dadao`/`.work`，须按既有约定软链主工作树产物根；否则四方的 BootROM/工具链解析失败，chipyard 因 `LD_LIBRARY_PATH` 缺 `libriscv.so` 报 rc=127；② `run_inst_tiny` 的 chipyard 库根由仓库根 `.work/source/chipyard` 派生，`--chipyard` 只换二进制、不换库根；③ gem5 全四方须 `--gem5` 与 `--gem5-config` 同时给（只给前者落回不存在的默认 config ⇒ rc=2）；④ `atomic_rmw.S` 是非 id 载体，清单/语义断言须按 `contracts/opcodes.yaml` 的 id 集合派生，不能按镜像 stem 一刀切；⑤ `lr` 的「先读后清/设标记」用注入 C/D 双向验证（故障不动状态、异常进入必清）。
**遗留问题**：`ISS-440`（另一 hart 同址同宽 store 清保留）单 hart 无观测载体，IDL 不建模（见待裁定）；`sc` 偶发失败与 `swym N` 时延属规范允许的实现自由度，IDL v0 不建模；无其它未完成项。
