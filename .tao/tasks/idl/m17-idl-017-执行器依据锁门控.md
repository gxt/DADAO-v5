**项目里程碑**：M17

**可并行分片**：否

**档位**：中改（复核 ≤40 min）
**状态**：待开始

## 背景（用户 2026-11-22 裁定 B）

M17 的定位是 **golden = IDL**，但执行器是按 `.idl` 正文**手写**（`idl/tools/idl_exec.py` 的 `@sem`，FP 走 `idl_fp` 薄封装）；现有门控只核语法（`check-idl-parse`）与渲染（`check-idl-sync`），**没有任何机制保证「正文改了，实现也被复核」**——若三平台都没改，四方差分仍绿，漂移隐形。

裁定 B = 加「**依据锁**」：锁的是**实现所依据的正文**，不是语义等价。改 `.idl` ⇒ 必须显式更新锁，评审在 diff 里看到「哪些 op/库函数变了、对应实现要不要跟」。

## 要做

1. 新增 `idl/data/exec_anchor.toml`（`--update` 生成，禁手改）：
   - `[[op]]`：263 条，每条 `id` + `book`（如 `SimRISC-04.idl`）+ `impl`（Python 函数名，便于回溯）+ `sha256`（该 id 的 operation 正文：从 `# id: <id>` 行到下一个 `# id:` 之前，按 `idl_render.py` 的切分口径）；
   - `[[lib]]`：`idl/lib/*.idl` 逐文件 `sha256`（**FP 语义在库里**，只锁 operation 正文会漏掉 `ft_scale` 这类改动）；
   - `schema = 1`。
2. 新增 `idl/tools/idl_check_anchor.py`（`--check` / `--update` / `--self-test`）：
   - `--check`：现场派生 263 个 operation + lib 文件集；集合相等、无重复、每条 sha 命中、`impl` 非空；任一不符 ⇒ rc=1（sha 差异）/ rc=2（集合/结构错误），逐条打印 `id / book / expected / actual`；
   - 复用 `idl_render.py` 的 `# id:` 切分，不另写一套；
   - `--update` 重写表（评审 diff）。
3. `Makefile` 新增 `check-idl-exec-anchor`（**L1**，纯静态、<1 s，无需安装根）；`docs/Process-07` 登记 L1 行 + §7 表行。
4. `idl/README.md` 补用法与「改 `.idl` 后必须 `--update` 并复核实现」的流程。
5. 改 `.idl` 的后续任务（含 FP 口径修正）必须同时更新本表——写进 README 与 Process-07。
