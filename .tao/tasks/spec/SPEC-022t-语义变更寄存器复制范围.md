# SPEC-022t: 语义变更：寄存器复制不允许覆盖范围

**模块**：spec
**项目里程碑**：M1→M2
**依赖**：`SPEC-014t`
**状态**：已验证

## 问题描述

0.5.3 中，寄存器复制类指令的源和目的寄存器范围可以重叠，硬件按序号递增逐对处理。0.5.4 改为：**不允许覆盖范围，否则报 ILLI 异常**。

## 已确认方案（用户 2026-09-27）

- **覆盖范围定义**：源范围与目的范围**有任何交集**即报 ILLI
- **ldm/stm**：只有一组寄存器（不存在源/目的两组），不存在重叠问题，不受影响
- **cs.***（条件赋值）：只有一个寄存器，**允许相同**（如 `cs.z rd10, rd10, rd11, rd12` 中 rd10 同时出现在条件和目的中）

## 受影响的指令

| 指令 | 变更 |
|------|------|
| `ra2rd rdHB, raHC, immu6` | 新增：源范围与目的范围有交集时 ILLI |
| `rb2rb rbHB, rbHC, immu6` | 同上 |
| `rb2rd rdHB, rbHC, immu6` | 同上 |
| `rd2ra raHB, rdHC, immu6` | 同上 |
| `rd2rb rbHB, rdHC, immu6` | 同上 |
| `rd2rd rdHB, rdHC, immu6` | 同上 |
| `rd2rf rfHB, rdHC, immu6` | 同上 |
| `rf2rd rdHB, rfHC, immu6` | 同上 |

> 注意：不同寄存器组之间（如 ra2rd、rb2rd、rd2rf、rf2rd）不会有编号交集（不同 bank），所以覆盖范围只在**同 bank** 指令（rd2rd、rb2rb）中实际可触发。
