# m13-spec-001: 退出码表调整（PASS 仅 0，FAIL 扩到 1–0x7F）+ ADR-0004 就地修订

**模块**：spec
**项目里程碑**：M13
**依赖**：无（`Machine-v5` 0.4.4-rc 已生效）
**可并行分片**：否（单册单写者）
**状态**：已验证

## 用户裁定（2026-11-11，原话）

> 「machine-v5的7.1，PASS需要64个吗？是不是0为PASS，1-7f是fail更合适，这样我们可以在每个测试文件中放127个测试用例，哪个出错报哪个的号即可。而原来的PASS，除了0之外，1-3f应该都没有用」
> 「1、改；2、就地修订ADR-0004；3、1-7f都用做失败点；4、不用动riscv-tests，后续会全部改为新格式，当前这个问题不影响」

## 背景

现行 `§7.1`：`0x00`–`0x3F` = PASS、`0x40`–`0x7F` = FAIL（guest 自定义）。

问题：**PASS 只需要一个值（0）**，`0x01`–`0x3F` 这 63 个码无用途；而 FAIL 只有 64 个点，限制「一个 ELF 的检查点数」。

## 目标

1. **`Machine-v5 §7.1` 表改为：**

| 范围 | 段 | 含义 |
|---|---|---|
| `0x00` | guest | **PASS** |
| `0x01`–`0x7F` | guest | **FAIL，值 = 失败点序号 1–127** |
| `0x80`–`0xBF` | 其它 cfx | 同步异常（`bit5:0 = cfxHA`）**不变** |
| `0xC0`–`0xFF` | monitor | 同步异常（`bit5:4` 模式 + `bit3:0` 位索引）**不变** |

2. **`ADR-0004` 就地修订**：`D3`/`Consequences` 中关于 guest 分区的表述同步为新表；状态行加 `rev. 2026-11-11`；`## 修订` 节记用户裁定原话与理由。
3. **`contract-isa`**：若引用了 guest 分区（`0x00–0x3F` / `0x40–0x7F`），按 `§7.1` 同步（spec 为真源）。
4. **版本**：`0.4.4-rc` → **`0.4.5-rc`**；`manifests/spec-readonly.lock.toml` 同笔更新（只 `Machine-v5` 一行变）。
5. **工具侧核对**（只核对，不扩大）：`tools/` 中若有依赖 `0x00–0x3F = PASS` 的判定，改为「exit == 0 即 PASS」；`0x40` 偏移的解析若存在，同步。**不改 riscv-tests 语料**（用户裁定：后续整体重做）。
6. **测试设计口径**：M13 的「每个 ELF 检查点数」上限由 **63 → 127**；写进 `discussing.md` 相关条目（由 architect 转达，不由子代理改）。

## 非范围

- 不改 riscv-tests 语料（后续重做）
- 不改 `0x80`–`0xFF` 两段的编码
- 不改任何实现（QEMU/gem5/chipyard）
