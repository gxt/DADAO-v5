# SPEC-185t: spec 自包含与 README 索引迁移

**模块**：spec
**项目里程碑**：M11
**依赖**：`SPEC-184t`（已验证；`Machine-v5` D10 收口）；与 `SPEC-186t` 串行改 `manifests/spec-readonly.lock.toml`
**状态**：待开始

## 执行环境
本地；只做 spec 文档的结构性自包含与索引迁移，不改任何规范语义。

## 背景

`spec/` 各册目前存在两类问题：

1. **自包含不足**：部分册依赖 ADR、`.tao/knowledge`、其它 spec 册或外部参考仓库才能读懂；任务书/实现方需要跨多处拼接上下文。
2. **索引分散**：`spec/README.md` 的分册索引、profile 投影、阅读顺序未随 M11 新增/修订册（`Machine-v5`、`DADAO-12` 等）同步。

本任务只做“让每册能独立读懂 + README 能作为唯一索引”，不改规范结论、数值、编码、异常路由。

## 目标

1. 每册 `spec/*.md` 顶部增加统一小节「本册范围与依赖」（或等价标题），写明：
   - 本册管什么、不管什么；
   - 依赖哪些册/ADR/契约（只引仓库可跟踪路径与 `§`）；
   - 关键术语在本册内的定义位置，或指向定义册的 `§`；
   - 本册的“非执行依赖”说明（参考仓库只作溯源）。
2. `spec/README.md` 重建为单册索引，并清理旧注记（如 `NUPERM` 等已删除原因名，改为指向现行 §5.2/§5.3）：
   - 全部分册清单（编号、标题、范围一句话）；
   - 两个 profile（Tiny/Node）的册子投影；
   - 推荐阅读顺序；
   - 与 `contracts/`、`.tao/contracts/` 的投影关系；
   - 已知缺口/未定项指针（不复制正文）。
3. 只改文档结构；任何规范语句的“应当/必须”、数值、编码、表项、异常语义**零改动**。

## 接口规范

### 1. 分册头

- 在每册版本行之后、正文之前插入「本册范围与依赖」小节；不改变现有 `##`/`###` 编号。
- 依赖引用格式统一为 `` `spec/<册>.md §x` `` / `` `ADR-00xx` `` / `` `contract-*.md §x` ``；不写具体运行期路径。
- 不复制其它册的规范正文；只做定义/指针，避免双真源。

### 2. `spec/README.md`

- 单册清单必须与 `spec/*.md` 实际文件一一对应（脚本枚举，不手写漏项）。
- profile 投影以 `Machine-v5`/`DADAO-12` 的现行口径为准；不新增 profile、不改 profile 语义。
- 不把 `tests/`、`components/` 的实现细节写成规范。

### 3. 锁与门控

- 改到的册同笔重算 `manifests/spec-readonly.lock.toml` 的 `sha256` 并写授权注记；未改册 sha 不变。
- 与 `SPEC-186t` 严格串行改锁；本任务不得在 `SPEC-186t` 未收口时并发改锁。

## 范围 / 非范围

**在范围内**：`spec/*.md` 的册头小节、`spec/README.md`、`manifests/spec-readonly.lock.toml`（仅改动册）、本任务书、`milestones.md`。

**不在范围内**：任何规范语义/数值/编码/异常路由；`contracts/**`、`.tao/contracts/**`、`.tao/adr/**`；`components/**`、`tests/**`、`tools/**`、`Makefile`；`docs/**`、`.tao/archive/**`。

## 验收标准

1. 分册头覆盖：`spec/*.md` 每册恰有 1 个「本册范围与依赖」小节；脚本枚举文件数与节数相等。
2. 语义零改动：`git diff` 只新增册头/索引，不改任何既有规范行；脚本比对“去掉新增小节后的正文”与基线逐字相等（按册）。
3. README 索引完整：`spec/README.md` 的册清单与 `spec/*.md` 文件一一对应；两个 profile 投影、阅读顺序、contract 投影三节存在且可机械解析。
4. 锁：改到的册 sha 与 `sha256sum` 逐字相等；未改册 sha 不变。
5. 门控：`make check-spec-readonly`、`check-spec-refs`、`check-spec-drift`、`check-spec-numbering`、`check-spec-purity`、`check-spec-cite-targets`、`check-spec-codeblocks`、`make check`（L1）rc=0。
6. 反例可达 FAIL：删一册的册头 / 改 README 清单少一册 ⇒ 断言 FAIL；`cp`+`md5sum -c` 还原后回绿。
7. 体例：完成区 ≤30 行；状态 `待验收`。
