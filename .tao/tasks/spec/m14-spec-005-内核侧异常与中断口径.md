## 背景

K2 的实现（`m14-linux-006`/`007`/`008`）要消费四条**当前只在 spec 层零散存在、契约层未归一**的口径，若不先钉住，内核与 QEMU 会各自猜：

1. **`excp_cause_info` 的覆盖范围**：`spec/Machine-v5 §4.4` 只规定 5 类（`CFXMEM`/`ILLI`/`UNDI`/`MALIGN`/`IALIGN`）的 `info`，其余按 `spec/DADAO-13 §2`（11 项）且「未规定者为 0」；`.tao/contracts/contract-see.md` 无此表。内核的 cause 分类/诊断打印要靠它。属 `discussing.md` 「M12 未决」遗留项之一。
2. **`escape` 的返回 cfx**：异常帧不保存 `prev_cfx`，`spec/Machine-v5 §4.2` 已给出结论（目标 cfx 恒为当前 cfx），但契约层只有「`cfxha` 必须是当前 cfx」一句，没有「跨 cfx 返回不存在」的显式推导。同属 M12 遗留（`discussing.md` 「M12 未决」）。
3. **异步中断的内核入口**：`contract-see §3` 已定「目标 cfx 直接投递、不经 monitor 中转、mask 位索引 = 目标 cfxha、pending 在目标 cfx `cg5 rc5`、mask 写/`escape` 后重踢」，但**没有**写出「内核在 `supv` 期收到 `TIMER` 时，入口寄存器 = `cfx_hart` 的 `<supv>_excp_vector`（`cg2 rc10`）/ 模式取 `cg2 rc8`」这一条落地事实——这是实现者最容易猜错的一处（会误以为进 `cfx_smon`）。
4. **内核侧 IE（中断使能）口径**：硬件只有 mask（当前 cfx 的 `<mode>_cfx_intr_mask` + 当前 mode monitor 的 `global_cfx_intr_mask`），**没有**状态寄存器里的 IE 位。内核 `local_irq_save/restore` 必须映射到某一只旋钮，且不得与「异步帧内硬件把 monitor 的 global mask 置全 1、`escape` 恢复」冲突。

本任务**只改契约口径**（`.tao/contracts/`），不实现、不改 `spec/`、不改组件。

## 目标

在 `.tao/contracts/contract-see.md` **新增 §6「内核侧异常与时间（v5 扩展，M14 K2）」**（体例照 `contract-syscall.md §8`–`§11` 的 v5 扩展节：条目 + 来源标注 + `[spec-decision]`），附录 A 增一行；该文件目前**没有**「变更记录」节 ⇒ 在附录 A 之后按 `contract-syscall.md §12` 的体例**新建**一节并追加本条。逐条内容：

1. **`excp_cause_info` 表**：11 项 cause（`CFXTRAP`/`CFXMEM`/`CFXREG`/`CFXESC`/`CFXPERM`/`ILLI`/`UNDI`/`RASOF`/`RASUF`/`MALIGN`/`IALIGN`）逐项写 `info` 的语义与单位（访存地址 / 指令编码 / `IP` 值 / 预备压栈返回地址 / 全零），并写明「本表之外为 0」；`TIMER`（`cfx_hart`）`info = 0`。来源：`Machine-v5 §4.4`（5 项）+ `DADAO-13 §2`（11 项）+ `DADAO-12 §4.7`（TIMER）。
2. **`escape` 返回 cfx 恒为当前 cfx**：明确「异常帧不含 `prev_cfx`，跨 cfx 返回不存在 ⇒ 内核 trap 入口只允许 `escape <当前 cfx>`；`cfxha != inner_cfx_code` ⇒ `CFXESC`」；并写明「`cg5 rc3`（`excp_cause_ip`）软件可写 ⇒ 内核可在 `escape` 前改写返回 IP，`escape` 的 `imms18 ∈ {0,1}` 只提供 `+0/+4` 两种偏移」（`DADAO-12 §3.6`、`§5.1`）。
3. **异步中断的内核入口**：`TIMER`（`1<<10`，目标 `cfx_hart`）在 `supv` 期投递时，vector 取 `cfx_hart` 的 `supv_excp_vector`（`cg2 rc10`，写值忽略低 2 位）、目标模式取 `cfx_hart` 的 `supv_switch_run_mode`（`cg2 rc8`，复位 `2 = supv`），帧在 `cfx_hart` 的 `cg5`；`escape cfx_hart, [excp_cause_ip, 0]` 即原地续跑（异步 `cause_ip` = 下一条指令地址）。同时写明「异步帧建立时硬件把**当前 mode monitor** 的 `global_cfx_intr_mask` 置全 1、`escape` 恢复并重踢 pending」⇒ 内核**不得**把该寄存器当软件 IE 旋钮。
4. **内核侧 IE 单旋钮**：`local_irq_disable/enable/save/restore` 映射到**当前 cfx 的 `<mode>_cfx_intr_mask`**（内核 = `cfx_smon` `cg2 rc4`，`supv` 行），位索引 = 目标 cfxha；`save` = 读回该寄存器、`restore` = 写回保存值；屏蔽期事件由硬件记 pending、解除后补投（**不**自建软件 pending）。
5. **内核时间口径（指针 + 仅补缺口）**：`cfx_time`（`cg10 rc0/rc1`，1 GHz、1 count = 1 ns）与 `cfx_hart` 定时器（`cg8 rc4/rc5`，`cmp` 为绝对时间、写 `cmp` 取消旧 deadline 并清 `TIMER` pending、`IMASK=1` 只置 pending 不投递）——已由 `§3` 冻结者**只写指针**；本节只补「内核可直接 `cfx2rd/cfx2rc` 读写这两个 cfx 的这部分寄存器（**前提是固件已按两轴放行、`hypv_cg_reg_deleg` 已开**）」与「`escape` 后 pending 补投不需要软件干预」。
6. **职责边界**：本节只归一化 v5 内核侧口径，不重定义上游语义；`spec/` 正文不改（`check-spec-readonly` 锁不动）。

§6 的 cause 表须写成**可被脚本逐项解析**的形态（一个 cause 一行、列固定），供 `m14-linux-009`（K2 收口门控）复用为静态断言——本任务不建门控、只保证可解析。
