# spec/ — 规范总索引

## 定位说明

- **规范＝内容层 / 唯一真源**：描述"应当是什么"，面向人阅读，允许歧义与自然语言；v5 自定**技术规范**（`Toolchain-01`/`Machine-01`）属**持续修订**的活规范，由 spec 模块任务按变更流程修改。
- **投影＝实现依据**：投影把规范**归一化**为机器/agent 可精确消费的形态，是实现的直接依据。投影分两层：
  - **机器可读数据**（编码表/ABI/合法性规则等），供工具消费；
  - **叙述型合约**（§ 编号 + `[spec §x]` 引用），供人/agent 阅读。
- **本目录同时含上游基线与 v5 自定技术规范**：`SimRISC-00…12`、`DADAO-11…23` 为**上游基线**（spec 模块任务可改上游并生成新版本）；`Toolchain-01`、`Machine-01` 为 **v5 自定技术规范**。二者同处一目录，取消历史上"原始规范 vs v5 规范层"的二分。
- **ADR 不在此目录**：架构决策记录（ADR）属**决策层**；ADR 只记决策、理由、被否方案与指向规范章节的指针，**不承载规范正文**。

## 投影表

投影落点属实现层，不在 spec 目录维护。

## 规范修订流程

轻量五步（不强制记 ADR）：

```text
1. 改规范（spec/）
2. 重算投影
3. 门控查漂移
4. 缺口登记（投影缺失者登记，若有）
5. 不强制记 ADR —— 仅「多方案取舍 / 外部契约 / 取向改变」才记
```

> **前置（MUST）**：改 `spec/` 任何册（含 v5 自定册与 `spec/README.md`）须**用户事先授权**；上游只读册另有 `sha256` 锁门控（`make check-spec-readonly`，已纳入 `make check`）。

## 册维护约定

> 本节只写 **`spec/` 目录特有**约定（标题编号 / 版本与变更记录）。

- **标题编号**：`##`→`N`、`###`→`N.M`、`####`→`N.M.K`（最深 `####`）；同册**唯一、连续、父节逐级**；**禁单包装层**（正文 `##` 恰 1 个且其下 `###` ≥2 ⇒ 应拍平）。**册内引用**只写 `§<标题文本>`（不带节号）；**跨册引用只写手册名**（不带 `§`、不带节号）。机器可读数据的 `spec_cite` 用 `手册: 助记符`（指令类）或 `手册: 小节标题`（非指令类）。门控：`check_numbering` / `check_spec_cite_targets`。
- **无编号尾段（固定顺序）**：`## 附录 A：汇编指令速查` → `## 附录 B：合法性检查` → `## 附录：版本与变更记录`。A/B 为 `SimRISC-01`…`12` 的生成区（A 单表、无 `###` 子标题、无分类列；B 落合法性清单），**必在册尾**且 A 在 B 前；`SimRISC-00` 无 A/B。门控：`check_numbering.py` / `check-asm-list-consistency` / `check-legality-drift`。
- **纯净化**：`spec/SimRISC-*` 只写规范内容（指令定义 / 编码 / 格式 / 语义 / 异常 / revision）；**禁** `scope` 范围标注、里程碑号、任务号、`ADR`/`ISS` 号、按范围的条数总账、旧表名前缀。门控：`check_spec_purity`。
- **`附录：版本与变更记录`**：二级标题、**不加编号**、**逆序**（最新在上）；三级标题 = `### <版本>（<发布日期>）`；顶部累积段 = `### <上一发布版本 z+1>-rc（未发布）`。**不用表格**；**变更记录集中于 `SimRISC-00`**（13 册条目按版本合并去重），`SimRISC-01`…`12` 不再单列；DADAO / Toolchain / Machine 各册仍各有一条。门控：`check_spec_changelog`。
- **发布动作**：把顶部 `-rc` 段去 `-rc` 并补发布日期；`-rc` 段只在确有未发布改动时新开。
- **版本号语义**：`x.y.z`——**`x=0` 表示尚未正式发布**（正式发布后 `x≥1`）；大改动 `y+1`、有影响的小改 `z+1`。
- **互锁组**：`SimRISC-00`…`SimRISC-12` 一组，`AEE↔ABI`、`SEE↔SBI`、`HEE↔HBI` 各一组；**组内版本必须一致**。
- **只读册纪律**：21 册以 `sha256` 锁定；改册须**用户事先授权原话** + **同一变更内更新锁**。
- **改动记录粒度**：**聚合**（按版本段）、**不限条数**、**不带任务号 / ADR 号**（只写"改了什么"）；"加记录"动作本身不引发 `-rc`。

## Rationale

本改造成立的条件与取舍如下（不立 ADR，理由与被否方案记录于此）：

- **为何把 spec 子目录合并进 `spec/`**：消除「原始规范 vs v5 规范层」的二义，使**单一目录＝单一真源**；引用不再需要在两处之间跳转或判断优先级。
- **为何 `SimRISC-*.md` / `DADAO-*.md` 不搬家**：保持与上游生成流程「spec 模块任务可改上游规范」的名称对应关系；上游按本规定生成新版本文档时，文件名与目录不变。
- **为何取消拆分独立的 cfx 规范分册**：cfx 系列别名与 DADAO 汇编同属「汇编语言」这一主题，**不应拆分**；cfx 约定正文并入 `Toolchain-01`，而 cfx **别名表**属**投影层**，不进 `spec/`。
- **为何生成物进投影层**：生成的别名表/指令表是**实现的依据**，须与规范正文分离，才能被漂移门控（`make check-cfx-aliases` 等）机械校验；规范正文保持人工可读。
- **为何不立 ADR**：本改造属**文档组织与流程取向**（目录合并、命名、索引与投影表），不涉及不可逆的架构取舍或多方案外部契约；被否方案（如保留 spec 子目录、把 cfx 拆为独立规范分册）已记录于本节，故不立 ADR。
